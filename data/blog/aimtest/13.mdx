> 대부분의 기능이 마무리되고 나니, 이제 눈에 띄는 건 ‘로딩 순간’이었다.
>
> 게임 화면이 열릴 때, 검은 캔버스와 메뉴 UI가 맵보다 먼저 나타나는 걸 보고 있었다. 대체로 짧은 순간이었지만 계속 거슬렸다.
>
완성도 있는 UI는 절대 이런 틈을 허용하지 않을 것이다. 본래는 전반적인 색상 기반 디자인을 손보려 했는데, 결국 이번 작업엔 로딩 컴포넌트를 추가하기로 했다.
> 

---

## 1. 문제 인식 – 맵보다 먼저 뜨는 검은 화면

게임의 구조상 `GameWorld` 컴포넌트는 메인 페이지에서 모드를 선택하고 진입하는 즉시 렌더링된다.

즉, 사용자가 시작 버튼을 누르기 전에도 이미 맵과 메뉴를 포함한 전체 레이아웃이 준비된 상태여야 한다.

그런데 가끔 SVG 맵 이미지가 로딩이 늦을 때, 화면이 아래처럼 보였다.

- 배경은 새까만 캔버스
- 메뉴 패널은 이미 나타남
- 타겟 컨테이너의 빨간 테두리는 먼저 보임

지금껏 눈치채지 못하고 넘어갔던 그 짧은 순간, 문득 눈에 들어온 그 장면을 보고는 그냥 지나칠 수가 없었다.

맵을 게임 창을 열기 전에 미리 다운 받아놓는 방법도 있지만 절대 효율적이지 않은 방법일 것이기 때문에, 나는 **이미지 로딩 완료 전에는 다른 요소를 보이지 않게** 해야겠다고 결정했다. **로딩 UI**를 추가하는 것이다.

---

## 2. 첫 시도 – 단순 로딩 오버레이 추가

처음엔 단순히 로딩 스피너를 띄워 가리기로 했다.

별도의 훅을 통해 이미지 상태를 추적하고, 아직 로드되지 않았다면 로딩 컴포넌트를 보여주는 식이다.

```tsx
<LoadingOverlay imageStatus={imageStatus} />

```

Tailwind와 Framer Motion을 함께 써서 기본적인 페이드 인/아웃 애니메이션도 적용했다.

생각보다 금방 구현됐고, 로딩 중엔 스피너가 잘 표시됐다.

그런데 또 예상치 못한 문제가 발생했다.

---

## 3. 두 번째 문제 – 먼저 그려지는 컨테이너와 메뉴

로딩이 끝나기 직전, 아주 짧은 순간 빨간 타겟 컨테이너가 번쩍하고 나타났다. 그리고 메뉴도 처음 화면 진입 시 애니메이션이 보여야 하는데, 로딩 화면인 동안 먼저 애니메이션이 실행되어서 보이지 않는 문제도 있었다.

`LoadingOverlay`가 정상적으로 화면을 덮고 있는데도, 맵 로딩 직후 캔버스 렌더 루프가 먼저 돌면서 정적으로 그려놓은 타겟 컨테이너가 보여버리고 메뉴도 렌더링 되어버리는 것이다.

렌더 루프보다 먼저 로딩 화면이 보이도록 단순히 순서를 앞당기면, 캔버스 컨테이너가 설정될 때 크기 인식을 제대로 하지 못했고 이를 수정하려면 상당한 노력이 필요해 보였다.

그건 내 수준으로는 오히려 더 비효율적인 방법이라고 생각했고, 다행히 더 간단한 방법이 있었다.

캔바스 컨텍스트는 먼저 설정하되, **렌더링 자체를 제어**하면 된다.

---

## 4. 해결 방법 – 이미지 상태를 기반으로 렌더링 제어

문제를 확실히 해결하려면 단순히 “덮는 것”이 아니라,

**무엇이 언제 렌더될지를 논리적으로 제어해야 했다.**

그래서 맵 이미지 로딩을 담당하는 훅 `useImageLoader` 에서 로딩 상태(`imageStatus`)를 밖으로 배출시키고, 이 상태를 추종하는 새로운 상태 `showMenu`를 만들었다.

그리고 이 `showMenu`를 기반으로 맵이 완전히 로드된 후에만 메뉴나 컨테이너가 렌더되도록 했다.

```tsx
const [showMenu, setShowMenu] = useState(false);

useEffect(() => {
  if (imageStatus === 'loaded') {
    setShowMenu(true);
  }
}, [imageStatus]);

```

그리고 렌더 루프 내부와 주요 UI 조건에 이 값을 추가했다.

```tsx
if (!showMenu) return; // 렌더 루프 조기 종료

{showMenu && (
  <StartMenu ... />
)}

```

결과적으로 맵이 로드되기 전에는

- **렌더 루프가 실행되지 않고**,
- **타겟 컨테이너나 메뉴도 보이지 않게** 되었다.

이제는 어떤 환경에서도 로딩 스피너 → 맵 → 메뉴 순으로 자연스럽게 전환된다.

---

## 5. 로딩 오버레이 개선 – 반응형 & 시각 완성도

마지막으로 로딩 컴포넌트 자체를 반응형으로 다듬었다.

화면 크기에 따라 스피너 크기와 폰트 크기를 단계적으로 확장해 전체화면에서도 답답하지 않게 했다.

```tsx
<div className="pointer-events-auto absolute inset-0 grid place-items-center bg-[#1a1a1a]">
  <div className="grid place-items-center gap-2 sm:gap-3 md:gap-4 lg:gap-5">
    <div className="h-8 w-8 animate-spin rounded-full border-[3px] border-green-300 border-t-green-500 sm:h-10 sm:w-10 sm:border-4 md:h-12 md:w-12 lg:h-14 lg:w-14 xl:h-16 xl:w-16" />
    <div className="text-xs font-semibold tracking-wide text-green-500 sm:text-sm md:text-base lg:text-lg xl:text-xl">
      Loading map…
    </div>
  </div>
</div>

```

기본 페이지 색상과 같게 해서 이질감이 들지 않도록 했다. 로딩이 끝나면 페이드 인으로 자연스럽게 캔바스가 이어지도록 색상을 설정했다.

## 6. 정리

단순히 로딩 스피너를 띄우기만 하는 작업일 거라고 생각했는데, 생각보다 많은 시간이 들어갔다.

**렌더링 타이밍 제어**, **로딩 상태 추적**, **시각적 전환 완성도**까지 다뤄야 했기 때문이다.
특히 렌더링 타이밍을 조정하기 위한 방법을 여러 가지 시도하는 과정이 조금 오래 걸렸다.

그래도 결과적으로 화면이 아래처럼 자연스러워졌다.

- 로딩 중: 스피너 + 맵과 이어지는 밝은 회색 배경
- 로드 완료: 맵 페이드 인 → 메뉴 애니메이션 동작
- 게임 시작 후: 완전한 전환

사소한 로딩 화면 하나지만, 검정 플래시와 붉은 직사각형이 보이지 않자 체감되는 완성도는 훨씬 커졌다.
