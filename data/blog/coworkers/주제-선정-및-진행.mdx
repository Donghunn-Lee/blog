## 1. 주제 선정

팀 미팅에서 결정된 코드잇에서의 마지막 프로젝트 주제 

**Coworkers** 
![](/static/images/velog/11c03cdd-cc64-487f-bda5-6966400c2cae-image.png)

```
업무 배정 및 현황 공유 서비스 구축을 목표로 하는 팀 단위 일정 관리 서비스.

실제 업무 프로세스에 최적화된 To-do 리스트 형태로

업무 생성, 공유, 현황 지표를 가시적으로 확인 할 수 있는 기능을 구현합니다.
```

## 2. 주제 선정 이유
난이도가 높은 주제였고, 높은 만큼 개발 역량 향상에 도움이 될 것이라는 의견.

일정 관리 서비스를 구현해보고자 하는 팀원들이 다수 있었고, 의견을 수렴하여 주제를 선정.

## 3. 프로젝트 진행 계획
### 1) 프로젝트 초기 환경설정
Next 프로젝트 생성 및 Tailwind CSS, TypeScript 관련 플러그인, ESlint 등 미팅 중 논의하여 결정.

추가로 Repository, Team 및 GitProject 생성까지 팀장인 내가 맡아 진행.

### 2) 공통 컴포넌트 개발

  만들 수 있는 공통 컴포넌트와 공통 작업을 먼저 분리하여 역할 분배.
  - InputField
  - TextField
  - Button
  - GNB(global Nav Bar) & SideBar
  - ImageUpload
  - DropDown
  - Modal
  - API 구현
  - global.css
  - 전역 상태관리(zustand)

  
+) API의 경우엔 모든 api를 작업 초기 단계에서 한 사람이 개발하여 통일성을 갖추고, 문제가 되는 테스트 속성은 없는지 조기에 발견할 수 있도록 함.

  
3) 페이지 분배
 - 팀원 1
   - 리스트 페이지
   - 리스트 상세 페이지
 
 - 팀원 2
   - 자유게시판 페이지
   - 게시글 상세 페이지
   - 게시글 작성 페이지
 
 - ***팀원 3 (본인)***
   - 로그인 페이지
   - 회원가입 페이지
   - 계정 설정 페이지
 
 - 팀원 4
   - 팀 페이지
   - 팀 생성/수정/참여 페이지
 
 - 팀원 5
   - 랜딩 페이지
   - 마이 히스토리 페이지
   - No-Team 페이지


### 4) 진행 방식

- 매일 오후 1시 팀미팅을 진행
진행상황 브리핑, 이슈 공유, 논의 사항 검토 순으로 이야기하며 회의록 작성

- git-flow 전략 채택
