React Query를 처음 사용했을 땐 이것의 어떤 점이 효율적이며 편리한지 잘 이해하지 못했었다. 하지만 조금 더 복잡한 데이터 처리가 이뤄져야 하는 상황을 맞닥뜨려보니, 서버 상태 관리를 제대로 하는 것과 하지 않는 것의 차이가 생각보다 크다는 것을 알 수 있었다.

## 1. React Query 리엑트 쿼리란?

리엑트에서 상태 관리를 위한 도구로는 리엑트에 내장된 **Context API, Redux, Recoil**등이 있다. 이들은 `useState`로 만들어진 상태들을 관리하며, 클라이언트 상태와 서버 상태를 같이 관리할 수 있다.

리엑트 쿼리란 **서버 상태(ServerState)**를 관리하기 위해 나온 라이브러리다. 사실 현재는 **Tanstack Query**로 그 명칭이 변경됐지만, 아직 React Query라고 부르는 경우도 많이 있다.

그렇다면 상태 관리 도구들이 있고, 여기서 서버 상태 역시 함께 관리할 수 있는데도 리엑트 쿼리가 필요했던 이유는 무엇일까? 서버 상태 관리는 무엇일까?

---

## 2. 서버 상태 관리

### 서버 상태 관리
서버 상태 관리란 **서버에 있는 데이터를 클라이언트 애플리케이션에서 효율적으로 다루는 것** 을 의미한다. 단순히 데이터를 가져오는 것을 넘어 비동기적으로 처리되는 데이터 요청 과정을 관리하고, 데이터를 캐싱하며, 서버와의 데이터 동기화를 위해 갱신하는 등의 동작을 관리하기 위해 각각의 상태를 만들어 처리 과정을 간소화하기 위해 만들어진 개념이다.

이 동작들은 서버와 통신에 따라 상태가 결정되기 때문에, 클라이언트 상태 관리 도구로 서버 상태를 관리하는 것에는 한계가 있다. 어째서 그런 것인지 서버 상태의 특징을 살펴보자.

### 서버 상태의 특징

#### 1) 제어 불가능
서버 상태는 클라이언트에서 제어할 수 없는 원격의 공간, 즉 데이터베이스나 외부 API에 존재한다. 요청의 성공/실패 여부를 정확히 예측할 수 없기 때문에, 클라이언트에서는 단순히 데이터를 가져오는 것 외에도 **로딩, 에러, 데이터 없음** 등의 다양한 상태를 고려해야 한다.

#### 2) 비동기적
데이터를 가져올 때 클라이언트는 네트워크를 통해 데이터베이스와 통신한다. 때문에 항상 비동기적이고, 이는 클라이언트 상태와 갱신 주기가 다름을 의미한다. 데이터 요청 후 응답이 오기까지 `로딩 중` 을 알리는 UI를 보여줘야 하며, 요청 완료 후에는 최신 상태로 업데이트해야 한다. 클라이언트에서 이 동작을 처리하려면 복잡한 설정이 필요하다.

#### 3) 공유 자원
여러 컴포넌트가 같은 데이터를 필요로 할 때, 각 컴포넌트가 개별적으로 API를 호출하면 **불필요한 중복 요청**이 발생한다. 또 한 컴포넌트에서 데이터를 수정하면 다른 곳에서도 즉시 변경사항이 반영되어야 하는데, 이를 수동으로 클라이언트에서 동기화 하는 것은 어려우며 비효율적이다.

#### 4) 오래된 정보 가능성
클라이언트의 상태는 오직 사용자와의 상호작용으로만 변경되지만, 서버 데이터는 언제든지 다른 사용자 등에 의해 변경될 수 있다. 클라이언트가 오래된 데이터를 가지고 있다면 최신이 아닌 데이터를 보여줄 수 있기 때문에 주기적으로 갱신할 필요가 있는데, 이는 성능 저하를 초래할 수 있다.

>*요약하자면, **서버 상태 관리**란 비동기적이고, 제어 불가능하며, 시간이 지나면 오래될 수 있는 서버 데이터를 클라이언트에서 안정적이고 효륭적으로 사용할 수 있도록 돕는 일련의 기술과 전략이다.*

## 3. 리엑트 쿼리가 해결하는 문제
앞서 살펴 본 서버 상태 관리가 필요한 서버 상태의 특징들을 생각하면서, 리엑트 쿼리가 어떤 문제들을 해결하고 편리함을 제공하는지 살펴보자.

### 1) 데이터 캐싱
리엑트 쿼리는 같은 요청을 여러 컴포넌트에서 반복 호출하지 않도록 한다. 받아온 데이터를 캐싱하며, 같은 데이터를 요청하는 경우 새로운 요청 없이 캐시에서 즉시 데이터를 제공한다.

### 2) 로딩/에러 상태 관리 자동화
사용자가 일일이 로딩, 에러 발생 등의 상태를 만들어 관리할 필요 없이, 리엑트 쿼리는 각각의 상태를 제공한다.

### 3) 리페치 및 무효화
리엑트 쿼리는 데이터를 변경하고 나면 기존의 캐시를 무효화하고, 새로운 데이터를 자동으로 요청해서 다시 캐싱한다. 수동으로 캐시를 무효화하여 데이터가 업데이트 되도록 하는것도 가능하다.

#### 4) 백그라운드 업데이트
데이터가 변경되었을 때, 기존엔 수동으로 다시 데이터 요청을 수행하거나 상태를 업데이트해서 화면을 갱신해야 하지만 리엑트 쿼리는 오래된 데이터를 우선 보여주면서 동시에 최신 데이터를 요청하여 사용자 경험을 향상시킨다. 데이터가 비어있는 상황을 줄여준다는 얘기다.

##### 5) 쿼리 키 관리
리엑트 쿼리는 각 데이터에 키를 지정하여 관리한다. 같은 키는 같은 데이터로 취급하며, 키를 사용해 간편하게 데이터를 요청할 수 있다.

## 4. 기본 사용법

### 1) 키 생성 및 데이터 요청

```tsx
import { useQuery } from "@tanstack/react-query";
import axios from "axios";

function Todos() {
  const { data, isLoading, isError } = useQuery({
    queryKey: ["todos"],
    queryFn: () => axios.get("/api/todos").then(res => res.data)
  });

  if (isLoading) return <p>로딩 중...</p>;
  if (isError) return <p>에러 발생!</p>;

  return (
    <ul>
      {data.map(todo => (
        <li key={todo.id}>{todo.title}</li>
      ))}
    </ul>
  );
}
```

- `queryKey` : 캐시 식별자
- `queryFn` : 데이터를 요청하는 함수
- 반환값 : `data`, `isLoding`, `isError`, `refetch` 등

### 2) Mutation (데이터 수정)
```tsx
import { useMutation, useQueryClient } from "@tanstack/react-query";

function AddTodo() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: newTodo => axios.post("/api/todos", newTodo),
    onSuccess: () => {
      queryClient.invalidateQueries(["todos"]);
    }
  });

  return (
    <button
      onClick={() => mutation.mutate({ title: "새 할 일" })}
    >
      추가
    </button>
  );
}
```

- mutation : `POST`, `PUT`, `Delete` 같은 쓰기 작업
- 성공 시 `invalidateQueries` 로 기존 캐시 무효화 -> 최신 데이터로 자동 갱신

### 3) 기타 고급 기능
- **Stail Time & gcTime(Cache Time)**: 데이터 신선도 조절
- **Prefetching**: 라우팅 전에 데이터 미리 불러오기
- **Infinite Queries**: 무한 스크롤 데이터 관리
- **Optimistic Update**: 서버 반영 전 UI 먼저 업데이트

## 5. 리엑트 쿼리의 장단점
장점이 훨씬 많은 리엑트 쿼리이지만, 그래도 주의점 정도는 있다.

### 장점
- 서버 상태 관리 단순화
- 캐싱 및 자동 리페치로 UX 개선
- 로딩/에러 상태를 깔끔하게 처리
- TypeScript와 궁합 좋음

### 단점
- 학습 비용 존재
- 전역 상태 관리 도구는 아님
- 캐싱 전략을 잘못 세우면 데이터 불일치 가능성 있음.


## 6. 정리
**React Query**는 **서버 상태 관리 라이브러리**다.
일반적인 상태 관리 도구가 클라이언트 상태(UI, 폼 값, 토글 등)를 다루는 반면, React Query는 **데이터 패칭·캐싱·동기화와 같은 서버 상태 관리**에 특화되어 있으며 **서버와 클라이언트 간의 데이터 일관성을 유지**하는 데 강점이 있다.

즉, **로딩/에러 상태 관리, 캐싱, refetch, 데이터 무효화** 같은 **반복적이고 복잡한 로직을 추상화**해 개발자가 비즈니스 로직에 집중할 수 있게 도와준다.
