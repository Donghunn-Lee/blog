React를 사용한다는 것은 React Hook을 쓰기 위함이라 해도 틀린 말이 아니다. 그만큼 Hook이라는 리엑트의 시스템은 리엑트에서 중요한데, 아무렇지 않게 이것 저것 써 왔지만 사실 나는 Hooks가 왜 만들어졌고, 어떻게 구성되어 있으며, 어떤 방식으로 동작하는지 전혀 모르고 있었다. 커스텀 훅을 만들어 보기도 했지만 훅을 제대로 모르는 상태였다면, 앞으로 더 좋은 훅을 만들고 잘 사용하기 위해 훅에 대해 자세히 알아봐야겠다.

## 1. React Hook

리엑트 훅은 React 16.8 버전부터 추가된 기능으로, 함수 컴포넌트에서도 클래스 컴포넌트에서처럼 `상태 state`와 `생명주기 기능(lifecycle features)`을 **연동할 수 있게 해주는 함수**이다. 당시 장점도 있지만 단점도 명확했던 클래스 컴포넌트를 뒤로하고, 비교적 간단한 함수 컴포넌트를 밀어주기로 판단한 React 팀이 **클래스 컴포넌트에서는 되지만 함수 컴포넌트에서 되지 않던 기능**을 함수 컴포넌트에서도 지원하도록 추가해 준 것이다.

그렇다면 함수 컴포넌트는 어떻게 상태와 생명주기 기능을 사용 가능하게 된 걸까.

## 2. 클래스 컴포넌트 vs 함수 컴포넌트

### 상태(state)

React의 클래스 컴포넌트는 **state**라는 속성, 즉 클래스 인스턴스의 멤버 변수를 가진다.

```jsx
class Counter extends React.Component {
  // React가 추적하는 "state" 키워드
  state = {
    count: 0,
  };

  render() {
    return (
      <div>
        <p>현재 카운트: {this.state.count}</p>
        <button onClick={() => this.setState({ count: this.state.count + 1 })}>
          증가
        </button>
      </div>
    );
  }
}
```

위 예시에서는 `count`가 `Counter`클래스가 가지는 상태가 된 것이다. 이후 `state`의 조작은 `setState`를 사용해서 하는데, `state`와 `setState`모두 클래스 인스턴스에 속한 **속성**과 **메서드**이기 때문에 `this`를 통해 접근해야 한다는 점이 특징이다.

### 생명주기(Lifecycle)

클래스 컴포넌트는 React가 제공하는 생명주기 메서드들을 통해 컴포넌트의 생성, 업데이트, 소멸 시점을 제어할 수 있다.

```jsx
class ExampleComponent extends React.Component {
  componentDidMount() {
    // 컴포넌트가 마운트된 후 실행
    console.log('컴포넌트가 마운트되었습니다.');
  }

  componentDidUpdate(prevProps, prevState) {
    // props나 state가 변경된 후 실행
    console.log('컴포넌트가 업데이트되었습니다.');
  }

  componentWillUnmount() {
    // 컴포넌트가 언마운트되기 전 실행
    console.log('컴포넌트가 언마운트됩니다.');
  }

  render() {
    return <div>예시 컴포넌트</div>;
  }
}
```

### 함수 컴포넌트의 한계

Hooks 이전의 함수 컴포넌트는 단순히 props를 받아서 JSX를 반환하는 순수 함수였다.

```jsx
function Counter(props) {
  // 상태를 가질 수 없음
  // 생명주기 메서드를 사용할 수 없음
  return (
    <div>
      <p>카운트: {props.initialCount}</p>
      {/* 상태 변경 불가능 */}
    </div>
  );
}
```

이러한 한계로 인해 함수 컴포넌트는 단순한 UI 렌더링에만 사용되었고, 상태 관리나 부수 효과 처리가 필요한 경우에는 클래스 컴포넌트를 사용해야 했다.

## 3. Hooks의 등장과 동작 원리

### Hooks의 핵심 아이디어

Hooks의 핵심 아이디어는 **함수 컴포넌트가 렌더링될 때마다 동일한 순서로 Hooks가 호출된다**는 것이다. 이는 React가 각 Hook의 상태를 배열로 관리하고 있기 때문이다.

```jsx
function ExampleComponent() {
  const [count, setCount] = useState(0);        // Hook 1
  const [name, setName] = useState('');         // Hook 2
  const [todos, setTodos] = useState([]);       // Hook 3

  useEffect(() => {
    console.log('count가 변경되었습니다:', count);
  }, [count]);                                  // Hook 4

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>증가</button>
    </div>
  );
}
```

위 컴포넌트에서 React는 내부적으로 다음과 같은 배열을 관리한다:

```javascript
// React 내부에서 관리하는 Hook 배열 (의사 코드)
const hooks = [
  { type: 'useState', value: 0, setter: setCount },      // Hook 1
  { type: 'useState', value: '', setter: setName },      // Hook 2
  { type: 'useState', value: [], setter: setTodos },     // Hook 3
  { type: 'useEffect', effect: fn, deps: [count] }       // Hook 4
];
```

### Hooks의 동작 과정

#### 1. 첫 번째 렌더링
```jsx
function ExampleComponent() {
  // React가 내부적으로 currentHookIndex = 0으로 설정
  const [count, setCount] = useState(0);        // hooks[0] 사용
  const [name, setName] = useState('');         // hooks[1] 사용
  const [todos, setTodos] = useState([]);       // hooks[2] 사용
  
  useEffect(() => {
    console.log('count가 변경되었습니다:', count);
  }, [count]);                                  // hooks[3] 사용
  
  // 렌더링 완료 후 currentHookIndex = 4
}
```

#### 2. 상태 업데이트 후 재렌더링
```jsx
// count가 1 증가한 경우

function ExampleComponent() {
  // React가 다시 currentHookIndex = 0으로 설정
  const [count, setCount] = useState(0);        // hooks[0]에서 기존 값(1) 반환
  const [name, setName] = useState('');         // hooks[1]에서 기존 값('') 반환
  const [todos, setTodos] = useState([]);       // hooks[2]에서 기존 값([]) 반환
  
  useEffect(() => {
    console.log('count가 변경되었습니다:', count);
  }, [count]);                                  // hooks[3]에서 기존 effect 반환
  
  // 렌더링 완료 후 currentHookIndex = 4
}
```

이렇게 **동일한 순서로 Hooks가 호출되어야만** React가 각 Hook의 상태를 올바르게 추적할 수 있다.

## 4. 주요 Hooks의 동작 원리

Hooks의 동작 원리를 살펴보기 위해, 가장 많이 사용되는 `useState`와 `useEffect`의 동작 과정을 자세히 살펴보며 React에서 상태와 생명주기가 관리되는 방식을 이해해보자.

### useState Hook

`useState`는 가장 기본적인 Hook으로, 함수 컴포넌트에서 상태를 관리할 수 있게 해준다.

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>증가</button>
    </div>
  );
}
```

#### useState의 내부 동작 (의사 코드)

```javascript
let hookIndex = 0; // 현재 Hook의 인덱스
const hooks = []; // 모든 Hook의 상태를 저장하는 배열

function useState(initialValue) {
  const currentIndex = hookIndex; // 현재 Hook의 인덱스 저장

  // 이미 초기화된 Hook인지 확인
  if (hooks[currentIndex] === undefined) {
    // 첫 번째 실행 - 이 Hook이 처음 호출되는 경우
    hooks[currentIndex] = {
      state: initialValue, // 초기값으로 상태 설정
      setState: (newValue) => {
        // 상태 업데이트 함수
        hooks[currentIndex].state = newValue; // 상태 변경
        // 컴포넌트 재렌더링 트리거
        scheduleUpdate();
      },
    };
  }

  hookIndex++; // 다음 Hook을 위해 인덱스 증가

  // [현재 상태값, 상태 업데이트 함수] 반환
  return [hooks[currentIndex].state, hooks[currentIndex].setState];
}
```

#### useState 동작 과정 설명

**1. 첫 번째 실행 (마운트 시)**

- Hook이 처음 호출되면 `hooks[currentIndex]`가 `undefined`
- 초기값으로 상태 객체 생성
- setState 함수 생성 (상태 변경 + 재렌더링 트리거)
- `[상태값, setState함수]` 반환

**2. 재렌더링 시**

- 이미 초기화된 Hook이므로 기존 상태 객체 사용
- 이전에 저장된 상태값 반환
- setState 함수는 동일한 참조 유지

**3. 상태 업데이트 시**

- setState 함수 호출
- 상태값 변경
- React의 스케줄러에 재렌더링 요청
- 다음 렌더링에서 새로운 상태값 반영

이러한 방식으로 useState는 함수 컴포넌트에서 상태를 지속적으로 관리한다.

### useEffect Hook

`useEffect`는 함수 컴포넌트에서 부수 효과(Side Effect)를 처리할 수 있게 해주는 Hook이다.

```jsx
function ExampleComponent() {
  const [count, setCount] = useState(0);
  
  useEffect(() => {
    document.title = `Count: ${count}`;
  }, [count]);
  
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>증가</button>
    </div>
  );
}
```

#### useEffect의 내부 동작 (의사 코드)

```javascript
function useEffect(effect, deps) {
  const currentIndex = hookIndex;

  if (hooks[currentIndex] === undefined) {
    // 첫 번째 실행 - 이 Hook이 처음 호출되는 경우
    hooks[currentIndex] = {
      effect, // 실행할 effect 함수
      deps, // 의존성 배열
      cleanup: undefined, // cleanup 함수 (아직 없음)
    };

    // effect 실행 - 컴포넌트가 마운트되거나 의존성이 변경되었을 때
    const cleanup = effect();
    if (typeof cleanup === 'function') {
      // effect가 cleanup 함수를 반환한 경우 저장
      hooks[currentIndex].cleanup = cleanup;
    }
  } else {
    // 이미 초기화된 Hook - 의존성 배열 비교 필요
    const prevDeps = hooks[currentIndex].deps;

    // 의존성 배열이 변경되었는지 확인
    const hasChanged =
      !deps || // deps가 null/undefined인 경우
      !prevDeps || // prevDeps가 null/undefined인 경우
      deps.length !== prevDeps.length || // 배열 길이가 다른 경우
      deps.some((dep, index) => dep !== prevDeps[index]); // 요소가 다른 경우

    if (hasChanged) {
      // 의존성이 변경되었으므로 effect를 다시 실행

      // 1. 이전 cleanup 실행 (컴포넌트 언마운트나 이전 effect 정리)
      if (hooks[currentIndex].cleanup) {
        hooks[currentIndex].cleanup();
      }

      // 2. 새로운 effect 실행
      const cleanup = effect();
      if (typeof cleanup === 'function') {
        hooks[currentIndex].cleanup = cleanup;
      }

      // 3. 새로운 의존성 배열 저장
      hooks[currentIndex].deps = deps;
    }
    // 의존성이 변경되지 않았다면 아무것도 하지 않음 (effect 실행 안함)
  }

  hookIndex++; // 다음 Hook을 위해 인덱스 증가
}
```

#### useEffect 동작 과정 설명

**1. 첫 번째 실행 (마운트 시)**

- Hook이 처음 호출되면 `hooks[currentIndex]`가 `undefined`
- effect 함수를 즉시 실행
- cleanup 함수가 있다면 저장

**2. 재렌더링 시**

- 이전에 저장된 의존성 배열과 새로운 의존성 배열 비교
- 의존성이 변경되었다면:
  - 이전 cleanup 함수 실행 (정리 작업)
  - 새로운 effect 함수 실행
  - 새로운 cleanup 함수 저장
- 의존성이 변경되지 않았다면 effect 실행 안함

**3. 언마운트 시**

- React가 컴포넌트를 제거할 때 저장된 cleanup 함수 실행

이러한 방식으로 useEffect는 컴포넌트의 생명주기에 맞춰 부수 효과를 관리한다.

## 5. Hooks의 규칙과 그 이유

### Hooks의 규칙

1. **최상위에서만 Hook을 호출해야 한다**
2. **React 함수 컴포넌트에서만 Hook을 호출해야 한다**

### 규칙이 필요한 이유

#### 조건문이나 반복문에서 Hook 호출 금지

```jsx
// 잘못된 예시
function BadExample() {
  const [count, setCount] = useState(0);
  
  if (count > 0) {
    const [name, setName] = useState('');  // 조건부 Hook 호출
  }
  
  for (let i = 0; i < count; i++) {
    const [item, setItem] = useState(null);  // 반복문 내 Hook 호출
  }
  
  return <div>Bad Example</div>;
}
```

위 코드가 문제가 되는 이유는 **Hook의 호출 순서가 렌더링마다 달라질 수 있기 때문**이다.

```jsx
// 첫 번째 렌더링 (count = 0)
function BadExample() {
  const [count, setCount] = useState(0);        // hooks[0]
  // if문이 false이므로 name Hook 호출 안됨
  // for문이 실행되지 않으므로 item Hook 호출 안됨
}

// 두 번째 렌더링 (count = 1)
function BadExample() {
  const [count, setCount] = useState(0);        // hooks[0] - count 값 반환
  const [name, setName] = useState('');         // hooks[1] - 새로운 Hook!
  const [item, setItem] = useState(null);       // hooks[2] - 새로운 Hook!
}
```

이렇게 되면 React가 Hook의 상태를 올바르게 추적할 수 없다.

#### 올바른 사용법

```jsx
// 올바른 예시
function GoodExample() {
  const [count, setCount] = useState(0);
  const [name, setName] = useState('');
  const [items, setItems] = useState([]);
  
  // 조건부 로직은 Hook 내부에서 처리
  useEffect(() => {
    if (count > 0) {
      // count가 0보다 클 때만 실행할 로직
      console.log('Count is positive');
    }
  }, [count]);
  
  return <div>Good Example</div>;
}
```

## 6. 커스텀 Hook의 동작 원리

### 커스텀 Hook의 정의

커스텀 Hook은 **"use"로 시작하는 함수**로, 다른 Hook들을 조합하여 재사용 가능한 로직을 만든다. 일반적으로 함수 컴포넌트에서 책임 관리를 목적으로 로직을 분리할 때 많이 사용된다.

```jsx
function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);
  
  const increment = () => setCount(count + 1);
  const decrement = () => setCount(count - 1);
  const reset = () => setCount(initialValue);
  
  return {
    count,
    increment,
    decrement,
    reset
  };
}
```

### 커스텀 Hook 사용

```jsx
function Counter() {
  const { count, increment, decrement, reset } = useCounter(0);
  
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={increment}>증가</button>
      <button onClick={decrement}>감소</button>
      <button onClick={reset}>리셋</button>
    </div>
  );
}
```

### 커스텀 Hook의 내부 동작

커스텀 Hook이 호출될 때도 동일한 Hook 배열에 추가된다.

```javascript
// 첫 번째 렌더링
function Counter() {
  // useCounter 내부
  const [count, setCount] = useState(0);        // hooks[0]
  
  // useCounter 반환 후
  const { count, increment, decrement, reset } = useCounter(0);
  
  // hooks 배열 상태: [useState Hook]
}
```

## 7. Hooks의 성능 최적화

### useMemo와 useCallback

Hooks는 렌더링마다 새로운 함수와 객체를 생성할 수 있어 성능 문제를 일으킬 수 있다. 이를 방지하기 위해 `useMemo`나 `useCallback`을 사용해 상태나 함수를 별도의 메모리에서 관리하여 렌더링 마다 재생성되지 않도록 할 수 있다.

```jsx
function ExpensiveComponent({ items }) {
  // 매 렌더링마다 새로운 함수 생성
  const handleClick = () => {
    console.log('Button clicked');
  };
  
  // 매 렌더링마다 새로운 객체 생성
  const config = {
    items: items,
    timestamp: Date.now()
  };
  
  return (
    <div>
      <button onClick={handleClick}>Click me</button>
      <ExpensiveChild config={config} />
    </div>
  );
}
```

#### 최적화된 버전

```jsx
function OptimizedComponent({ items }) {
  // 의존성이 변경될 때만 새로운 함수 생성
  const handleClick = useCallback(() => {
    console.log('Button clicked');
  }, []);
  
  // 의존성이 변경될 때만 새로운 객체 생성
  const config = useMemo(() => ({
    items: items,
    timestamp: Date.now()
  }), [items]);
  
  return (
    <div>
      <button onClick={handleClick}>Click me</button>
      <ExpensiveChild config={config} />
    </div>
  );
}
```

### useMemo와 useCallback의 내부 동작

```javascript
function useMemo(factory, deps) {
  const currentIndex = hookIndex;
  
  if (hooks[currentIndex] === undefined) {
    // 첫 번째 실행
    const value = factory();
    hooks[currentIndex] = { value, deps };
  } else {
    // 의존성 비교
    const prevDeps = hooks[currentIndex].deps;
    const hasChanged = !deps || !prevDeps || 
      deps.length !== prevDeps.length ||
      deps.some((dep, index) => dep !== prevDeps[index]);
    
    if (hasChanged) {
      // 의존성이 변경되었으면 새로 계산
      const value = factory();
      hooks[currentIndex] = { value, deps };
    }
  }
  
  hookIndex++;
  return hooks[currentIndex].value;
}
```

## 8. Hooks의 한계와 주의사항

### 클로저 트랩 (Closure Trap)

Hooks는 클로저를 기반으로 동작하기 때문에, 비동기 함수에서 최신 상태를 참조하지 못할 수 있다.

```jsx
function ClosureTrap() {
  const [count, setCount] = useState(0);
  
  // 잘못된 예시 - 클로저 트랩
  const handleClick = () => {
    setTimeout(() => {
      console.log(count);  // 항상 0을 출력 (클로저에 갇힌 값)
    }, 1000);
  };
  
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>증가</button>
      <button onClick={handleClick}>1초 후 로그</button>
    </div>
  );
}
```

#### 해결 방법

```jsx
function FixedClosureTrap() {
  const [count, setCount] = useState(0);
  
  // 올바른 예시 - useRef 사용
  const countRef = useRef(count);
  countRef.current = count;
  
  const handleClick = () => {
    setTimeout(() => {
      console.log(countRef.current);  // 최신 값 출력
    }, 1000);
  };
  
  // 또는 함수형 업데이트 사용
  const handleClick2 = () => {
    setTimeout(() => {
      setCount(prevCount => {
        console.log(prevCount);  // 최신 값 출력
        return prevCount;
      });
    }, 1000);
  };
  
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>증가</button>
      <button onClick={handleClick}>1초 후 로그</button>
    </div>
  );
}
```

## 9. 정리

React Hooks는 함수 컴포넌트에서 상태와 생명주기 기능을 사용할 수 있게 해주는 강력한 시스템입니다. Hooks의 핵심은 **렌더링마다 동일한 순서로 호출되는 Hook들의 상태를 배열로 관리**한다는 점입니다.

Hooks의 동작 원리를 이해하면 다음과 같은 이점이 있습니다.

1. **올바른 Hook 사용법**을 알 수 있습니다
2. **성능 최적화**를 적절히 적용할 수 있습니다
3. **버그를 예방**할 수 있습니다
4. **효율적인 커스텀 Hook**을 만들 수 있습니다

Hooks는 React의 함수형 프로그래밍 패러다임을 완성하는 중요한 기능이며, 클로저를 기반으로 한 상태 관리 시스템을 통해 함수 컴포넌트의 한계를 극복했습니다. 

Hooks의 규칙을 지키고, 클로저의 특성을 이해하며, 적절한 성능 최적화를 적용한다면 React 애플리케이션을 더욱 효율적으로 개발할 수 있습니다.
