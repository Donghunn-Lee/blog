React를 접하며 가장 먼저 듣게 되는 내용이 가상 돔, Virtual DOM이 아닐까 싶다. 그리고 브라우저에 있는 DOM과 VIrtual DOM은 무슨 차이일까 궁금증이 생겼을 것이다. 나 또한 그랬고, 어떤 식으로 성능을 향상시키는지 대략적으로는 이해하고 있다. 하지만 React를 있는 그대로 더 잘 다루기 위해서, 대략적이 아니라 조금 더 정확히 알아야 한다.

## 1. Virtual DOM

Virtual DOM은 실제 DOM의 가벼운 복사본이라고 생각하면 된다. React, Vue와 같은 현대적인 프레임워크에서 사용되는 개념으로, **UI의 이상적인 또는 "가상"적인 표현을 메모리에 유지하고 실제 DOM과 동기화**하는 프로그래밍 개념이다.

Virtual DOM을 이해하는 것은 현대 웹 개발에서 필수적이다. 실제 DOM 조작의 비효율성을 해결하고, 선언적인 UI 개발을 가능하게 하며, 크로스 플랫폼 개발을 지원하기 때문이다.

### Virtual DOM의 특징
- JavaScript 객체로 표현됨
- 실제 DOM보다 가벼움
- 메모리상에만 존재
- 실제 DOM과 비교하여 필요한 부분만 업데이트

### DOM과 Virtual DOM의 형태 비교
#### 실제 돔
```js
   div#root
   ├── header
   │   └── h1
   │       └── "제목"
   └── main
       └── p
           └── "내용"
```

#### Virtual DOM
위 DOM 트리는 아래와 같이 Virtual DOM으로 표현된다.
```js
   {
     $$typeof: Symbol(react.element),
     type: 'div',
     key: null,
     ref: null,
     props: {
       id: 'root',
       children: [
         {
           $$typeof: Symbol(react.element),
           type: 'header',
           props: {
             children: {
               $$typeof: Symbol(react.element),
               type: 'h1',
               props: {
                 children: '제목'
               }
             }
           }
         },
         {
           $$typeof: Symbol(react.element),
           type: 'main',
           props: {
             children: {
               $$typeof: Symbol(react.element),
               type: 'p',
               props: {
                 children: '내용'
               }
             }
           }
         }
       ]
     }
   }
```
이 트리의 형태를 정확히 이해할 필요는 없다. 다만 알고 가야 하는 것은 트리의 가벼움이다. 사실 이 트리만 보면 '실제 돔이 더 가벼운 거 아니야?' 하는 의문이 들 수 있다.

그것은 DOM이 **객체 노드로 이루어진 트리**라서 그렇다. 객체 노드엔 기본 속성, 스타일, 이벤트, 레이아웃 관련 등 일반적인 HTML 요소 노드인 경우 **약 1000개 이상의 속성**을 가진다. 편의상 각 노드의 정보를 모두 표현하기엔 너무 많아서 생략한 반면, React의 Virtual DOM은 표현할 수 있는 **5~6개의 필수 속성**만을 가질 정도로 가벼워졌다는 점만 이해하면 된다.

## 2. Virtual DOM의 동작 방식

Virtual DOM의 동작 방식을 이해하는 것은 성능 최적화와 디버깅에 매우 중요하다. 특히 React나 Vue와 같은 프레임워크를 사용할 때, 내부 동작 원리를 알면 더 효율적인 개발이 가능하다. Virtual DOM은 **실제 DOM 조작의 비효율성을 해결**하기 위해 설계되었으며, 그 동작 과정은 크게 세 단계로 나눌 수 있다.

### 1) 초기 렌더링 (Initial Render)
초기 렌더링은 컴포넌트가 처음 마운트될 때 발생하는 과정이다. 이 과정에서 Virtual DOM은 실제 DOM과의 첫 동기화를 수행한다.

1. **Virtual DOM 트리 생성**
   - 컴포넌트의 JSX/템플릿을 기반으로 Virtual DOM 트리 생성
   - 각 노드는 실제 DOM 요소에 대응하는 JavaScript 객체
   - props, state 등의 정보를 포함한 가벼운 표현

2. **실제 DOM 반영**
   - 생성된 Virtual DOM 트리를 실제 DOM에 반영
   - 이 과정에서 한 번의 DOM 조작으로 전체 트리 생성
   - 이후의 업데이트를 위한 기준점이 됨

### 2) 상태 변경 시 (State Change)
상태 변경은 Virtual DOM의 핵심 기능이 발휘되는 시점이다. 이 과정에서 Virtual DOM은 효율적인 업데이트를 보장한다.

1. **새로운 Virtual DOM 트리 생성**
  ```js
  // 이전 상태
  const prevVirtualDOM = {
    type: 'div',
    props: {
      children: [
        {
          type: 'h1',
          props: { children: '카운트: 0' }
        }
      ]
    }
  };

  // 상태 변경 후
  const newVirtualDOM = {
    type: 'div',
    props: {
      children: [
        {
          type: 'h1',
          props: { children: '카운트: 1' }
        }
      ]
    }
  };
  ```
   - 상태 변경을 감지하면 새로운 Virtual DOM 트리 생성
   - 이전 트리와 비교를 위한 기준이 됨
   - 컴포넌트의 새로운 상태를 반영

### 3) Diffing & Patching
이 단계는 Virtual DOM의 핵심인 비교와 업데이트 과정을 수행한다. 이 과정을 통해 실제 DOM의 불필요한 업데이트를 방지한다.

>#### Diffing 알고리즘
Virtual DOM의 핵심은 효율적인 비교 알고리즘이다. 이 알고리즘의 동작 방식을 이해하면 불필요한 렌더링을 방지하고 성능을 최적화할 수 있다. React의 경우 O(n³)의 복잡도를 가진 트리 비교를 O(n)으로 최적화했다. 비교는 **엘리먼트 타입**, **속성**, **자식 노드**들에 대해서 이루어지고, **성능 최적화**과정이 포함되어있다. Diffing 알고리즘에 대해 더 궁금하다면 따로 알아보길 바란다.


1. **Diffing 과정**
  ```js
  // 이전 트리
  <div>
    <h1>제목</h1>
    <p>내용</p>
  </div>

  // 새로운 트리
  <div>
    <h1>새 제목</h1>
    <p>내용</p>
  </div>

  // Diffing 결과
  {
    type: 'UPDATE',
    path: ['div', 'h1'],
    changes: {
      children: '새 제목'  // p 태그는 변경 없음
    }
  }
  ```
   - 이전 트리와 새로운 트리를 비교
   - 변경된 부분만 식별
   - 실제 DOM에 반영할 변경사항 결정

2. **Patching 과정**
  ```js
  // Diffing 결과를 바탕으로 실제 DOM 업데이트
  function patch(dom, changes) {
    if (changes.type === 'UPDATE') {
      const element = findElementByPath(dom, changes.path);
      if (changes.changes.children) {
        element.textContent = changes.changes.children;
      }
    }
  }

  // 실제 DOM 업데이트 실행
  patch(document.getElementById('root'), diffingResult);
  ```
   - 식별된 변경사항만 실제 DOM에 반영
   - 최소한의 DOM 조작으로 업데이트 수행
   - 배치 처리로 성능 최적화

## 3. Virtual DOM의 장점

Virtual DOM의 장점을 이해하면 왜 현대 웹 개발에서 이 개념이 필수적인지 알 수 있다. 특히 대규모 애플리케이션에서 그 가치가 더욱 빛난다.

### 1) 성능 최적화

- **선택적 업데이트**
  - 필요한 부분만 실제 DOM에 반영
  - 불필요한 렌더링 방지

- **배치 처리**
  - 여러 변경사항을 모아서 한 번에 처리
  - 브라우저의 리플로우/리페인트 최소화

- **메모이제이션**
  - 계산 비용이 큰 연산 결과 캐싱
  - 동일한 입력에 대한 중복 계산 방지

### 2) 개발 편의성

- **선언적 UI**
  - UI를 선언적으로 작성 가능
  - 상태 변화에 따른 UI 업데이트 자동화

- **크로스 플랫폼**
  - Virtual DOM을 다양한 플랫폼에 렌더링 가능
  - React Native, React VR 등에서 활용
  
- **디버깅 용이성
  - Virtual DOM의 상태 추적 가능
  - React DevTools 등을 통한 디버깅 지원

## 4. Virtual DOM의 한계

Virtual DOM의 한계를 이해하는 것은 적절한 사용과 최적화를 위해 중요하다. 모든 기술이 그렇듯이, Virtual DOM도 상황에 따라 장단점이 있다.

### 1) 오버헤드

- **초기 설정 비용**
  - Virtual DOM 트리 생성에 대한 오버헤드
  - 작은 애플리케이션에서는 불필요할 수 있음

- **메모리 사용**
  - Virtual DOM 트리를 메모리에 유지
  - 대규모 애플리케이션에서 메모리 사용량 증가

### 2) 최적화 필요성

- **불필요한 렌더링**
  - 잘못된 구현으로 인한 불필요한 렌더링 발생 가능
  - React.memo, useMemo 등의 최적화 필요

- **복잡한 애니메이션**
  - 복잡한 애니메이션의 경우 직접 DOM 조작이 더 효율적일 수 있음
  
- **서버 사이드 렌더링**
  - 초기 로딩 시 추가적인 처리 필요
  - 하이드레이션 과정에서의 성능 고려

## 5. 실제 DOM과의 비교

실제 DOM과 Virtual DOM의 차이를 이해하는 것은 웹 개발의 근본적인 이해를 돕는다. 이는 단순한 기술적 차이를 넘어, 현대 웹 개발의 패러다임 변화를 보여준다.

### 1) 직접 DOM 조작의 문제점

- **비효율적인 업데이트**
  - DOM 조작은 비용이 큰 작업
  - 여러 번의 DOM 업데이트로 성능 저하

- **상태 관리의 어려움**
  - DOM 상태와 애플리케이션 상태의 동기화 어려움
  - 버그 발생 가능성 증가

### 2 Virtual DOM의 해결책

- **효율적인 업데이트**
  - 변경사항을 모아서 한 번에 처리
  - 실제 DOM 조작 최소화

- **예측 가능한 렌더링**
  - 상태 변화에 따른 UI 업데이트가 예측 가능
  - 디버깅이 용이

- **상태 관리 통합**
  - 애플리케이션 상태와 UI 상태의 일관성
  - 단방향 데이터 흐름으로 인한 예측 가능성

## 6. 최적화 전략

Virtual DOM을 효과적으로 사용하기 위해서는 적절한 최적화 전략이 필요하다. 이는 단순한 성능 개선을 넘어, 사용자 경험과 개발 효율성에 직접적인 영향을 미친다.

### 1) 렌더링 최적화

- **불필요한 렌더링 방지**
  - React.memo, useMemo, useCallback 활용
  - 상태 업데이트 최적화

- **코드 스플리팅**
  - 필요한 컴포넌트만 로드
  - 초기 로딩 시간 단축

- **지연 로딩(Lazy Lodaing)**
  - 컴포넌트의 동적 임포트
  - 초기 번들 크기 최적화

### 2) 메모리 관리

- **가비지 컬렉션**
  - 사용하지 않는 Virtual DOM 노드 정리
  - 메모리 누수 방지

- **컴포넌트 설계**
  - 적절한 컴포넌트 분리
  - 재사용 가능한 컴포넌트 설계

- **이벤트 리스너 관리**
  - 메모리 누수 방지를 위한 이벤트 정리
  - 이벤트 위임을 통한 최적화

## 정리

Virtual DOM은 **실제 DOM 조작의 비효율성을 해결**하기 위해 도입된 개념으로, UI를 메모리상의 가벼운 JavaScript 객체로 표현하고 변경 사항만 실제 DOM에 반영하여 성능을 최적화합니다. 초기 렌더링 후 상태 변화에 따라 새로운 Virtual DOM 트리를 생성하고, **Diffing 알고리즘**을 통해 **변경된 부분만** 효율적으로 업데이트합니다. 이를 통해 선언적 UI 작성과 크로스 플랫폼 개발이 가능해지며, React.memo, useMemo 등의 기법과 코드 스플리팅, 지연 로딩 등을 통해 성능을 더욱 향상시킬 수 있습니다. 다만 초기 설정 비용과 메모리 사용 증가 같은 단점도 존재하므로, 원리를 이해하고 **적절한 최적화 전략**을 적용하는 것이 중요합니다.
