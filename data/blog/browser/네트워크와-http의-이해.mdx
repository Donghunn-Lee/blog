프론트 엔드 개발자는 웹 개발만 잘 하면 되는 게 아닌가 싶었지만, 실무에서의 얘기를 들어보면 네트워크에 대한 개념이 생각보다도 더 중요하다. REST API를 활용하는 때문임은 기본이며, 오류가 발생했을 때 그 이유를 빠르게 파악하거나 네트워크 보안을 강화하기 위해서도 중요한 개념이다.

## 1. 네트워크

네트워크는 컴퓨터들이 서로 통신할 수 있도록 연결된 시스템이다. 웹 개발에서 네트워크는 클라이언트(브라우저)와 서버 간의 통신을 가능하게 하는 핵심 요소가 된다.

### 네트워크의 기본 구성 요소

1. **클라이언트 (Client)**
   - 서비스를 요청하는 주체
   - 웹 브라우저, 모바일 앱 등

2. **서버 (Server)**
   - 클라이언트의 요청에 응답하는 주체
   - 웹 서버, API 서버 등

3. **IP 주소 (Internet Protocol Address)**
   - 네트워크상의 장치를 식별하는 주소
   - IPv4: 192.168.0.1
   - IPv6: 2001:0db8:85a3:0000:0000:8a2e:0370:7334

4. **포트 (Port)**
   - 서비스의 종류를 구분하는 번호
   - HTTP: 80
   - HTTPS: 443
   - SSH: 22

---

## 2. HTTP (HyperText Transfer Protocol)

HTTP는 웹에서 데이터를 주고받기 위한 프로토콜이다. 클라이언트-서버 모델을 기반으로 하며, 요청(Request)과 응답(Response)의 형태로 통신한다.

### HTTP의 특징

1. **무상태성 (Stateless)**
   - 각 요청은 독립적으로 처리
   - 이전 요청과 현재 요청 간의 연관성이 없음
   - 상태 유지가 필요한 경우 쿠키, 세션 등을 사용

2. **비연결성 (Connectionless)**
   - 요청-응답 후 연결 종료
   - 서버 자원을 효율적으로 관리
   - HTTP/1.1부터는 Keep-Alive로 연결 유지 가능

### HTTP 메서드

HTTP메서드는 HTTP를 통해 서버의 정보를 관리하기 위한 수단이다. 각각의 명령을 통해 서버와 소통하여 작업을 수행한다.

1. **GET**
   - 리소스 조회
   - 데이터를 URL에 포함하여 전송
   - 캐시 가능

2. **POST**
   - 리소스 생성
   - 데이터를 요청 본문에 포함
   - 캐시 불가능

3. **PUT**
   - 리소스 수정
   - 리소스의 전체 교체

4. **PATCH**
   - 리소스 부분 수정
   - 리소스의 일부만 수정

5. **DELETE**
   - 리소스 삭제

### HTTP 상태 코드

개발하면서 api를 사용해봤다면 개발자 도구에서 다음과 같은 코드들을 수없이 보았을 것이다. 대략 파악은 하고 있지만, 정확히 짚어가자면 다음과 같다.

1. **2xx (성공)**
   - 200: OK
   - 201: Created
   - 204: No Content

2. **3xx (리다이렉션)**
   - 301: Moved Permanently
   - 302: Found
   - 304: Not Modified

3. **4xx (클라이언트 오류)**
   - 400: Bad Request
   - 401: Unauthorized
   - 403: Forbidden
   - 404: Not Found

4. **5xx (서버 오류)**
   - 500: Internal Server Error
   - 502: Bad Gateway
   - 503: Service Unavailable

## 3. HTTP 요청/응답 구조

HTTP 메서드를 통한 요청과 응답을 확인해 보면 몇 가지 정보들을 확인할 수 있다.

### HTTP 요청 구조
```
GET /api/users HTTP/1.1
Host: api.example.com
User-Agent: Mozilla/5.0
Accept: application/json
```

1. **요청 라인**
   - HTTP 메서드
   - 요청 URI
   - HTTP 버전

2. **요청 헤더**
   - Host: 서버의 호스트명
   - User-Agent: 클라이언트 정보
   - Accept: 응답으로 받을 수 있는 컨텐츠 타입

3. **요청 본문**
   - POST, PUT 등의 메서드에서 데이터 전송

### HTTP 응답 구조
```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 1234

{
    "message": "success"
}
```

1. **상태 라인**
   - HTTP 버전
   - 상태 코드
   - 상태 메시지

2. **응답 헤더**
   - Content-Type: 응답 데이터의 형식
   - Content-Length: 응답 데이터의 크기

3. **응답 본문**
   - 실제 데이터

## 4. HTTPS (HTTP Secure)

HTTPS는 HTTP에 SSL/TLS를 적용하여 보안을 강화한 프로토콜이다. HTTP는 기본적으로 데이터가 암호화 되지 않고, 인증 수단도 없다. 이런 단점을 보완한 것이 HTTPS 이다.

### HTTPS의 특징

1. **암호화**
   - 데이터를 암호화하여 전송
   - 중간자 공격 방지

2. **인증**
   - 서버의 신원 확인
   - 인증서를 통한 검증

3. **무결성**
   - 데이터가 변조되지 않았음을 보장

## 5. REST API

REST(Representational State Transfer)는 HTTP를 기반으로 하는 API 설계 아키텍처이다. 우리가 서버와 통신을 하기 위해 가장 기본적으로 사용하는 통신 방법이다.

### REST의 주요 원칙

1. **리소스 중심**
   - URI는 리소스를 표현
   - 동사보다는 명사 사용

2. **HTTP 메서드 활용**
   - GET: 조회
   - POST: 생성
   - PUT: 수정
   - DELETE: 삭제

3. **상태 코드 활용**
   - 적절한 HTTP 상태 코드 사용
   - 클라이언트에게 명확한 응답 전달

### REST API 예시
```
GET    /api/users          # 사용자 목록 조회
GET    /api/users/1        # 특정 사용자 조회
POST   /api/users          # 사용자 생성
PUT    /api/users/1        # 사용자 정보 수정
DELETE /api/users/1        # 사용자 삭제
```

## 6. 정리

네트워크는 컴퓨터들이 데이터를 주고받을 수 있도록 연결된 구조입니다. 웹 개발에서는 **HTTP**가 대표적인 통신 프로토콜로, **클라이언트-서버** 모델을 기반으로 동작합니다. HTTP는 **무상태성**(stateless)과 **비연결성**(connectionless)을 특징으로 하며, 각 요청은 독립적으로 처리되고 요청-응답 후 연결이 끊깁니다. 주요 메서드로는 **GET, POST, PUT, DELETE** 등이 있으며, 상태 코드를 통해 요청 결과를 전달합니다. 보안이 필요한 경우 **HTTPS**를 사용해 데이터를 암호화하고 서버의 신원을 확인할 수 있습니다. 이러한 HTTP의 특징은 **RESTful API** 설계의 기반이 됩니다.
