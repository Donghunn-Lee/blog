UI 마무리 잔여였던 E50 차례다. 발단은 #112 프리마켓 실측 — 프리장에 헤더 현재가는 NXT 값으로 바뀌는데 차트는 KRX 기준이라, 같은 화면 안에서 값의 출처가 섞여 보이는 문제를 그때 등록해 뒀다. quote 경로가 X18 혼종과 물려 있어 probe로 현행 구조부터 확정하고 들어갔다.

probe가 정리해 준 출발점은 세 가지다.

- quote 도메인 모델에 **시장 구분 필드가 없다** — 헤더는 세션이 정해준 값 하나(J 또는 NX)를 받을 뿐, 그게 어느 시장 값인지 모른다
- KRX 종가는 SSR `initialPrice`로 이미 컴포넌트에 도달해 있다 — 라이브가 null일 때만 쓰일 뿐
- X18에 적어뒀던 `isNxtMiss` 역추론은 실코드가 없다. 주석 속 개념이었고, 실제 판정은 별개 술어 둘이 live null로 간접 수행 중이다

## 병기 구상에서 상시 토글로

처음 스코프 판정은 "세션 값(주) + KRX 기준값(부) 병기"였다. 근데 예전에 캡쳐해 둔 네이버 증권 화면을 꺼내 보면서 방향이 바뀌었다 — 모바일은 두 값 병기, PC는 KRX/NXT 탭이다. 병기는 헤더 밀도를 해치고, 토글이면 비NXT 종목엔 아예 안 뜨니 무영향이라 토글로 정했다.

![](/static/images/velog/f9535dfa-a698-4f09-a642-693ac0346fa1-image.png)


세션 한정 노출(pre·after에만)도 검토했는데, 정규장 표시를 다른 서비스들이 어떻게 하는지 찾아보고 접었다.

| 서비스 | 정규장 NXT 시세 접근 |
| --- | --- |
| 증권사 MTS/HTS (키움·미래에셋 등) | 통합/KRX/NXT 3-way 전환 버튼 상시 |
| 토스증권 | 통합 기본 + 설정에서 시장 선택 |
| 네이버 | PC 탭 상시 · 모바일 병기 상시 |

세션 따라 토글이 출몰하는 서비스는 없었다. 상시로 확정.

상시로 가니 판정 문제가 하나 되살아났다. "NX 라이브 응답이 있으면 NXT 종목"이라는 판정은 pre·after에서만 성립하고, regular의 J 응답은 그 종목이 NXT 거래 대상인지 아무것도 알려주지 않는다. 결국 `nx_eligible`을 SSR에서 읽기로 했다 — #099에서 eligibility 판정용으로 저장만 해 두던 컬럼이 처음으로 UI 소비자를 얻었다.

## 스냅샷 실측 두 건

구현 전 블로커가 둘 남아 있었다. NXT 탭 등락의 기준이 뭔지, 그리고 마감 후 NXT 탭에 어떤 값을 서빙할지. 스냅샷 5거래일 × nx_eligible 3,029건을 돌렸다.

| 확인 | 결과 |
| --- | --- |
| `un_close − un_change` vs KRX 전일 종가 | 3,028/3,029 일치 (예외 1건은 1원 편차) |
| `un_close` vs `nx_close` | **편차 0건** |
| 활성 종목 중 스냅샷 미커버 | 0건 |
| eligible 규모 | 2,650종목 중 604 (22.8%) |

un=nx 전수 일치는 좀 허무했는데, 생각해 보면 #099에서 스키마에 박아둔 주석("NXT 종목의 un_close는 20시 NXT 최종가") 그대로다. KRX가 닫힌 뒤의 체결은 전부 NXT니까. 이 실측이 설계를 세 군데 지웠다.

- 마감 후 NXT 탭 = **현행 스냅샷 서빙 경로 그대로** — nx 컬럼 별도 서빙, nx_change 계산 전부 불필요
- 등락 기준 = KRX 전일 종가 확정 — 어느 탭이든 응답값 그대로 표시하면 되고, 신규 계산이 없다
- 미커버 0 — 스냅샷 부재 폴백 설계 불요

NX 라이브 응답의 전일대비 기준은 세션 밖 시간이라 실측을 못 했다. 다만 새로 계산하는 등락이 없어진 시점에서 이건 구현 블로커가 아니라 현행 표시의 검증 항목이다. 다음 장중에 확인할 계획이다.

## 탭별 데이터 소스

| 세션 | KRX 탭 | NXT 탭 |
| --- | --- | --- |
| regular | J 폴링 (실시간) | NX 폴링 — **탭 선택 시에만** |
| pre · after | SSR EOD · 요청 0회 | NX 폴링 |
| after_close · closed | SSR EOD · 요청 0회 | 스냅샷 (현행 경로) |

- route에 `market=krx|nxt` 파라미터를 추가했다. 미지정이면 현행 세션 결정 그대로라 비NXT 종목 경로는 바이트 하나 안 바뀐다
- 훅은 market을 queryKey에 넣었다 — 탭 전환이 곧 폴링 대상 전환이라, regular NXT 탭의 추가 콜은 사용자가 실제로 그 탭을 보는 동안만 발생한다
- 비-regular KRX 탭은 `enabled: false`. KRX는 15:30에 닫혔고 정답이 이미 SSR로 와 있는데 null quote를 폴링할 이유가 없다

KRX 탭 라벨은 새로 정의가 필요했다. EOD 적재 전 구간(장 마감 직후 ~16시)엔 DB 최신 행이 전일이라, 행 날짜를 같이 내려 "장 마감 · 15:30"과 "전일 종가 · MM.DD"를 가른다. 여기서 함정이 하나 — 날짜 문자열 생성이 서버 로컬 타임존 종속이었다. Vercel(UTC)과 KST dev에선 안전하지만 UTC-N 서버면 하루가 밀린다. E50이 이 값을 등식 비교하는 첫 소비자라 KST-safe 재산출로 격리하고, 근본 수정은 F66으로 등록해 뒀다. 이 헬퍼가 처음엔 자체 SELECT를 날려서, raw 조회를 캐시 레이어로 빼 기존 조회와 공유하게 정리한 것까지가 사소한 뒷손질이다.

라벨 결정 로직 자체도 이번에 순수 함수로 뽑았다. 기존이 컴포넌트 안 중첩 삼항이었는데 market 축이 추가되면 더는 못 읽는 수준이라, 세션×market×라이브 유무 전 조합을 vitest 23케이스로 고정했다.

## 차트 구독 키

상세 차트는 헤더가 채워 둔 quote 캐시를 구독만 해서(subscribeOnly) 당일 봉을 라이브 병합한다. 헤더 쿼리 키에 market이 들어가는 순간 이 연결이 끊길 수 있다.

NXT 고정 구독안이 먼저 나왔는데 기각했다 — 기본 상태(regular + KRX 탭)에서 차트가 구독할 nxt 캐시엔 아무도 fetch를 안 하고 있고, 그렇다고 차트용 폴링을 따로 열면 on-demand 설계가 깨진다. 대신 **세션 기본 market 키**(regular→krx, 그 외→nxt)를 구독하게 했다. 토글 도입 전과 데이터 흐름이 동일하다.

남는 갭은 사용자가 비기본 탭에 머무는 동안 병합이 잠시 멎는 것. 명시적 조작 중에만 발생하고 복귀하면 재개되며 봉 자체는 서버 주기로 갱신되니 감수했다. 세션→기본 market 판정은 헤더 기본 탭 결정과 같은 함수를 쓴다.

## 폴더 탭, 두 번의 수정

토글 첫 판은 차트 툴바 스타일을 그대로 가져와 라벤더가 들어갔다.

![](/static/images/velog/3f8f2b2e-9849-454d-858d-9f86109bdc35-image.png)


이건 디자인 언어 위반이었다 — 헤더와 차트 섹션은 무채색 유지가 원칙인데, 유채색 활성 배지가 가격 바로 위에 앉은 거다. 무채색 segmented로 바꾸고, 거기서 한 번 더 — 알약형 그룹 대신 직각 버튼 두 개가 맞붙은 형태로 갔다가, 최종적으로 활성 탭의 하단 border를 뚫은 폴더 탭에 우측 연장선을 붙였다. #048에서 종목 상세 탭 nav에 쓴 것과 같은 메타포다. 활성 탭이 아래 가격 영역과 이어져 보이는 게 "지금 이 가격이 이 시장 것"이라는 토글의 의미와 맞아떨어진다.

![](/static/images/velog/17dd2101-e438-442d-9fad-3049ce44b761-image.png)


전환 애니메이션은 뺐다. 탭 전환은 시세 갱신이 아니라 소스 전환이라, #111에서 세운 countup 정책과 같은 결이다. 같은 이유로 가격 카운트업도 탭 전환 때는 억제했다 — KRX↔NXT 값 사이를 숫자가 굴러가면 시세가 움직인 걸로 오독된다. PriceCountUp에 `key={market}`을 줘 전환 시 remount로 정적 리셋되게 했는데, 컴포넌트 주석이 정확히 이 용법을 문서화해 두고 있었다.

## 정리

- **E50 종결** — NXT 거래 종목 헤더에 KRX/NXT 폴더 탭 토글 상시 노출. 기본 탭은 세션 활성 시장, 등락은 전 탭 응답값 그대로
- **스냅샷 실측** — un=nx 전수 일치·등락 기준 KRX 전일 확정으로 마감 후 서빙·등락 계산 설계가 통째로 소거
- **경로 신설 최소** — route market 파라미터와 nx_eligible SSR 조회 둘. 리스트(UN) 혼종·차트 판정콜은 X18에 그대로 남긴다
- **라벨 순수 함수화** — 중첩 삼항을 세션×market 매핑 함수로 추출, 23케이스 고정

병기로 시작해 상시 토글로 끝났는데, 중간의 방향 전환마다 근거가 조사와 실측에서 나왔다는 점에서 순서는 잘 밟은 세션이다. 특히 un=nx 실측 하나가 구현 분량을 눈에 띄게 줄였다 — 재기 전에 지었으면 안 쓸 서빙 코드가 남았을 거다.
