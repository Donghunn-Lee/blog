직전 글에서 EOD 적재를 15시 33분 선적재와 09시 10분 재조회로 가기로 정했었다. KIS 일봉이 밤사이 정규장 값으로 정정되니 저장 층은 KRX 공식 정의(정규장 OHLC)를 따르고 애프터 체결은 라이브 층에만 두자는 결론이었고, 애프터마켓 대응 항목(X27)의 마지막 미결이 이 구현이었다. 아침에 계약 열한 항목을 확정하고 구현 직전까지 갔다.

계획은 그 구현과 NXT 탭 결함(F93)·세션 라벨 정합(E83)을 병렬로 끝내는 것이었는데, 계약을 확정한 직후 방향을 바꿨다. 네이버와 MTS의 KRX 일봉이 20시까지의 체결을 캔들에 넣고 등락률만 15시 30분 기준으로 잡는 것을 다시 보고 나서다. 결과적으로 어제 기각했던 안을 채택했고, 일곱 커밋으로 X27을 닫았다.

## 기각 사유 재검토

| 어제 기각 사유 | 오늘 다시 보니 |
| --- | --- |
| 저장 캔들이 KIS 일봉 이력과 끊김 | 사실. 다만 정정본이 정규장 정의라 9/14 이후 KIS 일봉을 안 쓰면 되는 문제. 이력 단절이 아니라 소스 교체 |
| 백필 축이 끊김 | 반대. pykrx 기본 경로(네이버 정합)가 이미 20시 캔들. 어제 금지한 백필이 오히려 일치하는 소스 |
| 등락률 축이 끊김 | 오판. KIS 전일대비는 기준가(전일 정규장 종가) 기준이라 원하던 축 그대로. 끊기는 건 저장 종가 두 행의 차로 등락을 만드는 곳뿐 |

셋 중 실제로 남은 건 세 번째뿐이었고, 그건 컬럼 하나로 닫을 수 있는 크기였다. 대신 어제 확보한 "KRX 공식 일별매매정보와 일치"는 버린다. 조회 서비스라면 공식 문서보다 사용자가 옆 창에 띄우는 값과 맞는 쪽이 옳다고 봤고, 덤으로 당일 봉 라이브 병합의 최종 상태가 저장 행과 같아져 20시 스냅샷 전환 때 값이 되돌아가는 흔들림이 없어지며 NXT와 KRX의 마감이 20시로 같아진다.

## 소스는 20시 10분 다건 시세

| 후보 | 판정 |
| --- | --- |
| 일봉 TR run을 20:10으로 옮겨 그날 봉을 적재 | 기각. 50분 run이 정정 창(21:35 이후 어딘가)에 걸리면 종목별로 정의가 섞임. 정정 시각 probe가 선행 조건이 됨 |
| **20:10 다건 시세 TR 90호출** | **채택.** 현재가 응답은 그날 마지막 체결이지 재집계 대상이 아님. 2~3분. 스냅샷 job이 쓰던 호출 함수를 공용 모듈로 빼서 재사용 |

```
어제 계약                                            오늘
15:33 run  다건 시세 90호출 → OHLC 확정 · 거래량 잠정      20:10 run  다건 시세(KRX 채널) 90호출 → OHLCV + 기준가
09:10 run  일봉 TR 2,650호출 → 거래량 덮어쓰기             일봉 TR   → 9/11 이전 백필 전용 (상한 고정)
                                                     pykrx 백필 → 9/14 이후 갭 채움 소스로 복귀
```

일봉 TR을 9월 11일 상한으로 묶으면서 16시 당일 캡도 같이 걷어냈다. 당일을 적재하는 경로 자체가 사라졌기 때문이다. 거래량이 0인 종목이 하루 110개쯤인데 건너뛰면 매일 갭이 생겨 백필이 상시 절차가 되니, 기존 일봉이 하던 대로 네 가격을 마지막 체결가로 채운 flat 봉으로 적재한다.

## 등락률의 기준가를 컬럼으로

| 저장 종가 두 행의 차로 등락을 만드는 곳 | 성격 |
| --- | --- |
| 종목 헤더 (NXT 종목 KRX 탭 · 마감 후 · 개장 전) | 상시 |
| 검색 결과 행 | 라이브 실패 폴백 |
| 관심종목 31번째 이후 (라이브 30종목 한도) | 상시 |
| 일봉 차트 hover 범례 | 상시 |

상시 표면이 셋이라 컬럼을 넣었다. 값은 현재가에서 전일대비를 빼는 대신 응답의 기준가 필드를 그대로 저장한다. 권리락이나 병합처럼 기준가가 전일 종가와 달라지는 날에도 증권사 등락률 축과 같아지기 때문인데, 이 판단은 초기화 대조에서 바로 확인됐다. 9/14 기준가와 9/11 종가가 다른 종목이 다섯이었고 넷은 5:1 액면병합, 하나는 스팩 기준가 조정이었다. 9/13 이전 행은 NULL로 두고 조회 쪽에서 전일 종가로 폴백하니 이력은 건드리지 않았고, 차트 범례는 봉 payload에 손이 가서 별도 항목으로 뺐다(E84).

```
9/14·9/15 재적재 순서   컬럼 추가 → pykrx로 덮어쓰기 → 20:10 스냅샷(통합 종가 − 전일대비)로 기준가 채움
                        ※ 재적재 전에 채우면 새로 들어오는 9/15 행 2천 개가 빈 채로 남음
```

## 병렬로 닫은 셋

### NXT 탭 결함

마감 후 스냅샷 분기에 market 축을 더해 NXT 탭이면 NXT 컬럼을 서빙하고, 등락은 통합 종가에서 전일대비를 뺀 전일 종가 기준으로 다시 계산한다(F93). 관심목록 다건 시세는 통합 단일 축 계약 그대로 두었고, 저녁 실물에서 NXT 탭이 HTS NXT 종가와 맞는 것을 확인했다.

### 세션 라벨과 배지

| 라이브가 없을 때 헤더 라벨 | 규칙 |
| --- | --- |
| SSR 행 날짜 = 마지막 마감일 | 애프터마켓 마감 · 20:00 |
| SSR 행 날짜 < 마지막 마감일 | 전일 종가 · MM.DD |
| 행 날짜 불명 | 애프터마켓 마감 · (없음) |

문자열은 네이버 구간표로 통일했고(E83), 라이브가 없으면 표시 값이 SSR 행이니 라벨도 행 날짜만 보게 했다. "정규장 마감 · 15:30" 폴백이 20시 값 위에 앉던 모순이 규칙 하나로 사라졌다.

배지는 세션 기준으로 바꾸고 실물을 보니 관심종목 전 행에 "애프터"가 붙어 있었다. 세션이 정해지면 전 행이 같으니 행 정보가 아니라 섹션 정보다. 행 배지를 없앴고, 섹션 단위 한 줄 표기는 며칠 써보고 판단하기로 했다(E86).

(스크린샷: 관심종목 전 행에 "애프터" 배지가 붙은 홈 위젯)

### 지수 당일봉 거래량

국내 지수 현재가 스키마가 누적 거래량을 버려 당일 합성봉에 거래량이 없었고, 히스토그램이 전일 막대에서 끝나고 있었다(F96). 지수 현재가 TR에 누적 거래량이 천주 단위로 오는 것을 확인하고 실었다. 부수로 아침 run을 중간에 끊었더니 뒤 step인 지수 적재가 안 돌아 9/15 지수가 비어 있었는데, step 직렬 의존은 backlog에 적어 두었다(F97).

## 정리

- **X27 종결** — 저장 캔들 = KIS 일봉 당일 봉(정정 전) = 20:10 다건 시세. 등락 축 = 기준가. 일봉 TR 9/11 상한, pykrx 복귀. 9/16 전수 대조 시가·고가 100%, KIS 일봉 4종목 전부 일치
- **기준가 컬럼 신설** — 소비처 4곳 중 3곳 치환. 액면병합 4·스팩 1이 근거. 차트 범례는 E84로 신설
- **F93 종결** — 마감 후 NXT 탭 NXT 컬럼 서빙
- **E83 종결** — 라벨 네이버 정합, SSR 행 라벨 단일 규칙, 행 배지 제거. 섹션 라벨 E86 backlog
- **F96 종결** — 지수 당일봉 거래량. step 직렬 의존 F97 backlog
- **F94 삭제 · X29 강등** — 20:10 job이 거래량 공식 축을 직접 씀. KRX Open API는 정규장 정의라 EOD 소스 불가

어제 하루를 들여 공식 정의에 맞춘 설계를 오늘 버린 셈인데, 버렸다기보다 어제 확인한 사실(정정 시각·기준가·거래량 축) 위에서만 오늘 결정이 가능했다. 엄밀히는 기각 사유 셋 중 둘이 반대로 틀렸던 거라, 기각표를 하루 뒤에 다시 읽는 습관 하나는 얻은 듯하다.
