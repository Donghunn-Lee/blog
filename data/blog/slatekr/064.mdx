#062에서 종목 헤더에 실시간 현재가를 붙이면서, 정규장 밖 시간대를 여섯으로 갈랐다. 그때 두 가지를 다음으로 미뤘다. 하나는 공휴일 판정이고("휴장일엔 그대로 장 마감으로 두고 싶은데 F트랙에서 같이"), 다른 하나는 새벽에 전일 종가로 되돌리는 처리였다. 둘 다 그 세션에서 "일단 평일 기준으로만" 해두고 넘어간 자리다.

#063까지 실시간을 헤더·지수·관심종목 리스트에 다 얹고 나니, 이제 막 만든 그 기능에 구멍이 보였다. 평일 공휴일이면 화면이 장이 열린 것처럼 군다. 새 기능이나 디자인으로 넘어가기 전에, 방금 깔아둔 실시간 트랙의 정확성부터 닫고 가기로 했다.

이번 세션은 두 작업이다.

- **F15** — 평일 공휴일을 휴장으로 판정한다
- **F14** — 휴장일·장 마감일 때 헤더가 전일 등락을 0%로 지우던 걸 직전 거래일 값으로 남긴다

## 거래일과 휴장일 구분 표시

지금까지는 요일을 기준으로 거래일과 휴장일을 구분했다. 토·일이면 닫힘, 그 외 평일이면 시간대로 갈라 정규장·시간외를 판정한다. 다만 이 방식으론 주말은 막지만 평일 공휴일은 못 막는다. 설이든 추석이든, 그날이 화요일이면 함수는 정규장으로 친다. 그러면 공휴일에 지수 슬레이트가 KIS를 계속 부르고, 종목 헤더도 "개장 전"이나 "장중"으로 표시된다.

판정에 휴장일을 끼우는 건 정해진 수순인데, 정작 갈린 건 **휴장일 목록을 어디서 가져오느냐**였다. 후보가 셋이었다.

| 소스 | 장 전 판정 | 런타임 비용 | 유지보수 |
| --- | --- | --- | --- |
| 휴장일 상수 (연 갱신) | 가능 | 0 | 연 1회 갱신 |
| KRX 영업일 API | 가능 | 런타임 호출·캐시 필요 | 자동 |
| daily_prices 역산 | 불가 | 0 | 0 |

역산이 제일 먼저 떨어졌다. daily_prices는 그날 장이 끝나고 수집이 돌아야 행이 생긴다. 그런데 휴장 판정이 가장 절실한 시간대가 장 시작 전(06:00~09:00)이다. 그 시점엔 오늘 행이 아직 없으니, "오늘이 거래일인가"를 daily_prices만으론 답할 수 없다. F15가 고치려는 바로 그 케이스를 못 푸는 거라 제외했다.

KRX 영업일 API는 정답에 가깝다. 거래소가 직접 주는 데이터니 갱신도 자동이다. 근데 이걸 쓰면 세션 판정이라는, 모든 폴링이 거쳐 가는 길목에 런타임 외부 호출이 하나 붙는다. 캐시 레이어도 따로 둬야 한다. 안정적일 수는 있지만, 더 간단한 방법은 따로 있다고 생각했다.

그래서 휴장일 상수로 갔다. 날짜 목록을 코드에 박아두고, 그 안에 들면 닫힘으로 친다. 안정적이고, 런타임 비용이 0이고, 장 시작 전에도 판정이 된다. 비용은 1년에 한 번 목록을 갱신하는 것뿐이다.

```ts
export const KRX_HOLIDAYS_2026: ReadonlySet<string> = new Set([
  "2026-01-01", // 신정
  "2026-02-16", // 설날 연휴
  // ...
  "2026-12-31", // 연말 휴장
]);

export const isKrxHoliday = (dateStr: string): boolean =>
  KRX_HOLIDAYS_2026.has(dateStr);
```

### 상수로 박으면 연중에 바뀌는 건 어쩌나

상수의 약점은 분명하다. 연중에 휴장일이 바뀌면 어쩌나. 짚어보니 정기 공휴일은 연초에 다 확정된다. 음력 명절도 그 해 달력이 나오면 날짜가 고정이다. 흔들리는 건 임시공휴일과 선거일인데, 국무회의에서 지정하고 보통 몇 주 전 예고로 붙는다. 연에 많아야 한두 건이다.

다행히 미반영했을 때 피해가 작다. 빠뜨린 임시공휴일에 함수가 그날을 정규장으로 치면, 세션 라벨이 잘못 뜨고 폴링이 헛돈다. 다만 그날 거래가 없으니 KIS는 전일 종가를 그대로 돌려준다. 가격은 어제 값에 멈춰 있을 뿐 화면이 깨지진 않는다. 하루치 라벨 오표기로 끝나는 거라, 그건 발생할 때 상수에 한 줄 더하는 비용으로 받기로 했다.

### preopen과 closed를 가르지 않아도 됐다

세션에 휴장 판정을 넣는 건 주말 체크 바로 다음 줄 하나였다.

```ts
if (day === 0 || day === 6) return "closed"; // 주말
if (isKrxHoliday(date)) return "closed";     // 평일 공휴일
```

원래는 장 시작 전 구간(preopen)을 거래일이면 "개장 전", 휴장일이면 "장 마감"으로 갈라야 하나 고민했다. 그런데 휴장일을 통째로 closed로 떨어뜨리니 그 분기가 필요 없어졌다. 휴장일은 preopen 구간에 들어와도 closed가 되고, closed는 이미 "장 마감"으로 그려진다. 거래일 아침은 그대로 preopen("개장 전")으로 남는다. 결과적으로 화면에 손댈 게 없었다. 주말에 쓰던 마감 화면이 공휴일에 그대로 재사용된 셈이다.

휴장일을 closed로 묶은 데는 부수 효과도 있다. closed면 폴링을 안 도니까, 공휴일에 지수 슬레이트가 KIS를 계속 부르던 것도 같이 멎는다. 애초에 이 작업을 당긴 이유 중 하나였다.

>한 가지는 일부러 안 건드렸다.
>
>장 마감 후 20:00부터 다음 날 06:00까지는 자정을 넘기는 구간인데, 이 경계를 정밀하게 다루려면 "직전 거래일이 언제였나"를 거슬러 찾는 날짜 계산이 붙는다. 그건 휴장 판정과는 결이 다른 작업이라, 이번엔 휴장일을 통째로 닫는 단순한 규칙까지만 두고 멈췄다.

## 장이 닫히면 등락이 0%로 지워지던 문제

두 번째는 #062에서 깔아둔 새벽 리셋의 뒷정리다. 그때 06:00이 지나면 전일 종가에 등락 0%로 되돌리도록 했다. 새 거래일이 다가오면 어제 대비를 0으로 초기화하는, 증권사 화면이면 다 하는 처리다.

근데 다시 보니 우리 헤더는 그걸 좀 과하게 하고 있었다. 리셋을 거는 분기 하나가 세 경우를 한꺼번에 묶고 있었다.

```ts
const forceFlat = session === "preopen" || session === "closed" || isNxtMiss;
```

`preopen`은 거래일 개장 전이다. 새 거래일이 곧 시작되니 "전일 종가 + 0%"가 맞다. 문제는 `closed`였다. 휴장일이나 주말에도 이 분기에 걸려 등락이 0%로 박혔다. 증권 서비스는 장이 쉬는 날엔 직전 거래일 종가와 그날의 등락을 그대로 들고 있다가, 다음 개장일 새벽에야 0%로 되돌린다. 휴장일에 0%를 띄우는 건 그 표준과 어긋난다.

직접 확인해보니 이건 헤더에만 있는 문제였다. 관심종목 행은 리셋 분기가 아예 없어서, 실시간 값이 없으면 그냥 종가의 등락을 그대로 쓰고 있었다 — 우연히도 표준 동작이 이미 되어 있던 거다. 지수는 폴백 자체가 없어 값이 없으면 "—"로 빠진다. 결국 손볼 건 헤더 하나였다.

고치는 방향은 `preopen`과 `closed`를 떼어내는 거였다.

| 세션 | 가격 | 등락 |
| --- | --- | --- |
| preopen (개장 전) | 전일 종가 | 0% |
| closed (휴장·마감) | 전일 종가 | 직전 거래일 등락 |

```ts
const isPreopen = session === "preopen";
const isClosedLike = session === "closed" || isNxtMiss;

const displayChange = isPreopen
  ? 0
  : isClosedLike
    ? initialChange          // 직전 거래일 등락 유지
    : (live?.change ?? initialChange);
```

값은 이미 있었다. 헤더의 부모 서버 컴포넌트가 종가를 그리려고 최근 이틀 치를 가져오고 있어서, 그 둘이면 등락은 그 자리에서 계산된다. DB나 조회 함수를 건드릴 것 없이, 부모에서 전일 대비를 계산해 props로 내려주는 것만 더했다.

```ts
const initialChange = prev !== null ? latest.close - prev.close : null;
const initialChangeRate =
  prev !== null && prev.close !== 0
    ? ((latest.close - prev.close) / prev.close) * 100
    : null;
```

이걸 props로 받으니 헤더 안에서 종가 차이를 즉석으로 계산하던 코드가 중복이 됐다. 같은 값이라 props 쪽으로 합치고, 더는 안 쓰이게 된 prop 하나를 지웠다.

지수에도 같은 처리를 해주고 싶었는데, 지수는 EOD 폴백 자체가 없다. 직전 거래일 종가를 들고 있으려면 지수 과거 시계열을 어디서 받을지부터 정해야 하고, 그건 다음 작업으로 미뤄둔 소스 결정(X12)에 걸린다. 그래서 지수 폴백은 그 결정에 묶어 함께 처리하기로 하고 이번엔 헤더까지만 닫았다.

## 정리

- **휴장일 판정** — 세션 함수가 평일 공휴일을 정규장으로 치던 걸 막았다. 소스는 셋 중 휴장일 상수를 골랐다. 역산은 장 시작 전에 답을 못 내서, KRX API는 세션 판정 길목에 런타임 호출을 더해야 해서 뺐다. 휴장일을 통째로 closed로 떨어뜨리니 화면 분기도 폴링 정지도 따라왔다
- **장 마감 등락 표시** — 휴장일에 등락이 0%로 지워지던 걸 직전 거래일 값으로 남겼다. 한 분기에 묶여 있던 preopen(0%)과 closed(직전 등락)를 갈랐고, 값은 부모가 이미 들고 있던 이틀 치로 계산해 props로 내려, DB·조회는 손대지 않았다

휴장일 쪽은 코드 양으로 치면 몇 줄인데, 그 몇 줄을 어떤 소스로 채울지 정하는 데 대부분의 시간이 갔다. 빠르게 가려던 세션이라 더 그랬다. 정확한 API 대신 1년에 한 번 손이 가는 상수를 고른 게, 이 프로젝트 단계에선 맞는 선택이었다고 본다. 등락 쪽은 따로 큰 작업이 아니라 #062 리셋이 덜 갈라뒀던 자리를 정리한 것에 가까웠다.
