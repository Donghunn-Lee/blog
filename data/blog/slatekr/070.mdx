#069까지 화면·실시간 트랙이 대충 정리되면서, 마무리에 꼭 필요한 걸로 남은 게 차트 통합·AI 요약 컨텍스트 정비·전반 검수 정도였다. 그중 차트를 먼저 잡았다. 셋 중 유일하게 조사부터 설계까지 앞단이 긴 작업이고, 차트가 데모에서 눈에 제일 먼저 걸리는 화면이라서다.

처음 잡은 범위는 "종목 차트랑 지수 차트 컴포넌트를 하나로 사용하자"였는데, 작업을 설계하는 사이에 요구가 계속 붙었다. 종목 차트에도 일봉/월봉 탭을 주고, 일봉·월봉에 당일 값을 실시간으로 얹고, 당일 탭은 고정하고, 종목에도 당일 분봉을 넣고. 결국 한 세션이 아니라 다섯 조각(P1~P4)으로 쪼개서, 각 조각을 독립 커밋으로 닫았다. 갈렸던 자리 위주로 적는다.

## 컴포넌트 분리 효율성 검토

지난 세션 마지막에 "두 차트를 나란히 놓고 다시 보겠다"고 했던 근거가 이거였다. 원래 #066에서 지수 차트를 만들 때는 "종목이랑 별도로 둔다"고 결론 낸 자리다. 그때는 공통 코드가 팔레트랑 createChart 옵션 20~30줄뿐이라 합칠 이유가 없었다. 그런데 양쪽에 같은 기능(탭·당일봉·잠금)을 넣기 시작하니 그 근거가 흔들렸다.

그래서 코드를 짜기 전에 두 컴포넌트를 정밀 대조하는 조사부터 돌렸다. 결과가 예상보다 깔끔했다. createChart 옵션은 사실상 공통이고, 실제로 갈리는 건 세 개뿐이었다.

| 갈리는 축 | 종목 | 지수 |
| --- | --- | --- |
| priceFormat | 원 정수 (precision 0) | 지수 소수점 (precision 2) |
| 시간축 표시 | 없음 | 당일 탭만 |
| 탭·폴링 | 없음 (정적 일봉) | 당일/일봉/월봉 + 폴링 내장 |

세 번째가 제일 컸다. 지수 차트는 탭 상태도, 폴링도, 폴백도 전부 컴포넌트 안에 들고 있었다. 이걸 그대로 두면 못 합친다.

방향은 하나로 정리됐다. **렌더러는 `bars` 배열만 받는 순수 컴포넌트로 빼고, 폴링·탭·조회는 전부 밖으로 밀어낸다.** 차트는 그리기만 하고, 데이터를 언제 어떻게 받을지는 호출하는 쪽이 정한다.

```ts
type PriceChartProps = {
  bars: ChartBar[];
  precision: number;        // 종목 0, 지수 2
  timeVisible?: boolean;
  locked?: boolean;         // 뒤에 나옴
  dimBefore?: number;       // 뒤에 나옴
};
```

`ChartBar`는 `time`을 `string | number`로 받게 뒀다. 일봉은 날짜 문자열, 당일 분봉은 epoch인데, 정규화 쪽이 lightweight-charts의 타입을 몰라도 되게 컴포넌트 안에서 흡수한다.

이 단계(P1)는 동작을 하나도 안 바꾸는 순수 리팩터로 닫았다. 기존 두 차트가 이 렌더러에 그리기를 위임하게만 바꾸고, 화면은 픽셀 단위로 그대로. 팔레트가 세 파일에 중복돼 있던 것도 이참에 상수 하나로 모았다.

종합 정보의 미니 차트는 통합에서 뺐다. 얘는 선차트에 세션 필터까지 붙은 특수 케이스라, 통합 렌더러에 넣으면 분기가 역류한다. 쓰는 데가 셋째로 늘기 전엔 캔들 고정으로 두는 게 맞다.

## 당일(Intraday) 데이터 실시간성

일봉·월봉 차트는 장 마감 후 적재된 값(EOD)만 그리고 있었다. 오늘 값이 안 찍힌다. 여기에 당일 봉을 실시간으로 얹는 게 P2다.

당일 봉을 만들 재료는 이미 있었다. 실시간 현재가 응답에 당일 시가·고가·저가·현재가가 다 들어 있어서, 이 네 값으로 당일 일봉 한 개를 만들 수 있다. 분봉을 따로 받아 집계할 필요가 없었다.

문제는 이걸 **서버에서 붙일지, 클라이언트에서 붙일지**였다. 어차피 당일 탭은 실시간으로 매분 갱신할 거였는데, 서버에서 당일 봉을 또 만들면 서버 쪽 현재가 호출과 캐시가 클라이언트 실시간 갱신이랑 이중이 된다. 그래서 서버 조회는 EOD만 그대로 두고, 당일 봉 생성과 갱신을 클라이언트 한 곳으로 모았다. 폴링으로 현재가를 받아 배열 끝에 당일 봉을 붙이고, 매분 마지막 봉만 갱신한다.

여기서 두 가지가 딸려 나왔다.

**날짜는 서버가 계산한다.** 당일 봉의 거래일을 클라이언트 `new Date()`로 뽑으면 브라우저 시계나 타임존에 흔들린다. 조회 서비스에서 거래일이 틀리면 안 되고, 서버는 어차피 장 세션 상태를 휴장일까지 따져 계산하고 있었다. 그 옆에 거래일 계산을 하나 더 붙여 응답에 실었다. 장 전(pre)·장 후(after)는 "오늘"로, 자정 넘긴 새벽은 "직전 거래일"로 떨어뜨린다. 새벽에 그냥 "오늘"을 쓰면 아직 안 열린 오늘 봉이 어제 종가로 그려지기 때문이다.

**갱신은 setData가 아니라 update로.** 매분 전체를 `setData`로 갈아끼우면 사용자가 잡아둔 줌이 리셋된다. lightweight-charts도 실시간엔 마지막 봉만 `update`하라고 권한다. 그래서 렌더러가 데이터 변화를 보고, 마지막 봉만 바뀐 경우엔 `update`, 데이터셋 자체가 바뀐 경우(탭 전환)엔 `setData`로 가르게 했다.

지수 쪽은 같은 구조를 붙이면서, 당일 분봉 폴링이 홈이랑 지수 페이지에서 각자 돌던 걸 훅 하나로 합쳤다. 같은 응답을 두 번 받던 게 한 번으로 줄었다.

## 당일 탭 고정과 전일 흐림

당일 탭은 확대·축소·이동을 막고 당일 구간에 고정하기로 했다. 트레이딩 툴이 아니라 조회용이라, 당일 흐름을 그대로 보여주는 쪽이 맞다고 봤다.

잠금 자체는 `handleScroll`·`handleScale`을 끄면 된다. 걸린 건 전일 봉 처리였다. 지수 분봉 응답엔 최근 2~3거래일 봉이 딸려 오는데, 기본적으로 당일만, 다만 전일 봉 색을 흐리게 할 수 있으면 조금 남겨도 괜찮을 것 같다고 생각했다. lightweight-charts는 캔들마다 색을 따로 줄 수 있어서(per-bar color), 전일 봉만 옅은 색으로 칠하는 건 가능했다.

## 종목 당일 분봉

#066에서 지수는 10분봉으로 갔다. 1분봉을 하루치 못 받아서였다. 종목은 사정이 다른지 확인부터 했다.

조사해보니 종목 분봉 endpoint는 지수랑 파라미터 의미 자체가 달랐다.

| | 1콜 커버 | 봉 주기 | 하루 전체 |
| --- | --- | --- | --- |
| 지수 | ~100봉 | 선택 가능 | 10분봉 1콜 |
| 종목 | 30봉 | 1분 고정 | 1분봉 13콜 |

지수는 봉 주기를 골라 한 콜에 하루가 들어왔는데, 종목은 같은 자리 파라미터가 "시각 기준점"이라 1분봉 30개씩만 준다. 대신 기준점을 30분씩 앞으로 밀면 하루(약 390분)를 13콜로 다 받을 수 있었다. 한 번에 못 받아 적재까지 갔던 지수와 달리, 종목은 on-demand로 당일치가 가능했다. 실측하니 13콜에 1초 안쪽이었다.

폴링은 서버에 증분 캐시를 두는 대신, route가 13콜로 당일치를 만들고 짧게 캐시하는 방식으로 갔다. Vercel의 서버리스는 호출 사이에 메모리가 안 남아서 "직전 결과에 최근 1콜만 이어붙이는" 식이 깔끔하게 안 된다. 진짜 증분을 하려면 DB에 쌓아야 하는데 지금 단계에 그건 과하다. 호출당 13콜이 유일한 비용이지만, 트래픽 규모를 생각하면 감당된다.

실측에서 endpoint 특성 하나를 잡았다. **장중에 조회하면 아직 오지 않은 미래 시각 봉이 마지막 체결가로 채워져 돌아왔다**. 그대로 두면 차트 끝이 평평한 정지 봉으로 얼어붙는다. 현재 시각보다 뒤인 봉을 잘라내는 필터를 붙였다.

## 1분봉 밀도, 그리고 방향을 되돌린 자리

여기서 원래 계획이 한 번 틀렸다. 1분봉을 당일 잠금 뷰에 다 그려보니, 봉 하나가 2~3픽셀이었다. 캔들 몸통이랑 꼬리가 겹쳐서 사실상 선 그래프처럼 보였다. 세밀하게 보려고 1분봉을 골랐는데, 정작 캔들이 캔들로 안 보이는 상태가 됐다.

처음엔 5분봉으로 묶어서 봉을 키우는 쪽을 생각했다. 그런데 다시 보니 문제의 뿌리는 봉 개수가 아니라 잠금이었다. 당일을 고정해두니 390개가 좁은 폭에 억지로 들어간 거였다. 잠금을 풀면 사용자가 확대해서 원하는 구간을 크게 볼 수 있고, 좁은 화면에선 과거부터 잘려 최근만 보이면 된다. 봉을 줄이는 게 아니라 고정을 푸는 게 답이었다.

이건 앞서 당일 탭에 건 잠금을 되돌리는 결정이라, 지수 당일 탭까지 같이 풀기로 했다. 지수는 10분봉이라 여유가 있지만, 종목만 풀고 지수는 잠그면 동작이 어긋난다. 잠금 해제와 초기 뷰 정책, 크로스헤어로 시·고·저·종가를 띄우는 것까지는 데이터를 다 얹은 다음 기능 트랙에서 한 번에 하기로 하고 이번엔 미뤘다. 엄밀히는 잠금이 틀린 설계였다기보다, 1분봉을 얹기 전엔 고정으로도 괜찮아 보였던 거다.

## 정리

이번 세션은 차트 두 개를 하나로 합치는 데서 시작해, 당일 값을 실시간으로 얹고 종목 분봉까지 붙이는 아크였다.

- **P1 — 통합** — `bars`만 받는 순수 렌더러로 빼고, 폴링·탭·조회는 밖으로. 동작 변화 없는 리팩터로 닫았다
- **P2 — 당일봉 실시간** — 현재가 응답의 당일 OHLC로 당일 봉을 만들어 클라이언트에서 얹고, 마지막 봉만 갱신해 줌을 지켰다. 거래일은 서버가 계산
- **P3 — 당일 잠금·전일 흐림** — per-bar color로 전일 봉을 옅게, 뷰는 당일 중심으로. 타입은 안 늘리고 경계 비교로
- **P4 — 종목 분봉** — 1분봉 13콜 fan-out으로 당일치를 받아 전용 페이지에 탭으로

차트를 그리는 일보다, 데이터를 언제 어디서 받아 어떻게 얹을지를 정하는 데 손이 더 갔다. #066에서 한 번 "합치지 말자"고 했던 결론을 이번에 뒤집었는데, 같은 기능을 양쪽에 넣기 시작하면 분리해둔 값이 사라진다는 걸 실제로 확인한 셈이다. 잠금을 걸었다가 1분봉 앞에서 도로 푼 것도 비슷하다. 설계가 틀렸다기보다, 다음 조각을 얹기 전엔 안 보이던 게 얹고 나서 보였다.

## 다음 작업

차트 통합 자체는 닫혔고, 남은 건 위에서 미뤄둔 기능과 검수다.

- **H3 — 차트 도구** — 당일 잠금 해제(종목·지수 통일)와 초기 뷰 정책, 시·고·저·종가를 크로스헤어나 상단 한 줄로 띄우기, 기간 프리셋 버튼. 밀도 문제를 여기서 마무리한다
- **D — AI 요약 컨텍스트 정비** — 프롬프트 구조화와 재시도 정책. 독립 작업이라 언제든 끼울 수 있다
- **F — 검수** — 코드 전반 점검. 기능을 다 얹은 뒤 마지막 게이트로 돌리는 게 맞다

기능 트랙(H3)이 자연스러운 다음이다. 데이터는 이번에 다 얹었으니, 이제 그걸 보기 좋게 다루는 도구를 붙이면 차트가 한 단락 마무리된다.
