#070 에서 차트에 필요한 데이터들을 붙였다. 이제 보기 좋게 다루는 도구까지 넣고 나면 차트가 한 단락 마무리된다. 이번은 차트 기능 트랙(H3)의 첫 조각으로, 거래량·이평선·OHLC 표시를 얹는 게 목표였다.

그런데 하필 이날 KIS 서버가 점검이었다. 오전 8시부터 다음 날 정오까지 실시간 현재가랑 분봉이 다 막힌다. 그래서 계획을 데이터가 있는 것 위주로 잘랐다.

그런데 여기서 예상치 못한 문제까지 발생했다. 몇 시간이고 켜 둬도 문제 없었던 로컬 개발 서버가 갑자기 다운되기 시작했다. 켠 뒤에 몇 분 뒤면 다운됐고, 메모리 힙 문제로 보였다.

먼저 계획대로 작업하다가 확인한 문제라, 문제 해결은 다음 세션으로 미루고 이번엔 원인 분석과 해결 방안을 계획했다.

---

## 볼 수 있는 것만 먼저

KIS가 막히면 실시간·분봉은 화면으로 확인이 안 된다. 빌드는 통과해도 눈으로 못 보는 상태가 된다. 반면 거래량·이평선·OHLC 표시는 전부 이미 적재된 일봉(EOD)만으로 그려지고 검증된다.

그래서 이번 세션은 EOD로 끝나는 것만 하고, 잠금 해제나 툴바처럼 실시간이 필요한 건 복구 후로 미뤘다. 기준을 "지금 데이터가 있느냐"로 잡은 셈이다.

---

## 거래량·이평선·OHLC 표시

셋 다 #070에서 뽑아둔 순수 렌더러(`bars`만 받는 `PriceChart`)에 표시 옵션을 더하는 일이었다. prop 세 개가 붙었다.

```ts
type PriceChartProps = {
  bars: ChartBar[];        // 이제 volume 필드 포함
  // ...
  showVolume?: boolean;    // 거래량 히스토그램
  maPeriods?: number[];    // 이평선 기간
  showLegend?: boolean;    // OHLC 상단 표시
};
```

셋 다 안 넘기면 기존과 똑같이 동작한다. 지수 차트랑 종합정보 미니 차트는 이 prop을 안 받아서 그대로다.

- **거래량** — 종목은 `volume`이 이미 DB에서 도메인 모델까지 흘러오고 있었다. 백필이고 뭐고 없이 `ChartBar`에 필드 하나 더 싣고 렌더만 붙이면 됐다. 캔들과 같은 영역 하단 20%에 오버레이로 얹었다. 별도 칸(pane)을 새로 만드는 것보다 높이 계산이 안 붙어 간단하다. 지수는 DB엔 거래량이 있는데 조회·타입 경로에서 빠져 있어, 이건 지수 대칭 작업으로 미뤘다.

- **이평선** — 종가 이동평균은 `bars`에서 바로 나오는 값이라, 데이터를 밖에서 받지 않고 렌더러 안에서 계산한다. 기간만 `maPeriods`로 준다. 봉 개수가 기간보다 적으면 그 선은 건너뛴다. 지금은 일봉 1년치라 120일선이 뒤쪽만 그려지는데, 나중에 적재를 늘리면 알아서 채워진다. 어디에도 개수를 박아두지 않았다.

- **OHLC 표시** — 크로스헤어를 따라다니는 tooltip과 상단 고정 한 줄 중에 상단 한 줄로 갔다. tooltip은 봉 위를 떠다니며 캔들을 가리는데, 밀도 높은 차트에선 그게 더 거슬린다. 크로스헤어를 올리면 그 봉 값으로, 안 올리면 최신 봉 값으로 갱신한다. 다만 크로스헤어가 움직일 때마다 React state를 바꾸면 매 이동마다 리렌더가 도니, 값 텍스트만 DOM으로 직접 갱신하게 했다.

라벨은 한국식으로 다듬었다. O/H/L/C를 시/고/저/종으로, 거래량은 단위 없이 풀 숫자로, 날짜는 연-월-일 순으로. 종가 오른쪽엔 전일 대비 등락률도 색을 입혀 넣었다.

## 로컬 서버가 가끔 죽는 문제

`next dev`를 오래 켜두면 어느 순간 힙이 12GB까지 차서 서버가 내려갔다. 열어두면 몇 분 만에 다시 죽는 정도라 원인을 정리해봤다.

직접 원인은 Next 개발 서버의 누적형 메모리 특성이다. 컴파일 캐시나 HMR 상태 같은 걸 시간이 갈수록 힙에 쌓는데, 평소 개발에선 문제가 안 되다가 폴링이 걸린 채로 오래 두면 GC가 못 따라잡는 지점에 닿는다. 응답이 10초씩 걸리던 로그도 KIS가 느린 게 아니라, 이 GC 압박으로 이벤트 루프가 밀린 결과였다.

여기에 최근 작업이 부하를 얹었다.

- 분봉·현재가 폴링이 60초마다 도는 엔드포인트가 늘었다
- 종목 분봉은 한 번 받을 때 13콜을 병렬로 쏜다
- 티커별 캐시 함수가 모듈 스코프 Map에 계속 쌓여 GC 대상에서 빠진다

다만 이건 로컬만의 문제로, 배포 환경에선 재현되지 않는다. Vercel은 인스턴스 수명이 짧아 쌓일 틈이 없다. 확인하다 하나 걸린 게, 개발 모드에선 서버 캐시(`unstable_cache`)가 아예 동작하지 않는다는 점이다. "캐시를 붙여 부하를 줄이자"는 방향이 로컬 메모리엔 도움이 안 된다는 뜻이다. 그래서 당장은 확인을 프로덕션 빌드(`build && start`)로 돌려 피하고, 개발 중엔 힙 상한만 올려두는 선에서 버틴다. 근본 수정은 다음에 로컬 전용으로라도 잡을 계획이다.

배포 쪽은 이 크래시와 무관하지만, 점검하다 리스크 두 개를 확인했다.

- 현재가 조회 API 몇 개에 서버 캐시가 없어, 접속자가 늘면 KIS 호출도 같이 는다 → 60초 캐시를 붙인다
- 당일 분봉 API가 KIS 실패 응답(빈 값)을 길게 캐시해서, 복구된 뒤에도 한동안 빈 차트가 남을 수 있다 → 실패한 응답만 골라 캐시에서 퇴출한다

둘 다 지금 데모 규모에서 터지는 문제는 아니라, 배포 정비 때 같이 처리할 예정이다.

## 정리

KIS가 막힌 날이라, 적재 데이터로 되는 표시 기능만 얹고 실시간 쪽은 미룬 세션이었다.

- **거래량** — 종목 도메인에 이미 있던 값이라 렌더만. 하단 오버레이
- **이평선** — 렌더러 안에서 종가로 계산, 기간만 주입. 개수는 데이터 길이에 맞춰 자동
- **OHLC 표시** — 상단 한 줄, 크로스헤어로 갱신, 리렌더 없이 DOM 직접. 라벨·등락률·날짜는 한국식으로

표시 기능은 대부분 "이미 있는 데이터를 어떻게 보여줄까"라 손이 많이 가진 않았다. 오히려 시간을 쓴 쪽은 캐시였는데, 코드를 대기 전에 전제를 확인한 덕에 헛수고를 덜었다. dev에서 캐시가 안 도는 걸 몰랐으면, 로컬 메모리 잡겠다고 엉뚱한 데를 고칠 뻔했다.

## 다음 작업

차트 표시는 얹었고, 남은 건 이걸 다루는 도구와 미뤄둔 정비다.

- **H4 — 차트 툴바** — 탭을 당일/전체로 줄이고, 캔들/선·일/주/월·봉 개수 입력을 차트에 붙은 툴바로 통합한다. 주봉 리샘플과 선차트가 새로 들어간다
- **F16 — 로컬 서버 메모리** — 위 문제를 로컬 전용으로라도 잡는다
- **F17·F18 — 배포 캐시 정비** — 현재가 60초 캐시, 분봉 실패 응답 퇴출
- **H3·H5 — KIS 복구 후** — 당일 잠금 해제, 지수 차트에 이번 표시들 대칭

우선 다음 최우선 작업은 메모리 해결이다. 그 뒤는 차트에 표시가 붙었으니 사용자가 기간이나 봉 종류를 직접 고르는 도구다. 이걸 붙이면 차트가 조회 도구로 한 매듭 지어진다.
