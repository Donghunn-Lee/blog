#047 말미에 짚어둔 C17(StockTabNav 폴더 탭 디자인)을 이번 세션에 풀었다. SlateKR이라는 이름 자체가 "slate(판)"에서 왔는데, 종목 상세의 탭 nav가 일반 언더라인 탭이라 그 메타포가 시각으로 안 드러난다는 게 문제였다. 파일 폴더처럼 겹쳐진 판을 전환하는 모양으로 갈 수 있을지 — 그게 출발점.

원래 별도 의사결정 세션으로 분리할 작정이었는데 결정이 짧게 끝나서 본 구현까지 같이 갔다. 총 5개 커밋이며, 순서대로 styleguide에 패턴 정의 → 디자인 수정 → 본 페이지 적용 → inner panel 제거 → sticky 제거 작업을 진행했다.

## 4칸 그리드와의 통합 방식

처음부터 목표는 파일 폴더 탭 구조였다. 탭은 수정하면 되는데, 현재 종합 정보 슬레이트의 구조가 다른 것과 성격이 약간 달랐다.

차트·재무·공시는 단일 패널인데 종합정보는 2×2 그리드였다. 폴더 탭이 의미를 가지려면 탭과 그 아래 콘텐츠가 하나의 묶음으로 읽혀야 하는데, 4칸 그리드는 "하나의 묶음" 이라는 시각이 약해서 폴더가 어디로 이어지는지 모호해질 수도 있다고 생각했다.

- **A**: 4칸을 외곽 슬레이트로 감싸서 활성 탭과 연결
- **B**: 폴더 탭처럼 보이되 콘텐츠와 완전히 붙이지 않음 (연결감 약화)
- **C**: 종합정보 4칸을 단일 패널로 재설계

C는 #043~#047에서 어렵게 정착한 4칸 구조를 다시 깨야 했다. 폴더 메타포와의 정합은 완벽하지만 비용이 컸다. B는 폴더 탭의 본질 — 활성 탭의 하단 보더가 콘텐츠 패널과 연결되어 끊기는 것 — 을 살릴 수가 없다. 결국 "예쁜 라운드 탭" 수준에서 끝나는 모양이라 폴더 메타포가 전혀 성립하지 않는다.

A로 가기로 했다. 외곽 슬레이트의 시각 무게가 결정 포인트였는데, 무채색에 옅은 보더로 가볍게 잡으면 4칸 안쪽 독립감을 유지하면서 활성 탭과 묶이는 형태가 된다. 4칸 그리드는 그대로 두고 종합정보 탭이 활성일 때 외곽이 무채색으로, 다른 탭이 활성일 때는 그 탭의 색이 외곽으로 펼쳐지는 구조. 꼭 무채색이 아니더라도 옅은 색도 고려할 수 있을 것 같았다.

## 5-color 매핑 — lavender와 peach의 자리

폴더 탭이라면 각 탭에 색 정체성이 들어가야 메타포가 강해진다. SlateKR의 5-color 시스템(Sky, Sage, Amber, Lavender, Peach)을 탭에 어떻게 배정할지가 한 갈래로 갈렸다.

현재 사용 현황을 보면 Sky는 핵심지표·가격통계, Sage는 재무, Amber는 공시. Lavender는 원래 AI 공시 요약 사이드 패널용이었는데 #044에서 사이드 패널을 폐기하면서 자리가 비었다. Peach는 관심종목용으로 예약돼 있지만 미구현.

차트는 별도의 "차트 무채색 원칙"이 있었다. 다만 그건 차트 시각화 *자체*에 대한 원칙이지 차트 *탭*까지 무채색이어야 한다는 의미는 아니다. 비어 있는 lavender를 차트 탭에 배정하면 정체성이 살아난다.

| 색 | 도메인 |
| --- | --- |
| Sky | 가격/시세 (핵심지표, 가격통계) |
| Sage | 재무 |
| Amber | 공시 |
| **Lavender** | **차트** (신규 배정) |
| **Peach** | **관심종목** (도메인 확정, 적용은 추후) |

종합정보 탭은 "모든 정보를 모은 메타 레벨"이라 무채색. 다른 4탭이 각자 도메인 색을 갖고, 종합정보는 그 색들을 다 품는 자리. 의미 부여가 깔끔하게 닫혔다.

## styleguide에 패턴부터 정의

CLAUDE.md 원칙에 "디자인 작업은 styleguide 우선"이라 적어둔 게 있다. 폴더 탭은 토큰보다 한 단계 위인 패턴이라 styleguide에 새 섹션을 두는 게 자연스러웠다. Tabs 섹션을 SlatePanels와 MotionTokens 사이에 신설.

처음 잡은 형태는 cascade-stack이었다. 좌→우로 z-index 감소(z-40 → z-10) + `-ml-1.5` 음수 마진으로 인접 탭들이 6px씩 겹쳐 보이게. 4장의 폴더가 비스듬히 쌓여있는 책상 위 같은 시각.

![](/static/images/velog/8b1263d3-ec45-4052-8bff-e1ded5de9aff-image.png)


activeIndex=0(종합정보) 단일 데모에서는 자연스러웠다. 근데 본 페이지에 적용했더니 4가지 활성 케이스에서 어색함이 줄줄이 나왔다 — 활성이 중간(1, 2)일 때 좌측 비활성이 활성 위로 올라오는 z 순서 문제, 좌·우 끝 비활성 탭의 sharp 하단과 패널 rounded 상단 corner의 곡률 충돌. 몇 번 다듬어보다가 cascade 자체를 빼기로 결정. `gap-2` 간격 형태로 재정비.

cascade는 단일 데모로 봤을 땐 욕심이 좀 있었던 형태긴 해서 빼는 데 약간 미련이 남았다. 다만 폴더 메타포는 cascade가 아니어도 성립한다. 각 탭이 자기 색 폴더로 가지런히 정렬돼 있고, 활성 탭의 색이 외곽 패널로 펼쳐져 한 묶음으로 읽히는 형태. "겹친 폴더"가 아니라 "서랍 안에 가지런히 정렬된 폴더들"로 보이도록 했다..

## 탭의 활성/비활성 색을 통합

탭 색 매핑에서 한 번 더 결정이 바뀌었다.

원래는 활성 탭이 자기 accent의 진한 톤(외곽 패널과 동일), 비활성은 옅은 hint 톤으로 매핑하고 있었다. 하지만 활성 탭의 색이 어차피 외곽 패널로 펼쳐지니까 탭 자체 색을 활성/비활성에 따라 바꿀 필요가 없다고 판단했다.

모든 탭이 자기 accent의 동일 톤(외곽 패널 색과 같음)을 갖고, 활성/비활성은 텍스트(`font-medium` + `text-foreground` vs `text-muted-foreground` + `opacity-80`)와 z-index로만 구분. 4탭이 항상 자기 색 정체성을 또렷이 갖고 있어서, 활성 탭이 어떤 색의 영역을 펼치게 될지가 비활성 상태에서도 미리 보인다.

## StockTabPanel — 탭과 패널을 한 컴포넌트로

본 페이지 적용 시점에 결정 포인트가 또 있었다. 외곽 슬레이트 색이 활성 탭별로 바뀌어야 하는데, 그 매핑을 어디서 할지.

- A: 각 page가 자기 외곽 슬레이트를 렌더
- B: layout이 일괄 처리 (use client 경계 필요)
- C: 별도 entity 컴포넌트(`StockTabPanel`) 신설

C로 갔다. 폴더(탭 + 패널)가 "한 컴포넌트"라는 styleguide 컨셉과 정합도가 가장 좋고, 색·corner 매핑이 단일 출처에 모인다. layout은 Server Component 그대로 유지하면서 탭 nav + 외곽 패널을 묶은 client 컴포넌트가 children을 감싸는 형태.

```tsx
// layout.tsx
<StockTabPanel ticker={ticker}>{children}</StockTabPanel>
```

`StockTabNav`는 흡수해서 제거. 활성 판정 로직(#046에서 명시화했던 부분)은 그대로 가져오고, 색 매핑과 corner 처리가 한 파일 안에서 끝난다.

## inner StockPanel 제거 — compact/interactive 분기

여기서 panel-in-panel 문제가 따라왔다. 차트/재무/공시 각 section이 이미 자기 `StockPanel`을 갖고 있다. 외곽 `StockTabPanel`이 색을 책임지는 구조에서 내부 panel이 그대로 남으면 sage-on-sage, amber-on-amber 같은 이중 패널이 된다.

단순히 inner panel을 다 제거하면 되나 싶었는데, 종합정보 4칸 그리드 안의 카드들도 같은 section 컴포넌트(`StockChart`, `StockFinancials`, `DisclosuresSection`)를 사용한다. 4칸 안에선 외곽이 무채색이라 각 카드의 자기 색 panel이 필요하다. 두 사용처를 모두 보존해야 한다.

각 section에 이미 있던 분기 prop(`interactive`, `compact`)을 활용해서 panel 래핑 자체를 분기로 돌렸다.

```tsx
// 예: StockFinancials
if (compact) {
  return <StockPanel variant="sage">{...}</StockPanel>;
}
return <>{...}</>;
```

탭 풀 페이지에서는 inner panel을 풀고 콘텐츠만 노출, overview의 compact 미리보기에서는 panel 유지. 종합정보 4칸은 그대로, 다른 3탭은 panel-in-panel 해소.

![](/static/images/velog/f56fba6e-8485-4da8-a559-9782ba4779ad-image.png)


### 차트 background

차트 탭의 외곽이 lavender인 상황에서 lightweight-charts canvas 영역이 그 위에 놓이게 됐다. lavender가 차트 plot 영역으로 비치면 시각이 어색할 수 있어서 한 번 봤는데, 라이브러리가 자체 흰색 background를 canvas에 그리는 구조라 lavender는 차트 외곽 padding 영역에만 노출됐다. 차트가 lavender 위에 떠있는 흰 직사각형처럼 자연스럽게 보였다. 한 겹 더 두르면 오히려 panel-in-panel 인상이 다시 살아나서 그대로 두기로.

## sticky 제거

폴더 탭이 자리잡힌 후 sticky 동작을 검증하다가 일관되지 않은 동작을 발견했다. 화면 확대 비율에 따라 같은 스크롤 위치에서 sticky가 작동하기도 하고 안 하기도 했다. 기준을 명확히 잡기 어려웠다.

폴더 탭 메타포에서 sticky가 시각적으로 자연스러운지도 좀 애매했다. 활성 탭이 외곽 패널과 한 묶음으로 읽혀야 하는데, 스크롤 시 탭만 떠올라 콘텐츠와 분리되면 그 묶음감이 깨진다. 사용자 의견으로 sticky를 일단 제거.

대신 모바일에서 페이지 스크롤이 길어졌을 때 탭 전환을 도울 별도 UI(floating 리모컨)를 신설하기로 했다. C18로 별도 트랙 등록. 모바일 반응형 작업과 함께 묶어서 진행할 예정.

## 정리

작업량은 다섯 커밋이지만 결정 흐름은 단순했다.

- 폴더 탭의 본질을 다시 잡고 (옵션 B → A)
- 5-color 매핑에 lavender·peach를 채워서 시스템 완결성 확보
- 탭 색을 활성/비활성 무관 동일하게 (활성 표시는 텍스트와 패널 연결로)
- cascade를 빼고 gap 형태로 (4가지 활성 케이스에서 자연스러움이 더 중요)
- 탭과 외곽 패널을 `StockTabPanel` 한 컴포넌트로
- inner panel은 사용처 분기로 보존하면서 panel-in-panel 해소

#047에서 시작된 패턴이 하나 더 명확해졌다. shadcn primitive 의존이 자연스러운 영역과 직접 구현이 깔끔한 영역의 경계. #047에서 `TabsList` primitive를 수정한 사례에 이어, 이번엔 `StockTabNav`를 흡수하면서 `StockTabPanel`을 처음부터 직접 구현했다. 폴더 탭처럼 디자인 정체성이 강하게 들어가는 컴포넌트는 처음부터 직접 구현하는 게 정합도가 높다. 포트폴리오 정리 시점(트랙 G)에 한 번 정리할 항목이다.

부수적으로, sticky 검증 중에 iPhone 12 Pro 해상도로 페이지를 봤다가 모바일 반응형 검증이 부족하다는 게 확인됐다. F1 반응형 트랙을 단순 점검에서 "모든 페이지 섹션 대대적 반응형 점검 + 업데이트"로 범위 확장했다. 모바일 floating 탭 리모컨(C18)도 그 트랙과 묶어서 처리할 예정.
