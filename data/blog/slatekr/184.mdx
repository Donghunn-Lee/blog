직전 글에서 서류 제출 전에 닫아야 할 확인 항목을 넷 남겼다. daily 적재가 다시 초록으로 돌아오는지, 종목 헤더의 '정규장 마감 · 15:30' 라벨이 실제 창에서 맞게 뜨는지, 브라우저 탭 파비콘이 제대로 보이는지, 프로젝트 지침 파일이 저장소본과 같은지. 이번 세션은 그 넷을 닫고 로드맵을 어디까지 운영할지 정하는 자리였다.

계획은 넷을 닫은 뒤 이력서로 넘어가는 것이었는데, 이력서는 한 번 더 밀렸다. 이번엔 의도한 것이다. 이력서에 실을 예전 프로젝트 하나가 서버 만료로 죽어 있어 먼저 살렸고(별도 글로), 그 뒤 서류 작업은 이 시리즈 밖에서 하기로 했다. 그래서 이 글은 개발을 어디서 멈추는지 적는 글이다.

---

## 남은 확인 항목

| 항목 | 결과 |
|---|---|
| 프로젝트 지침 파일 | 저장소본으로 교체. 함께 쓰는 작업 지침도 코드와 어긋난 네 곳(route 파일 선언 · lib 폴더 파일명 · 상수 범위 · Server Action 줄) 정정 |
| 브라우저 탭 파비콘 | 라이트 · 다크 탭에서 형태 읽힘 |
| 1.5배 무상증자 종목의 지표 숨김 | 배포본에서 PER · EPS · 시가배당률 '—'와 사유 툴팁 확인 |
| '정규장 마감 · 15:30' 라벨 | 코드로 종결(아래) |
| daily 적재 초록 | 10월 14일 run으로 직전 글의 수정 검증. 신규 기업행위 한 건은 당일 처리(아래) |

지침 네 곳은 코드가 틀린 게 아니라 문서가 뒤처진 것이었다. 그 김에 컨벤션 전수조사를 한 번 더 돌릴지 생각했지만, 전수는 이미 여러 번 돌았고 직전 글의 외부 평가도 컨벤션 위반을 짚지 않았으니 지금 할 일은 아니라고 봤다.

### 정규장 마감 라벨 정합

이 항목은 KRX 탭이 15:30부터 16:00까지 '정규장 마감 · 15:30'과 확정 종가를 보여주는지 배포본에서 한 번 보는 것이었다. 그런데 그 30분 창을 놓쳤다. 다음 거래일을 기다리려다, 이게 코드로 확인되는 것 아닌가 싶어 장 세션 구조부터 다시 적었다.

| 시각 | KRX | NXT |
|---|---|---|
| 09:00 ~ 15:20 | 정규장 | 메인 |
| 15:20 ~ 15:30 | 정규장 | 휴지 |
| 15:30 ~ 15:40 | 마감, 가격 고정 | 휴지 |
| 15:40 ~ 16:00 | 시간외 종가매매, 가격 고정 | 애프터마켓 시작 |
| 16:00 ~ 20:00 | 애프터마켓(제외 종목 있음) | 애프터마켓 |

라벨의 창 경계와 문구, 탭별 분기는 전부 순수 함수에 있고 직전 글에서 코드로 확인한 값이다. 15:30부터 16:00까지 KRX 가격은 규정상 종가에 고정이라 "확정 종가"도 보장된다. 배포본에서만 볼 수 있는 건 탭을 켜 둔 채 15:30을 넘길 때 새로고침 없이 라벨이 바뀌는가 하나인데, 폴링이 세션 경계를 넘으면 재개되지 않는 결함(F114)으로 이미 수용한 것이라 새 양보가 아니었다. 실측 항목을 만들 때 코드로 안 되는 이유를 먼저 적었으면 창을 기다릴 일이 없었다.

### daily run — 수정 검증과 기업행위 한 건

10월 14일 run은 직전 글에서 넣은 두 수정의 첫 검증이었다. 청크 호출 실패 0, 결손 0, 지난주 처리한 기업행위 16건 재발 0으로 수정 쪽은 깨끗했다. red는 신규 기업행위 한 건 때문이었는데, 5:1 주식병합에 액면가 감액이 겹친 종목이 그날 변경상장된 것이다.

처리는 직전 글 절차 그대로 10분이었다. 배율이 5.215로 정수가 아니었고 변경상장 기준가와 KIS 수정주가 축이 1원 어긋났지만, 둘 다 저장 축을 KIS 수정주가로 두는 규칙 안에서 끝났다. 기업행위가 있는 날은 red가 뜨는 게 정상 운영 상태라는 건 #172에서 이 규칙을 만들 때부터 알던 것이라, 이번 건은 그 상태가 맞다는 걸 확인한 정도다. 처리 기록은 재적재 자동화(F119)의 설계 입력으로 남겼다.

## 프로젝트 마무리

제출 전에 할 코드 작업은 당장은 없다. 활성 트랙에 남은 건 코드 이해 투어(G2) 하나이고 그건 제출 뒤다. 나머지는 전부 백로그로 내려가 있다.

| 백로그 | 요지 |
|---|---|
| 컴포넌트 렌더 테스트(F101) | 테스트는 순수 함수뿐. README 주장 세 개의 증빙으로 3 ~ 5개만 |
| 모바일 성능 구조 점검(F127) | 종목 상세가 요청마다 외부 API를 기다리는 구조가 원인인지부터 |
| 차트 컴포넌트 분해(F129) | 1,200줄 한 파일. 회귀 위험이 커 장중 실측이 필요 |
| use cache 마이그레이션(F7) | 캐시 계층 전체 재설계라 대공사. 종목 상세 ISR이 여기 종속 |
| 기업행위 재적재 자동화(F119) | 지금은 수동 절차 10분. 주 3회 이상 red가 다시 나오면 |

로드맵은 끝내지 않고 멈춘다. 서류를 내고 나면 백로그를 하나씩 소진하거나 기능을 더하면서 같은 번호를 이어갈 생각이다. 그 사이 코드 이해 투어는 공부용이라 글로 쓰지 않고, 이력서 · 포트폴리오도 이 시리즈 밖이다.

## 정리

- **제출 전 확인 항목 종결** — 지침 파일 교체 · 파비콘 · 지표 숨김 · 라벨 · daily. 라벨은 배포본 대신 코드와 규정으로 닫음
- **F119 — 기업행위 단건 처리** — 10월 14일 run의 신규 1건, 절차 재사용 10분. 비정수 배율 · 1원 차는 KIS 수정주가 축으로 수용
- **개발 일단락** — 제출 전 코드 작업 없음. 활성 트랙은 G2, 나머지는 백로그. 재개는 서류 제출 뒤

4월에 시작해 184번째 세션이다. 이번 세션에서 한 일 자체는 적지만 어디서 멈추고 무엇을 남기는지 정한 세션이라 글로 남긴다. 다음 글은 지금까지 어떻게 작업했는지(로드맵 · 일지 · 세션 단위)를 돌아보는 회고로 시리즈를 일단락할 예정이다.

이력서나 포폴 등은 그동안 작업 계획에는 넣어왔지만, velog 시리즈에는 넣지 않고 따로 진행할 생각이다.
