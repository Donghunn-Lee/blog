#050에서 store를 다대다로 갈아엎고 읽기·전환만 되는 골격까지 만들었다. 이번 #051은 그 위에 **실제 조작**을 얹는 칸이다. 그룹 생성·이름변경·삭제, 그리고 종목 상세에서 어느 그룹에 넣을지 고르는 동선까지.

대체로 별 문제 없이 흘러가다 다중 관심 그룹 설정에서 좀 막혔다. 이 글의 무게도 거기 실린다.

## store에 action부터

#050에서 state 구조는 다 잡아놨고, 이번엔 조작 action만 채웠다.

```ts
createGroup(name)                       // order = max + 1
renameGroup(id, name)
deleteGroup(id)                         // membership 제거 + 고아 ticker GC
moveGroup(id, "up" | "down")            // order 스왑

addMembership(item, groupId): boolean   // 특정 그룹에 추가
removeMembership(ticker, groupId)        // 특정 그룹에서만 제거
```

판단이 필요했던 지점 몇 개.

- **기존 `addToWatchlist`는 시그니처 유지** — 종목 상세 별표가 쓰고 있어서 호출부를 안 깨는 게 우선. 내부만 `addMembership` 호출로 교체.
- **`removeFromWatchlist` vs `removeMembership` 분리** — 전자는 "관심종목에서 완전히 빼기"(전 그룹), 후자는 "이 그룹에서만 빼기". 의미가 달라 둘 다 남겼다.
- **`addMembership`을 boolean으로** — 신규 ticker가 상한을 넘으면 추가 안 하고 `false` 반환. 호출부에서 성공/실패를 나눠 처리하려고.
- **상한 50 → 100** — 그룹이 생기면 한 종목을 여러 그룹에 분류하게 되니 50은 좀 빠듯할 듯했다. 상수 한 줄이라 이 커밋에 묶음.

삭제는 **자식 종목 정리**를 같이 한다. 그룹을 지우면 그 그룹의 membership을 빼는데, 그 과정에서 **어느 그룹에도 안 남게 된 ticker**는 `stockMeta`에서도 지운다. 메타를 ticker당 한 벌만 들고 있는 #050 구조라, 참조가 0이 되면 메타도 비워야 한다.

## 삭제 confirm 모달 조기 도입

그룹 삭제는 **그 그룹에만 속한 종목까지 같이 사라지는** 파괴적 작업이다. confirm 수단이 필요했는데, 원래 모달(Dialog)은 #052에서 처음 도입할 계획이었다.

추렸던 후보는 다음과 같다.

| 수단 | 문제 |
|---|---|
| `window.confirm` | 스타일이 페이지랑 따로 놀고 모바일에서 조잡 |
| sonner 토스트 + 확인 버튼 | 몇 초 뒤 사라짐 → 파괴적 작업 막기엔 약함 |
| **AlertDialog** | 제대로 된 차단 모달. confirm 전용이라 용도 명확 ✅ |

결국 모달 도입을 일부 앞당겨 shadcn `alert-dialog`을 추가했다. 일반 Dialog(검색 모달용)는 #052에서 이어 붙이고, 이번엔 confirm만. styleguide에도 Modal 섹션을 새로 만들어 예시를 남겼다 — 디자인을 styleguide 기준으로 두기로 했으니 컴포넌트를 들이면 거기에 흔적을 남기는 게 맞다.

> **색 하나를 피했다.** AlertDialog 확정 버튼은 보통 destructive(빨강)인데, 이 프로젝트의 `--destructive`가 주가 상승색(빨강)과 hue가 거의 같다. 삭제 버튼이 상승 신호처럼 보이는 건 이상해서, 기본 variant(짙은 네이비)로 두고 destructive 빨강은 안 쓰는 패턴으로 굳혔다.

## 그룹 관리 UI는 우측 헤더로

CRUD 진입점 위치가 고민이었다. 처음엔 좌측 그룹 패널 각 행에 설정 버튼을 달려 했는데 — **모바일에선 좌측 패널이 상단 가로 스크롤 탭으로 접힌다.** 좁은 탭에 이름변경·삭제·순서이동을 다 넣는 건 무리다.

그래서 관리 액션을 **우측 리스트 헤더 한 곳**에 모았다.

- **좌측 탭** → 전환 전용
- **우측 헤더** → 선택된 그룹명 + 액션 (순서 `▲▼` · 이름변경 · 삭제)
- **"최근 조회" 탭** → 그룹이 아니니 관리 버튼 미표시

데스크탑·모바일 공통 자리라 분기가 없다. 그룹 **생성**만 좌측 패널 하단(모바일은 탭 끝)에 `+ 그룹 추가`로 뒀다.

생성과 이름변경은 **같은 인라인 입력**으로 처리했다. 빈 자리나 그룹명이 텍스트 인풋으로 바뀌고 → Enter 확정 / Esc·blur 취소. 모달까지 갈 일은 아니었다.

순서 이동은 `▲▼` 버튼으로 `order`를 인접 그룹과 스왑한다. #050에서 정렬을 전부 `order` 기준으로 통일해둔 덕에, 이 값만 바꾸면 좌측 탭이든 종목 상세 그룹 목록이든 다 따라온다. (드래그 정렬은 X9 트랙으로 분리)

## 관심종목 추가 UI — CSS로 숨긴 동작 오류

종목 상세 별표를 누르면 그룹 체크리스트가 떠야 한다. #050에서 별표는 "기본 그룹에 바로 등록"이었는데, 관심 그룹 기능이 도입되면서 **"어느 그룹에 넣을지 고르는 UI 열기"** 로 동작이 바뀐다.

처음 설계는 **데스크탑 Popover / 모바일 Sheet(바텀시트).** 좁은 화면에선 Popover가 답답할 것 같았다.

그런데 이 프로젝트엔 viewport를 JS로 감지하는 훅이 없었다. 분기는 전부 Tailwind `md:`로 **둘 다 렌더하고 CSS로 한쪽만 보이게** 하는 패턴. 기존 방식을 따라 Popover와 Sheet를 같은 `open` state로 묶고 `hidden md:block` / `md:hidden`으로 토글했다.

타입 체크는 통과했다. 그런데 dev에서 별표를 누르니 **아무 일도 안 일어났다.** Popover가 열렸다가 그 즉시 닫히는 거였다.

### 원인 — Radix DismissableLayer

> shadcn 컴포넌트는 [Radix](https://www.radix-ui.com/) 위에 Tailwind 스타일만 입힌 코드다. 즉 동작과 접근성은 전부 그 아래 Radix가 담당한다. 이번 버그도 스타일이 아니라 **Radix의 dismiss 동작**에서 났다.

Popover든 Sheet든 *"내 콘텐츠 바깥을 클릭하면 닫는다"* 로 동작한다. 그런데 `display:none`으로 가려진 Sheet 입장에선 **화면의 모든 클릭이 자기 콘텐츠 바깥**이다.

```
별표 클릭 → open = true
  → 숨어있던 Sheet: "바깥 클릭이네?" → onOpenChange(false)
  → 공유된 open이 즉시 false → Popover도 같이 닫힘
```

시각적으로 가렸을 뿐 **컴포넌트는 살아서 이벤트를 듣고 있었다.** `modal={false}`로 scroll lock·focus trap 부작용은 줄였지만 dismiss 자체는 못 막았다.

**CSS로 보이는 걸 가리는 것과, 컴포넌트의 동작을 끄는 건 다른 문제였다.**

### 1차 대응 → 최종

일단 JS 분기로 한쪽만 마운트했다. `matchMedia`를 `useSyncExternalStore`로 구독(이미 hydration 가드에 쓰던 도구라 결이 맞았다) → 데스크탑이면 Popover, 아니면 Sheet. 동시 마운트가 사라지니 충돌도 사라졌다.

근데 막상 모바일 바텀시트를 보니 별로였다. **별표는 상단 헤더에 있는데 피드백 창은 화면 아래에서 올라온다.** 시선이 위아래로 따로 논다.

그러다 "그냥 모바일도 Popover면 안 되나" 싶었다. 처음에 좁다고 단정했는데, 그룹 체크리스트는 그룹명 한 줄씩 쌓이는 짧은 리스트다. AI 요약처럼 긴 본문이 아니라 좁은 Popover에도 충분히 들어간다. 좁다고 본 게 좀 성급했다.

**Sheet를 들어내고 Popover 하나로 통일.** `matchMedia` 분기도 같이 걷어냈다.

- `align="end"` — 별표가 헤더 우측이라 우측 정렬
- 너비 `min(16rem, 100vw - 1.5rem)` — 모바일 잘림 방지

결과적으로 컴포넌트가 제일 단순해졌다. 분기도, 동시 마운트도 없다.

## 등록 피드백 — 토스트 → 인라인

체크리스트는 행을 누르면 그 자리에서 바로 등록·해제된다(즉시 commit). 처음엔 토스트를 띄웠는데 **상단 헤더랑 겹치고, 문구가 길어 줄바꿈**됐다.

위치를 옮길까 하다가, 토스트 자체가 이 맥락에 안 맞는단 생각이 들었다. **시선은 방금 누른 행에 가 있는데 피드백은 화면 구석에서 뜬다.**

그래서 행 우측에 인라인 완료 표시(`CircleCheck`)를 넣었다. 추가 성공 시 초록 체크가 잠깐 떴다 사라진다.

**체크박스가 이미 있는데 또 필요한가?** 따져보니 역할이 다르다.

| | 보여주는 것 |
|---|---|
| 체크박스 | "지금 이 그룹에 속해 있는가" = **상태** |
| 완료 표시 | "방금 이 행이 반영됐다" = **이벤트** |

여러 그룹을 빠르게 연속 체크할 때 체크박스만으론 어디까지 눌렀는지 흐려진다. 인라인 표시가 행 단위로 "이거 들어갔어"를 찍어준다.

- **추가에만 표시, 제거엔 없음** — 제거는 체크박스 풀림으로 충분. 의도한 비대칭.
- **그룹별 독립** — `Set`에 groupId 넣고 1.2초 뒤 제거. 같은 그룹 재클릭 시 기존 타이머 먼저 정리해 깜빡임 방지.
- **상한 초과(100개)일 때만 토스트** — 추가가 안 된 상황이라 행에 찍을 게 없고, 별도 알림이 맞다.
