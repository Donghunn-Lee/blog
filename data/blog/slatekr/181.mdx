README(G1)는 문구와 이미지, 성능 수치까지 직전 세션에 닫았다. 다만 그동안 본 것은 문장과 근거였고, GitHub에 실제로 그려진 모습을 판정한 적은 없었다. 제출 전 마지막 README 작업으로 렌더 화면을 캡처해 깨지는 곳만 고치고, 저장소 전체를 읽힌 검토에서 나온 지적들의 사실 확인도 같이 끝내기로 했었다.

계획은 README 1커밋과 판정 몇 건이었다. 실제로는 README 1커밋에 주석 정리 2커밋이 붙었고, 배포본 탭에 떠 있는 Vercel 기본 아이콘을 보고 로고를 만든 적이 없다는 걸 깨달아 로고 · 파비콘 · 네비바 적용이 더해졌다. 세션은 하루를 넘겼고 커밋은 여섯 개가 됐다.

## 렌더 캡처 판정

캡처는 데스크톱 다크 모드로 열 장을 보고, 기준 두 개로만 판정했다.

첫 두 화면에서 무엇을 하는 서비스인지 · 화면 · 강점 네 개 · 배포 링크가 보이는가, 그리고 깨지는 요소가 있는가. 첫 기준은 통과였다. 제목 아래 한 줄 정의와 배포 링크, 히어로가 첫 화면에 있고 둘째 화면에 「한눈에 보기」 표와 화면 네 장이 들어온다. 그래서 인라인 GIF, 다크 모드용 스크린샷, 헤더 아래 바로가기, 다이어그램 같은 후보는 전부 기각했다. 

| 깨진 곳 | 원인 | 조치 |
| --- | --- | --- |
| 「품질」의 모바일 스크린샷 아래에 문장 꼬리 한 줄 | 목록 항목 안의 `<img>`가 단락을 끊지 못해 inline으로 처리되고, 줄 상자가 이미지 높이로 늘어남 | `<p>`로 감싸 블록화 |
| Tech Stack 표 맨 위의 빈 행 | 헤더 행을 비워 둔 마크다운 표 | 헤더 라벨 추가 |
| 「한눈에 보기」 라벨이 "캐시 계/층"처럼 음절 중간에서 꺾임 | GitHub는 한글에 단어 단위 줄바꿈을 걸지 않고, 자동 표 레이아웃이 긴 열에 폭을 몰아줌 | HTML 표로 바꾸고 라벨 셀에 `nowrap` |

셋째는 처음에 단어 경계마다 `<br>`을 넣으려 했다가 접었다. 표 레이아웃은 열마다 내용의 최대 폭에 비례해 폭을 나누기 때문에, 라벨을 쪼개면 그 열의 최대 폭이 줄어 오히려 더 좁게 배분되고 "부분 실패"가 다시 꺾인다. 셀 내용을 깨지지 않는 한 덩어리로 만드는 수밖에 없었고, `nowrap` 속성이 GitHub의 sanitizer를 통과하는지는 추측하지 않고 Markdown API로 렌더해 확인한 뒤 적용했다.

## 주석에 남은 로드맵 번호

저장소 검토의 지적 가운데 하나가 코드 주석에 `F41` 같은 로드맵 번호가 남아 있다는 것이었다. 작업 맥락은 개발 일지 소관이고 코드에는 '왜'만 남긴다는 규칙이 있지만 이건 중반부터 추가한 규칙이라 빈틈이 있었다. 세어 보니 28개 파일 61줄(R10). 주석과 docstring만 대상이고 문자열이나 테스트 데이터는 처음부터 빠졌다.

```
규칙 1  번호만 지워도 문장이 성립하면 지운다            58줄
규칙 2  번호가 근거를 대신하던 줄은 코드에서 확인되는 사실로 고쳐 쓴다   3줄
규칙 3  코드로 근거를 알 수 없으면 손대지 않고 보고한다    0줄
```

판별 기준은 "이 파일이 처음부터 이렇게 쓰였다고 가정해도 성립하는 문장인가"였다. 그 기준으로 보면 "무변경"이나 "이식" 같은 말도 기준 시점이 있어야 뜻이 통하는 이력 표현이라 같은 줄에서 함께 걷어냈다. 고쳐 쓴 세 줄은 한도를 정한 근거가 "어느 세션의 관측"에서 "해외 지수와 테이블을 공유해 최신 날짜만으로는 국내 부분 실패를 잡지 못한다"로 바뀌는 식이다. web과 collector를 나눠 두 커밋으로 넣었다.

## 제출 전 판정 세 건

지난 세션에서 약식 종합평가를 했었는데, 그 대 발견된 검토 필요 사항들을 이번에 바로 처리했다.

| 항목 | 사실 확인 | 판정 |
| --- | --- | --- |
| 훅 로직을 복제한 테스트(F128) | 다섯 곳. 셋은 같은 식이 화면 코드에도 2 ~ 3벌씩 있고, 한 곳은 복제본이 이미 원본과 갈라져 있음 | **추출.** 셋을 순수 함수로 빼서 훅과 테스트가 같이 import, 둘은 한 줄짜리라 수용. 다음 세션 |
| 컴포넌트 렌더 테스트 환경(F101) | jsdom · Testing Library 미도입, README 한계 첫 줄에 공개돼 있음 | 제출 뒤. F128을 순수 함수로 풀면 훅 렌더 테스트의 동기가 사라지고, 남는 가치는 면접 소재 |
| 모바일 성능 probe(F130) | 착수 기준은 이미 정해짐(80점이 보이면 착수) | 다음 세션에 다른 작업과 병렬 |

복제 테스트는 지적 그대로였다. 훅이 바뀌어도 깨지지 않는 테스트인데, 그중 한 곳은 복제본이 인자 하나를 빠뜨려 원본과 이미 다른 식을 검증하고 있었다. 복제가 왜 위험한지를 실물로 보여 준 자리라 면접 소재로도 남겼다.

## 다섯 달 만에 만든 로고

배포본을 탭에 띄워 놓고 보니 아이콘이 Vercel 기본값이었다. 로고는 기획 초기에 모티브까지 그려 두었던 것이다. 색색의 슬레이트가 쌓인 육면체 하나가 종목 하나이고, 판 한 장이 정보 단위라는 그림이었는데(#023), 디자인 언어를 거기서 뽑아 쓰면서 정작 그 그림은 다섯 달 넘게 구현 목록에 없었다. 탭 아이콘은 배포 링크를 여는 순간 보이는 것이라 제출 전에 넣기로 했고, 네비바 적용은 README 이미지 재촬영을 동반해서 같이 갔다.

```
위     무채     가격 · 헤더와 같은 무채
중간   peach   핵심 지표
아래   sky     공시 · AI 요약
```

색은 좀 여러 번 바뀌었다. 토큰 안에서 고르려고 했는데 패널 배경 단계는 너무 연하고 강조 단계는 면으로 깔면 탁해서, 결국 토큰과 같은 색상에서 밝기만 올린 고정값을 로고 전용으로 두었다. 토큰의 강조색은 글자 대비 기준에 맞추느라 눌려 있는 값이고, 로고는 면이라 그 제약이 없다는 게 근거였다.

| 결정 | 판정 |
| --- | --- |
| 라이트 · 다크에서 색 전환 | 기각. 브랜드 색은 고정, 검정 판도 다크 네비바에서 묻히는 것을 감수 |
| 면마다 음영 | 기각. 24px에서는 입체감 대신 이음새만 늘어남. 판마다 한 색 |
| 육각형 바깥 프레임 | 기각. 고정색이라 프레임 색도 하나여야 하는데 양쪽 배경에서 보이게 하면 네 번째 무채가 생김 |
| 둥근 모서리 | 보류. 24 · 16px에서는 보이지 않아 제출 단계에 닿지 않음 |

### 24px에서 거칠어 보이던 선

넣고 보니 SVG인데도 선이 매끄럽지 않아 이미지를 따로 만들어 넣을까 싶었는데, 렌더 조건 쪽이었다.

| 원인 | 조치 |
| --- | --- |
| viewBox에 여백이 있어 24px 지정이 실제로는 19px | viewBox를 육각형 경계에 맞춤. 꼭짓점이 정수 px에 떨어지는 크기(24 · 28 · 32)만 사용 |
| 히어로 마크 높이가 글자 크기 기준이라 25.5px | 고정 28px |
| 판 사이에 둔 1px 투명 틈이 30° 사선이라 1x 화면에서 계단 | 틈을 없애고 판을 겹쳐 그림 |

남는 것은 1x 디스플레이에서 사선 자체의 안티앨리어싱이고, 그건 어떤 벡터 로고도 같다. 히어로 제목 옆에 마크를 넣으면서는 직전 세션에 폭별로 고정해 둔 히어로 높이가 바뀌지 않는지 네 폭에서 전후를 쟀고, 전부 같았다.

### 스타일가이드 링크

스타일가이드 페이지에 들어가는 길이 없다는 것도 이때 알았다. 제품 메뉴가 아니라 메타 페이지라 네비바가 아니라 푸터에 두었고, 이름은 토큰과 컴포넌트를 등재한 페이지에 맞는 "스타일가이드"로 했다. 페이지 제목이 "디자인 시스템"으로 돼 있는 건 범위를 부풀리는 말이라 뒤에 고칠 생각이다.

## 장중에 찍힌 스크린샷

네비바가 바뀌어 README 이미지 세 장을 다시 찍었는데, 오후 두 시 장중이었다. 모바일 종목 상세 캡처에서 가격은 그 시각의 값인데 거래량과 시가총액은 전 거래일 값이고 기준일은 당일로 찍혀 있었다. 이미지는 그대로 쓰기로 했다. 거래량과 시가총액의 정합까지 맞춰 보는 독자는 없을 것이고, 홈 캡처는 마감 상태라 세트가 갈리는 것도 같은 급의 차이다.

## 헤더의 축 불일치

화면 쪽은 별개였다. 배포본에서 같은 종목을 열어 보니 캡처와 같은 상태였고, 값이 오래된 것보다 기준일 라벨이 값과 다른 것이 문제라 새 항목으로 올렸다(F131).

| 값 | 어디서 오는가 |
| --- | --- |
| 가격 | 장중 시세 요청 |
| 거래량 · 시가총액 | 전 거래일 저장 행 |
| 기준일 | 당일 |

거래량은 시세 응답에 누적 값이 함께 오고 시가총액은 상장주식수에 현재가를 곱하면 되니 계산식으로 바꾸면 끝나는 것 아닌가 싶었는데, 두 값을 서버 렌더에서 클라이언트로 옮기는 일이라 스켈레톤 높이와 hydration, 마감 뒤 저장 행과 같아지는지의 검증이 따라온다. 최소안은 기준일을 저장 행 날짜로 맞추는 라벨 한 줄이고, 값을 장중에 맞추는 쪽은 다음 세션에 코드를 읽고 정하기로 했다. 리뷰어가 업무 시간에 배포본을 연다는 점에서 제출 전 항목이다.

## 정리

- **G1 종결** — 렌더 결함 2건 수정, 「한눈에 보기」 표를 HTML로 바꿔 음절 줄바꿈 제거. 모바일 · 라이트 판정은 제외
- **R10 종결** — 28파일 61줄. 삭제 58 · 고쳐 씀 3 · 보류 0, 두 커밋
- **F128 · F101 · F130 판정** — 복제 테스트 3곳 추출은 다음 세션, 렌더 테스트 환경은 제출 뒤, 모바일 성능 probe는 다음 세션 병렬
- **F131 신설** — 장중 헤더의 거래량 · 시가총액 · 기준일이 가격과 다른 축. 최소안은 라벨
- **로고 · 파비콘** — 기획 초기 모티브를 고정 4색 단색 마크로 구현. 네비바 · 히어로 · 파비콘 세트 · README 이미지 3장
- **스타일가이드 진입** — 푸터 링크

가벼운 작업을 모아 둔 세션이었는데 로고 하나가 하루를 더 먹었다. 탭 아이콘이 배포 링크를 여는 첫 순간에 보인다는 점에서 지금 하는 게 맞았지만, 색을 네 번 바꾸는 동안 토큰 안에서 골라야 한다는 전제를 먼저 의심했으면 두 번이면 됐을 것이다. 엄밀히는 로고를 늦게 만든 게 아니라, 다섯 달 전에 그려 둔 그림을 할 일에 넣지 않았던 쪽이 맞다.
