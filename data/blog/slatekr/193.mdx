가상 시세 생성기 작업이 지난 글까지로 코드 · 데이터 작업은 끝나 문서 정리와 재배포(V6)만 남은 상태였다. 그런데 재배포 전에 화면을 다시 둘러보다가 넣고 싶은 기능이 두 가지 생겼다. 15:30이 지나면 종목 헤더에서 정규장 종가를 볼 곳이 없다는 것과, KRX 탭과 NXT 탭의 가격이 언제 봐도 같다는 것이다.

계획에는 없던 작업이지만 README와 스크린샷을 새 화면 기준으로 한 번에 맞추려면 재배포 앞에 넣는 게 낫다고 판단했다. 두 기능 모두 넣었고, 밤에 작업한 탓에 장중 화면은 보지 못해서 그 확인은 다음 거래일로 남겼다.

## 정규장 종가 줄
 
[#159](/blog/slatekr/159/)에서 일봉 종가를 20:00 애프터마켓 마감 값으로 옮기고, 등락의 기준은 전일 15:30 정규장 종가(기준가)로 뒀다. 그 뒤로 헤더는 15:30이 지나면 애프터마켓 가격을, 20:00 이후에는 20:00 종가를 보여 준다. 그러다 보니 다음 날 등락의 기준이 되는 15:30 종가는 화면 어디에도 남지 않았고, 저녁에 본 종가와 다음 날 기준가가 왜 다른지 화면만으로는 알 수 없었다.
 
그래서 가격 아래에 정규장 종가를 작은 한 줄로 두기로 했다. 값은 KRX 탭 · NXT 탭 · 탭이 없는 종목 모두 KRX 15:30 종가 하나다. NXT는 정규장을 15:20에 닫지만 다음 날 기준가가 되는 건 KRX 종가라서 NXT 값은 따로 두지 않았고, 기준가가 오늘 기준으로 넘어가는 08:00부터 정규장이 끝날 때까지는 줄을 숨긴다.
 
| 시간대 | 정규장 종가 줄 |
|---|---|
| 15:30 ~ 20:00 | 표시, 그날 종가 |
| 20:00 ~ 다음 거래일 08:00 · 주말 · 휴장일 | 표시, 마지막 거래일 종가 |
| 08:00 ~ 15:30 | 숨김 |

## 15:30 전 종가 차단
 
실데이터에서는 15:30 전에 그날 종가가 아예 없었지만, 생성기는 날짜와 시드로 하루 경로를 전부 계산하기 때문에 오전 10시에도 그날 15:30 종가가 이미 계산돼 나온다. 화면에서 줄을 숨기는 것만으로는 부족하다고 판단했는데, 응답에 값이 실려 있으면 개발자 도구의 네트워크 탭이나 API를 직접 요청하는 것으로 그대로 보이기 때문이다.
 
그래서 값을 만드는 서버 함수의 첫 줄에서, 요청받은 날짜의 정규장이 아직 끝나지 않았으면 값을 내보내지 않게 했다. 줄을 숨길지는 화면 쪽에서, 값을 내보낼지는 서버 쪽에서 따로 판단하는 구조다. 15:29에는 값이 없고 15:30부터는 같은 시각의 현재가와 같은 값이 나오는 것을 테스트로 고정했다.
 
```ts
export const getRegularClose = async (ticker: string, date: string, now = new Date()) => {
  // 그날 정규장이 끝나기 전에는 종가를 내보내지 않는다
  if (date > getKrxLastCloseDate(now)) return null;
  // …
};
```

## 정규장 종가 줄 자리 예약
 
헤더 값은 서버가 페이지를 그릴 때 넣어 둔 저장 행과 클라이언트 요청의 응답, 두 곳에서 온다. [#182](/blog/slatekr/182/)에서 거래량 · 시가총액 · 기준일이 화면에 보이는 현재가와 같은 소스를 따르게 했는데, 정규장 종가도 같은 판정을 따르게 했다. 응답 값이 보이는 중이면 그 응답에 실린 종가를, 저장 행이 보이는 중이면 그 행 날짜의 종가를 쓰기 때문에 어제 가격 옆에 오늘 정규장 종가가 붙는 일은 생기지 않는다.
 
남은 문제는 줄이 나타나는 순간이었다. 줄을 보일지는 시각으로 정해지는데 값은 응답이 와야 생기고, 값이 왔을 때 줄을 그리면 그 순간 아래의 통계 행과 차트가 한 줄씩 밀린다(레이아웃 시프트).
 
| 후보 | 판정 |
|---|---|
| 값이 도착하면 줄을 그리기 | 기각. 응답이 올 때 아래 행이 한 줄 밀림, 요청이 실패하면 줄이 생기지 않아 상태마다 헤더 높이가 다름 |
| **표시 시간대면 빈 줄부터 그리기** | **채택.** 줄을 그릴지는 시각으로, 값은 응답으로 따로 정함. 응답이 늦거나 실패해도 높이가 같음 |

## 스켈레톤 줄 예약
 
헤더가 준비되기 전에 보이는 스켈레톤에도 같은 문제가 있었다. 처음에는 스켈레톤이 서버가 미리 만들어 둔 정적인 모양이라 보는 시각을 알 수 없다고 보고, 줄이 보이는 시간이 더 긴 쪽에 맞춰 줄이 있는 모양으로 고정했다. 이렇게 하면 정규장 중에는 스켈레톤이 실제 헤더보다 한 줄 크다.
 
하지만 빌드 출력을 다시 확인해 보니 ISR은 홈뿐이고 종목 페이지는 요청마다 서버에서 그리는 동적 경로였다. 홈처럼 1시간 전에 만들어 둔 HTML을 다시 쓰는 페이지라면 서버 시계로 나눠 그릴 수 없지만, 종목 페이지의 스켈레톤은 요청 시각에 그려지니 서버 시계로 판정해도 된다. 그래서 레이아웃에서 헤더와 같은 판정 함수로 줄을 넣을지 정해 스켈레톤에 넘기도록 고쳤다.
 
```
전: 스켈레톤은 항상 줄 포함 → 정규장 중에는 실제 헤더보다 한 줄 큼
후: 요청 시각으로 판정 → 표시 시간대에만 줄 포함, 어느 시간대든 실제 헤더와 같은 높이
```

## KRX · NXT 탭 가격 차이
 
생성기는 종목마다 하루 가격 경로를 하나만 만들고 KRX · NXT · 통합 화면은 그 경로를 시간대만 다르게 잘라 보여 준다. 그래서 [#124](/blog/slatekr/124/)에서 만든 KRX/NXT 탭을 눌러도 두 탭의 가격이 항상 같았다. 경로를 하나 더 만드는 대신 NXT 현재가에만 틱(호가 단위) 몇 개의 차이를 더하기로 했고, 경로 · 분봉 · 일봉과 KRX 탭 값은 그대로 둔 채 NXT 탭의 현재가와 마감 뒤 NXT 종가 두 값만 바뀌게 했다.
 
| 항목 | 규칙 |
|---|---|
| 크기 | 0 · 1 · 2 · 3틱이 35 · 40 · 20 · 5%, 위아래 절반씩 |
| 난수 | 종목 · 날짜 · 분으로 만든 별도 시드. 기존 경로 추첨은 그대로, 같은 분에는 같은 값 |
| 적용 시간 | 두 시장이 같이 체결되는 09:00~15:19 · 16:00~20:00 |
| 마감 뒤 | 20:00 봉의 차이를 NXT 종가에 그대로 적용, 저녁 · 주말에도 같은 값 |
 
처음에는 대체로 1~2틱, 드물게 3틱 차이를 생각했다. 하지만 실제 두 시장은 같은 가격이거나 1틱 차이인 시간이 많아서, 항상 다르면 오히려 어색해 보일 것 같아 같은 값도 35% 넣었다. 그래도 65%는 두 탭이 다른 값을 보여 준다.

## 적용 시간과 가격 범위
 
차이를 모든 시간에 주지 않은 건 통합 가격과의 관계 때문이다. 프리마켓과 15:40~15:59는 NXT에서만 체결되는 시간이라 통합 가격이 곧 NXT 가격이어야 하고, 여기에 차이를 주면 NXT 탭과 차트가 같은 체결을 두고 다른 값을 보여 주게 된다. 적용 여부는 지금 시각이 아니라 마지막으로 체결된 봉의 시각으로 판정했는데, 그러면 봉이 없는 15:20~15:29에는 15:19의 값이 따로 처리하지 않아도 그대로 남는다.
 
호가 단위가 바뀌는 경계(49,950원 위는 50,000원, 그 위는 50,100원)는 한 칸씩 넘어가게 했고, 가격이 벗어날 수 있는 범위는 처음 잡은 것에서 한 번 바꿨다.
 
| 후보 | 판정 |
|---|---|
| 당일 고저 안으로 제한 | 기각. 개장 직후처럼 고저 폭이 좁으면 차이가 거의 나오지 않음, 실제 NXT는 KRX 고저 밖에서도 체결됨 |
| **상 · 하한가 안으로만 제한** | **채택.** NXT 시세의 고가 · 저가는 벗어난 가격을 포함하도록 넓힘 |

## 정리
 
- **정규장 종가 줄 구현** — 15:30부터 다음 거래일 08:00까지 가격 아래 한 줄, 값은 KRX 15:30 종가 하나
- **15:30 전 종가 차단** — 생성기에서는 미리 계산되는 값이라, 화면에서 숨기는 것과 별개로 서버가 내보내지 않음
- **줄 자리 예약** — 표시 시간대면 값이 없어도 같은 높이의 빈 줄, 스켈레톤도 요청 시각으로 같은 판정. 처음엔 줄이 있는 모양으로 고정했다가 종목 페이지가 동적 경로인 걸 확인하고 수정
- **NXT 시세 차이 구현** — NXT 현재가와 마감 뒤 종가에만 0~3틱, 두 시장이 같이 체결되는 시간에만 적용. 경로 · 차트 · KRX 값은 그대로
- **DB 무료 플랜 전환** — 지난 글에서 미뤘던 것, 표시 용량이 내려간 걸 확인하고 전환
값을 만드는 것 자체는 간단했고, 시간을 쓴 곳은 그 값을 언제 내보낼지와 화면에서 자리를 어떻게 잡아 둘지였다. 15:30 전 종가처럼 실데이터에서는 생각할 필요가 없던 문제가 생성기에서는 생긴다는 건 이번에 처음 따져 본 것 같다.
