#060에서 KIS 토큰 캐시와 정규화 레이어까지, 실시간 트랙의 바닥을 깔았다. 이번 세션은 그 위에 fetch 래퍼부터 패널까지 경로를 이어서, 홈에 지수 슬레이트를 실제로 올리는 작업이다.

구현 자체는 #060의 다음 작업에 적어둔 순서 그대로다. 그런데 작업 중간에 "KIS로 현재가가 되는데 KRX EOD는 대체 왜 받아야 하나"라는 의문이 한 번 들었고, 데이터 소스 그림을 처음부터 다시 따져보게 됐다.

---

## 코어 위에 경로 잇기

작업은 세 단위로 나눴다. `fetch 래퍼` → `route handler` → `폴링` 훅 순서다.

fetch 래퍼는 #060에서 만든 토큰 발급과 normalizer를 결선해서 도메인 모델만 내보내는 얇은 층이다. `getKisToken()`으로 토큰을 얻고, KIS 지수 현재가를 호출하고, Zod로 응답 봉투만 검증한 뒤 normalizer에 넘긴다. 토큰 실패·네트워크 오류·파싱 실패가 제각각이지만, 호출부에서 일일이 분기하고 싶지 않아서 전부 `null`로 흡수하고 실패 종류는 로그로만 남겼다.

```ts
export const fetchIndexQuote = async (iscd: string): Promise<IndexQuote | null> => { ... }
```

route는 코스피·코스닥·코스피200 셋을 `Promise.allSettled`로 한 번에 부른다. 굳이 allSettled를 쓴 건 섹션 독립 원칙 때문이다. 셋 중 하나가 실패해도 나머지 둘은 그려야지, 한 지수 때문에 패널 전체가 빈 화면이 되면 안 된다. rejected와 정상-null을 한 갈래로 모으는 작은 헬퍼를 두고, 고정 키 객체로 응답을 내보냈다.

```ts
const pick = (r: PromiseSettledResult<IndexQuote | null>): IndexQuote | null =>
  r.status === "fulfilled" ? r.value : null;
```

폴링 훅에서 한 가지 정한 게 있다. 지수는 장중에만 움직이고 15:30 이후엔 종가에 멈춰 있으니, 장이 닫혀 있으면 폴링도 멈추는 게 맞다. route 응답에 `marketOpen` 플래그(KST 평일 09:00~15:30 판정)를 실어 보내고, 훅은 그 값으로 `refetchInterval`을 끈다.

```ts
refetchInterval: (q) => (q.state.data?.marketOpen ? 60_000 : false),
```

장 마감 후엔 60초마다 같은 종가를 다시 받아올 이유가 없으니, 닫혀 있으면 한 번 받고 멈춘다. 사람이 장중에 새로고침 없이 켜두면 1분 간격으로 갱신되고, 장이 끝나면 자연히 정지한다.

## 무채색으로 둔 지수 패널

패널 디자인에서 정한 건 두 가지다. 색을 줄 것인가, 그리고 어떤 형태로 묶을 것인가.

![](/static/images/velog/3c2df3da-fc59-49b6-9fc3-5b15c4429358-image.png)


색부터 보면 홈 안내카드가 이미 sky·lavender·peach 틴트를 쓰고 있어서, 지수에까지 도메인 색을 얹으면 한 화면에 색이 너무 많아진다. 지수는 시장 전체의 온도라 특정 도메인에 매이지도 않고. 그래서 패널 자체는 무채색으로 두고, 색은 등락에만 줬다 — 상승 빨강, 하락 파랑. 이 등락색은 차트가 쓰던 `price-up`/`price-down` 토큰이 이미 있어서 그대로 가져다 썼다.

형태는 패널형과 인라인형을 두고 봤다. 인라인은 테두리 없이 페이지에 녹아드는 가벼운 형태인데, 시장 지수치고는 너무 묻혔다. 홈에 이미 최근조회·관심종목 패널이 리듬을 만들고 있어서, 같은 패널 언어로 들어가는 쪽이 일관됐다. 살짝 떠 있는 카드 안에 세 지수를 세로선으로 나누고, 현재값을 24px로 키워 한눈에 읽히게 했다. v1은 차트 없이 숫자만이라, 숫자에 무게를 안 주면 빈약해 보인다.

값이 바뀔 때 count-up은 종목 상세 헤더에서 구현해 둔 걸 재사용했다. 부분 실패는 칸 단위로 갈라서, 한 지수만 못 받으면 그 칸만 "—"로 두고 나머지는 정상으로 둔다.

배치는 최근조회 아래, 관심종목 위에 넣었다. 검색·최근조회가 개인 이력 묶음이고, 그 다음에 시장 → 내 관심종목으로 내려가는 흐름이 자연스러웠다.

## KIS로 현재가가 되는데 과거는 어떻게 쌓나

작업하다 문득 걸린 의문이다. KIS로 지수 현재가를 받을 수 있고, 15:30 이후에 호출하면 그게 사실상 그날 종가다. 그러면 지수 차트나 기간 통계에 쓸 과거는 어디서 오나 싶었다.

처음엔 KIS 현재가 API만 떠올려서, 이건 "지금" 한 점만 주니 과거는 다른 소스로 받아야 한다고 정리했다. 그런데 확인해보니 KIS에 종목 기간별 시세(일/주/월/년) API가 따로 있었다(`FHKST03010100`). 시작·종료 일자와 주기(D/W/M/Y)를 넘기면 일봉을 배열로 돌려준다. 과거도 KIS로 받을 수 있다는 얘기다. 현재가 API 하나만 보고 "KIS는 한 점만 준다"고 넘겨짚었던 거다.

그렇다고 현재가 폴링으로 과거가 쌓이는 건 아니다. 폴링은 "지금"을 계속 덮어쓸 뿐이라, 차트용 시계열은 어느 쪽이든 따로 받아 DB에 적재해야 한다. 결국 문제는 "현재가를 어디서 받느냐"가 아니라 "과거 시계열을 어느 소스로 적재하느냐"였다.

결론적으로 후보는 원점으로 돌아왔다. 이번에 승인된 KRX Marketplace 지수와, 아직 안 찍어본 KIS 지수 기간별 차트 두 갈래다. 어느 쪽이 호출량·과거 범위 면에서 나은지는 다음에 probe 결과를 보고 정하기로 했다.

| 필요 데이터 | 소스 | 저장 |
| --- | --- | --- |
| 장중 현재가 (지수·종목) | KIS REST | 휘발성, 화면 폴링만 |
| 종목 과거 OHLCV | pykrx | DB `daily_prices` |
| 지수 과거 OHLCV | 미정 (KRX Marketplace / KIS 기간별) | DB (테이블 신설 예정) |

이번 세션에서 확정한 건 "장중 현재가는 KIS"까지다. 과거 시계열 소스는 종목만 정해졌고 지수는 열어뒀다. 한 점짜리 현재가 API만 보고 "과거는 다른 소스" 같은 그림을 너무 빨리 굳혔던 셈이라, 다음엔 후보 endpoint를 실제로 찍어본 뒤에 닫는 게 맞다고 봤다.

## 장외에서 받은 NXT 현재가

KIS 호출이 장외에도 되는지 보려고 장 종료 이후에 한 번 찍어봤다. 기본 시장 구분(`J`, KRX 본장)으로는 현재가가 15:30 종가에 멈춰 있었다. 그런데 시장 구분을 `NX`(넥스트레이드)로 바꿨더니 시간외 체결가가 살아서 갱신되고 있었다. 본장과 별개로 NXT 세션 가격이 따로 도는 거였다.

지수 슬레이트엔 지금 안 쓰지만, 종목 실시간 현재가를 붙일 때 쓸 수 있는 발견이다. 정규장 중엔 본장과 NXT 가격이 거의 같고 시간외엔 NXT만 의미가 있으니, 종목 트랙에서 "장중 J / 시간외 NX"로 가르면 된다. 그건 다음 세션 몫이다.

## 정리

- **실시간 트랙 결선** — fetch 래퍼 → route(`allSettled` 부분 실패 처리 + `marketOpen` 플래그) → 폴링 훅(장 닫히면 `refetchInterval` 정지) 세 커밋으로 코어 위에 경로를 이었다
- **무채색 지수 패널** — 안내카드 색과 부딪히지 않게 패널은 무채색, 등락만 기존 `price-up`/`price-down` 토큰으로. 인라인 대신 패널형으로 묶고 최근조회 아래 배치
- **과거 소스 점검** — KIS에도 기간별 시세 API가 있음을 확인. 종목 과거는 pykrx 유지, 지수 과거는 pykrx가 깨져 있어 KRX Marketplace와 KIS 기간별 두 후보를 다음 probe로 결정
- **NXT 현재가 발견** — 장외에서 `NX` 시장 구분으로 시간외 체결가를 받을 수 있음을 확인, 종목 트랙용으로 메모

지수 슬레이트가 홈에 떠서, 며칠 데이터 소스로 끌어온 트랙이 처음으로 화면에 드러났다. 구현 자체는 #060에서 깔아둔 코어 덕에 결선 위주로 비교적 매끄러웠다. 오히려 손이 간 건 소스 분담이 정말 맞나 다시 의심한 쪽이었는데, pykrx 우회로가 막힌 건 찍어서 확인했지만 KIS에도 과거 조회가 있다는 걸 뒤늦게 보면서 과거 소스 그림은 닫히기는커녕 한 번 더 열렸다. 한 점짜리 현재가만 보고 그림을 빨리 굳히려던 걸 한 번 접고, 다음에 후보를 마저 찍어보기로 했다.

## 다음 작업

지수 현재가가 붙었으니, 다음은 같은 실시간 경로를 종목으로 넓히는 순서다.

- **E15** — 종목 상세 헤더에 실시간 현재가를 붙인다. 이번에 발견한 NXT 시간외 구분을 route 분기에 넣고, IndexSlate에 인라인으로 둔 등락 표시는 두 번째 사용처가 생기는 이 시점에 공용 컴포넌트로 추출한다
- **E16** — 등락률·거래량 상위 같은 시장 데이터로 홈에 슬레이트를 하나 더 두는 안. 관심종목 패널 높이를 줄이고 같이 배치해 홈 밀도를 보강하려는 것인데, KIS 순위 API의 권한·스키마 조사(X11)가 먼저다
- **X5 / E17** — 지수 과거 차트를 위한 지수 EOD 적재. pykrx 지수가 막힌 게 확인됐으니, 남은 KRX Marketplace와 KIS 지수 기간별 차트를 probe로 비교해 소스를 정하고, 지수 테이블을 신설한다

E15가 자연스러운 다음 작업이다. 지수에서 만든 fetch·폴링 패턴을 거의 그대로 종목에 가져다 쓰면 되고, 인라인으로 미뤄둔 등락 표시도 그때 정리하면 된다.
