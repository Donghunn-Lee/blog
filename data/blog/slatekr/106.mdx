모바일 반응형의 마지막이다. 뭐 다시 수정사항이 눈에 띄면 추가 작업이 있을 수는 있지만, 계획상으로는 마무리다.

이번 세션 대상은 지수 페이지 — #092에서 master-detail로 다시 짤 때 모바일을 미뤄뒀던 화면이라, 이번엔 밀도 조정이 아니라 레이아웃부터 정해야 했다. 셀렉터 패턴을 정하고 detail을 압축하고 나니 지수와 종목의 차트 툴바가 서로 다르게 생긴 게 눈에 들어와서, 툴바 일관성까지 이번 몫으로 끌어왔다. 어려운 결정보다는 정리에 가까운 회차라 글도 요약 위주로 적는다.

---

## 셀렉터 — 상단 가로 스크롤 칩

모바일에선 데스크톱 2단이 그대로 세로로 쌓여, detail 아래에 지수 카드 일곱 장이 통째로 늘어서 있었다. 지수를 바꾸려면 차트를 지나 목록까지 내려갔다 다시 올라와야 하는 동선이다.

| 후보 | 구조 | 걸리는 점 |
| --- | --- | --- |
| 상단 가로 스크롤 칩 | 칩 선택 → 아래 detail 스왑 | 화면 밖 칩은 스와이프 필요 |
| 리스트↔detail 교체 | M3 compact 정석. 토스는 지수별 전용 라우트 | 지수 7개 왕복엔 과함, 라우트 분리는 서버 구조까지 번짐 |
| 아코디언 | #090 형태로 회귀 | 차트 인라인 펼침의 스크롤 비용을 #092에서 이미 확인 |
| bottom sheet | 리스트 유지 + 시트로 detail | 차트 드래그와 시트 제스처 충돌, sheet primitive 신규 도입 |

방법은 상단 칩으로 정했다. 지수 일곱은 고정이고 동질이라 탐색형 리스트가 아니라 뷰 전환기에 가깝고, 전환기라면 셀렉터가 detail 위에 상시로 있는 게 맞다. probe에서 확인한 데이터 구조도 이 선택을 받쳐줬다 — 데이터 훅이 선택과 무관하게 전 지수를 통합 캐시로 받고 있어서, 셀렉터 UI를 뭘로 바꾸든 배선 비용이 0이었다.

구현 요점만 추리면 이렇다.

- **rail 변형 대신 경량 신규(IndexChipStrip)** — Collapsible·세로 셀 구조에 가로 칩을 조건 분기로 심는 것보다 깨끗하다. 셀 데이터 파생은 rail과 같은 `buildIndexCell` 경로 재사용
- **edge bleed** — 스트립을 `-mx-4 px-4`로 뷰포트 끝까지 확장. 잘린 트레일링 칩이 스크롤 단서가 된다
- **선택 칩 scrollIntoView** — `?index=SPX` 딥링크로 해외 지수에 진입하면 선택 칩이 화면 밖에 있을 수 있다
- **scrollbar-hide 유틸 신설** — 백로그에 "실제 가로 스크롤 생기면"으로 걸어둔 F11의 트리거가 여기서 충족됐다
- **분기 축 이원화** — 칩↔rail 레이아웃은 md로 하단 탭바(#104)와 노출 구간을 맞췄고(640~768 이중 nav 방지), 밀도·타이포는 E39와 같은 sm 축

## Detail 압축 — 스탯 두 줄

스탯이 라벨 위·값 아래의 세로 셀이라 모바일에서 두꺼운 블록이 됐고, 그만큼 차트가 밀렸다. 차트를 가격 바로 아래로 올리는 안(증권 앱 관례)도 목업으로 놓고 봤지만, DOM 순서를 건드리지 않는 인라인 압축으로 갔다 — 기간 수익률이 차트보다 먼저 보이는 위계가 조회 서비스 성격에 맞기도 했다.

- **StatCell 가로 인라인화** — sm 미만에서 라벨·값을 한 줄로. 52주 셀만 `w-full`을 줘 flex-wrap 자연 개행이 [52주 저·고] / [1M·3M·1Y] 두 줄로 정리되게 했다
- **거래량은 가격 밑으로** — "2.8억" 축약이 가격 옆에선 좀 어정쩡해서, 스탯에서 빼 micro 폰트의 콤마 풀 숫자 행으로 갈랐다
- **해외 기준일 셀은 모바일 숨김** — 헤더 기준시각 라벨과 날짜가 항상 중복이었다
- **페이지 프레임·h1은 E39 처방 그대로** — /ranking·/watchlist와 같은 계층인데 타이틀 스타일이 달랐던 것도 이 참에 통일

타이포는 raw 스케일 여덟 곳을 role 토큰으로 치환했다. 1차 매핑은 종목 헤더를 peer로 봐서 지수명=종목명, 가격=현재가로 갔는데, 적용해 보니 방향이 반대였다 — 축소하러 들어간 세션에서 가격이 모바일 24→28px로 커졌다. detail pane은 상단 칩이 정체성을 분담하는 전환 패널이라 종목 헤더와 완전한 peer가 아니라고 다시 판정했고, 한 단계씩 내리니 데스크톱은 원래 픽셀로 정확히 복원되고 모바일만 줄었다(지수명 18/16, 가격 24/20).

## 차트 툴바 — 같은 툴바가 두 벌

지수 차트를 종목과 나란히 두고 보니 툴바가 2행으로 갈라져 있고 버튼도 커 보였다. probe로 대조하니 두 파일이 각자 인라인 구현이었다. #090에서 시각을 한 번 맞춘 뒤로 공유 코드가 없으니, #105의 높이 통일이 종목에만 적용되면서 도로 벌어진 상태였다.

| 통일 방식 | 내용 | 판정 |
| --- | --- | --- |
| 컴포넌트 추출 | 툴바를 ChartToolbar로 | props 15개 + 분기 4축(분봉 그룹·intraday 게이트·타이틀/기준일 슬롯). 중복 제거가 아니라 잘못된 추상화가 된다 |
| 공유 상수 | 버튼 배열 3종(완전 동일 사본) + 클래스 상수 3종만 이동 | 드리프트 원인 제거, 상태 배선은 각자 유지 |

공유 상수를 도입했다. 크기 조정이 모듈 한 곳의 노브가 되는 게 부수 수확인데, 바로 다음 단계에서 쓰였다.

h-7을 지수에 이식하고 실기기로 보니 폰트만 12→11로 줄고 높이는 24→28로 커져서, 축소 체감이 상쇄돼 있었다. h-7은 #105에서 터치 타깃 근거로 올린 값이고 그때 "체감 이상하면 revert"를 단서로 달아뒀는데, 이번 피드백이 그 관측의 결론이 된 셈이다. 모바일만 h-6으로 내리고 데스크톱은 유지했다.

```ts
// chartToolbar.ts — 모바일 축소, sm에서 원값 복원. 양 차트가 함께 움직인다
export const TOOLBAR_GROUP_CLS =
  "inline-flex h-6 sm:h-7 items-stretch gap-0.5 rounded-md border ...";
```

지수 툴바가 2행이던 건 크기 문제가 아니라 wrap 단위였다. 툴바가 [게이트 그룹, 클러스터 div] 2아이템 구조라 좁은 폭에서 클러스터가 통째로 개행됐던 것 — 그룹들을 래퍼 직계로 평탄화해 종목과 같은 그룹 단위 wrap으로 바꿨다.

## 차트 잔여 작업 처리

- **높이 반응형** — 지수 차트의 450 고정을 종목의 320/450 + useIsMobile 패턴으로 이식했다. dynamic 로딩 스켈레톤이 498px로 실차트와 48px 어긋나 있던 것도 툴바+차트 산식(356/490)으로 정합
- **레전드 y축 겹침** — 원인이 지수 쪽이 아니라 공용 컨테이너였다. 레전드 max-width가 가격축 폭을 예약하지 않는 구조라, 값이 긴 지수(소수 2자리+등락%)에서 먼저 드러났을 뿐이다. `left-3 right-14`로 축 폭을 예약해 종목 차트도 같이 수혜
- **종목 헤더 스택 재배치** — 제목 옆에 있던 툴바를 기준일 아래로 내려 제목→기준일→툴바→차트 순으로. 양 차트가 "툴바 = 차트 직상단 우측"으로 같아졌고, 기준일 라벨이 없을 때 차트 위 여백이 4px로 좁아지던 불균형도 함께 사라졌다

## 정리

- **E40** — 지수 페이지 모바일: 상단 칩 셀렉터, detail 스탯 두 줄 압축과 거래량 행 분리, role 치환·E39 프레임 정렬. 이걸로 E36 4분할 종결
- **차트 일관성** — 툴바 공유 상수화(컴포넌트 추출 기각), 모바일 높이 h-6 복귀, 지수 차트 높이 반응형·스켈레톤 정합, 레전드 축 폭 예약, 종목 헤더 스택 재배치
- **관측 이관** — h-6 버튼 오탭 체감, 레전드 right-14 예약폭. 이상 시 각각 모듈 한 곳 조정으로 끝난다

신규 레이아웃 세션으로 들어갔는데 지나고 보면 절반은 기존 처방의 이식이었다 — E39 프레임, #103의 role 층과 높이 패턴, #105의 툴바 값. 앞 세션들이 만든 처방이 그대로 먹히는 걸 보면 4분할로 쪼갠 순서가 맞았던 것 같고, 거기에 두 벌로 벌어져 있던 툴바를 회수한 게 이번 회차의 몫이었다. 모바일 반응형 아크는 여기서 닫는다.
