국내 시세를 공개 서비스에 쓸 수 없어 가격 계열을 가상 시세 생성기로 바꾸는 작업이 거의 마무리 단계다. 다만 따로 안내가 없어 화면만 봐서는 가격이 가상인지 알 수 없었고, 생성기는 외부 API 없이 계산만 해서 실패할 일이 없으니 그동안 만들어 둔 실패 처리 화면도 볼 수 없는 상태였다.

계획은 모든 화면에 가상 데이터 안내를 붙이고, 출처 페이지를 지금 구조에 맞게 고치고, 가격 API에 지연 · 실패를 주입하는 토글을 만드는 것(V4)이었다. 범위는 계획대로 끝났지만 첫 방문 안내는 화면에 띄워 보고 형태를 한 번 바꿨고, 확인하던 중 생성기 쪽 결함 두 건을 새로 찾았다.

## 재배포 전 판정 두 건

착수 전에 지난 글 끝에 남겨 둔 판정 두 가지를 먼저 정리했다.

### 가상 지수의 기준 수준

가상 지수는 앵커 날짜에 정해 둔 기준값을 중심으로 움직이는데, 그 값이 코스피 2,600이었다. 11월 6일 실제 종가가 5,059.69였으니 홈 첫 줄의 지수가 실제의 절반 수준으로 보이는 셈이었고, 확인해 보니 지수 12개가 전부 2024년 무렵 수준에 머물러 있었다.

| 지수 | 기존 기준값 | 11월 6일 실제 종가 | 변경 |
|---|---|---|---|
| 코스피 | 2,600 | 5,059.69 | 5,000 |
| 코스닥 | 780 | 644.27 | 650 |
| S&P 500 | 5,800 | 7,376.86 | 7,400 |
| 닛케이 225 | 39,000 | 57,434.77 | 57,000 |

종목 가격은 결산일의 실제 수준을 배당으로 역산한 값을 기준점(핀)으로 쓰는데, 지수는 이 규칙을 따르지 않기로 했다. 지수는 홈 첫 줄에서 오늘의 시장 수준으로 읽히는 값이라 배포 시점 수준에 맞추는 게 맞다고 판단했고, 반올림한 수준값이라 시세를 재배포하는 것도 아니다. 나머지 8개 지수도 같은 규칙으로 바꿨다.

### 상한가가 나오지 않는 문제

하루 수익률을 정규분포로 뽑다 보니 상한가는 3만 거래일에 1건꼴이고 하한가는 사실상 나오지 않았다. 등락률 순위 1위도 보통 15% 안팎이라 순위 화면에 상한가 표시가 뜰 일이 없었는데, 실제 시장에서는 거의 매일 몇 종목씩 상한가가 나온다.

| 후보 | 판정 |
|---|---|
| t분포로 뽑기 | 기각. 좌우 대칭이라 하한가도 상한가만큼 나오고, 평범한 날의 모양까지 같이 바뀜 |
| GARCH(변동성 군집) | 기각. 전날 상태를 이어 받는 구조라, 앵커 날짜에서 과거 방향으로도 이력을 만드는 생성 방식과 맞지 않음 |
| **점프 추가** | **채택.** 건수 · 상승 비율 · 크기를 따로 조절, 점프만 별도 시드라 나머지 날은 그대로 |

구현은 재배포 뒤로 미뤘다. 분포를 바꾸면 전 종목의 이력이 다시 그려지고, 생성기에는 같은 날짜를 언제 봐도 같은 값이 나와야 한다는 약속이 있어서 배포 전에 넣어야 한다고 생각했었다. 그런데 이력이 바뀌어 곤란해지는 쪽이 있는지 따져 보니 생성한 가격은 DB에 저장되지 않고 관심종목도 가격을 들고 있지 않았다. 그래서 그 약속을 DART 적재나 날짜 진행 같은 입력이 바뀌어도 이력이 그대로라는 뜻으로 좁히고, 모델을 고치는 건 재배포 단위로 허용하기로 했다.

## 가상 데이터 안내

실제 종목명과 재무를 그대로 쓰는 만큼, 가격을 실제 시세로 오해하지 않도록 가상이라는 걸 분명히 알려야 했다. 그래서 모든 페이지 헤더 아래에 한 줄 배너를 두었다.

> 시세 · 지수 · 순위는 가상 데이터입니다. 재무 · 공시는 DART 실데이터입니다.

- **첫 방문 안내** — 처음 들어온 사람에게 한 번 보여 주는 카드
- **출처 페이지** — 맨 위에 가상 데이터 안내 섹션 추가. 출처 표에서 KIS · KRX · 공공데이터를 빼고, 시세 · 지수 · 순위는 자체 생성기 · 종목 목록과 상장주식수는 DART로 교체
- **문구 · 툴팁** — 화면에 남아 있던 KIS 언급 3곳 수정, 핵심 지표 툴팁에 현재가가 가상 시세라 PER · PBR이 실제와 다르다는 줄 추가

배너에는 장애 주입 토글도 같이 들어가는데, 토글 상태는 쿠키에 있다. 배너가 들어가는 루트 레이아웃에서 쿠키를 읽으면, 1시간에 한 번 만들어 둔 HTML을 모두에게 주던 홈(ISR)이 요청마다 서버에서 다시 그리는 방식으로 바뀐다. 그래서 배너 문구는 서버에서 그리고 쿠키를 읽는 토글만 hydration이 끝난 뒤 클라이언트에서 읽게 했고, 빌드 결과에서 홈이 그대로 ISR 1시간인 것도 확인했다.

## 장애 주입 위치

실시간 시세가 잠깐 실패했을 때의 화면은 [#076](/blog/slatekr/076/) ~ [#078](/blog/slatekr/078/)에서 만들었다. 실패한 값 자리에 "—"와 일시 지연 배지를 띄우고, 섹션 하나가 실패해도 나머지는 그대로 두는 구조다. 그런데 생성기로 바꾼 뒤로는 가격 쪽 실패가 생기지 않아서, 쿠키 하나로 가격 API 요청에 3초 지연이나 실패를 넣는 토글을 만들고 어디서 넣을지를 정했다.

| 후보 | 판정 |
|---|---|
| 생성기를 부르는 어댑터 안 | 기각. 순위 · 지수 route는 결과를 `unstable_cache`에 담아 두는데, 캐시가 차 있으면 어댑터가 호출되지 않아 주입이 가끔만 걸리고, 실패가 캐시되면 토글을 켜지 않은 사용자도 그 실패를 받음 |
| 서버 첫 렌더까지 | 기각. 서버 컴포넌트에서 쿠키를 읽으면 홈 ISR이 풀리고, 주입 코드가 컴포넌트마다 퍼짐 |
| **가격 route의 try 첫 줄** | **채택.** 캐시를 꺼내기 전에 요청마다 판정, 실패는 throw해서 각 route의 기존 catch가 만드는 실패 응답을 그대로 탐 |

```ts
try {
  await applyDemoFault(req); // 캐시보다 앞, 요청마다. 지연은 3초 대기, 실패는 throw
  const { fetcher, key } = getCachedFetcher(kind, session, tradingDate);
  const payload = await fetcher();
```

실패가 캐시에 남는 문제는 [#075](/blog/slatekr/075/)에서 한 번 겪었다. 그때는 실패를 감지하면 캐시를 지우는 식으로 막았는데, 이번엔 주입을 캐시보다 앞에 두는 것만으로 같은 문제가 생기지 않는다. 주입은 가격 route 10곳에만 넣고, 검색 · 공시 · 관심종목 저장처럼 가격과 무관한 route는 그대로 뒀다. 가격만 실패해야 재무 · 공시 섹션이 그대로 남는 게 보이기 때문이다.

- **쿠키** — 지연 3초 / 실패 응답 두 가지, 1시간 뒤 자동 해제라 켜 둔 채 잊어도 사이트가 계속 고장 나 보이지 않음
- **위치** — 배너 오른쪽 팝오버, 켜져 있으면 배너에 상태 표시
- **반영** — 고르면 새로고침. React Query 캐시만 초기화하면 훅마다 초기 데이터 설정이 달라 결과가 제각각

## 섹션별 실패 화면

| 섹션 | 지연 3초 | 실패 |
|---|---|---|
| 홈 국내 지수 | 스켈레톤 3.9초 | 2.0초 뒤 오류 문구 |
| 홈 시장 순위 | 스켈레톤 4.0초 | 1.0초 뒤 오류 문구 |
| 홈 해외 지수 | 종가 먼저, 3.0초 뒤 현재가 | 종가 유지, 오류 문구 없음 |
| 관심종목 가격 | 셀 스켈레톤 3.3~3.7초 | "—"와 일시 지연 배지 |
| 재무 · 공시 · 핵심 지표 | 정상 | 정상 |

![실패 모드의 종목 상세 — 헤더 일시 지연 배지, 재무 · 공시는 정상](/static/images/slatekr/191-1.png)

국내 지수와 순위의 실패 시점이 1초 벌어진 건 두 route가 실패를 알리는 방식이 달라서다. 순위는 #076에서 정한 대로 200 응답에 실패 flag를 실어 보내서, React Query는 성공으로 받아 재시도하지 않고 화면은 flag를 보고 곧바로 오류 문구를 띄운다. 국내 지수는 500을 보내 재시도 한 번(1초 대기)을 거친 뒤에 오류가 뜬다. 200 쪽은 실패 응답에도 세션 정보가 실려 있어 순위 캡션이 유지되고 폴링도 계속 돌기 때문에, 장애가 풀리면 다음 폴링에서 저절로 돌아온다.

국내 지수 route의 500은 평소에는 도달하지 않는 안전망이다. 지수별 실시간 시세가 실패하면 그 칸만 종가로 대체해 200으로 보내는 구조라서, 주입이 try 첫 줄에서 throw하지 않는 한 이 경로로 올 일이 없다. 데모에서는 섹션 오류로 보이는 것으로 충분해서 그대로 두었다.

## 첫 방문 안내 형태 변경

첫 방문 안내는 처음에 화면 가운데 모달로 띄웠다. dev 서버에서 열어 보니 페이지가 뜨자마자 어두운 배경 위로 라이선스 제약과 투자 판단 주의가 올라와서, 안내라기보다 오류 창처럼 보였다. 배경만 빼는 방법도 생각했지만 모달은 열려 있는 동안 스크롤을 잠그고 포커스를 안에 가두며, 바깥을 처음 누르면 그 클릭을 모달을 닫는 데 쓴다. 배경만 빼면 화면은 멀쩡해 보이는데 눌리지 않는 상태가 돼서 오히려 더 고장 난 것처럼 보일 것 같았다.

사용자가 무언가를 결정해야 하는 안내가 아니라서 화면을 막을 이유가 없다고 판단했고, 쿠키 동의 배너가 뜨는 자리의 작은 카드로 바꿨다. 강조는 색 대신 굵기로만 줬다. 이 서비스에서 빨강 · 파랑은 등락, 노랑 계열은 경고를 뜻해서 색을 입히면 다시 경고처럼 보이기 때문이다.

```
전: 화면 가운데 모달 · 어두운 배경 · 스크롤 잠금 / 라이선스 이유로 시작해 투자 주의로 끝나는 문구
후: 우하단(모바일은 탭 바 위) 카드 · 화면 그대로 / 가격이 가상 데이터라는 문장 먼저, 이유와 주의는 보조 줄
기록: sessionStorage(탭마다 따로라 새 탭으로 연 종목마다 다시 뜸) → localStorage + 문구 버전
```

## 정리

- **V4 종결** — 배너 · 첫 방문 안내 · 출처 페이지 · 문구 3곳 · 지표 툴팁. 홈은 ISR 그대로
- **장애 주입은 가격 route의 캐시 앞** — 10곳, 실패는 각 route의 기존 실패 응답 그대로. 재무 · 공시는 실패 모드에서도 정상
- **첫 방문 안내 비모달 카드** — 결정이 필요 없는 안내라 화면을 막지 않고, 강조는 굵기로
- **재배포 전 판정** — 지수 기준값은 배포 시점 수준의 반올림 값 12개, 상한가는 점프 방식으로 재배포 뒤. 이력 불변은 입력에 대한 약속으로 좁힘
- **V3-c 신설** — 2016~2023 휴장일, NXT 종목 KRX 탭 애프터 시작 시각

이번 작업은 대부분 화면 문구와 배치였고, 판단에 시간을 쓴 곳은 장애 주입 위치와 첫 방문 안내 형태 두 군데였다. 토글은 데모용으로 만들었지만 로딩과 실패 화면을 점검할 때도 꽤 쓸모가 있을 것 같다.
