계속해서 쌓이던 UI 마무리 sweep을 소진하고, 이번 #125는 리팩토링 sweep 진입이었다. 근데 세션 계획을 잡다가 방향을 틀었다 — [#089](https://velog.io/@dh82680/SlateKR-089-로드맵-정리-마무리-스코프-확정과-Phase-4-전환)에서 Post-portfolio Backlog로 내려보낸 항목이 이후 작업하면서 어느샌가 40건 넘게 쌓여 있었다. 내릴 때는 "출시 후 후보"라는 한 마디로 충분했는데, 마무리가 실제로 가까워지니 그 목록을 다시 열어 볼 필요성을 느꼈다. 저 중에 정말 출시 후로 미뤄도 되는 것과, 지금 안 하면 안 되는 게 섞여 있을 거라서.

그래서 이번 세션은 코드를 한 줄도 안 건드리고, 1차, 2차 중간점검에 이어 마무리 점검으로써 백로그 전체를 결판내는 데 썼다. R sweep은 다음으로 밀었다.

## 판정 정책 — 전건 조사 후 결정

#089의 필터는 "활성이냐 백로그냐"를 가르는 기준이었다. 이번엔 백로그 안쪽을 가르는 기준이 필요했고, 정책을 하나로 정했다.

**기본적으로 다 처리한다고 생각하고, 조사(probe)는 전 항목 한 번씩 돌린다. 조사 결과 "조치 불요"로 끝나는 것도 처리로 친다.**

이 정책이 좋았던 건 "할까 말까"를 "조사할 수 있나 없나"로 바꿔준다는 점이다. 훑어보니 백로그 항목은 세 부류로 갈렸다.

| 부류 | 처리 |
|---|---|
| 기술 조사 잔여가 실제로 있는 것 | probe 1회 → 결과로 판정 |
| 조사할 게 없고 로드맵에 논거가 기명시된 것 | 문서상 종결 (F7·F63·F66 등 "구조 리스크만" 계열) |
| 기술이 아니라 스코프 의사결정만 남은 것 | 이번 세션에서 만들지/버릴지 결판 |

세 번째가 기능 확장류다. 이건 probe를 돌려도 "조치 불요"가 나올 성격이 아니라서, 기대 효과 순으로 전부 나열해놓고 하나씩 결정했다.

## 확장류 결판

18건을 효과 순으로 세워놓고 갈랐다. 결과만 요약하면:

| 판정 | 항목 |
|---|---|
| **편입** | 재무 배당 축(E47), 지수 intraday 통일, 지수 차트 기간 확장(E44), 익명 사용자 서버 저장(X7), 메모장(X8), 순위 카테고리 2종(E22), 지수 페이지 nav 진입점(신규), 그룹 모달 밀도(E12 재정의) |
| **드롭·삭제** | 컨센서스 조사(X1), 시총 변동 알림(E21), treemap(X10), 주식수 시계열(X15), 이격도·거래증가율 |
| **출시 후 유지** | 차트 전체보기(H4), 드래그 정렬(X9), 외화 재무(X22) |

몇 개는 결정 과정에 곁가지가 있었다.

**지수 intraday 통일** — 원래 백로그엔 E43(해외 4종 분봉 승격)·E59(SSR 플래시)·G5(국내 1분선)가 따로 흩어져 있었다. 근데 "지수 차트도 종목 차트처럼 1분봉으로 통일하면 어떤가"라는 관점으로 보니 셋이 한 아크였다. 특히 E59는 #124에서 "심야 이용자 규모"를 근거로 수용 판정했던 건인데, 그 논거가 US 지수만 본 거였다 — 아시아 3종은 장중이 한국 낮이라 플래시가 그대로 보인다. 판정을 뒤집고 아크에 흡수했다. E61로 통합 등록.

**E22 순위 카테고리** — 여기가 좀 꼬였다. 후보였던 이격도는 TR 실호출로 응답 형태까지 확인해놓고 드롭했다. 실측이 끝난 뒤에 "기술적 지표가 조회 서비스 순위에 있을 이유가 있나"를 자문했고, 답이 없었다. 순서가 반대였어야 했는데, 대신 KIS 명세 목록을 직접 열어보다가 더 나은 후보가 나왔다 — **관심종목등록 상위**. 사용자들이 실제로 뭘 들여다보는지의 집계라 조회 서비스 성격에 맞는다. 시총 상위와 함께 2종으로 확정했다. 하나 주의할 게, 이건 KIS 고객 집계라 SlateKR 자체 관심종목 기능과 이름이 겹친다. UI 라벨에서 출처를 갈라줘야 한다.

**X7 익명 사용자 저장** — 로그인 없이 사용자를 기억하는 구조가 가능한지부터가 질문이었다. 조사해보니 구조 자체는 표준적이다: 첫 방문에 UUID 발급 → httpOnly 쿠키 → 요청마다 자동 동봉 → DB에 UUID 키로 저장. 진짜 비용은 쿠키가 아니라 **스토어 전환**이다. 지금 관심종목은 Zustand persist로 localStorage에 즉시 반영되는데, 이걸 서버 왕복으로 바꾸면 낙관적 업데이트·실패 롤백·SSR hydration 정합·기존 데이터 마이그레이션까지 전부 서버 계약으로 승격된다. 세션 2~3개짜리 중형 아크. 그래도 "저장" 플로우가 기기 안에서만 도는 게 늘 아쉬웠어서 편입했다. 메모장(X8)은 이 인프라가 깔리면 소형이라 후속으로 같이.

**H4 전체보기** — iPhone Safari가 일반 요소에 Fullscreen API를 보장하지 않는다는 걸 확인하고 접었다. 17.2 베타에서 Feature Flag 뒤에 잠깐 등장했다는 기록은 있는데, 기본 설정에서 도는 안정 출하 근거를 못 찾았다. 화면 회전 강제(`screen.orientation.lock`)도 iOS는 미지원. 하려면 CSS 오버레이 + "기기를 돌려주세요" 안내 조합뿐인데, 이 정도면 출시 후 후보로 충분하다.

## 장중 창에서 E50 잔여 검증 — 그리고 F68

트리아지 사이, 장이 닫히기 전에 #124에서 이월한 E50 검증을 끼워 넣었다. 기본 탭·on-demand 폴링·비NXT 회귀 전부 이상 없었고, 블로커였던 NX 등락 기준도 양 탭 등락값이 일치하는 걸로 **KRX 전일 종가 기준**이 확정됐다. E50은 이걸로 진짜 종결이다(프리장 육안 하나만 다음 개장일 아침으로).

근데 검증하다가 새 문제를 하나 봤다. **분봉이 전부 1분씩 밀려 있다.** HTS에서 개장 봉은 09:01봉인데 우리 차트는 09:00봉이다. 42분 체결이 43분봉이 아니라 42분봉에 찍힌다.

원인은 경로 추적으로 바로 나왔다. KIS 분봉 응답의 시각 필드가 "그 분 00~59초 체결"을 뜻하는 **봉 시작 시각**이고, 우리는 그 값을 그대로 라벨로 쓴다. HTS 관행은 마감 시각 라벨이다. 규약이 반대인 거다.

고치는 건 단순 +1분 시프트가 아니었다. 경로를 전수로 따라가 보니:

- 세션 갭 컷은 raw 시각을 그대로 비교해서 **무영향**
- 1분→10분 리샘플의 floor 버킷은 END 라벨 기준에선 **경계가 깨진다** — 09:01~09:10이 한 봉이어야 하는데 floor(10분)는 09:00~09:09를 묶는다
- 종목 1분봉과 지수 10분봉이 같은 변환 헬퍼를 쓰니 **지수는 10분 밀려 있다**
- 테스트 스위트 곳곳에 시각 하드코드가 있다

시프트를 정규화 단계에 넣을지 최종 인코딩에 넣을지부터 설계가 필요한 건이라, F68로 등록하고 단독 세션으로 뺐다. HTS와 봉 라벨이 어긋나는 건 조회 서비스에서 그냥 둘 수 없는 종류다. 사실 이 세션 최대 수확이 이 발견인 듯하다 — 검증하러 들어갔다가 넉 달 묵은 규약 오류를 찾았다.

## probe 6종

결정에 실측이 필요한 것들은 한 번에 묶어 돌렸다. 다섯은 CC 통합 probe로, 둘(X7·H4)은 위에 적은 대로 웹 조사로.

| probe | 질문 | 답 |
|---|---|---|
| 국내 지수 1분봉 | KIS TR이 1분을 지원하나 | **지원.** 봉 주기 파라미터 60초 지정, 콜당 102봉(100분 커버) |
| 해외 4종 분봉 | NI225·HSI·SHCOMP·DAX가 US와 같은 스키마인가 | **동일.** 4종 전부 정상 응답, 15분 지연도 일치 |
| DART 배당 | 배당 데이터를 어디서 얻나 | **alotMatter.** DPS·시가배당률·배당성향, 우선주 행 동봉 |
| 이격도 TR | 응답 형태는 | 확인 완료 — 후 드롭 (위 참조) |
| 분봉 시각 경로 | F68 영향 범위 | 위 참조 |

**국내 1분봉**의 나머지 숫자도 나쁘지 않았다. 4개 지수 × 정규장 390분 = 하루 최대 1,560행, 7일 retention이면 750KB 수준. 30분 주기 append로 콜은 하루 192회. 수용해야 할 제약은 둘 — 연속 조회(페이지네이션)가 세 경로 모두 막혀 있어서 cron이 100분 넘게 죽으면 그 구간은 못 되찾는다는 것, 그리고 과거일 조회가 안 돼서 **백필이 불가능**하다는 것. 적재를 시작한 날부터만 쌓인다. 어차피 해외 파이프라인도 같은 조건으로 돌고 있으니 새로운 리스크는 아니다.

**해외 4종**은 화이트리스트 두 곳만 넓히면 소비측이 상수 참조로 자동 확장되는 구조까지 확인됐다. 다만 진짜 비용은 다른 데 있었다 — intraday route의 캐시·세션 판정이 전부 US 세션 상수 하나에 물려 있다. 아시아·유럽 지수가 들어오면 코드별 세션 축 분기가 필요하다. 화이트리스트는 10분, 세션 축은 반나절짜리다.

**배당**은 응답 규약이 독특했다. 미배당 종목도 15행이 그대로 오고, 값 슬롯만 "-"로 채워진다. status 분기가 아니라 값 파싱에서 갈라야 한다는 뜻이다. 손실 상태에서 배당한 종목의 배당성향이 음수로 오는 케이스도 샘플에서 확보했다. 그리고 collector 코드에 "dps는 별도 처리 필요"라는 주석이 이미 있었는데 — 그 별도 처리의 답이 이번에 나온 셈이다.

## 로드맵 v4

결정이 다 모이니 변경량이 기존 "변경 지시" 양식을 넘어서서, 로드맵을 v4로 전면 재구성했다.

- 활성 트랙에 **기능 확장 버킷 신설** — 마무리 단계에 확장 버킷이 생기는 게 좀 모순 같지만, #089의 버킷 원칙("마무리의 일은 성격으로 묶인다")대로면 이것도 하나의 성격이다. 의존 순서(F68 → E61 → E44 → E47 → …)로 배열했다
- **구조 정리 버킷** — X18(NXT 구조 통일)과 E57(에러 격리 확산). X18은 착수 조건인 프리장 실측이 E50 잔여 육안과 같은 08:00~08:50 창이라 한 세션으로 묶었다
- Backlog에 **종결·삭제 기록 섹션** — 삭제 9건·흡수 6건을 명시적으로 남겼다. 지운 항목이 어디 갔는지 나중에 찾게 될 걸 알아서

삭제 목록에는 몇 달을 끌고 다닌 번호들이 들어갔다. 선물 지수, 종목 분봉 DB 축적, 다우 시세 제약 추적 같은 것들. 판정 근거가 쌓일 만큼 쌓인 항목들이라 지우는 데 미련은 없었다.

## 정리

- **백로그 전수 판정** — "전부 조사 1회" 정책으로 40여 건을 편입·probe·문서상 종결·삭제로 전량 분류. 백로그에 남은 건 진짜 출시 후 후보뿐이다
- **확장 편입 확정** — 지수 intraday 통일(E61), 배당 축(E47), 사용자 서버 저장(X7) 등 8건. 근거는 전부 이번 세션 probe와 실측에서
- **E50 종결** — 장중 검증 전 항목 green, NX 등락 기준 KRX 전일 확정
- **F68 발견** — 분봉 라벨이 START 규약이라 HTS 대비 1분(지수 10분) 밀림. 경로 전수 완료, 수정은 리샘플 버킷 재설계 동반
- **로드맵 v4** — 기능 확장·구조 정리 버킷 신설, 종결·삭제 기록 명시

#089가 "안 할 것을 정한" 세션이었다면 이번엔 "미뤄둔 것 중 할 것을 다시 건진" 세션이다. 코드 0줄에 실호출 11번짜리 세션인데, 이후 열 몇 세션의 방향이 여기서 다 정해졌다.

## 다음 작업

의존 관계상 F68이 제일 앞이다. 새 지수 1분 파이프라인이 틀린 라벨 규약 위에 올라가면 안 되니까.

- **F68** — 분봉 시각 라벨 규약 수정. 시프트 적용 지점 설계와 리샘플 버킷, 테스트 시각값까지
- **E50 pre 육안 + X18** — 개장일 08:00~08:50 창이 잡히는 날 우선 편성

그다음 E61(지수 intraday 통일)로 들어간다. 이번에 확정한 스코프대로면 마무리가 좀 길어졌지만, 건질 걸 건지고 늘어난 거라 방향은 맞다고 본다.
