SlateKR은 포트폴리오로 제출할 프로젝트이고, 남은 작업은 README 마감(G1)이다. README의 스크린샷은 지난 몇 세션의 표기 변경으로 낡았고 성능 수치는 한 번도 잰 적이 없어서, 이번 세션에는 배포본을 PageSpeed Insights(이하 PSI)로 측정하고 화면을 다시 캡처했다.

측정값 가운데 모바일 홈의 레이아웃 이동 점수(CLS)가 세 번 중 한 번만 크게 튀었는데, 이를 재현하다가 모바일 홈이 로드 직후 저절로 500px쯤 내려가는 버그를 찾아 고쳤다. 그 스크롤이 가리고 있던 글꼴 교체 이동도 함께 고쳤고, 도중에 넣은 카드 여백 수정이 데스크톱 CLS를 되돌린 건은 다음 세션으로 넘겼다.

---

## 배포본 측정과 화면 캡처

홈과 종목 상세(삼성전자)를 모바일 · 데스크톱으로 3회씩 측정해 중앙값을 냈다. 트래픽이 적어 실사용자 데이터(CrUX)는 없으므로 전부 lab 수치다. 데스크톱은 두 페이지 모두 성능 100이었고, 모바일은 LCP가 4초대였으며 접근성과 SEO에 실패한 감사가 몇 건 있었다.

| 페이지 | 성능 | 접근성 | SEO | LCP | CLS |
|---|---|---|---|---|---|
| 홈 · 모바일 | 69 | 93 | 91 | 4.2s | 0.037 (1회 0.329) |
| 홈 · 데스크톱 | 100 | 93 | 91 | 0.7s | 0.016 |
| 종목 상세 · 모바일 | 78 | 94 | 100 | 4.7s | 0.124 |
| 종목 상세 · 데스크톱 | 100 | 94 | 100 | 0.7s | 0.026 |

스크린샷은 README의 기존 여섯 자리를 같은 구도로 다시 찍고, 모바일 화면과 부분 실패 화면 두 장을 더했다. 손으로 찍지 않고 headless 브라우저 스크립트로 만들어 뷰포트 · 배율 · 관심종목 상태를 고정했는데, 덕분에 이후 화면을 고칠 때마다 명령 한 번으로 다시 찍을 수 있었다.

## 감사 실패 항목 수정

접근성과 SEO 점수를 깎은 감사는 세 종류였다. 실패한 요소가 보고서에 특정돼 있어 대부분 작은 수정으로 끝났다.

| 감사 | 원인 | 조치 |
|---|---|---|
| 글자 대비 (3곳) | 보조 글자색에 알파를 얹어 4.15 ~ 4.48:1 | 알파 제거로 10:1 이상. 같은 조합 3곳도 함께 수정 |
| 글자 대비 (히어로 카드) | 비활성 카드 전체에 투명도 60% | 유지. 가장 진한 글자색으로도 4.04:1 |
| 터치 영역 크기 | 캐러셀 점 6px · 최근 조회 칩 높이 13.5px | 보이는 크기는 두고 터치 영역만 24px |
| 링크 문구 | 홈의 "전체 보기" 3개가 같은 문구 | 화면에 보이지 않는 섹션명을 앞에 붙임 |

히어로 카드는 글자색 토큰을 바꿔서 풀 수 있는 문제가 아니었다. 옆 카드를 흐리게 해 가운데 카드로 시선을 모으는 것이 의도한 표현이라 그대로 두었고, 그 결과 홈 접근성 점수는 96이 상한이 됐다. 링크 문구는 보통 aria-label로 풀지만, 이 감사가 화면 텍스트(innerText)만 본다는 것을 Lighthouse 소스에서 확인하고 sr-only 텍스트를 썼다.

## 세 번 중 한 번만 튀는 CLS

모바일 홈의 CLS는 두 번은 0.037, 한 번은 0.329였다. PSI가 지목한 요소는 「주요 지수」 섹션이고 원인은 웹 글꼴이었다. 글꼴 파일의 응답을 2초 늦춰 재현을 시도했지만 0.037만 나왔다. 로드 중 스크롤 위치를 같이 기록해 보니 글꼴이 도착하기 전에 페이지가 이미 500px쯤 내려가 있었다. 그 상태에서는 위쪽 텍스트가 다시 그려져도 브라우저가 보고 있던 위치를 유지하도록 스크롤을 보정하기 때문에(스크롤 앵커링) 이동이 점수에 잡히지 않는다.

```
홈 모바일 CLS 0.329
 = 0.293  글꼴이 바뀌며 히어로 제목이 2줄 → 1줄 (페이지가 맨 위에 있을 때만 잡힘)
 + 0.037  지수 스켈레톤이 실제 셀보다 높음 (매번)
```

스크롤을 막고 다시 재자 0.293이 나왔고, 두 성분의 합이 PSI 값과 맞았다. 세로로는 28px만 움직이는데 값이 큰 이유는 제목의 마지막 구절이 줄이 바뀌면서 가로로 291px 이동하기 때문이었다. 세 번 중 한 번만 튄 것은 글꼴이 스크롤보다 먼저 도착한 회차였던 셈이고, 남은 질문은 페이지가 저절로 내려간 이유였다.

## 페이지를 끌어내리던 탭 스크롤

원인은 홈 하단 시장 순위의 탭 줄이었다. 탭이 화면 폭을 넘칠 때 선택된 탭이 보이도록 `scrollIntoView({ block: "nearest" })`를 호출하고 있었는데, 이 메서드는 대상이 보일 때까지 스크롤 가능한 조상을 전부 움직인다. `nearest`는 최소한만 움직이라는 뜻이지 세로로는 움직이지 말라는 뜻이 아니어서, 탭 줄이 첫 화면 아래에 있는 모바일 홈에서는 로드 0.3초쯤 뒤 페이지 전체가 탭 줄까지 내려갔다.

```
전  선택 탭.scrollIntoView({ block: "nearest" })      → 탭 줄과 페이지가 함께 움직임
후  탭 줄.scrollLeft = 선택 탭이 보이는 가장 가까운 위치  → 탭 줄만 움직임
```

에뮬레이션에서만 본 현상이어서, 고치기 전에 iPhone으로 배포본을 열어 새로고침 때 화면이 내려가는 것을 먼저 확인했다. 수정은 페이지를 움직일 수 없는 방식을 택해 탭 줄 컨테이너의 가로 스크롤 값만 직접 정하고, 위치 계산은 순수 함수로 분리해 테스트를 붙였다. 로드 2초 시점의 스크롤 위치는 412px 폭에서 476 → 0, 390px에서 504 → 0이 됐고 탭을 바꿀 때의 동작은 그대로다. 같은 호출이 지수 페이지의 칩 줄에도 있지만 재현되지 않아 두었다.

![](/static/images/velog/055a1b6a-2ca9-4fb2-9c4f-583b62bdf266-image.png)

## 스크롤과 같이 고친 히어로 줄바꿈

스크롤만 고치면 다른 문제가 드러난다. 지금까지는 스크롤이 글꼴 교체 이동을 가려 주고 있었으므로, 페이지가 맨 위에 머물게 되면 412px 폭에서 0.293이 매번 잡힌다. 그래서 제목과 설명의 줄 수가 글꼴에 좌우되지 않게 하는 수정을 같은 배포에 넣었다.

| 후보 | 판정 |
|---|---|
| 제목 아래에 2줄 높이를 미리 확보 | 기각. 웹 글꼴로 1줄이 되면 제목 아래 28px이 빈 채로 남음 |
| 글꼴 표시 방식을 optional로 변경 | 기각. 교체 이동은 사라지지만 첫 방문에서 한글이 시스템 글꼴로 남을 수 있음 |
| **모바일에서 줄바꿈 위치를 고정** | **채택.** 글꼴과 무관하게 제목 2줄 · 설명 2줄 |

줄을 끊는 위치는 폭이 넓은 fallback 글꼴에서도 360px 화면에 3줄이 되지 않는 지점으로 골랐다. 대가는 히어로 높이로, 모바일에서 제목과 설명이 항상 2줄씩이 되면서 폭에 따라 19.5 ~ 47.5px 높아졌다. 글꼴을 늦춘 재현에서 CLS는 360px 0.145 → 0.0001, 412px 0.296 → 0.005로 내려갔는데, 390px에서는 0.009였던 값이 오히려 0.094로 올라 있었다.

## 여백을 줄이자 돌아온 이동

390px의 새 이동은 스크롤이나 줄바꿈이 아니라 도중에 넣은 다른 수정에서 왔다. 캐러셀의 공시 카드와 핵심 지표 카드 아래 여백이 길어 보여서 프리뷰 영역이 고정 높이 대신 내용 높이를 따르도록 바꿨고, 동작 줄이기(reduced-motion) 설정에서 공시 배지가 투명한 채로 남던 버그도 이때 고쳤다. 배포 후 다시 측정하자 홈 데스크톱의 CLS가 0.016에서 0.126으로 올라가 있었다.

| 페이지 | 성능 | 접근성 | SEO | CLS |
|---|---|---|---|---|
| 홈 · 모바일 | 69 → 85 | 93 → 96 | 91 → 100 | 0.037 (1회 0.329) → 0 |
| 홈 · 데스크톱 | 100 → 95 | 93 → 96 | 91 → 100 | 0.016 → **0.126** |
| 종목 상세 · 모바일 | 78 → 76 | 94 → 100 | 100 | 0.124 → 0.113 |
| 종목 상세 · 데스크톱 | 100 | 94 → 100 | 100 | 0.026 → 0.025 |

고정 높이는 여백이면서 받침이기도 했다. 글꼴이 바뀔 때 가운데 카드의 설명이 2줄에서 1줄로 줄어드는데, 전에는 양옆 카드의 고정 높이가 캐러셀 높이를 붙잡고 있어 아래 섹션이 움직이지 않았다. 받침이 사라지자 캐러셀이 218px에서 201px로 줄고 「주요 지수」가 17px 올라온다. 원인을 공시 칩의 줄 수로 짐작했는데, 커밋은 맞게 짚었지만 요소는 틀렸다.

| 후보 | 판정 |
|---|---|
| 공시 카드만 고정 높이로 복원 | 보류. CSS 주입 시뮬레이션에서 0.125 → 0.015. 줄인 여백이 6 ~ 9px 돌아오고 360px에서 칩이 칸을 넘침 |
| 가운데 카드 설명의 줄 수 고정 | 보류. 폭마다 성립하는지 미확인 |
| 가운데 카드 문구 축소 | 다음 세션. fallback 글꼴에서도 1줄인지 확인 후 적용 |

데스크톱 첫 방문에서 아래 섹션이 17px 한 번 움직이는 정도라 체감은 작다. 캐러셀에 시장 순위 카드를 하나 더 넣을 생각이어서 높이와 문구가 어차피 다시 바뀌므로, 홈 캐러셀 정비(E100)로 묶어 다음 세션에 한 번에 처리하기로 했다. 모바일 LCP 3.8 ~ 3.9초와 종목 상세 모바일의 CLS 0.113은 커밋 하나로 끝나지 않는 구조 문제여서 README의 한계에 수치를 적고 backlog로 보냈다. 앞쪽은 렌더링 차단 CSS와 클라이언트에서 그리는 라이브 가격이 LCP 요소인 점이, 뒤쪽은 스켈레톤이 실제 내용보다 60 ~ 96px 낮은 점이 원인이다.

## 정리

- **G1 진행** — 배포본 PSI 2회 측정 · 스크린샷 8장을 스크립트로 촬영. README 이미지 교체와 수치 기재는 이월
- **모바일 홈 자동 스크롤 수정** — 탭 줄의 `scrollIntoView`가 페이지를 약 500px 내리던 버그. 탭 줄의 가로 스크롤만 정하도록 변경, 글꼴 교체 이동을 막는 히어로 줄바꿈 고정과 함께 배포
- **감사 실패 항목 수정** — 글자 대비 6곳 · 터치 영역 2종 · 링크 문구 3개. 히어로 비활성 카드의 흐림은 유지, 동작 줄이기에서 배지가 안 보이던 버그 수정
- **E100 신설** — 카드 여백을 줄인 뒤 돌아온 홈 데스크톱 CLS 0.126. 시장 순위 카드 추가와 묶어 다음 세션
- **backlog 2건** — 종목 상세 스켈레톤 높이 불일치, 그리고 투자경고처럼 KRX 애프터마켓에서 제외되는 종목의 헤더가 '애프터마켓'으로 표시되는 문제(가격은 정확하고 라벨만 어긋남)

점수를 올리려고 고친 항목은 사용자가 체감할 변화가 아니었고, 이번 세션의 성과는 측정값 하나가 왜 튀는지 따라가다 나온 버그 쪽에 있었다. 코드 전수조사는 몇 번 거쳤지만 자동 스크롤은 화면을 실제로 재 봐야 나오는 종류였던 것 같다. 이 영역은 하나를 고칠 때마다 가려져 있던 이동이 하나씩 드러났는데(스크롤, 제목 줄바꿈, 카드 높이), 마지막 것은 내가 넣은 수정이 만든 것이라 좀 머쓱하다.
