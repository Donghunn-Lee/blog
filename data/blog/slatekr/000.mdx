새로운 프로젝트를 하나 시작해보려고 한다.

지금 내 포트폴리오는 **Aim Test**가 중심이다.  
이 프로젝트는 복잡한 실시간 상호작용을 시간축, 렌더 파이프라인, 책임 분리 관점에서 구조적으로 해결한 점이 강점이라고 생각한다.

반면, 검색 → 상세 → 저장 흐름이 있는 서비스형 웹앱이나  
외부 데이터를 조회형 UI로 구조화하는 경험은 상대적으로 덜 드러날 수 있다고 느꼈다. 팀 프로젝트 경험이 있긴 하지만, 이번에는 조금 더 주도적으로 구조를 설계하고 구현한 결과물을 만들고 싶었다.

그래서, 이 부분을 보완할 새 프로젝트를 기획하게 됐다.

> **본 게시글은 초기 기획안이며, 실제 구현 과정에서 구성과 우선순위는 일부 달라질 수 있습니다.**

## Project - SlateKR

`SlateKR`은 국내 상장 기업의 가격, 재무, 공시 정보를 구조화해  
사용자가 종목의 핵심 내용을 빠르게 파악할 수 있도록 돕는 **조회형 서비스 웹앱**이다.

단순히 데이터를 많이 보여주는 것이 아니라,  
차트, 핵심 지표, 재무 요약, 공시 같은 정보를 한 화면에서 읽기 쉽게 정리하는 것을 목표로 한다.

프로젝트 이름은 `Slate`라는 단어에서 가져왔다.  
하나의 판 위에 정보가 정돈되어 놓인 느낌,  
그리고 한 종목 안에서도 차트, 재무, 공시 같은 여러 레이어가 층처럼 구성되는 이미지를 반영하고 싶었다.

초기 구상 단계에서 생각하고 있는 핵심 기능은 다음과 같다.

- 종목 검색 및 상세 조회
- 가격, 재무, 공시 정보의 구조화된 제공
- 기업의 특징을 빠르게 파악할 수 있는 태그/배지 형태의 요약
- 일부 공시에 대한 AI 요약 기능

---

## 기획 의도

이번 프로젝트를 기획한 가장 큰 이유는  
기존 포트폴리오와는 결이 다른 역량을 보여주고 싶었기 때문이다.

지금까지 만든 프로젝트에서는 실시간 상호작용, 상태 흐름 제어, 구조 리팩토링 같은 부분을 비교적 강하게 보여줄 수 있었다.  
반면, 실제 서비스형 웹앱에서 자주 마주치는 구조는 상대적으로 덜 드러난다고 느꼈다.

예를 들면 이런 것들이다.

- 검색에서 상세 페이지로 이어지는 흐름
- 외부 데이터를 화면에 맞게 정리하는 방식
- 저장과 재방문이 있는 사용자 흐름
- 공개 페이지를 고려한 구조
- 데이터가 많은 화면에서 정보 우선순위를 설계하는 작업

그래서 이번 프로젝트는  
단순히 “주식 관련 사이트를 하나 만들어본다”기보다,  
**조회형 서비스 웹앱을 실제 제품처럼 설계해보는 것**에 더 가깝다.

도메인으로 주식을 선택한 이유도 비슷하다.  
~~단순히 내가 관심 있는 분야라서가 아니라,~~
주식 정보는 가격, 재무, 공시처럼 성격이 다른 데이터가 섞여 있고,  
이 정보들을 그대로 나열하면 보기 어렵지만 잘 정리하면 꽤 명확한 구조를 만들 수 있을 것 같았다.

즉, 이 프로젝트에서 중요한 건  
새로운 정보를 만들어내는 것이 아니라,  
이미 흩어져 있는 정보를 **더 읽기 쉬운 형태로 구조화하는 것**이라고 생각했다.

또 하나 중요하게 본 점은  
이 프로젝트를 투자 판단 서비스처럼 만들고 싶지는 않았다는 것이다.

추천 종목을 고르거나, 강한 해석을 붙이거나,  
AI가 무언가를 대신 판단해주는 쪽으로 가기 시작하면  
범위도 커지고 프로젝트 성격도 많이 달라진다.

그래서 이번 프로젝트는  
종목을 평가하는 서비스라기보다,  
**판단에 필요한 정보를 빠르게 조회하고 정리해서 보여주는 서비스** 쪽으로 방향을 잡았다.

태그, 배지, AI 요약 같은 기능이 들어가더라도  
이 역시 어디까지나 정보를 더 빨리 이해할 수 있도록 돕는 보조 레이어로 두고 싶다.

## 기술 스택

현재 기준으로 생각하고 있는 기술 스택은 다음과 같다.

### Frontend
- Next.js
- React
- TypeScript
- Tailwind CSS

### 상태 / 데이터
- Server Component 기반 데이터 조회
- TanStack Query
- Zustand

### UI / 기타
- shadcn/ui
- chart 라이브러리
- OpenDART 등 외부 데이터 API

아직 구현 전 단계이기 때문에  
세부 라이브러리나 적용 범위는 개발을 진행하면서 일부 조정될 수 있다.  
다만 전체적으로는 **서비스형 웹앱 구조**를 만드는 데 적합한 조합을 기준으로 가져가려고 하며, 생산성을 높이기 위해 shadcn/ui 같은 라이브러리도 적극 활용해볼 생각이다.

## 최종 목표

이 프로젝트의 1차 목표는  
국내 상장 종목의 핵심 정보를 검색하고, 조회하고, 저장할 수 있는 흐름을 갖춘  
완성도 있는 조회형 서비스 웹앱을 만드는 것이다.

조금 더 구체적으로는 아래와 같은 결과물을 목표로 하고 있다.

- 종목 검색 후 상세 페이지로 자연스럽게 이동할 수 있는 구조
- 가격, 재무, 공시를 한 화면에서 읽기 쉽게 보여주는 정보 구조
- 관심 종목을 저장하고 다시 확인할 수 있는 흐름
- 일부 데이터가 없거나 실패하더라도 전체 화면이 무너지지 않는 처리
- 공개 상세 페이지를 고려한 기본적인 SEO 구조
- 모바일과 데스크톱 모두에서 무리 없이 읽히는 UI

그리고 그 위에  
공시 분류, 체크포인트 배지, AI 요약 같은 보조 기능을 얹어  
단순한 데이터 나열이 아니라  
조금 더 읽기 쉬운 서비스 경험으로 확장해보고 싶다.

최종적으로는 이 프로젝트를 통해  
“실시간 인터랙션 중심 프로젝트를 했던 개발자”에서 한 걸음 더 나아가,  
**조회형 서비스 웹앱도 구조적으로 설계하고 구현할 수 있는 프론트엔드 개발자**라는 점을 보여주는 결과물을 만드는 것이 목표다.
