#098 끝에 probe 셋을 걸어뒀다 — X20 선행 확인, X21 분봉 과거일 실측, 그리고 이월된 F32 장중 항목. 판정 재료만 모으는 세션으로 계획했는데, 결과가 나올 때마다 계획이 고쳐졌다.

## 정규장 UN/J 편차 실측

#092에서 현재가 소스가 상세(J/NX)와 리스트(UN)로 갈린 채 남았고, 시간외엔 값이 어긋나는 걸 확인했었다. 남은 질문은 정규장 중엔 어떤가였다. 10종목 × 3회 반복 실측 결과:

| 종목군 | 가격 | 거래량 |
| --- | --- | --- |
| 비NXT (4종목) | 전 회차 diff 0 — **완전 일치** | 동일 |
| NXT (5종목) | 최대 0.4% 어긋남 — 콜 사이 체결이 낀 **시차성** | 항상 UN = J + NX — **구조적** |

순간 스냅에선 NXT 종목도 J=NX=UN이 완전히 일치하는 관측이 있어서, 가격 쪽은 구조 문제가 아니라 타이밍 문제라는 게 갈렸다. 정리하면 — "확장시간대에만 보인다"고 적어뒀던 혼종이 **정규장에도 보인다**. X18의 입력으로 넘겼다.

같이 이월됐던 KOSDAQ 거래량 ~1% 차이는 노출 지점을 다 뒤져보니 실질 1곳(지수 상세의 거래량 셀)뿐이었다. 억 단위 소수 1자리 표시라 반올림 경계에서만 갈리는 수준 — 감수 유지, 기준 표기만 B5 툴팁 작업에 편입.

## 분봉 과거일 조회 실측과 X21 강등

X21(종목 분봉 DB 축적)의 걱정은 "분봉 TR이 당일만 주면 실익이 준다"였다. 실측 결과는 반대 방향이었다.

| TR | 과거일 지정 | 캡 |
| --- | --- | --- |
| FHKST03010200 (현행 당일분봉) | DATE 파라미터 **무시** — 항상 오늘 | 30봉/콜 |
| FHKST03010230 (일별분봉) | 임의 과거일 **그대로 반환** (1개월 전까지 확인) | 120봉/콜 · 연속조회 미지원 |

일별분봉 TR이 과거일을 on-demand로 준다. 저유동성 종목은 지정일 봉이 120개가 안 되면 앞 세션 봉으로 채워 보내는 성질이 있어서, 소비 측 날짜 필터가 필수라는 것까지 확인했다.

그런데 이게 X21을 살리는 게 아니라 죽였다.

- 해외 지수 적재(E29)는 KIS가 최근 봉만 줘서 **지금 안 쌓으면 소실** — 축적이 필수였다
- 종목 분봉은 필요할 때 물으면 온다 — **소실 압력이 없다**
- DB 축적의 성격이 "데이터 확보"에서 "콜 절감 캐시"로 내려앉았고, 마무리 단계에 캐시 최적화를 새로 세울 이유는 없다

이런 이유로 X21은 백로그로 내렸다. 다만 이 실측은 버려지지 않았다 — 바로 다음 문제의 해법이 됐다.

## 주말에 비는 intraday 차트

주말에 서비스를 열어보니 종목이든 지수든 당일 차트가 비어 있었다. 원하는 동작은 분명했다 — **거래일엔 당일, 휴장일엔 직전 거래일 세션.** F36으로 잡고 게이트부터 전수 조사했다.

원인은 종목과 지수가 달랐다.

- **종목** — 세션이 closed면 KIS를 부르지도 않는 하드 게이트. #090에서 "오늘 것만 준다"는 주석을 반증하고 걷어냈던 비거래일 게이트가, #092의 NXT 확장세션 도입 때 되돌아와 있었다. 휴장일 표시 정책이 아니라 확장세션 로직 진입을 막는 성능 판단에 가까워 보였고, 그 부산물로 주말 blank가 남은 거다
- **지수** — 게이트가 아예 없어서 KIS의 주말 응답에 좌우되는데, 그 거동의 실측 기록이 프로젝트에 없었다. 코드만으론 원인 확정 불가

### 종목: 일별분봉 폴백

게이트를 도로 걷는 대신 방금 실측한 일별분봉 TR로 폴백을 넣었다. 휴장일에 현행 TR이 뭘 주는지는 #090의 일요일 실측 한 번이 근거의 전부라, 거기 기대느니 **날짜를 명시해서 묻는 쪽이 결정적**이다.

- NXT 종목은 휴장일에도 애프터마켓 종가까지 보여야 해서 UN × 과거일 조합을 추가 실측 — 08시 프리마켓부터 20시 애프터 마감까지 확장 세션 봉이 그대로 왔다
- 구현: anchor fan-out(NXT는 UN 7앵커로 08~20시, 비NXT는 J 3앵커로 정규장) → 지정일 필터(앞 세션 bleed 방어) → dedup
- 거래일 새벽은 무변경 — 등락률과 같은 결로 초기화 유지, NXT 8시·비NXT 9시부터 당일 봉이 쌓인다
- 차트에 **"MM-DD 기준" 라벨**을 붙여 라이브든 폴백이든 어느 세션인지 드러나게

### 지수: 파라미터 하나로

종목처럼 일별분봉 대응 TR을 찾았는데 후보가 전부 404였다. 그러다가 현행 TR에 날짜 파라미터를 그냥 얹어봤더니 — 그대로 받았다. 종목 baseline에선 무시되던 파라미터가 지수 TR에선 동작한다. 새 TR도 fan-out도 없이 파라미터 하나와 날짜 필터로 끝. 소비측 필터 3곳이 과거일 봉을 걸러내지 않는 것도 확인하고 무변경으로 뒀다.

코드로 닫을 수 있는 검증은 닫았고(vitest 337 passed), 실환경은 이번 주말에 본다.

## UN 종가 스냅샷 — 시장 구분 필드 실측

X20 원안은 "매 거래일 통합 종가 + **체결 시장 구분** 저장"이었다. 선행 probe 결과:

- UN 응답 필드 전수 조사 — 체결 시장을 알려주는 필드 **없음**. UN 필드 집합은 J·NX의 부분집합이고 UN에만 있는 필드가 0개
- multi-quote 배치 상한 **30 확정** — 초과분은 에러 없이 앞 30건만 오는 조용한 절단
- NX를 배치로 던지면 비NXT 슬롯이 절단되지 않고 **sentinel(전 필드 0)로 자리를 지킨 채** 온다

사실 필드 부재는 어렴풋이 알던 결과다. #092에서 판정을 "NX로 불러서 빈 응답이면 비NXT"로 세운 것 자체가 UN이 아무 신호도 안 준다는 관찰 위였으니까. probe가 실제로 보탠 건 UN 단독 대체 경로의 확정적 폐기, 그리고 배치의 성질 둘이다.

silent slice는 부수 수확으로 이어졌다. 호출부를 전수 조사하니 홈 관심종목 미리보기가 그룹 최대 100종목을 상한 없이 넘길 수 있는 경로였다 — 31번째부터는 라이브값도 실패 배지도 없이 조용히 빠진다. 본 페이지가 이미 의도적으로 30개 캡을 쓰고 있어서, 미리보기도 같은 상수를 공유하는 명시 slice로 정렬해 닫았다.

그리고 NX 배치의 sentinel 성질에서 X20이 재정의됐다. 스냅샷이 판정콜을 대체하는 게 아니라, **판정 자체를 캡처 시점으로 옮긴다.**

> 저녁에 UN 90콜로 통합 종가를, NX 90콜로 전 종목 eligibility를 한 번에 뜬다. #092에서 "리스트 소스만 확보되면"이라며 X18을 파킹했던 그 소스가 부산물로 나온다.

## 저녁 관측과 당일 구현

남은 전제는 하나 — 20시(NXT 애프터 마감) 이후 UN이 확정 종가로 멈추는가. 20시 11분에 관측을 돌렸다.

| 확인 | 결과 |
| --- | --- |
| 확정성 | 3분 간격 두 스냅 전 필드 diff 0 — 완전 정지 |
| UN의 정체 | NXT 종목 = NX 최종가 · 비NXT = KRX 종가 |
| eligibility 판정 | NX prpr>0 단독으로 성립 (30종목 중 경계 케이스 0) |
| 배치 = 단일 | 값 불일치 0건 |

한 번에 전제가 다 서서 바로 구현까지 갔다.

- **quote_snapshots 테이블** — 스키마에 주석 하나를 박았다: NXT 종목의 un_close는 20시 NXT 최종가라 daily_prices의 KRX 종가와 **다른 게 정상**
- **캡처 collector** — 실행 게이트는 "거래일이고 20:05 이후"일 때만 열리고 우회 레버 없음. #098 end 캡과 같은 철학이다. 첫 캡처 2,651/2,676 — 빠진 25건은 거래정지 종목의 자연 skip
- **20:10 cron** — 뒤에 나올 정각 지연 관측을 반영해 분 오프셋으로
- **오프아워 웹 서빙** — after_close·closed·preopen에서 DB 우선, 해당 날짜 스냅샷이 통째로 없으면 기존 KIS 경로 폴백

서빙에서 결정이 하나 필요했다. 비NXT 종목의 단건 quote에 스냅샷 값을 그대로 주면, 종목 헤더가 "NX 응답이 있다 = NXT 종목"으로 역추론해온 탓에 라벨이 틀어진다.

| 안 | 결과 | 판단 |
| --- | --- | --- |
| 값 그대로 서빙 | "애프터마켓 종가 · 20:00" 라벨 — 비NXT는 20시에 거래가 없으니 **오표시** | 기각 |
| 헤더 로직 수정 | 라벨은 맞지만 UI 무변경 원칙 위배 | 기각 |
| **비NXT는 null 서빙** | 역추론 보존 → UI 완전 무변경. 값은 어차피 KRX 종가로 동일 | **채택** |

KIS 콜 제거는 어느 안이든 똑같이 달성된다. 판정의 정보원이 NX 콜에서 nx_eligible 컬럼으로 바뀌었을 뿐이다. 이걸로 X18의 남은 스코프도 줄었다 — 리스트 소스는 확보됐고 오프아워 판정은 사라졌으니, 잔여는 라이브 세션의 차트 판정콜과 quote 혼종 정리로 좁혀진다.

## KIS 전환 첫 실전 run

#098에서 전환한 종목 일봉의 첫 자동 run이 이날 저녁이었다. cron이 3시간 늦게 돌기 시작해서 잠깐 긴장했는데:

- 트리거는 schedule이 맞았다 — GitHub Actions의 **정각(minute 0) 스케줄은 전 세계 워크플로가 몰리는 피크**라 이 정도 지연이 난다
- end 캡 덕에 몇 시에 돌든 오염이 없는 구조라 데이터는 무사 — #098 설계가 의도한 그대로
- verify PASS · 5종목 공표 종가 대조 **전부 일치** — 전환 검증 종료
- 한 종목이 연결 끊김으로 빠졌는데, 다음 run의 incremental이 자동 회수하는 경로

남긴 건 둘이다. cron 분을 정각에서 옮기는 1줄(F37), 그리고 fetch_prices가 추정 12분 대비 1시간이 걸린 것 — 러너 네트워크인지 KIS 응답인지 표본 1로는 못 가르니 며칠 추이를 본다.

## 정리

- **F32 장중 실측** — 비NXT는 정규장 UN==J 완전 일치, NXT는 정규장에도 편차(가격 시차성 · 거래량 UN=J+NX). KOSDAQ 거래량 표기는 B5로
- **X21 강등** — 일별분봉 TR의 과거일 on-demand 확인으로 소실 압력이 사라져 캐시 성격으로. 백로그
- **F36 완결** — 휴장일 intraday 폴백. 종목은 일별분봉 fan-out(NXT는 08~20시), 지수는 현행 TR의 날짜 파라미터 발견으로 파라미터 하나. 주말 실환경 검증만 잔여
- **X20 완결** — UN/NX 2-pass 저녁 캡처 + 오프아워 스냅샷 서빙. 판정콜의 정보원을 콜에서 컬럼으로, X18 리스트 소스 확보
- **부수** — 관심종목 미리보기 조용한 절단 수정, #098 전환 검증 통과, cron 정각 지연 판정

실측 다섯 번이 계획을 세 번 고쳐 쓴 세션이었다. 아침에 세운 계획엔 F36도, X20 당일 완결도 없었다. 대신 실측이 열어주는 길을 그때그때 탔는데, 돌아보면 방향은 일관됐다 — 요청 전에 알 수 없던 것들을 전부 "물어보고 판별"에서 "기록해두고 읽기"로 옮기고 있다.
