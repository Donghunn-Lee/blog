데이터 계층을 설계하고, placeholder 홈페이지를 만들었다.
홈 화면에 검색창을 올리고 나서 바로 자동완성을 만들고 싶었는데, 순서를 바꿨다. UI보다 API를 먼저 만들었다.

이유는 단순하다. 드롭다운에 뭘 보여줄지 모르는 상태에서 UI를 설계하면 더미 데이터로 만들고 나중에 다시 손대야 한다. DB에 종목 데이터가 이미 들어가 있으니까 API 먼저 만들고 실제 데이터로 바로 붙이는 게 맞다고 봤다.

---

## API Route

`GET /api/search?q=검색어` 형태로 만들었다. 종목명 또는 종목코드 부분 일치 검색, 최대 10개 반환.

처음엔 2글자 이상일 때만 쿼리를 실행하려 했는데, 생각해보니 불필요한 제약이었다. "삼" 한 글자만 쳐도 삼성전자가 바로 뜨는 게 훨씬 자연스럽다. 서버 부하는 UI에서 debounce 300ms를 걸면 충분히 감당된다.

브라우저에서 `/api/search?q=삼성` 치니까 10개 결과가 바로 나왔다. DB 연결과 `searchStocks` 함수가 이미 있었으니 route 파일은 간단했다.

## 자동완성 UI

UI를 만들면서 신경 쓴 부분이 몇 가지 있었다.

**race condition.**
빠르게 타이핑하면 이전 요청의 응답이 현재 요청보다 늦게 도착할 수 있다. AbortController로 새 요청이 시작될 때 이전 요청을 취소했고, AbortError는 state 업데이트 없이 early return 처리했다. 이걸 빠뜨리면 타이핑 속도에 따라 결과가 뒤섞인다.

**외부 클릭 처리.**
click 이벤트로 처리하면 문제가 생긴다. 드롭다운 항목을 클릭하면 input의 blur가 먼저 발생해서 드롭다운이 닫혀버린다. onMouseDown은 blur보다 먼저 발생하기 때문에 이걸 활용했다. 드롭다운 항목에도 onMouseDown과 e.preventDefault()를 함께 써서 blur 전에 클릭을 처리했다.

**키보드 탐색.**
위아래 화살표로 이동, Enter로 선택, Esc로 닫기. 드롭다운이 닫혀 있을 때 Enter는 onSubmit을 그대로 호출하고, 열려 있을 때는 선택된 항목이 있으면 라우팅, 없으면 드롭다운을 닫는다.

**debounce**
lodash 없이 setTimeout과 clearTimeout으로 직접 썼다. 이 용도 하나 때문에 라이브러리를 추가하는 건 과했다.
