## 지수 조회 lib 신설

화면 작업 전에 `index_daily_prices`를 읽는 lib가 아예 없었다(#065에서 적재만 하고 web에선 안 읽었다). 종목 일봉 lib(`prices.ts`) 패턴을 그대로 따와서 `lib/indices.ts`를 만들고 세 함수를 뒀다.

| 함수 | 용도 |
| --- | --- |
| `getLatestIndexPrice` | EOD 폴백용 직전 거래일 1행 |
| `getIndexDailyPrices` | 일봉/월봉 차트용 시계열 |
| `getIndexIntradayPrices` | KIS 10분봉 (당일 장중) |

여기서 타입을 하나 가를지 말지가 좀 걸렸다. 처음엔 종목이 쓰는 `StockPriceSnapshot`을 재사용하려 했는데, 지수는 등락(change·changeRate)을 같이 들고 다녀야 PriceChange 렌더가 되고, 애초에 종목과 도메인 의미도 다르다. 그래서 `IndexDailySnapshot`을 따로 뒀다. 인트라데이는 한 번 더 갈렸는데, 이건 아래 차트 쪽에서 이유가 분명해진다.

## 장 마감 지수 폴백

#064에서 헤더·관심종목은 직전 거래일 등락을 유지하게 닫았는데, 지수만 폴백 소스가 없어 남겨뒀던 자리다. 이제 데이터가 있으니 채웠다.

구현에서 스펙과 한 군데 달라졌다. 원래는 IndexSlate에서 Server Action으로 폴백을 부르려 했는데, IndexSlate가 `'use client'`라 Server Component로 바꾸려면 홈 페이지까지 손대야 했다. 그래서 폴백 조회를 `/api/index-quotes` route 안으로 넣어, 실시간 3건과 폴백 3건을 한 응답에 같이 실어 내렸다. 폴링과 한 요청에 묶이니 데이터 흐름도 더 깔끔했다.

셀은 3단계로 떨어진다.

```
live 있음    → 실시간 현재가
live 없음    → "직전 거래일" + 종가 + 등락 (폴백)
둘 다 없음   → "데이터 없음"
```

## 종목 차트 캔들 전환

선차트에서 캔들로 바꾸는 건 series 타입 교체라 간단했는데, lightweight-charts v5에서 API가 바뀐 게 하나 있었다.

```ts
// v4
chart.addCandlestickSeries({ ... })
// v5 — 타입을 import해서 첫 인자로
chart.addSeries(CandlestickSeries, { ... })
```

색은 국내 관행대로 상승=빨강·하락=파랑으로 갔다. "차트 섹션은 무채색 유지"라는 디자인 가이드와 부딪히지만, 캔들은 2색이 없으면 상승·하락 구분이 안 되니 우선 적용하고 styleguide 검토 대상으로 남겼다. 색값은 리터럴 hex로 박았다 — 처음엔 CSS 변수를 쓰려 했는데 테마가 oklch라 그런 rgb 변수가 없었다.

월봉은 일봉을 resample하는 순수 함수로 처리했다(`open`=월 첫 시가, `close`=월 마지막 종가, `high`/`low`=월간 극값).

## 지수 10분봉, 1분봉이 아닌

지수 슬레이트에 당일 차트를 붙이는 작업인데, 원래 내가 넣고 싶었던 건 1분선이었다. 사전 조사 세션에서 KIS 분봉 endpoint를 probe로 찍어보니, on-demand로는 1분봉 하루 전체를 그릴 방법이 없었다.

| 봉 주기 | 1콜 커버 | 하루 전체 |
| --- | --- | --- |
| 1분봉 | 최근 100분만 | 불가 (과거 조회 파라미터 없음) |
| 10분봉 | ~96봉 | **당일 09:00~15:30 전체 ✓** |

KIS 분봉은 "호출 시점 기준 최근 100봉"만 돌려주고, 시각이나 날짜로 거슬러 올라가는 입력이 없다. anchor를 우회로 넣어봐도 전부 무시됐다. 그러니 1분봉 하루치(약 390분)는 한 번에 못 받고, 받으려면 장중에 계속 쌓아 적재하는 수밖에 없다. 반면 10분봉은 100봉이면 1000분이라 하루가 한 콜에 다 들어온다.

SlateKR은 트레이딩 툴이 아니라 조회형 서비스라 1분 해상도가 핵심 가치는 아니다. 설계로 보여줄 것(실시간 폴링·세션 상태·fallback)은 해상도와 무관하기도 하다. 그래서 10분봉 on-demand로 일단락하고, 1분봉 적재는 나중 과제(G5)로 미뤘다.

route는 지수별로 `unstable_cache`를 60초씩 걸고, 응답엔 마커를 걸러 담는다. KIS 10분봉 응답엔 `999999`/`888888` 같은 마커 행이 일자별로 한 쌍씩 섞여 오는데, 6자리 정상 시각만 남기고 쳐냈다.

### 폴링은 setInterval이 아니라 setTimeout

장중에만 돌고 장이 닫히면 멈춰야 하는데, `setInterval`로 깔면 멈추는 조건을 따로 관리해야 한다. 대신 `setTimeout`으로 한 번 호출하고, 응답의 `marketOpen`이 `false`면 다음 호출을 아예 스케줄하지 않는 식으로 짰다. 자기가 자기를 다시 거는 구조라, 장이 닫힌 응답을 받는 순간 자연히 멎는다. 세션 판정도 클라이언트에서 따로 부르지 않고 서버 응답 하나에 맡겼다.

## 지수 미니 차트

마지막은 지수 슬레이트 각 셀의 현재가 아래에 작은 차트를 붙이는 일이다. 코스피·코스닥·코스피200 셋 다 한 번에.

처음 풀사이즈 차트로 만들었다가 한 번 갈아엎은 자리가 여기다. 초안에선 홈 아래에 큰 차트 3개를 깔았는데, 원래 계획은 미니 차트를 슬레이트 안에 넣는 거였다. 큰 차트는 별도 지수 페이지(나중에)로 가야 했다. 방향을 되돌리면서 두 가지를 정리했다.

**미니는 선차트로 고정.** 슬레이트에서 흐름만 한눈에 보는 용도라 140px짜리에 캔들 ~96개를 그려봐야 잘 안 보인다. 면 그라데이션 선차트가 맞다. 캔들/선 토글은 크게 보는 별도 차트 페이지에 두기로 했다.

**폴링은 하나로.** 차트가 셋이라고 각자 폴링하면, `/api/index-intraday`가 어차피 3지수를 한 번에 주는데 같은 응답을 60초마다 세 번 받아 자기 것만 골라 쓰는 꼴이 된다. 그래서 미니 차트는 데이터를 직접 안 받고 prop으로만 받는 순수 렌더러로 만들고, 폴링은 슬레이트가 한 번 해서 세 셀에 나눠 내렸다.

```
IndexSlate
├─ useIndexIntraday()   ← 폴링 1개, 3지수 응답
└─ IndexCell × 3
   └─ IndexMiniChart bars={...}   ← 자기 지수 배열만
```

## 정리

이번 세션은 #065에서 쌓아둔 지수 데이터를 화면으로 끌어올린 작업이었다.

- **E19** — 장 닫힌 시간의 지수 EOD 폴백. 폴백 조회를 route에 합쳐 실시간과 한 응답에 실었다
- **종목 캔들 전환** — v5 `addSeries` API로 교체, 국내 관행 색
- **지수 일봉/월봉 + 10분봉** — 1분봉은 KIS 제약상 적재가 필요해 미루고, 한 콜에 하루가 들어오는 10분봉으로 일단락했다
- **E13 미니 차트** — prop 기반 순수 렌더러 + 폴링 1개로 슬레이트 셀마다 선차트를 붙였다

차트 자체보다 "어떤 해상도로, 어디서 폴링해서, 무슨 타입으로 시간을 표현할까"를 정하는 데 더 손이 갔다. 데이터는 #065에서 다 준비됐는데도 그랬다. 결국 화면에 올리는 일은 데이터를 받는 일과 별개의 결정이 줄줄이 붙는다는 걸 다시 확인한 세션이었다.
