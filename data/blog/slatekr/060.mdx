이번 세션은 로드맵 X5(KRX OpenAPI 검증)와 E15(실시간 현재가)를 같이 다룬 세션이다. 시작은 KRX 지수 데이터소스 검증 하나였는데, 끝에는 데이터소스 전체 그림이 바뀌고 KIS 실시간 트랙의 바닥까지 깔았다. 직전 #060-계획에서 "KRX Marketplace 일원화 + 실시간은 KIS REST 폴링"으로 방향을 정하고 probe 작성을 핸드오프로 넘겼다. probe 코드를 작성하고 검증하는 것부터 시작했다.

---


## 데이터소스의 시간축 분담

작업 전에 머릿속 그림부터 정리할 필요가 있었다. 지수 슬레이트 구현을 위해 **KRX와 KIS를 같이 사용하기로 했다.**

KRX는 종가 기준 확정 데이터, KIS는 장중 실시간 데이터로 사용한다. 두 소스는 **확정된 과거인가 변동중인 현재인가**로 갈린다.

| 구분 | 소스 | 역할 | 저장 |
| --- | --- | --- | --- |
| EOD (장 마감 후 확정값) | KRX Marketplace | 어제까지의 확정 데이터 — 차트·통계·일봉의 기반 | DB 적재 |
| 장중 실시간 현재가 | KIS REST | 오늘 진행 중인 값 (미확정) | DB 안 씀, 화면 폴링만 |

KIS는 DB를 갱신하지 않는다. 장중(09:00~15:30)에만 폴링으로 화면에 얹는 휘발성 overlay다. 오늘 장이 끝나면 그날 종가는 다음 EOD 수집 때 KRX에서 확정값으로 DB에 들어가고, 그 시점부터 오늘도 "확정 과거"가 되어 KRX 데이터로 표시된다. 지수든 종목이든 이 규칙은 똑같다. 그래서 분담은 EOD=KRX / 장중=KIS다.

## probe 먼저, 정규화는 실측 후

정규화 코드를 짜기 전에 probe부터 돌린 건, KRX 응답을 실제로 한 번 받아두기 위해서다. Spec 문서로 필드 구조는 알 수 있지만, 권한 상태나 데이터가 며칠 치까지 차 있는지는 호출해봐야 안다.

probe로 확인한 건 세 가지다.

권한은 유가증권 OHLCV(`stk_bydd_trd`)만 승인돼 있고 지수 3종과 코스닥(`ksq_bydd_trd`)은 401이었다. 신청만 해두고 승인이 안 난 상태라 예상된 결과고, 계정 단위라 endpoint별 문제도 아니다.

freshness는 월요일 오후 2시대에 당일 데이터가 0건, 직전 영업일까지만 946건이었다. 당일 종가는 장 마감 후에 들어오므로 collector cron을 오전에 걸면 전일치만 받는다. cron 기준 시각은 마감 후 유입 시점에 맞춰 따로 잡았다.

스키마는 Spec과 맞춰 확인했다. 종가가 `TDD_CLSPRC`처럼 `TDD_` 접두를 쓰는 것까지 응답 그대로 받아 정규화에 쓸 필드를 확정했다.

지수 정규화 선작성은 보류했다. 미리 짜둘 수도 있었지만, 지수 endpoint가 401이라 적재도 패널 렌더도 막혀 있어서 정규화만 만들어둬도 화면에 보이는 결과가 없다. 승인이 난 뒤 지수 응답을 받아 한 번에 진행하는 게 맞다고 봤다.

## KIS 실시간 지수 조회 가능

KIS는 매매까지 되는 API라 종류가 수백 개다. 실시간 폴링에 필요한 것만 추렸다. 포털 문서가 JS로 렌더돼서 페이지만으로는 정확한 호출 스펙(URL·tr_id·응답 필드)을 못 긁는데, KIS가 공식 [GitHub](https://github.com/koreainvestment/open-trading-api)에 예제 코드를 올려둬서 거기서 실측값을 뽑았다.

| 용도 | API | tr_id |
| --- | --- | --- |
| REST 토큰 | 접근토큰발급 | — |
| 종목 현재가 (단건) | 주식현재가 시세 | FHKST01010100 |
| 종목 현재가 (다건) | 관심종목(멀티종목) 시세조회 | FHKST11300006 |
| 지수 현재가 | 국내업종 현재지수 | FHPUP02100000 |

핸드오프에서 열어뒀던 질문 두 개가 probe로 닫혔다.

하나는 "전종목을 한 번에 가져올 수 있나"였다. KIS는 종목별 단건 조회가 기본이라, 관심종목이 수십 개면 그만큼 호출해야 하나 걱정했는데, 멀티종목 조회가 **한 호출에 최대 30종목**을 받는다. 관심종목 30개까지는 1회, 초과분만 분할하면 된다.

다른 하나는 실시간 지수의 소스였다. 계획 단계에선 지수를 KIS로 받을지 확정을 못 했는데, probe에서 코스피(0001)·코스닥(1001)·코스피200(2001)이 다 정상으로 나왔다. 이게 이번 세션에서 그림을 바꾼 지점이다. **장중 지수는 KRX 지수 endpoint 승인을 안 기다려도 KIS로 지금 된다.** KRX 지수 승인은 EOD 과거 차트·통계에만 필요한 일로 밀려났고, 막혀 있던 홈 지수 패널(E13)이 그만큼 풀렸다.

probe 응답을 보다 한 가지는 일부러 안 쓰기로 했다. KIS 현재가 응답에 per·pbr·eps가 같이 딸려 오는데(삼성전자 PER 53.66 식으로), 이건 KIS 산식이라 우리가 DART로 계산하는 값과 다르다. 실시간에선 가격만 쓰고 밸류에이션은 기존 DART 경로를 그대로 둔다. 안 그러면 출처가 둘로 갈려서, 예전에 겪은 EPS 불일치 같은 문제가 또 생긴다.

## KIS 토큰 캐시

여기부터는 실제 코드다. KIS 토큰은 발급이 1분당 1회로 제한되고 하루(86400초) 만에 만료된다. 폴링할 때마다 발급하면 바로 제한에 걸리니, 유효한 토큰을 서버 메모리에 캐시하고 만료 전까지 재사용하는 게이트가 필요했다.

세 가지를 신경 썼다.

**만료 직전 토큰으로 폴링하다 중간에 만료되는 걸 막으려고, `expires_in`에서 10분을 빼고 만료로 친다.** 그리고 **동시 발급 방지**. 폴링이 여러 개 동시에 "만료됐다"를 보면 발급이 겹쳐서 1분 제한에 걸린다. 발급이 진행 중이면 그 Promise를 캐시해서 동시 요청이 같은 발급을 함께 기다리게 했다(single-flight). 마지막으로 **실패는 throw가 아니라 분기 타입으로 돌려준다** — 이건 프로젝트에서 Gemini 요약 등에 쓰던 패턴 그대로다.

```ts
export type TokenResult =
  | { ok: true; token: string }
  | { ok: false; error: TokenError };

export const getKisToken = async (): Promise<TokenResult> => {
  if (isValid(_cached)) return { ok: true, token: _cached.token };
  if (_inflight) return _inflight;             // 발급 중이면 같은 Promise 공유
  _inflight = requestToken().finally(() => { _inflight = null; });
  return _inflight;
};
```

Vercel 서버리스라 인스턴스가 여러 개 뜨면 각자 토큰을 갖지만, 같은 키로 복수 토큰이 허용되고 인스턴스당 발급도 1분 1회 안이라 문제는 없다. DB나 Redis로 토큰을 공유하는 건 지금 단계엔 과해서 안 했다.

## 정규화 레이어 — 같은 의미, 다른 필드명

KIS 원본 응답을 그대로 UI에 넘기지 않는다. lib에서 도메인 모델로 변환하는 건 이 프로젝트의 기존 규칙이다. probe로 실제 필드를 봤더니, 같은 "현재가"인데 호출하는 API마다 키 이름이 달랐다.

| 의미 | 단건 | 멀티 | 지수 |
| --- | --- | --- | --- |
| 현재가 | stck_prpr | inter2_prpr | bstp_nmix_prpr |
| 전일대비 | prdy_vrss | inter2_prdy_vrss | bstp_nmix_prdy_vrss |
| 등락률 | prdy_ctrt | prdy_ctrt | bstp_nmix_prdy_ctrt |

필드명은 다르지만 의미 구조는 같다. 그래서 공통 코어(`LiveQuoteCore`: 현재가·대비·등락률·방향·시고저)를 두고, 종목은 거래량을, 지수는 상승/하락 종목수를 더하는 식으로 확장했다. 종목과 지수를 단일 모델로 억지로 합치면 한쪽에만 있는 필드가 optional 범벅이 되거나 정보를 버려야 해서, 공통은 묶고 차이는 살리는 쪽으로 갔다. 단건과 멀티는 같은 종목 데이터라 도메인 모델은 하나(`StockQuote`)로 모으되, 소스 필드가 다르니 normalizer만 둘로 나눴다.

변환에서 두 가지를 방어적으로 처리했다. KIS 값은 전부 문자열이라 숫자로 바꾸는데, 빈 문자열이나 누락은 0이 아니라 null로 둔다. 핵심값(현재가·대비·등락률)이 하나라도 깨지면 그 quote는 통째로 null을 반환해서 화면에 올리지 않는다. 등락 부호도 KIS는 상한·상승·보합·하한·하락 5종으로 주는데, 조회 서비스에서 쓰는 색은 빨강·파랑·회색 셋뿐이라 up/down/flat 3종으로 접었다. 상한/하한 구분은 지금 화면에 안 쓰니 굳이 남기지 않았다.

```ts
const toNum = (v: string | undefined): number | null => {
  if (v === undefined || v.trim() === "") return null;
  const n = Number(v);
  return Number.isNaN(n) ? null : n;
};
```

장중에만 의미 있는 작업이라 시간이 좀 빠듯했는데, 토큰 캐시와 정규화까지가 실시간 트랙의 바닥이라 여기까지를 이번 세션 목표로 잡고 닫았다. fetch 래퍼부터 route handler, 폴링 훅, 패널은 이 위에 얹는 일이라 다음으로 미뤘다.

## 정리

- **데이터소스 시간축 분담** — EOD는 KRX Marketplace, 장중 현재가는 KIS REST. 지수·종목 공통이고, KIS는 DB를 갱신하지 않는 화면 overlay다
- **probe 2종 실행** — KRX는 유가증권 OHLCV만 승인·지수와 코스닥은 미승인, 당일 데이터는 마감 후 유입. KIS는 토큰·현재가·멀티·지수 4종 다 정상이고 지수도 실시간으로 받힌다
- **KIS 토큰 캐시** — 1분 1회 발급 제한 대응. 만료 버퍼 + single-flight + 분기 타입
- **정규화 레이어** — 공통 코어에 종목·지수를 확장, 단건/멀티 normalizer 분리, 빈값 null 가드와 부호 3종 축약

기능만 보면 화면에 보이는 변화는 아직 없는 세션이다. 그런데 probe를 돌린 덕에 "지수는 KRX 승인을 기다려야 한다"는 전제가 "장중 지수는 KIS로 지금 된다"로 바뀌었고, 막혀 있던 홈 지수 패널의 길이 열렸다. 며칠 데이터소스 문제로 끌어온 트랙이었는데, 명세만 보고 짜는 대신 실제로 찍어본 게 가정을 두 번 바로잡았다. 만들기 전에 확인하는 일에 시간을 쓴 셈이다.

## 다음 작업

실시간 트랙의 바닥을 깔았으니, 다음은 그 위에 데이터가 흐르는 경로를 잇는다.

- **E15** — KIS fetch 래퍼(토큰 + normalizer 결선) → route handler(장중 판별, revalidate) → 폴링 훅(TanStack refetchInterval) → 실시간 패널 순서로 올린다
- **E13** — 장중 지수 패널은 KIS로 진행할 수 있어 KRX 승인과 분리해 먼저 손댄다. 관심종목 2단은 실시간 뒤로
- **X5** — KRX 지수 3종과 코스닥 endpoint 승인이 나면 probe를 다시 돌려 지수명·스키마를 확정하고, EOD 적재를 KRX로 일원화한다

route와 패널이 붙어야 화면에 숫자가 도는 게 보일 텐데, 그건 장중에 검증해야 하는 작업이라 다음 세션에서 시간을 보고 진행할 계획이다.
