#119에서 등록한 F59(OHL=0 fill 봉 서빙 정규화)와 F60(상장폐지 is_active 동기화)을 계획대로 묶었고, 여력이 남아 F61(지수 row floor)까지 편승했다. 세션 초입에 지난주부터 지켜보던 홈 미니 차트 장중 플래시(#118)의 소멸도 최종 확인하고 관측을 닫았다.

probe는 두 건을 한 번에 돌렸다. 따로 갈 이유가 없는 게, 두 이슈가 독립이 아니다 — 폐지 종목을 서비스에서 어떻게 치울 건지(F60)가 정해져야 flat 변환을 어디까지 적용할지(F59)가 정해진다.

---

## OHL=0 106,672행의 구성비

#119에서 "구성비 판별 선행"으로 걸어둔 그 조사다. 결과는 걱정보다 깨끗했다.

| 분류 | 규모 | 근거 |
| --- | --- | --- |
| 정지·폐지 상태로 잔존한 fill | **0행** | 최근 봉까지 OHL=0인 티커 없음 |
| 진성 무거래·과거 정지 구간 fill | ~99.9% | close=직전종가 · volume=0 |
| 오염 의심 | 102행 (0.1%) | volume>0 7행 + close≠직전 95행, 교집합 0 |

230360을 지난 세션에 정리한 뒤로 "지금 정지 중인데 fill이 노출되는" 케이스는 없다. 남은 리스크는 거래 재개된 종목의 과거 정지 구간과 SPAC류 무거래일 fill이 52주 저가를 0원으로 끌어내리고 캔들 축을 무너뜨리는 것 — 정확히 #119에서 본 그 증상이다. 오염 102행은 2016~2021년 백필 잡음으로 보여서, 실값 재적재 판단만 F35에 넘겼다.

소비처 쪽 조사가 구현 방향을 정해줬다. daily_prices의 O/H/L을 실제로 쓰는 경로는 **캔들 차트 3개소와 52주 range 계산 하나뿐**이고, 나머지 다섯 경로(검색·재무 PER·관심종목 배치 등)는 close만 읽는다. 그리고 그 네 소비처가 전부 `prices.ts`의 row→snapshot 매핑 3개소를 지나간다. 왜곡의 진입로가 한 파일 안으로 좁혀진 셈이다.

## 매퍼 하나로 닫기

방향(서빙 정규화)은 지난 세션에 정했으니 이번엔 위치다. 소비처마다 변환을 끼우는 안도 있었지만, 세 매핑이 완전히 동일한 걸 확인하고 공용 순수 함수로 추출했다.

```ts
export const rowToSnapshot = (row: DailyPriceRow): StockPriceSnapshot => {
  const isFlatFill = row.open === 0 && row.high === 0 && row.low === 0;
  return {
    // ...
    open: isFlatFill ? row.close : row.open,
    high: isFlatFill ? row.close : row.high,
    low: isFlatFill ? row.close : row.low,
  };
};
```

정규화가 lib 경계에 있으니 도메인 모델 규약으로 flat이 보장되고, DB의 10만 행은 재적재 없이 배포 한 번으로 닫힌다. 부분 0(open만 0인 류)은 건드리지 않고 통과시킨다 — 그건 fill이 아니라 오염 신호다.

폐지 종목 분기를 둘지 잠깐 고민했는데 안 뒀다. 구성비에서 폐지 잔존 fill이 0이기도 하고, 뒤이어 F60이 폐지 종목의 화면 자체를 닫으니 flat이 렌더될 자리가 없다. OHL=0인데 close까지 0인 행도 사전 쿼리로 0행 확인 — flat 후에도 0이 남는 케이스는 없다.

Vitest 7케이스를 붙여 515 passed.

## is_active — 스키마엔 있는데 아무도 안 쓰던 컬럼

F60 probe의 결론은 한 줄이었다. **is_active에 값을 쓰는 코드가 0건이다.** 컬럼은 default true로 태어나 아무도 건드리지 않고, fetch_stocks의 upsert에도 SET 절에 없다. 재밌는 건 웹 쪽인데, 검색·상세·랭킹 쿼리엔 `is_active = true` 필터가 전부 걸려 있었다. 걸러낼 준비는 다 돼 있고 관리하는 쪽만 없던 상태다.

이탈 감지 소스는 둘을 놓고 봤다.

| 안 | 걸리는 점 |
| --- | --- |
| 최근 60거래일 시세 부재 휴리스틱 | 신규 상장 미백필 종목을 폐지로 오탐, 최근 폐지 종목은 시세가 남아 미탐 |
| FSS 목록 이탈 | — |

FSS가 종목 목록의 소스라 이탈 기준이 정의상 맞다. 대신 FSS 응답이 어느 날 반 토막으로 오면 전 종목이 비활성될 수 있어 가드를 이중으로 뒀다 — 수집 2,000종 미만이면 동기화 skip, 이탈이 30종을 넘어도 skip. 넘으면 로그만 남기고 사람이 본다. `--force` 같은 우회 레버는 이번에도 안 만들었다. 재상장은 upsert의 DO UPDATE에 `is_active = true`를 넣어 목록 복귀 시 자동 복구된다.

## 첫 실행부터 울린 가드

로컬 첫 실행: 이탈 후보 **32종 > 상한 30**, 동기화 skip. 설계대로 동작한 건데, 리스트를 보니 그냥 넘길 수가 없었다. 스팩들 사이에 신세계푸드, 현대홈쇼핑, 더존비즈온, 코오롱ENP가 있다.

대형주 넷이 오탐이면 FSS 수집 이상 신호라 UPDATE 전에 웹으로 확인했다. 전부 실제 폐지였다 — 신세계푸드는 이마트 완전자회사 편입으로 8월 11일, 현대홈쇼핑은 지주사 주식교환으로 7월 20일, 더존비즈온은 EQT 인수 후 7월 15일, 코오롱ENP는 코오롱인더스트리 흡수합병. 올해 자진 상폐·합병 소멸이 이렇게 몰린 줄은 사실 이번에 알았다.

probe 때 휴리스틱으로 추정한 폐지 후보가 15종이었는데 실기준이 32종인 이유도 여기서 풀렸다. 최근 폐지 종목은 60거래일 시세가 멀쩡히 남아 있어 휴리스틱이 못 본다. 추정이 틀렸다기보다 그 방식이 구조적으로 못 보는 영역이 컸던 거다.

처리는 가드를 완화하는 대신 수동 경로를 보강했다. 상한 초과 WARN에 이탈 전체 목록과 수동 UPDATE용 `ARRAY[...]` 리터럴을 그대로 찍게 고치고, 검증 끝난 32종을 일괄 UPDATE. 재실행하니 "이탈 종목 없음"으로 수렴했다. 초회 백로그는 일회성인데 그걸 위해 상한을 올리면 가드가 상시로 물러진다.

화면 확인까지 — 폐지 종목이 검색에서 사라지고, 상세 직접 진입은 404. 기존 필터들이 그제야 일을 시작했다.

## 검증 과정에서 나온 신규 항목

**미백필 신규 종목(F64)** — 폐지 후보 대조 중에 daily_prices가 아예 0행인 종목 5종이 걸렸다. 폐지가 아니라 실거래 중인 신규 상장들인데, 최근 조회 행에선 live quote로 가격이 멀쩡히 뜨고 상세에 들어가면 "가격 데이터 없음"이 나온다. 리스트와 상세가 서로 다른 말을 하는 상태다. fetch_prices의 인크리먼트가 MAX(date)+1 기준이라 행이 0개인 티커는 시작점 자체가 없는 구조로 의심되는데, 티커 선정 경로부터 probe가 필요해 등록만 했다.

**404 페이지 부재(E55)** — 폐지 종목 404를 눈으로 보고 나서야 알아챘는데, not-found가 Next 기본 화면 그대로다. F60이 404로 떨어지는 실트래픽을 이제 실제로 만들기 시작했으니 전역·종목 상세 not-found와 error 페이지를 프로젝트 스타일로 저작할 차례다.

F61은 지수 verify에 국내 4종 count floor를 추가하는 것으로 한 문장 분량이라 조용히 편승 종결.

## 정리

- **F59 종결** — 구성비 판별(폐지 잔존 0 · 오염 0.1%) 후 `rowToSnapshot` 공용 매퍼로 서빙 flat 정규화. 차트 축 붕괴와 52주 저가 0원이 코드 배포 한 번으로 닫혔다
- **F60 종결** — FSS 이탈 기준 is_active 동기화 + 이중 가드. 첫 실행에서 가드 발동 → 32종 웹 검증 → 수동 정리 → 이탈 0 수렴. 웹은 기존 필터가 그대로 작동
- **F61 종결** — index_daily_prices 국내 4종 row-count floor
- **신설** — F64(미백필 신규 종목) · E55(fallback 페이지 정비)

#116의 장중 오적재에서 시작해 F56 → F58 → F59·F60으로 이어진 데이터 안정성 라인이 이번 세션으로 닫혔다. 조회 서비스에서 "있는 데이터가 정확한가"만큼 "없어야 할 종목이 없는가"도 정확성이라는 걸, 폐지 종목 32종이 검색에 잡히던 상태를 치우면서 새삼 확인했다.
