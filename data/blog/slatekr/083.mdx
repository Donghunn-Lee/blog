그동안 마무리, 마무리 하면서 세 달이나 이어질 줄은 몰랐다. 그리고 이제는 정말 끝이 보인다. 저번에 ai 공시 요약 컨텍스트를 구조화하고, 로드맵에서 공시 관련 작업을 이어서 진행하기로 했다.

[#012](https://velog.io/@dh82680/SlateKR-012-공시-분류-레이어-공시-태그)에서 공시 배지를 만들 때 거래소 행정 공시는 태그를 안 달기로 했었다. [#021](https://velog.io/@dh82680/SlateKR-021-AI-공시-요약-4-공시-분류와-파싱-정돈)에서 미분류를 65건에서 24건으로 줄일 때도, 불성실공시법인지정예고나 거래정지 같은 건 당장 정하기 어렵다고 판단해 "경계선"으로 묶어 다음으로 미뤘다. 데이터를 더 쌓고 별도 사이클에서 보자고 적어뒀다.

D6이 그 사이클이다. 미분류로 둘지 별도 축을 팔지 정하는 게 이번 목표였다.

## 미분류 1,164건

DART 공시 목록(`list.json`) 응답에는 제출인명(`flr_nm`) 필드가 있다. 대부분은 회사명인데, 거래소가 직접 내는 공시는 `코스닥시장본부` 또는 `유가증권시장본부`로 찍힌다. 이걸 축으로 최근 3개월을 훑었다.

거래소 발신 공시가 **1,164건** 나왔다. 그 중 SlateKR DB에 있는 종목만 남기면 1,036건, 576개 종목이다.

현재 분류기에 그대로 통과시켜봤다.

| 반환값 | 건수 |
| --- | --- |
| `null` | 1,162 |
| 오분류 | 2 |

커버리지가 약한 게 아니라 **0이었다.** 그리고 오분류 두 건이 좀 고약했다.

```null
조회공시요구(풍문또는보도) (주주총회효력정지 가처분 …)
  → SHAREHOLDER_MEETING   ("주주총회" 매칭)

기타시장안내 (분기보고서 미제출 관련 상장폐지 절차 미진행)
  → FINANCIAL             ("분기보고서" 매칭)
```

두 번째가 문제다. FINANCIAL은 AI 요약을 차단하는 유형이다. **상장폐지 절차 공시가 정기보고서로 잡혀서 요약이 막혀 있었다.**

배지가 신호로서 가치를 가지려면 노이즈를 없애야 한다는 게 #012의 원칙이었는데, 정작 신호가 가장 센 쪽이 통째로 빠져 있었던 셈이다.

## 유형 코드 I003

#021에서 DART API의 공시상세유형 코드 `pblntf_detail_ty`를 발견했지만 활용은 보류했었다. 이유는 두 가지였다.

> DART 유형 코드는 행정 분류 기준이고, `classifyDisclosure`는 "주가 영향 가능성"이라는 다른 분류 기준을 갖는다. 1:1 매핑되지 않는다.

변경 비용도 컸다. 키워드 보강은 한 파일이면 끝나는데 유형 코드를 받으려면 Zod 스키마부터 호출처까지 네 파일 이상이었다.

이번엔 사정이 달랐다. 문서를 뒤져보니 거래소공시(`I`) 하위에 세분 코드가 있었다.

```null
I001  수시공시
I002  공정공시
I003  시장조치/안내      ← 이거다
I004  지분공시
```

**`I003 시장조치/안내`.** 이름부터 딱 맞았다. 문자열 매칭보다 공식 코드가 낫다는 게 당연해 보여서, 축을 갈아탈 생각으로 실측을 돌렸다.

동일한 3개월 구간으로 `I003`을 조회하고, `flr_nm` 기준 집합과 대조했다.

| | 건수 |
| --- | --- |
| I003 | 1,769 |
| flr_nm 거래소 | 1,164 |
| 교집합 | 1,076 |
| **I003 − flr_nm** | **693** |
| **flr_nm − I003** | **88** |

양쪽으로 다 어긋났다.

**I003에는 있는데 거래소 발신이 아닌 693건** — 대부분 `기업설명회(IR)개최(안내공시)` 587건이었다. 회사가 내는 IR 안내다. 유형 이름이 "시장조치**/안내**"인 게 힌트였는데 그땐 눈에 안 들어왔다. 거래소 조치와 회사 안내가 한 코드에 묶여 있다.

문제는 반대쪽이다. **거래소 발신인데 I003에 안 잡힌 88건.**

```null
불성실공시법인지정예고          15
조회공시요구(풍문또는보도)        7
투자유의안내                    5
기타시장안내 (개선기간 부여)      9
기타시장안내 (상장폐지 이의신청서 제출)  5
```

D6에서 가장 중요한 것들이 정확히 여기 있었다. **I003을 축으로 썼으면 불성실공시법인지정예고를 통째로 놓쳤을 거다.**

#021에서 적어둔 예측이 그대로 맞았다. DART 유형 코드는 행정 분류고 우리는 주가 영향 기준이다. 코드가 있다는 것과 그 코드가 내 기준으로 잘 나뉜다는 건 다른 얘기였다.

한 겹 더 들어가면, `flr_nm`은 **누가 제출했는가**라는 1차 사실이고 `I003`은 **DART가 어떻게 분류했는가**라는 파생 라벨이다. 파생 라벨은 만든 쪽의 기준을 따르지 내 기준을 따르지 않는다.

```ts
const EXCHANGE_FILERS = ["코스닥시장본부", "유가증권시장본부"] as const;

export const isExchangeFiled = (flrNm: string): boolean =>
  EXCHANGE_FILERS.some((filer) => filer === flrNm);
```

문자열 매칭이 취약한 건 맞다. 다만 이건 KRX 법인의 조직명이라 잘 안 바뀌고, 바뀌면 배지가 **한꺼번에 사라진다.** 시끄럽게 실패하는 쪽이 조용히 오분류하는 쪽보다 낫다.

대조군도 찍어뒀다. #082에서 다뤘던 공급계약과 타법인취득이 `I001`(수시공시)에 들어 있었다. 만약 유형 `I` 전체로 필터를 걸었다면 멀쩡히 분류되던 공시까지 같이 날아갔을 거다.

## 화이트리스트에서 블랙리스트로

축이 정해졌으니 이제 그 1,036건 안에서 선을 그어야 했다. 거래소 공시라고 다 배지를 달면 안 된다.

`report_nm`으로 집계하니 고유 유형이 **168개**였다.

| report_nm | 건수 |
| --- | --- |
| 소속부변경 | 215 |
| 주권매매거래정지 (주식의 병합, 분할 등 전자등록 변경, 말소) | 115 |
| 주권매매거래정지해제 (액면병합 주권 변경상장) | 111 |
| 주권매매거래정지해제 (감자 주권 변경상장) | 29 |
| 조회공시요구(현저한시황변동) | 27 |
| 주권매매거래정지해제 (상장폐지에 따른 정리매매 개시) | 17 |
| 불성실공시법인지정예고 | 15 |

상위 세 개가 42%인데 셋 다 절차적이다. 소속부변경은 코스닥 정기 재분류고, 나머지 둘은 액면병합·주식병합 때 며칠 거래를 멈췄다 푸는 거다. 반대로 조회공시요구나 불성실공시 같은 건 건수가 적다. **신호가 셀수록 드물다.** 배지가 신호이려면 이 분포를 그대로 반영해야 한다.

처음엔 화이트리스트로 잡을 생각이었다. 노이즈 배지가 하나 섞이면 배지 체계 전체가 무너지는데, 놓치는 건 지금과 같은 상태(배지 없음)일 뿐이다. 실패 비용이 비대칭이니 좁게 가는 게 맞다고 봤다.

168행을 다 펼쳐놓고 보니 생각이 바뀌었다.

**꼬리가 전부 고신호였다.** 1건짜리들을 몇 개 옮겨보면 이렇다.

```null
기타시장안내 (상장적격성 실질심사 사유 추가 발생)
기타시장안내 (회생절차 폐지결정 관련 시장조치 미진행)
주권매매거래정지 (중요한 영업정지)
조회공시요구(풍문또는보도) (대표 등 주요 경영진 횡령·배임 피소설)
```

이런 게 60개 넘게 흩어져 있다. 화이트리스트로는 이걸 다 담을 수 없고, 다음 분기에 새 사유가 나오면 또 놓친다. 반대로 노이즈는 소수의 정형 패턴에 몰려 있다 — 소속부변경, 변경상장, 권리락·배당락, 영문상호 변경.

그리고 화이트리스트를 걱정하게 만든 오탐 문제가 사실 이미 사라져 있었다. **`flr_nm` 게이팅을 최상단에 두면 키워드가 거래소 발신 공시 안에서만 돈다.** 회사 공시로 새어나갈 경로가 구조적으로 없다.

결정적인 건 실패 방향이었다. 새 서식이 생겼을 때 화이트리스트는 **조용히 놓치고**, 블랙리스트는 **시끄럽게 배지를 띄운다.** 거래소가 새로 만들 서식이라면 절차적인 쪽보다 규제 쪽일 가능성이 높다. 그렇다면 시끄러운 실패가 낫다.

키워드를 짤 때 함정이 하나 있었다. `정지`로 매칭하면 `주권매매거래정지해제`에도 걸린다. 어미가 아니라 **사유**로만 걸러야 했다.

```ts
const PROCEDURAL_KEYWORDS = [
  "소속부변경", "권리락", "배당락", "약명및영문명", "의무보유",
  "변경상장", "전자등록 변경", "무상증자", "자본감소",
  "단일판매공급계약", "중요내용공시", "합병결정 철회",
  "SPAC", "우회상장",
] as const;
```

덕분에 `주권매매거래정지해제 (상장폐지에 따른 정리매매 개시)` 17건은 살아남는다. 정리매매 개시는 상장폐지 확정이니 이 목록에서 가장 센 신호다. `정지`나 `해제`로 걸렀으면 이게 날아갔을 거다.

최종 분류기는 이렇게 됐다.

```ts
export const classifyDisclosure = (
  disclosureNm: string,
  flrNm: string,
): DisclosureType | null => {
  if (isExchangeFiled(flrNm)) {
    if (PROCEDURAL_KEYWORDS.some((kw) => disclosureNm.includes(kw))) return null;
    return DisclosureType.MARKET_ACTION;
  }

  for (const { type, keywords } of PATTERNS) {
    if (keywords.some((kw) => disclosureNm.includes(kw))) return type;
  }
  return null;
};
```

`flr_nm` 게이팅이 맨 위에 있으니 거래소 공시는 회사 키워드 매칭을 아예 타지 않는다. **아까 그 오분류 두 건이 코드를 따로 안 고쳐도 사라졌다.**

1,036건 재검증 결과는 `MARKET_ACTION` 447 / 절차적 `null` 589 / **기존 5종 0건**이었다. 마지막 줄이 게이팅이 제대로 물렸다는 확인이다.

## 요약 입력에 섞인 CSS

거래소 공시가 요약할 만한 문서인지 보려고 원문을 찍었는데, 앞 300자가 통째로 CSS였다.

```null
.xforms_input{border:1px solid #000;} .xforms_select{...}
```

`stripTags`가 `<STYLE>` 태그는 지우는데 **태그 사이의 텍스트는 안 지운다.** 태그만 벗기는 정규식이라 당연한 동작이었다.

```ts
const stripTags = (xml: string) => xml.replace(/<[^>]+>/g, "");
```

거래소 서식만의 문제인 줄 알았다. 대조군으로 #082에서 다뤘던 회사 공시 네 건을 같이 찍어봤다.

| 공시 | 수정 전 | 수정 후 | CSS 비중 |
| --- | --- | --- | --- |
| 유상증자결정 | 3,833 | 3,833 | 0.0% |
| 임원소유상황보고 | 1,527 | 1,527 | 0.0% |
| 공급계약 | 1,573 | **587** | 62.7% |
| 타법인취득 | 2,924 | 1,938 | 33.7% |
| 소속부변경 | 1,110 | **124** | 88.8% |
| 조회공시요구 | 1,194 | 208 | 82.6% |
| 불성실공시법인지정예고 | 1,447 | 461 | 68.1% |

XForms 서식을 쓰는 공시 전반의 문제였다. **#082에서 "공급계약 1,573자 불변 ✓"이라고 대조군 삼았던 그 숫자가 사실은 62.7%가 CSS였다.** 원문이 안 바뀐 건 맞으니 그때 판정 자체는 유효한데, 실제 본문은 587자였다.

CSS가 없던 두 건이 정확히 불변인 게 이번엔 과잉 삭제가 없다는 대조군 역할을 했다.

수정은 함수 하나 추가하고 `stripTags` 앞에 끼우는 것이었다. [F24](https://velog.io/@dh82680/SlateKR-082-공시-원문-표-유실과-facts-상한-재조정)로 미뤄둔 표지 blob 제거와 달리, 여기선 XML 태그 경계가 명확해서 본문을 잘못 지울 위험이 없다. `<SCRIPT>`나 HTML 주석은 여덟 건 전부에서 안 나와서 손대지 않았다.

## 요약 버튼에 게이트가 없었다

처음 설계는 "거래소 발신 공시는 AI 요약을 전면 차단"이었다. 소속부변경이 124자, 불성실공시가 461자다. 제목과 라벨:값 몇 줄이 전부라 요약할 부담 자체가 없어 보였다.

근데 CSS를 걷어내고 나니 **공급계약이 587자**였다. 불성실공시(461자)와 126자 차이다. 그리고 공급계약은 지금도 요약을 하고 facts를 아홉 개 뽑는다.

"짧아서 요약 가치가 없다"가 맞다면 공급계약도 막아야 한다. 안 막고 있다. 논리가 안 맞았다.

CSS 제거 **전** 숫자로 감각을 잡고 있었던 게 원인이다. D9로 착시가 걷혔는데 판단을 갱신하지 않았다. 결국 거래소 발신 전면 차단은 접고, `MARKET_ACTION` 447건은 요약을 열기로 했다.

게이트를 옮기려고 `DisclosuresSection`을 읽다가 다른 걸 발견했다. **버튼에 원래 게이트가 없었다.**

```tsx
<button type="button" onClick={handleToggleClick}>
  {isExpanded ? "닫기" : "AI 요약"}
</button>
```

분류값을 참조하지 않는다. FINANCIAL 차단은 `route.ts`에만 있었다. 그러니까 사업보고서 행에서 버튼을 누르면 로딩이 돌다가 **서버가 `not_summarizable`로 거절**했다. 누를 수 있게 생긴 버튼이 실패하고 있었다.

#021에서 "AI 요약 대상 사전 필터링 검토"를 다음 작업으로 적어뒀었다. UI 통합 단계에서 판단하겠다고 했는데, 그대로 안 붙은 채 지나간 거다.

게이트를 분류 결과 하나로 통일했다.

```ts
const type = classifyDisclosure(d.disclosureNm, d.flrNm);
const summarizable = type !== null && type !== DisclosureType.FINANCIAL;
```

이 한 줄이 세 갈래를 동시에 잡는다.

- 절차적 거래소 공시 → `null`
- 배지가 안 붙는 회사 공시 → `null`
- 정기보고서 → `FINANCIAL`

`route.ts`의 검사는 그대로 뒀다. 클라이언트가 먼저 막으니 이제 2차 방어선 역할로 돌아간다.

## 배지와 버튼

배지 색을 정하려고 토큰을 펼쳐봤는데 자리가 없었다.

| 카테고리 | hue |
| --- | --- |
| MAJOR_EVENT | 25 (빨강) |
| SHAREHOLDER_MEETING | 60~80 (앰버) |
| AUDIT | 185 (청록) |
| FINANCIAL | 260 (파랑) |
| OWNERSHIP | 305 (보라) |

색상환이 거의 다 찼다. 빈 구간 중 쓸 만한 건 로즈(345)뿐인데 MAJOR_EVENT와 40도밖에 안 떨어진다. 하필 가장 중요한 두 배지가 빨강 두 개로 헷갈리게 된다. 게다가 국내 증시는 빨강이 상승이라 악재 배지에 빨강 계열을 쓰면 오독의 여지가 있다.

그래서 담백하게 무채색으로 정했다.

![](/static/images/velog/ed8a32a1-af65-467c-ba36-c0171ac43dd1-image.png)

```css
--disclosure-market-action-bg:   oklch(0.955 0.006 85);
--disclosure-market-action-text: oklch(0.34 0.012 85);
```

애초에 시장조치는 **여섯 번째 색이 아니라 다른 축**이다. 나머지 다섯은 회사가 낸 문서의 종류인데, 시장조치는 거래소가 그 종목에 취한 조치다. 발신 주체가 다르고, 다섯 중에는 없는 방향성(악재)을 갖는다. 색상환에 하나 더 끼워넣으면 "그냥 여섯 번째 카테고리"가 되어버린다.

명도 0.34는 기존 다섯 종(0.48~0.60)보다 확연히 어둡다. 파스텔 배지들 사이에서 흑백 하나가 오히려 눈에 걸린다. 회색이 약해 보이는 건 옅은 회색일 때 얘기다.

버튼 쪽은 시행착오가 좀 있었다. 요약이 안 되는 행에 그냥 빈 칸을 두면 고장난 것처럼 보인다. 그래서 사유를 알려주는 물음표 툴팁을 붙였다.

| 상황 | 문구 |
| --- | --- |
| 정기보고서 | 원문이 길고 수치가 많아 요약 시 왜곡 위험이 있습니다. |
| 절차적 거래소 공시 | 원문이 짧아 요약 없이 바로 확인할 수 있습니다. |
| 미분류 | 요약을 제공하지 않는 유형의 공시입니다. |

여기서 `disabled` 속성은 쓸 수 없었다. 포인터 이벤트를 안 받아서 **툴팁이 안 뜬다.** 비활성인데 이유를 볼 수 없으면 아무것도 안 한 것보다 나쁘다. `aria-disabled`로 상태만 알리고 hover는 살렸다.

버튼을 흐리게 하고 옆에 물음표를 두는 것까지 만들어놓고 화면을 봤더니, **활성 버튼과 비활성 버튼이 구분이 안 됐다.** 둘 다 테두리 있는 박스에 같은 글자다. 색 대비만으로는 목록을 훑을 때 안 걸린다. 물음표가 레이아웃 흐름에 끼어서 물음표 있는 행만 버튼이 왼쪽으로 밀리는 문제도 같이 나왔다.

결국 **비활성 행에서는 버튼을 아예 안 그리고 물음표만** 남겼다.

![](/static/images/velog/2fbb64c9-fe2d-4630-860f-d108fcccc3db-image.png)


둘이 같은 자리를 배타적으로 쓰니 정렬 문제가 통째로 사라졌다. 버튼이 있느냐 없느냐는 색 대비보다 훨씬 강한 신호이기도 하다. 누를 수 있게 생긴 게 없으니 어포던스도 정직해진다.

물음표를 버튼 박스 **안**에 넣는 안도 검토했는데 접었다. 누를 수 있는 것처럼 보이고, 589건이 물음표 밭이 되면 예외가 정상보다 눈에 띈다.

## 정리

- **판별 축은 `flr_nm`** — DART 공식 코드 `I003`은 양방향으로 어긋났다. IR 안내 693건이 딸려오고 불성실공시 계열 88건이 빠진다. 행정 분류 기준과 주가 영향 기준은 1:1로 안 맞는다는 #021의 예측이 그대로 확인됐다.
- **화이트리스트가 아니라 블랙리스트** — 꼬리가 전부 고신호였다. 새 서식에 대해 화이트리스트는 조용히 놓치고 블랙리스트는 시끄럽게 티를 낸다.
- **게이팅 순서가 오분류를 지웠다** — `flr_nm` 검사를 최상단에 두니 거래소 공시가 회사 키워드를 아예 안 탄다. 별도 패치 없이 두 건이 정리됐다.
- **CSS 노이즈** — `stripTags`가 `<STYLE>` 안쪽 텍스트를 남기고 있었다. 공급계약 본문의 62.7%가 CSS였다.
- **요약 게이트 통일** — 버튼에 원래 게이트가 없어서 서버가 거절하고 있었다. 분류 결과 한 줄로 합쳤다.

이번 세션은 미분류 1,164건을 447 대 589로 가르는 일이었는데, 정작 시간은 **어디에 선을 그을지가 아니라 무엇을 축으로 삼을지**에 더 썼다. 공식 코드가 있으니 그걸 쓰면 된다는 게 처음 생각이었고, 실측 두 번으로 접혔다.

#021에서 미뤄둔 세 가지가 이번에 한꺼번에 돌아온 것도 좀 재밌었다. 유형 코드, 경계선 항목, 요약 버튼 사전 차단. 그때 "데이터가 쌓이면 다시 본다"고 적어둔 게 정확히 제 역할을 했다.
