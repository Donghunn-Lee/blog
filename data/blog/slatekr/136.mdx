#135에서 배당 축을 닫으며 지표 보강(X13·X4)을 다음으로 넘겼다. X13은 KIS 재무비율 TR로 9개 지표를 한 콜에 받는 건이고, X4는 DART의 단일회사 주요지표 API였다. 둘 다 조사만 돼 있었고, 재무 슬레이트가 17행이라 어디까지 더 넣을지가 먼저였다. 같은 아침엔 #131에서 고친 F71(열어둔 탭의 개장 감지)의 개장 쪽 실증도 걸려 있었다.

계획은 E65(CDN 캐시 헤더)를 서두에 소화하고 지표 보강으로 가는 것이었는데, E65는 시작 전에 백로그로 내렸고, 지표 보강은 KIS를 붙이지 않는 쪽으로 끝났다. 대신 F71 실측 중에 지수 미니차트가 개장 전에 구간마다 다른 화면을 보여주는 걸 발견해 F79로 등록하고 같은 날 구현했다. 실증은 내일 아침이다.

## 08:50 각성 실측

08:49에 홈을 열어두고 리로드 없이 기다렸다. #131 수정은 closed 상태에서도 느린 주기로 계속 묻게 한 것이라, 확인할 건 두 가지였다.

| 시각 | 관측 | 판정 |
|---|---|---|
| 08:50~09:00 | 지수 quote·분봉 요청이 120초 간격, 응답은 `marketOpen: false` | closed 주기 유지 |
| 09:01 | 헤더가 `장 마감 · 기준일 09-02` → `실시간 · 09:01`로 전환, 리로드 없음 | **각성** |
| 09:01~ | 요청 간격 60초로 전환, 09:04에 당일 봉 유입 | 정규 주기 복귀 |

깨어나는 상한이 120초였으니 09:02 안이면 green이고, 실제로는 09:01이었다. F71은 이걸로 닫았다.

## E65를 시작하지 않은 이유

E65는 #134 계측으로 근거가 서 있었다. 지수 일봉 전량 route가 압축 후 283KB에 웜 TTFB 0.4초인데, `Cache-Control`이 `max-age=0`이라 CDN이 매번 origin으로 보내고 있었다. `s-maxage` 한 줄이면 두 번째 방문자부터 edge 응답이다.

그런데 이 route는 차트를 왼쪽 끝까지 당겼을 때 한 번 불리는 경로다. 사용자가 체감하는 건 그 한 번의 0.4초이고, 기능 영향은 없다. 남는 가치가 "서버 캐시 위에 CDN 캐시를 한 층 더 얹었다"는 서술 한 줄인데, 그걸 위해 세션 서두를 쓰는 게 맞나 싶었다. 계측 결과는 비고에 남기고 백로그로 내렸다.

## KIS 재무비율 9지표와 현재 슬레이트

X13은 조사가 끝난 상태였지만 실측 기록이 남아 있지 않아 삼성전자로 연간·분기 한 콜씩 다시 받았다. 9지표를 현재 17행과 대조하니 붙일 게 거의 없었다.

| KIS 지표 | 현 슬레이트 | 판정 |
|---|---|---|
| EPS · BPS · ROE · 부채비율 | 있음 (DART 기반) | 중복. 게다가 값이 다름 |
| 매출·영업이익·순이익 증가율 | 없음 | DB의 5년치 실적으로 전년 대비 계산 가능 |
| SPS | 없음 | 매출 ÷ 발행주식수로 계산 가능 |
| 유보율 | 없음 | 자본금·잉여금이 DB에 없어 KIS 없이는 불가 |

값이 다르다는 게 결정적이었다. 삼성전자 2025년 BPS가 KIS 63,997원, 우리 DART 값이 71,679원으로 12%가 벌어졌다. 어느 쪽이 틀린 게 아니라 산정 기준(연결·별도, 주식수)이 다른 것으로 보이는데, 그렇다면 한 화면에 두 소스를 섞을 수 없다는 #100 이후의 원칙이 그대로 적용된다. 이미 있는 네 지표는 KIS 값을 받아도 쓸 수 없고, 계산 가능한 지표는 굳이 받을 이유가 없다. 그러면 collector와 테이블, 주간 스텝, secrets를 새로 얹어서 얻는 순증분이 유보율 한 행이다.

X4도 같이 접었다. 실행 결과 파일이 없어 다시 보니 필수 파라미터 허용값조차 확정이 안 된 상태였고, 제공 시작이 2023년 3분기라 5년 열을 채울 수 없었다.

## 성장률을 파생으로

| 후보 | 판정 |
|---|---|
| X13 풀 아크 | 기각. 유보율 1행을 위해 collector·테이블·스텝 신설 |
| 17행으로 종결 | 보류. 성장률이 있으면 어떤지 감이 안 와서 |
| **성장률 3행을 DART 실적에서 파생** | **채택.** collector 0, 순수 함수 하나. 넣어보고 아니면 빼기로 |

규칙은 셋으로 고정했다.

```
연간   : 전년 연간 대비
분기   : 전년 동분기 대비 (Q4 파생 행 포함)
null   : 비교 대상 없음 · 기준값 ≤ 0 · 현재값 없음
```

기준값이 0 이하일 때 증가율을 억지로 만들지 않았다. HTS는 그 자리에 흑자전환·적자전환을 쓰는데, 지금은 "—"로 두고 필요해지면 라벨을 붙이기로 했다. 창의 첫해(2021년)도 비교 대상이 없어 비어 있는데, 이 한 열을 채우자고 조회를 6년으로 늘리진 않았다.

배치는 각 지표 바로 아래다. 매출 아래 매출증가율, 영업이익률 아래 영업이익증가율, 순이익률 아래 순이익증가율. 종합정보 탭의 6행 요약은 그대로 뒀다.

![](/static/images/velog/06c437bd-33aa-41ce-aceb-1d23d669ebb2-image.png)


붙이고 나서 아침에 받아둔 KIS 값과 맞춰봤다.

| 2025년 | 우리 | KIS | 차이 |
|---|---|---|---|
| 매출 증가율 | 10.88% | 10.88% | 0 |
| 영업이익 증가율 | 33.23% | 33.23% | 0 |
| 순이익 증가율 | 31.65% | 31.22% | +0.43%p |

앞의 둘은 소수 둘째 자리까지 같았다. DART 실적으로 계산한 값이 KIS의 공식 산식과 같은 정의라는 뜻이라, 파생으로 대체한 판단이 사후에 확인된 셈이다. 순이익만 차이가 나는데 KIS가 지배주주 순이익을 쓰는 듯했고, 우리는 당기순이익 정본을 그대로 뒀다.

## 지수 미니차트의 개장 전 화면

F71을 보는 동안 미니차트가 눈에 걸렸다. 08:00대에는 "장중 데이터 없음"이었는데, 08:50 폴링부터 전날 분봉이 라벨 없이 그려졌다.

| 구간 | 세션 | 조회 거래일 | 화면 |
|---|---|---|---|
| 06:00~08:00 | preopen | 전일 | 전일 봉 |
| 08:00~08:50 | pre | **오늘** | "장중 데이터 없음" |
| 08:50~09:00 | preopen | 전일 | 전일 봉 |

probe로 경로를 따라가니 route에도 클라에도 개장 전 분기는 없었다. 세션 상태를 거래일로 바꾸는 공용 함수가 `pre`만 오늘로, 나머지 개장 전은 전일로 돌려주고, 지수 route는 그 날짜로 DB와 KIS를 조회할 뿐이었다. `pre`가 오늘인 건 종목 쪽 NXT 프리마켓 봉 때문이고 지수에는 그 시간대 데이터가 없으니, 지수에서만 가운데 50분이 빈 구간이 된 것이다. #102에서 "개장 전엔 전일 차트"로 두었던 것이 그 뒤 프리마켓 세션이 끼면서 지수에선 세 토막이 난 걸로 보인다.

## 빈 차트와 "개장 전"

공용 함수는 종목이 쓰니 건드릴 수 없고, 지수 쪽에서 개장 전을 어떻게 보일지만 정하면 됐다.

| 후보 | 판정 |
|---|---|
| 06:00~09:00 전 구간 전일 봉 | 기각. 헤더가 "장 마감 · 기준일"이라 정합은 맞지만, 개장을 기다리는 화면에 차트가 이미 그려져 있음 |
| **06:00~09:00 전 구간 빈 차트 + "개장 전"** | **채택.** 등락률을 0으로 초기화하는 것과 같은 취급. HTS도 개장 전 당일 차트는 비어 있음 |

구현은 지수 조회 함수에서 `pre`·`preopen`이면 DB·KIS를 부르지 않고 빈 배열을 돌려주는 것으로 시작했다. 양쪽 실패의 null과는 구분해서, 클라에서 실패 문구가 뜨지 않게 했다. 클라가 개장 전을 아는 방법은 분봉 응답을 늘리지 않고, 지수 quote 응답에 이미 있는 세션 값을 기존 판정 헬퍼에 넣는 것으로 했다. 지수 상세 차트가 개장 전 today-bar 병합을 막을 때 쓰던 것과 같은 경로다.

```
헤더  : 실시간 · HH:MM  →  개장 전 · 기준일 MM-DD  →  장 마감 · 기준일 MM-DD
셀    : 차트를 불러오지 못했어요  /  개장 전  /  장중 데이터 없음
```

테스트는 붙이지 않았다. 조회 함수가 개장 전에 fetch를 안 한다는 걸 검증하려면 DB와 캘린더를 mock해야 하는데 repo에 그 선례가 없고, fix 하나 때문에 mock 인프라를 들이는 건 크기가 안 맞았다. 판정 헬퍼는 기존 테스트가 세션 전부를 덮고 있고, 나머지는 내일 08:00~09:00 창에서 본다.

한 가지는 열어뒀다. 09:00 각성 뒤 09:04까지 "장중 데이터 없음"이 유지되는 빈 구간인데, 이건 개장 전 표시와 무관한 별개 현상이다.

| 후보 | 확인 방법 |
|---|---|
| 각성 전 마지막 요청 시각에 따른 폴링 간격 | 요청 시각 기록 |
| 09:00 첫 빈 응답이 regular 캐시 TTL 동안 고정 | 응답의 봉 수 추이 |
| KIS 지수 1분 봉의 첫 봉 발행 지연 | 서버 로그의 첫 봉 시각 |

"KIS는 지연이 거의 없을 것"이라고 생각했는데 그것도 실측한 적이 없는 가정이었다. 내일 같은 창에서 요청 서너 건만 기록하면 셋 중 어느 쪽인지 갈린다.

## 정리

- **F71 종결** — 08:50 열어둔 탭이 09:01에 리로드 없이 각성, 주기 120초 → 60초 전환 확인
- **E65 백로그** — CDN 캐시 근거는 성립하나 체감이 좌측 전량 로드 1회뿐, 기능 영향 0
- **X13·X4 드롭** — 9지표 중 4개는 DART 중복(BPS 12% 불일치), 3개는 파생 가능, 순증분은 유보율 1행
- **성장률 3행** — DART 실적에서 전년 대비 파생, 슬레이트 20행. 매출·영업이익 증가율은 KIS 값과 소수 둘째 자리까지 일치
- **F79** — 세션→거래일 매핑 부작용으로 개장 전 화면이 세 토막. 지수만 빈 차트 + "개장 전"으로, 실증은 내일

KIS를 붙이려고 시작한 세션이 KIS를 안 붙이는 것으로 끝났는데, 파생값이 KIS 공식값과 자리수까지 맞는 걸 보고 나니 그게 맞는 방향이었다는 확신이 좀 든다. F79는 #102 결정을 지수에 그대로 물려받았다고 생각하고 있었던 게 문제였고, 실측 창에 앉아 있지 않았으면 계속 몰랐을 종류다.
