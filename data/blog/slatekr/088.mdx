## 다크모드 도입 결정

트리아지에서 다크 모드를 뺐던 근거는 단순하다. 라이트 모드로 기능이 멀쩡하고, 마무리 단계에 새 작업을 크게 벌일 이유가 약하다는 거였다. 다크 모드는 배경색 몇 개 바꾸는 일이 아니라 5색 시스템 전체를 어두운 바탕에서 다시 잡아야 하는 일이라, 비용이 제법 든다고 판단했다.

그런데 결정을 번복하고, 작업 전 실제 비용을 코드로 확인해보니 예상과 달랐다. 확인할 게 세 가지였다.

| 확인 항목 | 예상 | 실제 |
| --- | --- | --- |
| ThemeProvider 배선 | 필요 | 이미 마운트됨 (next-themes, 토글 UI만 없음) |
| 차트 다크 대응 | 컴포넌트마다 배선 필요 | 이미 `useTheme` + 라이트/다크 팔레트 분기 완료 |
| 커스텀 토큰 다크값 | 일부 | 41개 전부 없음 |

내가 비용의 절반으로 잡았던 차트 쪽이 이미 되어 있었다. 캔들의 빨강/파랑은 증권 서비스에선 다크에서도 안 바꾸는 게 관행이라 그대로 두면 되고, 배경·격자·축 텍스트를 테마별로 넘기는 배선도 이전 차트 작업 때 이미 깔려 있었다. 남은 실작업은 **커스텀 토큰 41개에 다크값을 채우는 것 하나로 좁혀졌다.** additive하고 되돌리기 쉬운 작업이라 리스크도 낮았다. 그래서 함으로 돌렸다.

엄밀히는 "비용이 작다"기보다 이미 깔려 있던 배선 덕에 남은 작업만 작았던 거지만, 어느 쪽이든 판단을 바꾸기엔 충분했다.

## shadcn 브리지 — raw 재선언을 지우다

토큰 구조를 보자 핵심이 하나 잡혔다. 이 프로젝트는 shadcn 토큰이 SlateKR 커스텀 토큰을 참조하도록 `:root`에서 연결해둔 상태다.

```css
:root {
  --background: var(--bg-base);      /* shadcn이 SlateKR을 가리킴 */
  --foreground: var(--text-primary);
}
```

그런데 `.dark` 블록은 이 연결을 무시하고 raw 값을 다시 박고 있었다.

```css
.dark {
  --background: oklch(0.09 0 0);     /* 브리지를 덮어쓴 raw 값 */
}
```

다크 모드가 없던 시절의 흔적이다. `--bg-base`에 다크값이 없으니, `--background`를 어둡게 만들려면 raw로 우회하는 수밖에 없었던 거다.

여기서 CSS 변수의 성질 하나가 열쇠였다. 커스텀 프로퍼티는 **쓰는 시점에 그 자리에서 해석된다.** 즉 `.dark`가 `--bg-base`에 다크값을 주기만 하면, `--background: var(--bg-base)`를 다시 선언하지 않아도 `var()`가 알아서 다크값을 물어온다. raw 재선언은 재작성 대상이 아니라 **삭제 대상**이었다.

- `.dark`에 커스텀 41개 다크값을 채운다.
- `:root`에서 `var()`로 브리지된 shadcn 토큰의 `.dark` raw 선언은 지운다 (`--background`·`--foreground`·`--card`·`--border` 등 12개).
- SlateKR 대응이 없는 shadcn 토큰만 raw로 남긴다 (`--primary`·`--ring`·차트·사이드바 계열).

결과적으로 배경 계열 값이 SlateKR 토큰 한 곳으로 모였다. 재작성이 아니라 삭제라 손도 덜 갔다.

## 덤으로 닫힌 F8

이 정리에 [#041](링크)에서 남겨둔 문제 하나가 딸려 풀렸다. 그때 `text-primary` 클래스가 shadcn `--primary`가 아니라 SlateKR `--text-primary`를 가리키도록 `@layer utilities`에 raw로 override를 박아뒀는데, 문제는 `--text-primary`에 다크값이 없다는 거였다. 다크로 넘어가면 shadcn 쪽은 밝은 회색으로 뒤집히는데 `.text-primary`를 쓰는 텍스트만 어두운 네이비로 남아, 어두운 배경에 어두운 글씨가 되는 구조였다. 로드맵에 F8로 적어둔 잠재 충돌이 이거다.

별도 작업이 필요할 줄 알았는데, 41개 토큰을 저작하는 데 `--text-primary`가 포함돼 있어 다크값을 채우는 것만으로 저절로 닫혔다. `@layer utilities` override는 그대로 두고, 가리키는 토큰에 다크값만 생긴 셈이다.

## 5색 다크값 — 미묘한 채도

가장 손이 많이 간 건 5색 팔레트의 배경 tint였다. 라이트에서 각 색의 배경은 따뜻한 오프화이트 위에 얹힌 옅은 색이다. 이 값을 어두운 바탕으로 그대로 옮기면 관계가 뒤집힌다 — 옅은 tint가 어두운 배경 위에선 오히려 밝게 떠버린다. 명도만 내리는 식으론 안 되고 값을 다시 잡아야 했다.

몇 번 헤맸다. 채도를 과하게 낮췄더니 색이 빠져서 배경이 비치는 반투명 회색막처럼 보였고, 그렇다고 라이트 값을 그대로 어둡게만 누르면 탁한 흙색이 됐다. 결국 **명도는 어두운 base보다 한 단계 위로 올리되 채도는 유지하는** 쪽으로 정리됐다. 어두운 바탕일수록 배경에 색이 분명히 남아야 패널이 색으로 읽힌다.

두 색은 개별 조정이 필요했다.

- **amber(핵심 지표)** — 헤더가 하락(파랑) 종목일 때 바로 아래 큰 패널이 주황이라 온도 충돌이 심했다. 채도를 조금 낮춰 톤을 눌렀다.
- **lavender(차트)** — hue 특성상 어두운 배경에서 같은 채도라도 다른 색보다 가라앉아 보여, 소폭 올려 다른 패널과 강도를 맞췄다.

나머지 등락 색은 hue를 고정하고 명도만 올렸다. 상승/하락 색은 의미가 고정된 신호라 다크에서도 색상 자체가 흔들리면 안 된다.

## 테마 토글 버튼

계속 개발자 도구로 `.dark` 클래스를 붙였다 뗐다 하기 번거로워, 헤더에 토글을 먼저 넣었다. 어차피 다크 모드에 필요한 컴포넌트이기도 했다.

한 가지 짚은 건 hydration이다. 서버는 현재 테마를 모르는데 클라이언트는 아니까, 마운트 전에 테마 기반 아이콘을 그리면 서버/클라이언트 마크업이 어긋난다. 마운트 가드로 막았는데, 이 프로젝트는 이미 `useSyncExternalStore`로 같은 처리를 하는 컴포넌트(관심종목 프리뷰)가 있어 그 패턴을 그대로 가져왔다. 미마운트 구간엔 같은 크기의 빈 버튼을 두어 레이아웃이 흔들리지 않게 했다. Navbar는 서버 컴포넌트로 두고 토글만 클라이언트로 분리했다.

## 자잘한 정리

다크값을 훑다가 눈에 걸린 것들을 함께 손봤다. 과정보다 결론만 적는다.

- **차트 슬레이트에 lavender 확산** — 차트 탭 본체엔 lavender가 적용돼 있는데 종합정보 탭 미니차트와 지수 차트 페이지는 무채색으로 빠져 있었다. 알고 보니 패널 래퍼가 이미 `variant="lavender"`를 지원하는데 호출부에서 안 넘기고 있던 거라, prop 하나씩 넘겨 맞췄다. 새 패턴을 만들 일이 아니었다.
- **툴팁 다크 배경** — 툴팁이 shadcn `--primary`를 배경으로 써서 다크에선 흰 배경으로 뒤집혔다. `--primary` 자체를 건드리면 버튼까지 다 바뀌니, 툴팁 컴포넌트에서만 다크 배경(배경보다 한 단계 밝은 어두운 회색)을 덮었다. 소스가 한 곳이라 세 군데 툴팁에 전부 반영됐다.
- **공시 필터 비활성 칩** — 비활성 칩 배경이 투명이라 슬레이트 배경과 구분이 안 됐다. 활성·호버와 단계가 지도록, 호버보다 옅은 값을 줘서 라이트에선 살짝 진하게·다크에선 살짝 밝게 읽히게 했다.
- **군더더기 제거** — 홈 시장 순위 슬레이트의 세션 라벨(실시간/장 마감 등)은 바로 위 지수에서 이미 기준 시각을 주고 있어 중복이라 뺐고, 종합정보 탭에 떠 있던 AI 요약 힌트도 위치가 애매해 제거했다. AI 홍보는 홈에서 이미 하고 있고, 공시에 관심이 있으면 공시 탭을 눌러볼 테니 거기서 다시 살릴 계획이다.

## 정리

- **다크 모드 도입** — 트리아지의 "안 함"을 뒤집었다. probe로 차트 배선과 ThemeProvider가 이미 되어 있음을 확인해, 남은 작업이 커스텀 토큰 저작 하나로 좁혀진 게 근거였다.
- **shadcn 브리지** — `.dark`의 raw 재선언을 지우고 `:root`의 `var()` 브리지가 다크값을 물어오게 했다. 배경 계열이 SlateKR 토큰 한 곳으로 통일됐다.
- **F8 해소** — 다크값 저작에 `--text-primary`가 포함돼, #041에서 남긴 shadcn 충돌이 별도 작업 없이 닫혔다.
- **5색 다크값** — 배경 tint는 명도를 올리고 채도를 유지하는 쪽으로. amber·lavender만 개별 조정하고 등락 색은 hue를 고정했다.
- **토글 + 자잘한 UI 정리** — 헤더 토글, 차트 lavender 확산, 툴팁·필터 칩 다크 대응, 군더더기 제거.

배경 몇 개 바꾸는 일로 시작할 뻔했는데, 실제로 무게가 실린 건 shadcn과 커스텀 토큰이 다크에서 어떻게 연결되는지였다. #041에서 한 층 들여다봤던 토큰 레이어를, 이번엔 라이트/다크 두 모드가 한 토큰을 공유하는 구조로 다시 본 셈이다.

## 다음 작업

이번에 C5·F8·F9가 다크 모드 도입으로 정리되면서, 미뤄둔 로드맵 트리아지를 마무리하고 Phase 4로 넘길 차례다.

- **로드맵 트리아지 확정** — 판단 필요로 남은 항목(use cache 마이그레이션, 가격 쿼리 통합, 검색 페이지네이션 방식 등)을 정하고, 출시 후로 미룰 것과 삭제할 것을 갈라 Phase를 넘긴다.
- **H6 — 거래량 섹션 구분** — 종합정보 차트의 거래량 범례 라벨이 깨져 있고, 가격/거래량 사이 구분선이 없다. 한 캔버스 안에서 두 영역을 시각적으로 나누는 작업이다.
- **데이터 안정성 점검** — 지표 기준 표기, 단위 의심 데이터, bigint 산술 경로 등을 한 번에 훑는다.

구현은 거의 닫혔고, 남은 건 로드맵을 접고 제출물을 다듬는 결이다.
