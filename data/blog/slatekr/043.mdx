[#042](https://velog.io/@dh82680/SlateKR-042-Parallel-Routes-적용)에서 Parallel Routes 본 적용을 끝내며 두 개편안을 같이 적어뒀다. 종합정보 탭 2×2 그리드와 공시 탭 인라인 확장. 이번 세션은 그중 첫 번째다.

분량을 보고 둘을 한 세션에 묶지 않기로 했다. 공시 인라인 확장은 `SummarySlate` 폐기와 상태 관리 재설계가 같이 들어가서 같이 하기엔 볼륨이 크다고 판단했다.

## 종합 정보의 4번째 칸

종합 정보 탭은 첫 화면이고, 이름 그대로 종합 정보인 만큼 다양한 정보를 함축적으로 제공해야 한다고 생각했다. 그래서 다른 탭의 요약 버전으로 약식 차트, 재무, 공시를 각 1칸씩 할당했다. 그런데 아직 마지막 1칸이 정해지지 않은 상태였다.

빈 칸에 넣을 대상으로 처음 떠올린 건 **외국인·기관 수급**이었다. 종목 수급 파악에 꽤나 중요한 지표이면서, 한 칸으로 최근 며칠 정도 정리해두면 좋을 것 같다고 생각했다.

하지만 이건 금새 후보에서 제외할 수밖에 없었다. 역시 문제는 데이터 확보. 크롤링도 생각해봤지만, 이전에도 얘기했듯 약관상 회색지대라 깔끔하게 포기했다.

### 52주 레인지와 기간 수익률

결과적으로 이미 확보한 데이터를 가공하는 방법을 고려했고, 결정된 게 이거다. OHLCV 한 가지에서 뽑을 수 있는 두 지표를 한 칸에 묶어 넣기로 했다.

- **52주 레인지** — 고/저 + 현재가 위치 바
- **기간 수익률** — 1M / 3M / 1Y

시각(바)과 수치(% 텍스트)가 성격이 안 겹치고, 약식 차트가 "모양"이라면 이쪽은 "위치와 변동"이라 보완적이었다.

## lib 함수 추가

`lib/prices.ts`에 두 가지가 추가됐다.

```ts
// 1년치를 날짜 기준으로 받는 쿼리
const getPricesForStats = (ticker: string) => { ... }

// 받은 배열로 52주 레인지 + 1M/3M/1Y 수익률 계산
const getPriceStats = (prices: DailyPrice[]): PriceStats => { ... }
```

### 왜 개수가 아니라 날짜 기준인가

기존 `getDailyPrices(ticker, limit)`는 개수 기준이라 휴장일·신규상장으로 범위가 흔들린다. 1년이 정확히 252거래일이 아니다 보니 "1년치"가 살짝 부정확해진다.

```sql
WHERE date >= CURRENT_DATE - INTERVAL '1 year' AND ticker = $1
ORDER BY date ASC
```

가져온 배열의 첫 행이 곧 1년 기준점이 된다. 1M/3M도 같은 방식으로 각 기간 시작일 이후 첫 거래일 종가를 기준점으로 잡고, 데이터가 부족하면 해당 기간은 null.

### 도메인 타입

```ts
type PriceStats = {
  range52w: {
    high: number;
    low: number;
    current: number;
    position: number;  // 0~1
  } | null;
  returns: { period: "1M" | "3M" | "1Y"; value: number | null }[];
};
```

`position`은 52주 최저~최고 사이 현재가의 위치다. UI에서 바 위에 마커를 찍을 때 그대로 쓴다. high와 low가 같으면 0 나눗셈이 되는 케이스만 0으로 막아뒀다.

파생 지표 계산은 lib 안에서. 이번에도 그동안 지켜오던 정규화 레이어 책임 그대로다.

## 디자인을 같이 손보지 않은 이유

구조 위주로 작업하다 보니 디자인적으로 고쳐야 할 부분이 여러 곳 보였다. 다만 이번엔 구조까지만. 헤더 톤, 차트 라벨, 인터랙션 범위, 칸 사이 정렬 같은 건 종합정보 4칸을 한 번에 보면서 손보는 게 자연스럽다. 다음 공시 개편 이후로 디자인 트랙 세션을 따로 잡았다.

당장 눈에 띈 것들만 정리해두면:

**칸 헤더 톤 불일치**

| 칸 | 헤더 |
|---|---|
| 약식 차트 | `005930 — 최근 3개월` (종목코드) |
| 재무 요약 | 작은 폰트, 토글 버튼 함께 |
| 공시 미리보기 | `최근 공시 (최근 3개월)` |
| 가격 통계 | `가격 통계` |

2×2로 묶었지만 내부 스타일에 차이가 있어 4칸이 같은 패널로 안 읽힌다.

**약식 차트 미리보기 정식화**

라벨이 종목코드 기반이라 차트 탭 풀 차트용 느낌이 그대로 남아있다. 줌·팬 인터랙션도 살아있는데 미리보기 맥락엔 과하다. 호버 시 십자선·날짜 표시만 남기는 쪽이 적절해 보인다.

**행 높이 정렬**

차트 칸과 재무 칸 사이 높이 차이가 보인다. 그리드 한 행 높이가 차트(고정 높이)에 맞춰지면서 재무 칸 하단에 공백이 남는 형태다. 재무 표와 헤더 간격을 늘려 채우거나 차트 height를 줄여 맞추는 방향으로 풀린다.

이번 세션에서 막아둔 건 칸이 칸을 넘치는 문제뿐이다. 재무·공시 미리보기의 폰트·패딩을 줄였고, 공시 카테고리 배지가 좁은 칸에서 줄바뀜이 일어나는 걸 `whitespace-nowrap`으로 한 줄 유지하게 했다. 배지는 정의상 한 줄짜리 라벨이라 컴포넌트 자체에 박는 게 맞았다.

## 정리

![종합정보 탭 2×2 그리드](/static/images/velog/7c93c757-7634-4288-91b3-2ad48bbd970b-image.png)

종합정보 탭이 약식 차트 / 재무 요약 / 공시 미리보기 / 가격 통계 네 칸으로 묶였다.
각 칸 우상단의 "전체 보기 →"로 해당 탭으로 넘어가고, 가격 통계만 별도 탭이 없어 버튼이 없다.

비활성 슬롯 상태 보존이 본격적으로 활용되려면 공시 인라인 확장과 차트 탭 토글이
들어와야 한다. 이번엔 그 무대가 깔린 셈이다.

디자인적으로는 공시 슬레이트 개편 작업 이후 한 번에 작업한다.
