시장 순위는 #079에서 홈 슬레이트로, #080에서 필터 페이지로 만들면서 카테고리를 등락률·거래량 둘로 두고 끝냈다. 그때 이격도·거래증가율 같은 추가 카테고리는 파라미터를 다시 실측해야 해서 미뤘고, #125 스코프 정리에서 그 둘은 빼고 시가총액 상위와 관심종목등록 상위 두 종으로 확정해 두었다. 시총은 TR이 확인돼 있었고, 관심종목등록은 TR 자체를 아직 안 본 상태였다.

계획은 두 종을 데이터 층에 붙이고 탭 두 개를 더하는 것이었다. 실제로는 탭을 두 개 더하는 대신 우측에 있던 토글까지 걷어내고 카테고리를 여섯 탭으로 펼치는 재구성이 됐다. 데이터 층 커밋 하나, UI 커밋 둘로 끝났다.

---

## 명세에 없던 필수 파라미터

관심종목등록 상위는 한 콜씩 두 번 받았다. 전체 시장으로 한 번, 코스닥 필터로 한 번이다.

| 확인 항목 | 결과 |
|---|---|
| 응답 구조 | 단일 배열 30행, 연속 페이지 없음 |
| 순위 근거 필드 | 등록 계좌 수로 보이는 정수 (삼성전자 14,644,928 · SK하이닉스 11,782,842), 내림차순 정합 |
| 기존 거래량 매퍼가 쓰는 9필드 | 전부 존재 |
| 시장 필터 | 코스닥 지정 시 30행 모두 코스닥, 누출 0건 |
| 명세 외 파라미터 | 고정값 하나가 필수. 공식 예제 코드에만 있고 명세 문서엔 없음 |

마지막 줄이 실측을 고집한 이유다. 명세 엑셀을 열어 볼 수도 있었는데, #079에서 행 개수라고 생각했던 파라미터가 조건 필드였던 일이 있어서 문서보다 응답을 먼저 보기로 했다. 시총 쪽도 "확인됨"이라고 적어두긴 했지만 캡처 파일이 남아 있지 않아 한 콜 더 받았고, 시가총액이 억 원 단위 문자열로 온다는 것과 티커 필드명이 거래량 응답과는 같고 등락률 응답과는 다르다는 것을 거기서 확인했다.

값을 어디에 둘지는 짧게 갈렸다.

| 후보 | 판정 |
|---|---|
| **카테고리 전용 필드 둘 (시가총액·등록 수)** | **채택.** 카테고리별 포맷이 자연스럽고 타입이 값을 그대로 말함 |
| 공통 `metricValue` 하나 + 카테고리별 라벨 | 기각. 지금 필요 없는 추상화 |

처음엔 두 필드를 `null` 허용으로 잡았다가, 기존 거래량·거래대금 필드가 optional인 걸 보고 커밋 전에 맞췄다. 엄밀히는 어느 쪽이 낫다기보다 한 타입 안에 두 관례가 섞이는 게 싫었던 쪽에 가깝다.

## 정렬 토글이 아니라 탭인 이유

홈에서도 여섯 카테고리를 다 보고 싶어서 UI를 손보기로 했는데, 여기서 처음 떠올린 안은 우측 토글을 정렬 방향 토글로 바꾸는 것이었다. 지금은 등락률 탭에서 상승/하락, 거래량 탭에서 거래량/거래대금을 고르는 토글인데, 이걸 카테고리 공통의 오름차순/내림차순 버튼으로 일반화하면 탭 수를 안 늘리고도 정보가 늘 것 같았다.

이 안은 접었다. KIS 순위는 상위 30건을 고정으로 내려주는 TR이라, "오름차순"은 시장 하위 30개가 아니라 **같은 30개를 30위부터 보여주는 것**일 뿐이다. 시총 탭에서 오름차순을 누르면 화면은 시총 하위 순위처럼 보이는데 실제로는 30위 대형주가 맨 위에 오는 셈이라, 무의미한 걸 넘어 오독을 만든다.

그리고 지금의 상승/하락 토글은 정렬 방향이 아니었다. 상승률 상위와 하락률 상위는 서로 다른 조회이고 결과 집합도 다르다. 정렬 토글로 일반화하면 그 차이가 지워진다.

| 후보 | 판정 |
|---|---|
| 우측 토글을 오름/내림 정렬로 일반화 | 기각. 상위 30건 고정 응답에서 방향 반전은 정보가 아니고, 상승/하락의 조회 차이가 사라짐 |
| **상승·하락·거래량·거래대금을 각각 독립 탭으로 승격, 토글 제거** | **채택.** 카테고리 축이 하나가 되고, 토글이 쓰던 폭이 탭으로 돌아옴. HTS 메뉴 구조와 같음 |

```
전:  [등락률 | 거래량]              (상승 | 하락) 또는 (거래량 | 거래대금)
후:  [상승 | 하락 | 거래량 | 거래대금 | 시총 상위 | 관심 등록 상위]
```

## 여섯 탭을 한 줄에

탭이 여섯이면 폰 폭에서 넘친다. 커밋 순서를 먼저 정했다. 탭을 여섯으로 늘린 뒤 스크롤을 붙이면 중간 커밋이 넘친 상태로 남으니, 현행 두 탭에 스크롤 스트립을 먼저 씌우고 그다음 탭을 채웠다.

스트립은 네이티브 가로 스크롤에 양끝 fade를 얹고, 좌우에 chevron 버튼을 둔 형태다. 폰트는 role 토큰에서 한 단계 내렸다. 화살표를 언제 보일지는 한 번 바꿨다.

| | 처음 | 수정 |
|---|---|---|
| 표시 기준 | `md` 이상에서만 렌더 | 스크롤 폭이 보이는 폭보다 클 때만 렌더 |
| 데스크톱 `/ranking` | 폭이 남는데 비활성 화살표가 보임 | 미표시 |
| 모바일 | 넘치는데 화살표 없음 | 표시, 끝단은 비활성 |

브레이크포인트로 나누니 정작 넘치는 쪽엔 화살표가 없고 안 넘치는 쪽엔 있는 역전이 생겼다. 판정을 화면 폭이 아니라 overflow 여부로 옮기니 홈과 페이지 어느 쪽이든 필요할 때만 나온다. 리사이즈 순간 화살표 폭만큼 탭이 밀리는 건 감수했다. 화살표가 탭 밑줄 여백 때문에 텍스트보다 아래로 내려가 보이던 것도 같이 잡았다.

## 탭 정의를 한 곳에

탭이 여섯이 되면서 홈 슬레이트, `/ranking`, 홈에서 페이지로 넘기는 링크, URL 파싱 네 곳이 같은 표를 봐야 했다. 스트립을 만들 때 링크 생성 함수가 탭·방향·거래량 기준·시장 네 인자를 받고 있었는데, 시총과 관심종목엔 방향도 기준도 없어서 이 시그니처는 늘릴수록 어색해졌다.

```ts
const RANKING_TABS = [
  { id: "up",           label: "상승",        ... fluctuation + 상승 },
  { id: "down",         label: "하락",        ... fluctuation + 하락 },
  { id: "volume",       label: "거래량",       ... volume + 거래량 },
  { id: "trade-value",  label: "거래대금",      ... volume + 거래대금 },
  { id: "market-cap",   label: "시총 상위",     ... market-cap },
  { id: "top-interest", label: "관심 등록 상위", ... top-interest },
] as const;
```

탭 id 하나가 조회 조건 조합을 대신하고, 네 곳은 이 배열만 본다. URL도 `?tab=&market=`으로 줄였다. #080에서 정한 "로컬 state가 소스, URL은 따라감" 구조는 그대로고, 옛 방향·기준 파라미터는 하위 호환 없이 버렸다. 공개 링크가 돌아다니기 전이라 매핑을 남길 이유가 없었다. 데이터 층에서 `fluctuation ? … : …`로 갈리던 자리는 kind 나열식으로 바꿔 새 kind가 빠지면 tsc가 잡게 했다.

카테고리마다 우측 값 열은 등락률·거래량·거래대금·시가총액·등록 수로 갈리고, `/ranking` 하단에 "KRX 기준 집계 · 관심종목은 KIS 고객 등록 수 기준" 한 줄을 뒀다. 우리 관심종목 기능과 이름이 겹쳐서 출처는 적어야 했다.

## 홈 640~768 구간의 여백

![](/static/images/velog/6a6885e9-5fcb-4b4f-b83b-9270c75ca9dd-image.png)

홈 슬레이트가 관심종목과 위아래로 쌓이는 640~768px 구간에서 종목명과 가격 사이가 꽤 비어 보였다. 종목명 칸을 여덟 글자 폭으로 고정하고 숫자를 왼쪽에 붙일까 생각했는데, 그렇게 하면 여백이 가운데에서 오른쪽 끝으로 옮겨갈 뿐이고 종목명 길이 편차는 고정폭 안에서도 남는다. 이름은 왼쪽, 숫자는 오른쪽에 붙는 리스트에서 가운데 여백은 숫자 열을 세로로 맞추는 자리라 죽은 공간이 아니라고 보고 그대로 뒀다. 채운다면 기준값을 가운데 열로 노출하는 방향뿐인데, 상승·하락 탭은 기준값이 이미 우측에 있어 지금 넣을 이유가 없었다.

## 정리

- **카테고리 두 종** — 관심종목등록 상위는 실측으로 명세 외 필수 파라미터를 잡음. 시총도 캡처가 없어 한 콜 추가
- **값 열** — 카테고리 전용 optional 필드 둘. 공통 metric 추상화는 기각
- **정렬 토글 기각** — 상위 30건 고정 응답에서 방향 반전은 오독만 만듦. 상승·하락·거래량·거래대금을 독립 탭으로 승격, 우측 토글 제거
- **탭 스트립** — 스트립 먼저, 탭 채우기 나중. 화살표는 브레이크포인트가 아니라 overflow 기준
- **탭 정의 단일 소스** — 배열 하나가 조회 조건·라벨·URL을 대표, 네 소비처 통일

두 탭 더하려던 작업이 nav 재구성으로 끝났는데, 정렬 토글을 접는 판단이 없었으면 탭 넷에 토글 셋이 얽힌 화면이 됐을 것 같다. #080에서 "카테고리는 화면이 먼저 서 있어야 뭘 얹을지 보인다"고 미뤄뒀던 게 여기서 맞아떨어진 셈이다.
