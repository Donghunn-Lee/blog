어제 8시대 실측에서 관심목록이 개장 전에도 전일 등락을 보이던 결함을 고치고 나서, 그 창에서만 볼 수 있는 확인 세 건을 오늘 아침으로 넘겨뒀었다. 08:00~08:50에 비NXT 종목의 관심목록 등락이 0인지, NXT 종목 상세의 기본 탭이 어느 쪽인지, 그리고 봉 수로 바꾼 인트라데이 초기 창의 우측 여백이 실물에서 어떻게 보이는지다. 관측할 때마다 항목이 두세 개씩 늘어 활성이 줄지 않던 터라, 실측 뒤에는 로드맵을 유저플로우 기준으로 다시 자르는 세션을 따로 잡아뒀었다.

계획은 실측 → 재트리아지 세션이었다. 실제로는 실측이 판정을 기다리던 항목을 전부 닫아서 트리아지는 한 번의 정리로 끝났고, 그 자리에서 남은 소형 항목 구현으로 넘어갔다. 커밋 여섯이고, 그중 하나는 잡아뒀던 것과 다른 문제를 고친 것이다.

## 8시대 실측과 로드맵 정리

| 항목 | 관측 | 판정 |
|---|---|---|
| 비NXT 관심목록 등락 (08:00~08:50) | 홈 위젯·관심종목·검색 결과 모두 0 | 어제 리셋 규칙이 이 창도 덮음. 개장 전 route 분기 누락으로 적어둔 구조 리스크(F67)는 승격 불요 |
| NXT 종목 기본 탭 | NXT, KRX 탭은 등락 0 | 리스트의 통합 시세 값과 진입 후 값이 같음. 보류해둔 값 축 판정 항목(E81) 삭제 |
| 초기 창 우측 여백 | 1·5·15분 모두 자연스러움 | 상수 30/10 유지 |
| 09:00 첫 봉 유입 | 창 급수축 없이 1슬롯 이동 | 통과 |
| 리스트 등락 | 09:00 넘기며 0 → 실등락 | 통과 |
| 해외 지수 마감 라벨 | `장 마감 · 05:00` | 통과 |

판정이 갈리는 항목이 없으니 별도 세션이 필요 없었다. 어제 정한 기준(정보가 틀리게 읽힘 → 설명 부재 → 소형 결함 → probe 1회 → 더 잘 보여주고 싶음)을 그대로 대면 종목 일봉 payload 판단·배당 이력·종목 전일 봉 전체 서빙 셋이 마지막 등급이라 백로그로 내렸고, 남은 활성은 설명 한 줄짜리 둘과 1커밋짜리 하나였다. 관측 세션을 시작한 이후 처음으로 로드맵이 줄었다.

## legend에 남아 있던 거래량 0

#116에서 거래량을 제공하지 않는 S&P 500·나스닥 100의 거래량 pane을 뺐는데, 차트 legend의 `거` 필드는 그대로 0을 찍고 있었다(F87). 캔들에 마우스를 올리면 거래량 시리즈와 join된 값이라 자연히 비는데, 미호버 상태의 최신봉과 라인 hover 경로는 봉 원본의 volume 0을 그대로 읽고 있었다. 게이트를 어디에 두느냐만 정하면 되는 작업이라, legend에서 거래량 미제공 지수 목록을 다시 참조하는 대신 pane을 켜고 끄는 데 이미 쓰는 prop 하나로 legend도 같이 끄게 했다. 그 prop이 "미제공 목록에 없음 AND 해외 인트라데이 뷰가 아님"을 이미 합성한 값이라 pane과 legend가 서로 어긋날 길이 없다.

## DJI 분봉 미제공 고지를 어디에 둘 것인가

다우존스는 KIS가 장중 시세와 분봉을 주지 않아 #107에서 일봉만 표시하기로 종결했었다. 그 결과 지수 상세에 당일/전체 토글 자체가 없는데, 왜 없는지 설명이 어디에도 없는 상태였다(E77). 처음엔 /credits 페이지의 데이터 출처 섹션에 한 줄 넣는 것으로 커밋했다. 커밋하고 화면을 다시 보니 사용자가 혼란을 느끼는 순간은 US 장중에 S&P 500은 라이브로 움직이는데 다우는 전일 종가에 흐리게 멈춰 있을 때이고, 그때 /credits를 열어볼 사람은 없다. /credits 한 줄은 제공 범위 고지라 그대로 두고, 혼란이 생기는 자리인 DJI 차트 하단에 같은 내용의 캡션을 붙였다.

## 차트 하단 캡션 둘

마침 NXT 종목 차트에도 같은 모양의 캡션이 필요했다. 프리마켓 → 정규장 → 애프터마켓을 한 시간축에 잇는 통합 차트는 HTS 관례라 형태는 유지하되, 축을 읽을 수단이 배지뿐이라 하단에 `08:00–08:50 NXT 프리마켓 · 09:00–15:30 KRX · 15:30–20:00 NXT 애프터마켓` 한 줄을 두기로 했던 항목이다(E80). 소비처가 둘이라 공용 컴포넌트는 만들지 않고 기존 하단 주석 타이포 role을 공유하는 문단 하나씩으로 뒀다. 일봉 뷰에는 세션 축이 없으니 인트라데이 뷰에서만 보이고, NXT 여부를 어느 축에서 읽을지는 골라야 했다.

| 후보 | 판정 |
|---|---|
| 분봉 응답에서 파생한 확장 세션 플래그 | 기각. 폴링 뒤 비동기로 확정돼 캡션이 나중에 끼어들며 차트가 밀림 |
| **SSR로 받는 NXT 가능 여부 prop** | **채택.** 헤더 KRX/NXT 토글과 같은 소스. 첫 렌더에 확정돼 레이아웃 점프 없음 |

세션 시각은 15:30으로 뒀다. 코드의 세션 테이블이 그 값이고 툴팁·헤더 라벨도 전부 같은 축인데, NXT 애프터 첫 체결은 15:40이라는 실측 주석이 남아 있어 잠깐 망설였다. 캡션은 제도 시간이지 첫 체결 시각이 아니고, 캡션만 15:40이면 화면에 두 축이 생긴다.

## 탭 복귀 refetch의 실체

다른 탭에 갔다 돌아오면 분봉이 다음 폴링까지 멈춰 보이는 문제를 "hidden 중 폴링 정지 → 복귀 후 다음 tick 대기"로 이해하고, 복귀 시 즉시 refetch 하나 넣는 1커밋으로 잡아뒀었다(E76). probe를 돌리니 그 전제가 틀렸다. 훅 셋 모두 TanStack Query라 창 포커스 복귀 refetch가 기본값으로 이미 돌고 있었고, 종목 상세는 복귀 순간 요청이 나가 봉이 바로 채워졌다.

| | 종목 분봉 | 지수 분봉 |
|---|---|---|
| route 서버 캐시 | 없음, KIS 직행 | `unstable_cache` 60s/120s |
| 복귀 첫 응답 | 최신 봉 | 캐시에 있던 오래된 항목 |
| 신선해지는 시점 | 즉시 | 다음 tick |

지수만 멈춰 보이던 이유는 Next 데이터 캐시의 stale-while-revalidate(SWR)였다. TTL이 지난 뒤 첫 요청은 저장돼 있던 항목을 그대로 돌려주고 재검증만 뒤에서 시작하니, 탭이 10분 숨어 있었으면 복귀 직후엔 10분 전 봉이 나온다(실제로 12:23 로드에 12:13 값). 헤더 현재가가 먼저 갱신되는 건 그 훅만 raw interval이라 hidden 중에도 폴링을 계속해서였다. 종목은 반대로 캐시가 없어 복귀 때마다 KIS를 부르는데, 그게 마감 후에도 나가고 있었다. 이쪽은 복귀 refetch를 활성 세션 안으로 게이트했고, 축은 응답의 세션 값이 아니라 클라이언트 시계로 잡았다. 폴링이 멈춘 동안 응답 세션이 갱신되지 않아 개장 전에 연 탭이 09:00 이후 돌아와도 갇히기 때문이다.

## 지수 stale 응답 1회 재조회

응답이 stale인지 알려면 route가 언제 조립된 값인지 실어 보내야 한다. #144에서 현재가 route에 넣은 `fetchedAt`을 분봉 route 둘에도 같은 자리, 캐시 단위 안에서 캡처하도록 넓혔다. 재검증이 응답 뒤 실제로 완료되는지는 실측으로 확인했다. 국내는 `age` 93.6초짜리 응답 3초 뒤에 3.2초, 해외는 132.3초 → 3.2초였고, Next 소스에서도 stale 반환 후 재검증을 Vercel의 `waitUntil`로 넘기는 경로를 봤다.

| 후보 | 판정 |
|---|---|
| 종목처럼 캐시를 걷고 KIS 직행 | 기각. 지수 호출이 "키 수 ÷ TTL"에서 사용자 비례로 바뀜 |
| 탭 복귀 이벤트에 몇 초 뒤 2차 refetch | 기각. 저트래픽 첫 로드도 같은 stale인데 못 덮음 |
| **응답 나이가 TTL을 넘으면 3초 뒤 1회 재조회** | **채택.** 재검증된 항목을 캐시 히트로 받아 KIS 호출 0. 첫 로드도 덮음 |

| 판정 | 정규장 tick 실측 | 결과 |
|---|---|---|
| 나이 > TTL | 64.6초 → stale | 정규장 내내 route 요청 tick당 2회, KIS 호출 두 tick당 1회 → 매 tick |
| **나이 > TTL + 15초** | 64.6초 → 정상 | **채택.** 평상시 변화 0, 90초 이상 숨어 있던 탭만 |

```
재조회 = 응답 나이 > TTL + 15초  이고  이 응답이 재조회의 결과가 아닐 때, 3초 뒤 1회
```

폴링 60초와 TTL 60초가 정렬돼 있어 평범한 tick도 만료 직후에 닿는데, 64.6초는 60초 주기가 약속한 신선도 그대로라 stale로 볼 값이 아니었다. 정상 tick의 초과분은 내 폴링 지터 몇 초뿐이라 15초면 오탐이 없다. 재조회로 받은 응답이 또 stale이어도 다시 나가지 않게 막았고, 이게 없으면 KIS가 죽어 재검증이 계속 실패할 때 요청이 꼬리를 문다. 차트·레일·칩이 각자 예약해도 진행 중인 요청에 합류해 route로는 한 번만 나간다.

## 정리

- **F87 종결** — legend 거래량 필드를 거래량 pane과 같은 prop으로 게이트. 미호버·라인 hover 경로의 0 노출 제거
- **E77 종결** — /credits 한 줄에 더해 DJI 차트 하단 캡션. 혼란이 생기는 자리에 설명
- **E80 종결** — NXT 종목 인트라데이 뷰 하단 세션 구간 캡션. SSR prop 축, 15:30 제도 시간
- **E76 종결** — 전제 정정. 복귀 refetch는 원래 동작했고 실체는 지수 route의 SWR stale. 종목은 마감 후 복귀 KIS 호출을 세션 게이트로 차단, 지수는 응답 나이 기준 1회 재조회
- **E81 삭제 · F67 조치 불요** — 아침 실측으로 판정. 기본 탭 NXT, 비NXT 등락 0
- **백로그 강등 셋** — 종목 일봉 payload 판단·배당 이력·종목 전일 봉 전체 서빙

관측 세션마다 늘기만 하던 로드맵이 처음으로 줄었다. 사실 재트리아지 세션까지 따로 잡아둔 건 판정이 갈릴 걸 예상해서였는데, 실측이 다 닫아버려서 남은 건 정리뿐이었다. 그러다가 1커밋으로 잡아둔 탭 복귀 항목이 전제부터 틀린 걸로 나와 세션 후반을 다 썼다. 엄밀히는 문제가 없던 게 아니라 원인을 잘못 짚어둔 거지만, 그 덕에 종목 쪽 KIS 누수를 덤으로 잡았다.
