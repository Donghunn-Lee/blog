#061에서 지수 슬레이트를 홈에 올렸다. 다음은 종목 현재가다. 지수 슬레이트에서 만들어 둔 경로를 종목 상세 헤더로 옮겨, 종목 현재가도 장중에 실시간으로 도는 작업이다.

미러링 자체는 패턴이 이미 있어서 큰 고민이 없었다. 손이 간 건 두 군데다. 하나는 "배포하고 나면 KIS 토큰을 어떻게 관리하나"였고, 다른 하나는 "정규장이 아닐 때 가격을 어디서·어떻게 보여주나"였다. 종목은 지수와 달리 시간외(NXT) 가격이 따로 도는 데다, 새벽이나 장 마감 시간대에 접속한 사람에게 뭘 보여줄지까지 정해야 했다.

## 배포 후 토큰을 어떻게 관리할까?

지금 토큰은 서버 메모리(모듈 스코프)에 캐시해 두고 만료 전까지 재사용한다. #060에서 임시로 깔아둔 구조다. 다만 이건 어디까지나 임시, 개발 단계에서나 쓰는 방법이고, 배포한 다음 어떻게 관리할지를 결정해야 했다.

KIS 토큰 발급은 **1분에 한 번**으로 제한된다. 그리고 Vercel은 서버리스라 요청이 몰리면 인스턴스가 여러 개 뜨고, 인스턴스마다 메모리 캐시가 따로 논다. 사용자가 거의 없는 포폴이라 당장의 문제는 아니지만, 인스턴스가 동시에 여러 개 떠서 각자 토큰을 발급하려 들면 1분 제한에 부딪힐 수 있다. 같은 키로 부르면 유효한 토큰을 다시 내려주긴 해도, 매끄러운 그림은 아니다.

결국 결정해야 하는 건 토큰을 어디에 저장할지다. 받은 토큰을 저장해 두고, 유효기간 안에는 재사용, 만료될 때만 새로 발급하는 식. 발급을 인스턴스마다 따로 할 게 아니라 한 곳에 모아두는 게 핵심이다. 가진 인프라 안에서 선택할 수 있는 방법은 많지 않았다.

| 방식 | 구조 | 비고 |
|---|---|---|
| 현행 (모듈 스코프) | 인스턴스별 메모리 | 인스턴스 간 비공유, 1분 제한에 취약 |
| cron 발급, Neon 공유, 앱 읽기 | cron이 주기 발급→DB 기록, 앱은 읽기만 | 발급 책임을 앱에서 분리 |

이미 Neon DB와 GitHub Actions cron을 둘 다 굴리고 있어서, 토큰을 DB 한 행에 두고 cron이 주기적으로 갱신하는 쪽으로 방향을 잡았다. 발급을 앱 경로에서 빼면 인스턴스가 몇 개가 뜨든 발급은 cron 한 군데서만 일어나니, 1분 제한이나 동시 발급 같은 문제가 구조적으로 사라진다. 앱은 평소엔 DB만 읽고, 토큰이 만료됐거나 비어 있을 때만 한 번 발급해 채우는 fallback을 두면 cron이 한 번 걸러도 버틴다.

다만 이번 세션엔 구현까지 가지 않고 결정만 해뒀다. 지금 폴링이 도는 건 지수 패널 하나뿐이고 종목도 상세 한 종목씩이라, 모듈 스코프 캐시로도 실사용에 문제가 없다. 관심 종목까지 현재가를 적용하면서 작업해도 늦지 않다.

중간에 refresh_token으로 갱신하는 흐름도 문서에 있었는데, 제휴사용으로 보여서 개인 키에는 그냥 재발급이 표준일 듯해 넘겼다. 다만 확신은 아니라 도입할 때 다시 볼 항목으로 남겨뒀다.

## 종목 헤더로 현재가 적용

현재가를 받아 화면에 얹는 경로는 지수에서 만든 걸 거의 그대로 가져왔다. 토큰을 얻어 KIS 종목 현재가를 부르고, 응답 봉투만 Zod로 검증한 뒤 normalizer에 넘겨 도메인 모델로 돌려주는 fetch 래퍼, 그 위에 단일 종목용 route, `marketOpen`으로 폴링을 켜고 끄는 훅. 종목 현재가 정규화는 #060 때 이미 만들어 둬서, 새로 짠 건 호출 래퍼 정도였다.

헤더는 원래 서버 컴포넌트라 EOD 종가를 그려두고 있었다. 여기에 실시간을 얹는 방식은, 가격·등락 부분만 클라이언트 서브컴포넌트로 떼고 서버가 그린 종가를 초기값으로 넘기는 형태로 갔다. 첫 렌더는 SSR 종가가 그대로 뜨고, 폴링 응답이 들어오면 그 위를 실시간 값이 덮는다. 장이 닫혀 있으면 폴링이 안 도니 종가가 그대로 남는다.

![](/static/images/velog/e2b9b8a8-c480-4ae0-aba9-744c16b339f3-image.png)


지수 패널에 인라인으로 둔 등락 표시(▲▼·색·퍼센트)를 공용 컴포넌트로 뺄까 잠깐 봤는데, 이번엔 그대로 뒀다. 헤더는 등락을 "원" 단위에 부호를 붙여 보여주고, 지수 패널은 단위 없이 ▲▼와 절대값으로 보여준다. 표기가 이미 둘로 갈려 있어서, 하나로 묶으려면 variant나 단위 옵션을 받는 설계가 먼저다. 사용처가 헤더·지수 둘뿐인 지금은 추출 이득보다 그 설계 비용이 크다. 세 번째 사용처가 생기는 관심종목 리스트에서 같이 정리하는 게 맞다고 봤다.

## 정규장 하나에서 여섯 시간대로

원래 장 열림 판정은 평일 09:00~15:30이냐만 보는 함수 하나였다. 지수는 정규장에만 움직이니 그걸로 충분했다. 그런데 종목은 사정이 다르다. #061에서 확인한 대로, 장이 끝난 뒤에도 시장 구분을 `NX`(넥스트레이드)로 바꿔 부르면 시간외 체결가가 따로 돈다. 그러면 "지금이 정규장인가"만으론 부족하고, "지금이 어느 시간대고 어느 시장 구분으로 불러야 하나"를 알아야 한다.

NXT 거래시간은 프리마켓 08:00~08:50, 메인 09:00:30~15:20, 애프터마켓은 15:40부터 20:00까지다. 정규장(09:00~15:30)과 시작도 끝도 조금씩 다르다. 이 시간대들을 그대로 분기에 넣으려고, 판정 함수를 boolean 하나에서 여섯 상태를 돌려주는 형태로 바꿨다.

```ts
type KrxSession =
  | "regular" | "after" | "after_close"
  | "pre" | "preopen" | "closed";

const getKrxSessionState = (now = new Date()): KrxSession => { ... };
```

| 시간대(평일) | 상태 | 호출 | 화면 |
|---|---|---|---|
| 09:00~15:30 | 정규장 | KRX(J) 폴링 | 실시간 |
| 15:30~20:00 | 애프터마켓 | NXT(NX) 폴링 | 실시간 |
| 20:00~06:00 | 애프터 종료 | NX 1회 | NXT 종가 |
| 06:00~08:00 | 장 시작 전 | 호출 안 함 | 전일 종가 + 0% |
| 08:00~08:50 | 프리마켓 | NX 폴링 | 실시간 |
| 주말(공휴일 미설정) | 장 마감 | 호출 안 함 | 전일 종가 + 0% |

route는 이 상태를 받아 시장 구분만 가른다. 정규장은 `J`, 시간외 계열은 `NX`, 장이 완전히 닫힌 시간대는 아예 부르지 않는다.

```ts
if (session === "regular") {
  quote = await fetchStockQuote(ticker, "J");
} else if (session === "after" || session === "after_close" || session === "pre") {
  quote = await fetchStockQuote(ticker, "NX");
}
// preopen·closed는 호출 없이 전일 종가 + 0%
```

### 비 거래 시간 표시

#### 1) 애프터 마켓 종료 이후
NXT 거래시간은 프리마켓 08:00~08:50, 메인 09:00~15:20, 애프터마켓은 15:40~20:00. 정규장(09:00~15:30)과는 시작·끝이 조금씩 어긋난다. 코드에서는 정규장 마감 직후(15:30)부터 바로 after로 분류해 15:30~15:40 갭을 흡수한다.

20시 이후는 그냥 "장 마감"으로 묶어서, KIS를 안 부르고 KRX 종가만 보여줄 생각이었다. 그런데 문득 그렇게 되면 밤에 접속한 사람은 NXT에서 가격이 움직였어도 그걸 못 본다는 생각이 들었다. 대부분의 증권 서비스에선 15:40 ~ 20:00 시간에 nxt거래가를 보여준다.

다행히 KIS가 시간대로 호출을 막는 건 아니라(제한은 초당 호출 수지 시각이 아니다), 20시 이후에도 `NX`로 부르면 그 시점 NXT 종가가 온다. 그래서 애프터마켓이 끝난 뒤에도 그 종가는 화면에 남기기로 했다. 대신 값이 더 안 바뀌니 폴링은 끄고 한 번만 받는다.

#### 2) 새벽 시간대
그 다음이 새벽 처리였다. 밤새 NXT 종가를 보여주다가, 다음 거래일이 가까워지면 어느 순간 기준을 새 날짜로 옮겨야 한다. 증권사 화면들이 새벽에 전일대비를 0%로 되돌리는 게 이 처리다. 일반적으로 05:00 ~ 06:00 으로 하는 듯해서, 06:00을 기준으로 잡았다. 06:00부터 프리마켓 전까지는 KIS를 부르지 않고, 전일 KRX 종가와 등락률 0%로 보여준다.

#### 3) 비 nxt 종목 관리
NXT는 전 종목이 아니라 주요 800개 정도만 거래된다. 그 밖의 종목을 시간외에 `NX`로 부르면 값이 안 온다. 이건 버그가 아니라 원래 안 도는 종목이라, 그럴 땐 종가로 폴백하고 "장 마감"으로 표시한다. 시간외 분기를 넣을 때 이 빈 응답을 정상 흐름으로 받게 해둬서, 혹시 프리마켓 쪽에서 값이 예상과 다르게 안 와도 화면이 깨지지 않고 종가로 떨어진다.

추가로 개장일 장전에는 "개장 전", 휴장일에는 그대로 "장 마감"으로 표시하고 싶었는데, 휴장일 판정에 대한 부분이 바로 뚝딱 되는 부분은 아니라 F트랙의 공휴일 판정 항목이 있어서 그 때 같이 작업하기로 했다.

## 정리

- **종목 헤더 실시간 현재가** — 지수에서 만든 fetch·route·폴링 패턴을 헤더로 옮겼다. 가격·등락만 클라이언트로 떼고 서버 EOD를 초기값으로 넘겨, 첫 렌더는 종가·이후 실시간으로 덮는 구조다
- **토큰 운영 방향** — Vercel 다중 인스턴스와 1분 발급 제한 때문에, 토큰을 Neon 한 곳에 두고 cron이 갱신하는 쪽으로 정했다. 구현은 폴링이 늘어나는 관심종목 라이브화 때로 미뤘다
- **거래 시간대 여섯 분기** — 정규장(J)·애프터마켓(NX)·애프터 종료·장 시작 전·프리마켓·장 마감으로 갈라, 20시 이후 NXT 종가는 남기고 06:00부터 전일 KRX 종가+0%로 되돌린다. NXT 미지원 종목은 KRX 종가로 폴백
- **등락 표시 추출 보류** — 헤더와 지수의 표기가 달라, 공용화는 세 번째 사용처(관심종목)에서

종목 현재가 자체는 지수 패턴을 옮기는 일이라 금방 붙었다. 시간이 간 건 그 바깥이었다. 토큰을 배포 환경에서 어떻게 다룰지, 정규장 밖 시간대마다 뭘 보여줄지를 정하는 쪽이 정작 길었다. 화면에 뜨는 결과는 "현재가가 실시간으로 돈다" 한 줄인데, 그 한 줄이 도는 시간대를 가르는 데 대부분의 판단이 들어간 세션이었다.

## 다음 작업

헤더는 실시간이 됐지만 관심종목·최근조회 리스트는 아직 저장 시점 종가 그대로다. 다음은 그 리스트를 살리는 순서다.

- **E18** — 관심종목·최근조회 리스트에 실시간 현재가를 붙인다. 헤더처럼 종목마다 따로 부르면 호출이 너무 많아져서, 한 번에 최대 30종목을 받는 멀티 조회를 쓴다. 지수·헤더에 흩어둔 등락 표시도 이 세 번째 사용처에서 공용 컴포넌트로 뺀다
- **A6** — 토큰을 Neon 공유 캐시로 옮긴다. cron이 발급해 DB에 기록하고 앱은 읽기만, 만료 시 한 번 발급하는 fallback. 폴링이 늘어나는 E18과 같이 묶는다
- **X12** — 지수 과거 OHLCV 소스를 정한다. KIS 지수 기간별 차트와 KRX Marketplace 지수 둘을 probe로 찍어 호출량·과거 범위를 비교한다

관심종목 리스트가 실시간이 되면 토큰 공유가 같이 필요해지니, E18과 A6는 한 세션에 붙여 가는 게 자연스럽다.
