9월 14일 KRX 애프터마켓 첫날, KIS 일봉이 마감 후에도 그날 마지막 애프터 체결을 종가로 돌려주는 것을 봤다. 공식 종가는 15시 30분 값이라는 게 제도인데 벤더 일봉이 다른 말을 하고 있었고, 그 값을 그대로 적재하면 되돌리기 어려운 구조라 하루치 EOD 적재를 멈춰 둔 채였다. 애프터마켓 대응 항목(X27)의 마지막 미결이 이 EOD 축이었다.

계획은 화요일 07시 30분에 일봉을 다시 떠서 밤사이 정정 여부와 다음 날 기준가를 보고 적재 시각을 정하는 것이었다. 07시 30분은 놓쳤고, 대신 개장 직전 08시 46분 덤프와 KRX 공식 데이터 대조로 판정을 끝냈다. 코드 커밋은 없었지만 EOD 적재의 소스와 시각, 헤더 표시 방향, 그리고 실물 검증에서 나온 결함 하나까지 다음 세션의 계약이 정해졌다.

## 밤사이 정정된 일봉과 기준가

07시 30분을 놓친 게 치명적인지부터 따졌다. 정정 여부는 개장 후에도 전일 봉이 한 칸 밀릴 뿐 값은 그대로 받을 수 있고, 기준가 필드는 장중이 오히려 명확하며, 잃는 것은 "밤사이 정정인지 개장 시 정정인지"의 구분뿐이라 적재 시각 결정엔 영향이 없었다. 실제 데드라인은 16시 cron이었다. 9/14가 비어 있는 채로 16시 run이 돌면 종목별 마지막 적재일 다음 날부터 받는 규칙 때문에 9/14가 애프터 종가로 굳는다. 그래서 첫 액션은 덤프가 아니라 cron 정지였다.

| 주성엔지니어링 9/14 | 마감 후 21:35 KIS 일봉 | 익일 08:46 KIS 일봉 | KRX 공식(일별매매정보) |
|---|---|---|---|
| 종가 | 202,500원 | **206,000원** | 206,000원 |
| 저가 | 195,000원 | **201,500원** | 201,500원 |
| 거래량 | 892,311주 | 892,311주 | 892,311주 |
| 9/15 기준가 | — | 206,000원 | — |

KIS 일봉은 밤사이 종가·고가·저가를 정규장 값으로 되돌리고 거래량만 애프터 포함으로 남겼는데, 이게 KRX 공식 정의 그대로였다. 대우건설·삼성전자까지 세 종목 네 필드가 KRX Open API 일별매매정보와 전부 일치했다. 기준가가 15시 30분 종가라는 건 기준가 필드보다 장전 시간외 종가매매 체결이 먼저 말해줬다. 08시 30분대에 주성엔지니어링 614주가 206,000원에 체결돼 있었고, 이 매매는 규칙상 전일 종가로만 체결된다. 중간에 pykrx로 찍은 9/14 종가가 202,500원으로 나와 "KRX 공식이 애프터 값으로 바뀐 건가" 하고 잠깐 흔들렸는데, pykrx 기본 소스가 네이버라 마지막 체결가를 돌려준 것이었다. 9/14 이후 날짜에 pykrx 백필을 쓰면 안 된다는 제약이 하나 추가됐다.

## 16시 이후 15시 30분 종가를 주는 요청

정정을 확인했으니 남은 건 "저녁에 정확한 종가를 어디서 받나"였다. 전날 16시 31분 덤프 전체를 뒤져도 206,000원이 어디에도 없었고 KIS 9/9 공지에도 시세 REST 변경은 없어서 "KIS엔 없다"고 단정했었다. 그런데 시장이 기준가를 15시 30분으로 잡는데 그 값을 주는 요청이 없을 리 없다는 의심 쪽이 맞았다. 후보를 넓혀 16시 36분에 다시 probe를 돌렸다.

| 후보 | 판정 |
|---|---|
| 현재가·일봉·일자별·시세2·투자자 TR | 기각. 전부 애프터 값 |
| 시간외 현재가·시간외 일자별 TR | 기각. 시간외단일가 폐지로 시간외 필드 전부 0, 가격은 애프터 추종 |
| 잔고조회 "KRX정규장종가" 옵션 · 실시간 체결 장 구분 코드 | 기각. 계좌 보유 종목 한정 / WebSocket 구독 한도 |
| **당일 분봉 TR의 15:30 봉** | **채택.** 16시 이후에도 192,800원 유지. 15:31~15:59 fill 봉 거래량 0, 16:00 첫 애프터 봉 196,400원으로 교차 확인. 단 종가만 |
| **15:31~16:00 현재가 TR** | **채택.** 이 창의 시가·고가·저가·종가가 익일 정정 봉과 완전 일치. 시간외 종가매매는 종가로만 체결돼 값이 안 움직임 |
| KRX Open API 일별매매정보 | 보류. 전일분은 시장당 1호출로 공식값이지만 당일분은 16시 19분에도 빈 응답 |

15:30 봉이 마감 후의 유일한 경로였는데 종가만 주고 고가·저가는 못 준다. 그래서 눈이 간 곳이 15시 31분부터 16시까지 30분이다. 이 창에선 현재가 TR 한 번이 네 값을 전부 확정치로 준다.

## 30분 창과 2,650종목

문제는 fetch_prices가 2,650종목에 50분 걸린다는 것이다. 종목당 1.1초가 일정하게 찍히는데 호출 간격 sleep은 0.15초라 14%뿐이고 나머지는 Actions 러너에서 KIS와 Neon을 오가는 왕복이라, sleep을 없애도 42분이다. 동시성이나 배치 upsert는 collector 실행 모델을 바꾸는 일이라 이 시점에 열고 싶지 않았다.

우회는 이미 쓰고 있던 TR에 있었다. 20시 10분 스냅샷이 다건 시세 TR로 30종목씩 받는데, 이 응답에 시가·고가·저가·종가·거래량이 다 있다. 2,650종목이 90호출, 2~3분이면 창 안에 넉넉히 들어온다.

## 15:33 선적재와 아침 재조회

| 안 | 판정 |
|---|---|
| 16시 run 유지 + 익일 아침 덮어쓰기 | 기각. 저녁 내내 애프터 종가가 "장 마감 · 15:30" 라벨 옆에 앉음 |
| 아침 단독 적재 | 기각. 코드 변경은 0이지만 매일 15:30~09:10 가격 통계·일봉이 전일 값 |
| **15:33 다건 시세 선적재 + 09:10 기존 run이 마지막 저장일을 다시 받아 거래량 정규화** | **채택.** 시가·고가·저가·종가는 15:33에 확정, 거래량만 익일 확정. 15:33 실패 시 09:10 run이 그날을 포함해 자가 회수 |
| 네이버식 20시 캔들을 별도 컬럼으로 저장 | 기각. 저장 층에 종가 정의가 둘이 됨 |

```
전                                                후
16:00 run  일봉 TR 2,650호출 → 당일 행 (애프터 오염)     15:33 run  다건 시세 90호출 → 당일 행 (OHLC 확정 · 거래량 잠정)
                                                   09:10 run  일봉 TR 2,650호출 → 마지막 저장일 다시 받아 거래량 덮어쓰기
증분 시작점 MAX(date)+1                              증분 시작점 MAX(date)
```

09:10 run이 마지막 저장일을 다시 받는 것은 #098에서 "EOD는 한 번 들어가면 그대로여야 한다"며 기각했던 overlap 재조회를 되살리는 결정이다. 그때의 전제는 소스가 확정값만 준다는 것이었는데, 이제 KIS 일봉은 밤사이 스스로 정정되는 소스가 됐으니 마지막 날을 다시 쓰는 건 위험이 아니라 요구가 됐다. 우회 레버를 두지 않는 원칙은 그대로라 15:33 job은 15:31~16:00 밖에서는 아무것도 하지 않고, 첫 실측은 수요일 15시 33분에야 가능하다. 그때까지는 16시 cron을 09시 10분으로 옮겨 두고 9/14를 정정본으로 적재했다.

## 저장은 공식 축 하나, 라이브는 오버레이

머리가 아팠던 건 "종가"가 셋이라서였다. 15시 30분 공식 종가, 20시 애프터 마지막 체결, 그리고 일봉 캔들이 쓰는 20시 값이 포함되는 종가. 원칙을 하나로 세우니 정리됐다.

| 층 | 정의 | 소비처 |
|---|---|---|
| 저장 (daily_prices) | KRX 공식. 정규장 OHLC + 애프터 포함 거래량 | 등락률 · PER/PBR · 52주 · 가격 통계 · 일봉 이력 · 백필 |
| 라이브 (현재가 · 스냅샷 · 통합 분봉) | 지금 마지막으로 거래된 값 + 세션 라벨 | 헤더 · 배지 · 분봉 · 당일 봉 병합 |

이건 앱이 이미 하고 있던 구조고, 애프터마켓이 깨뜨린 건 저장 층이 15시 30분 직후에 안 채워진다는 것뿐이었다. 거래량이 09시 10분까지 정규장 값으로 남고 20시 스냅샷 전환 때 애프터 포함 값에서 되돌아가는 흔들림은 남는데, 이건 지금도 있는 현상이라 고지 한 줄로 수용했다. 20시 10분에 KRX 채널 누적 거래량만 따로 덮어쓰는 안은 호출 90개와 스냅샷 job이 daily_prices를 건드리는 결합을 대가로 치러야 해 backlog로 뒀다(F94). KRX Open API는 익일 제공이면 이점이 호출 수뿐이라 같이 backlog로 내렸다(X29).

## 헤더 표시 방향과 세션 라벨

KRX 탭에 애프터 가격을 어떻게 놓을지도 이번에 닫았다. 다른 서비스는 두 패턴이 공존했다. 네이버는 마지막 체결가를 헤드라인에 두고 구간 라벨을 붙이며 일별시세도 20시 값을 쓰는 반면 등락률은 15시 30분 기준이고, 뉴스 시세 위젯은 17시 28분에도 정규장 종가를 유지하고 있었다.

| 후보 | 판정 |
|---|---|
| KRX / KRX 애프터 / NXT 탭 셋 | 기각. 탭 축은 거래소지 세션이 아님. NXT 탭도 프리·메인·애프터를 라벨로 나눔 |
| **애프터 현재가 헤드라인 + 세션 라벨, 공식 종가는 EOD 패널** (현행) | **채택.** NXT 탭과 대칭, 등락률은 전일 15:30 기준이라 공식 축과 이미 정합 |
| 15:30 고정 + 애프터 별도 표시 | 보류. 헤더에 가격 표면이 둘 |

라벨 문자열은 네이버 구간표에 맞추기로 했다(E83). "장 마감"은 "정규장 마감", "애프터마켓 종가"는 "애프터마켓 마감"으로, 후자는 비공식 종가에서 "종가"라는 단어가 빠지는 게 오히려 정확하다. NXT 탭은 15:20·15:40 경계를 새로 두고, 네이버가 07:10부터 쓰는 "개장전"은 08:00 초기화 축을 지키기 위해 들이지 않았다. 배지는 20시 10분 스냅샷 전수 대조에서 판단이 바뀌었다. 비NXT 2,045종목 중 1,563종목(76%)이 정규장 종가와 다른 값을 갖고 있었다. 애프터마켓 이전엔 NXT 604종목만 대상이라 "이 값은 장외"가 정보였는데 2,000종목이면 벽지다. 헤더는 세션 라벨이 이미 말하니 배지를 빼고, 라벨이 없는 관심종목·검색 행에서만 "프리"·"애프터"로 남긴다.

## 실물 검증에서 나온 NXT 탭 결함

| 확인 항목 | 결과 |
|---|---|
| KRX 탭 라벨 "애프터마켓 종가 · 20:00", 등락 전일 기준 | 정상 |
| 비NXT 장외 배지 | 미표시. 9/15 EOD가 없어 비교 대상 부재, 15:33 적재 후 재확인 |
| 분봉 20시까지 | 정상 |
| 삼성전자 KRX 탭 / NXT 탭 | **NXT 탭 250,500원, HTS NXT 종가 250,000원** |
| 지수 불변 | 정상 |

스냅샷 원본은 통합 250,500원·NXT 250,000원으로 맞았고, NXT 탭으로 route에 직접 요청해도 통합 값이 왔다. 마감 후 스냅샷 분기가 market 인자 없이 통합 컬럼만 서빙하고 있었다. 회귀는 아니다. #124에서 5거래일 3,029건 대조로 통합과 NXT 종가가 전수 일치하는 것을 보고 "마감 후 NXT 탭은 스냅샷 경로 그대로"라며 NXT 컬럼 서빙을 설계에서 지웠는데, 그 등식은 KRX가 닫힌 뒤의 체결이 전부 NXT라서 성립한 것이었고 애프터마켓이 그 전제를 무효화했다. 결함이라기보다 그때 지운 코드가 다시 필요해진 것에 가깝다. 마감 후·휴장·개장 전 세 세션이 같은 경로라 주말 내내 NXT 604종목이 틀린 값을 보이는 셈이라 수요일 안에 고친다(F93). 수정은 스냅샷 결정 함수에 market 축을 더하고 NXT 등락을 전일 KRX 종가 기준으로 다시 계산하는 50줄 안팎이다.

## 정리

- **X27 EOD 축 판정** — KIS 일봉은 밤사이 정규장 OHLC로 정정, 거래량은 애프터 포함. KRX 공식과 세 종목 네 필드 일치, 기준가 15:30. 07:30 실측 없이도 판정 가능했음
- **X27 잔여 — 15:33 선적재 설계** — 다건 시세 TR 90호출로 OHLC 확정 적재, 09:10 run이 마지막 저장일을 다시 받아 거래량 정규화. #098에서 기각한 overlap 재조회 부활. 20시 캔들 저장 기각. cron 16:00→09:10 임시 이동, 9/14 적재 완료
- **F93 신설** — 마감 후 NXT 탭이 통합 값 서빙. #124 un=nx 전제의 무효화, 회귀 아님. 수요일 수정
- **E83 신설** — 세션 라벨 네이버 구간표 정합, 배지 프리/애프터, 헤더 배지 제거·리스트 유지
