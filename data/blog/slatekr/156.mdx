4월에 시작한 프로젝트가 구현을 일단락했고, 남은 건 9/14 시장 구조 변경 대응(X27)과 제출물이다. 제출물의 본체는 README(G1)다. 대기업이 아니라 중소·스타트업 지원을 전제하니 채용 담당자가 GitHub을 직접 열어볼 확률이 높고, 반년 걸린 프로젝트의 완성도를 길지 않은 문서로 보여줘야 한다.

계획은 토~일 초안이었고, 결과는 일곱 번 고친 v7에 코드베이스 사실 대조까지다. 코드는 한 줄도 안 건드린 세션이다.

---

## 어디서부터 들어갈 것인가

README에 뭘 얼마나 적을지 감이 없어 접근 순서부터 갈랐다.

| 후보 | 판정 |
|---|---|
| 리팩토링 sweep을 먼저 돌리며 내용을 같이 정리 | 기각. 컨벤션 점검은 README가 다루는 층(아키텍처·결정)을 안 건드림. 스코프만 섞임 |
| 구현 내용을 전수 조사해 목록부터 뽑기 | 기각. README는 인벤토리가 아니라 큐레이션. 인벤토리는 이미 일지 155건 |
| **골격을 먼저 잡고 초안, 초안이 주장한 것만 대조** | **채택.** 대조 범위가 README에 실린 주장으로 한정돼 비용 최소 |

정보가 부족하지 않을까 싶었는데, 프로젝트 지침 문서에 스택·아키텍처·제약이 이미 있어 배포 URL과 테스트 스토리(#087)만 보태면 됐다.

## 무엇을 강조할 것인가

처음 떠오른 건 실시간성, 데이터 정합성, AI 공시 요약이었다. 근데 셋 다 기능 관점이고, 프론트엔드 채용자는 설계 관점으로 읽는다. 같은 내용을 축만 바꿨다.

```
실시간성       → API 호출 한도 안에서 장중 갱신을 성립시킨 캐시 계층
데이터 정합성  → 한 섹션의 실패가 페이지로 번지지 않는 장애 격리
AI 공시 요약   → LLM 출력을 검증 가능하게 만든 스키마 구조
(빠져 있던 것) → 서버/클라이언트 경계와 상태 분리, 테스트 기준
```

"실시간"은 #140에서 내린 표현이라 README에서도 쓰지 않는다. 데이터 파이프라인(Python)은 프론트엔드 채용 문서에서 리드가 아니라 한 문단으로 내렸다.

### 이전 README에서 가져온 것

AimTest README를 다시 읽었다. 첫 화면의 질문 한 줄이 이후 결정 전부를 관통하는 구조, 결정마다 "초기 구현 → 문제 → 결과(숫자)" 서사, 깊이는 블로그 링크로 위임하는 방식은 가져왔다. 341줄 분량, 기능 나열로 흐른 UX 절, 한 문장씩 끊긴 문단, 근거 없는 "크게 향상" 류 결론은 버렸다. 품질(테스트) 절이 없던 것도 이번엔 반대로 간다. slatekr을 마무리하고 나면 AimTest 도 다시 조금 손 보며 업데이트 할 생각이다.

## 결정 네 개를 축 하나로

결정은 캐시 계층, 장애 격리, AI 출력 검증, 로그인 없는 관심종목 동기화 넷으로 골랐다. 문제는 도입 질문이었다. "언제 갱신하고, 실패하면 무엇을 보여줄 것인가"로 잡으니 앞의 둘만 답하고 뒤의 둘이 축 밖에 남았다.

```
갱신 주기   →  1. 캐시 계층 (negative caching 함정, 분봉 호출 26→7)
장애 폴백   →  2. 섹션 격리 (empty/error 분리, 직전 정상 응답 유지)
데이터 검증 →  3. AI 요약 스키마 (Zod 단일 소스, 판단 축 없는 출력)
            →  4. 익명 동기화 (server-wins 단방향, 쓰기 차단)
```

질문을 세 축으로 넓히니 넷이 다 들어갔다. 각 결정의 서사는 그때 쓴 글(#037·#075·#081·#141)에서 "초기 구현이 뭐였고 무엇이 그걸 무너뜨렸는지" 한 장면씩만 가져왔다. 기능 나열 절은 두지 않고 스크린샷 캡션이 대신한다.

## 문서와 실물의 어긋남

초안이 주장한 사실 44개를 코드베이스와 대조했다. 아홉이 어긋났다.

| 유형 | 예 |
|---|---|
| 수치 | AI 요약 facts 상한 8 → 실제 18. 에러 종류 4 → 7 |
| 용어 | "최근 검색" persist → 실제는 최근 조회 종목 |
| 층 오인 | `fetch` revalidate → 실제는 route segment `revalidate` |
| 예외 누락 | "페이지 전체 client 없음" → 관심종목 페이지 하나가 예외 |
| 목록 누락 | collector에 캘린더·배당·상장일·스냅샷 빠짐 |

지침 문서 기준으로 쓴 부분이 실물과 벌어져 있었다. 대부분은 문서가 갱신을 못 따라온 것이고, 관심종목 페이지의 `use client`는 지침이 금지한 항목이 남아 있던 거라 리팩토링 sweep(R1)에 올렸다. `typecheck` 스크립트 부재도 같이 — README가 네 가지 게이트를 말하는데 package.json엔 셋만 보인다.

## 용어

교정을 한 번 잘못 갔다. "조용한 구멍" 같은 풀어쓴 표현을 silent failure로 바꾸는 건 맞았는데, 그 기세로 재시도·무효화·불변식까지 영어로 밀었더니 문장당 영어가 셋씩 붙었다. 기준을 다시 세웠다.

| 기준 | 표기 |
|---|---|
| 한글이 표준 | 재시도 · 무효화 · 병합 · 불변식 · 멱등 |
| 한글이 없거나 어색 | silent failure · negative caching · graceful degradation · last-known-good · server-wins |
| 첫 등장만 병기 | 단일 소스(single source of truth) · 직전 정상 응답(last-known-good) |
