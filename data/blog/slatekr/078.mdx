지난 몇 편에서 실시간 시세가 잠깐 실패했을 때 화면이 어떻게 굴러가야 하는지를 표면마다 채워왔다. #075에서 서버 쪽에 눌러앉는 빈 값을 지웠고, #076에서 종목 차트에 실패 문구를, #077에서 지수 차트와 종목 현재가까지 붙였다. 이번엔 마지막으로 남은 표면, 관심종목 차례였다.

넓힐 대상은 관심종목 페이지와 홈페이지에 있는 관심종목 프리뷰다.

---

## single을 multi로

#077에서 종목 하나의 현재가(single quote)에 collapse랑 flag를 붙였다. 관심종목은 여러 종목 시세를 한 번에 받아오는 multi quote를 쓴다. 골격은 같으니 그대로 옮기면 되는 일이었다.

옮기기 전에 multi 쪽이 지금 어떤 상태인지부터 봤는데, #077 이전의 single이랑 판박이였다. 실패하면 500을 던지고, 그러면 이 응답을 받는 훅(`useMultiQuote`)이 throw한다. 결과적으로 관심종목 목록이 통째로 빈다 — 한 종목이 문제여도 전부.

첫 단계는 #077과 똑같은 collapse다. 500을 200으로 내리고, 요청한 티커를 전부 null로 채운 뒤 세션 정보를 실어 보낸다. 세션이 실려야 화면이 skeleton에서 풀려나고, 남아 있는 값으로 자연스럽게 떨어진다.

```ts
// catch: 500 대신 200으로 내려보내고 세션을 실음
return Response.json({
  quotes: allNull(tickers),   // 요청 티커 전부 null
  failed: allTrue(tickers),   // (아래 참조)
  marketOpen, session,
});
```

여기까진 single을 거의 베낀 셈이라 특별할 게 없었다. 갈린 지점은 그다음이었다.

---

## 30개 중 하나만 실패할 때

single은 종목이 하나라 실패도 하나다. 근데 multi는 관심종목을 최대 30개까지 한 번에 받는다. 그중 딱 하나만 실패하는 경우가 생긴다. 사실 이건 #077에서 이미 한 번 겪은 모양이다. 지수도 코스피·코스닥·코스피200 셋을 같이 내려주다 보니, 하나만 죽을 수 있었으니까.

그때는 응답 맨 위에 지수별 실패 map을 얹어서 풀었다. 여기도 같은 손을 쓰면 되는데, 다른 점이 하나 있다. 지수는 셋으로 고정이지만 관심종목은 사람마다, 그때그때 티커가 다르다. 그래서 고정 키가 아니라 티커를 키로 하는 map이 된다.

```ts
failed: { "005930": false, "000660": true, "035720": false }
//        삼성전자 정상      SK하이닉스 실패    카카오 정상
```

이걸 왜 boolean 하나로 안 뭉치냐면, 뭉치는 순간 부분 실패가 사라지기 때문이다. 30개 중 1개가 안 왔다고 맨 위에 `failed: true` 하나만 세우면, 멀쩡히 값이 온 29개까지 "지연 중"으로 깎인다. 실패를 실패한 종목에만 남기려면 종목별로 표시를 들고 있어야 한다.

| 방식 | 문제 |
|---|---|
| 맨 위에 `failed: boolean` 하나 | 하나만 실패해도 전체가 실패로 뭉개짐 |
| 값마다 `{ quote, failed }`로 묶기 | 응답 모양이 바뀌어 이 값을 쓰는 화면을 전부 수정 |
| 맨 위에 티커별 map | 모양은 그대로 두고 실패만 종목별로 |

세 번째로 갔다. 마침 시세를 받아오는 함수가 이미 티커별로 응답을 맞춰보고 있어서, 그 판정을 map으로 펴 내기만 하면 됐다. #077 지수 때랑 결이 같은데, 키가 고정에서 가변으로 바뀐 정도다.

---

## 화면 — 값은 남아 있으니 배지만

관심종목 카드는 실시간이 실패해도 보여줄 게 있다. 라이브 시세와 별개로, 전일 종가 기반 값이 늘 따로 들어오기 때문이다. 그러니 #077 현재가 때와 똑같은 상황이다 — 값은 그대로 두고 "일시 지연" 배지만 얹으면 된다. 실패한 티커의 행에만 배지가 붙고, 나머지는 라이브 그대로 흐른다.

배지는 종목 헤더에 쓰던 걸 글자도 색도 그대로 가져왔다. 등락 빨강·파랑이랑 부딪히지 않게 무채색으로 뒀는데, 이건 #077에서도 짚었던 초기 설계 당시 정해둔 원칙이다.

---

## 홈 프리뷰는 배지보다 구조가 먼저

관심종목 페이지 행은 폭이 넉넉해서 종목명 옆에 배지가 자연스럽게 앉는다. 그런데 홈에 있는 관심종목 프리뷰는 상위 세 개만 좁게 추린 거라, 같은 배지를 이름 옆에 붙여보니 좀 어색했다.

들여다보니 배지가 문제라기보단 프리뷰 자리가 문제였다. 지금 프리뷰는 담긴 내용에 비해 넓은 칸을 혼자 차지하고 있다. 오른쪽이 휑하다. 그래서 이걸 어떻게 앉힐지 — 옆에 다른 슬레이트를 하나 더 놓아 가로로 두 단을 만들지, 아니면 프리뷰를 작게 줄여 오른쪽 패널로 뺄지 — 를 정하는 게 배지 위치를 손보는 것보다 먼저다.

배지는 실패를 읽어 표시하는 로직이라, 프리뷰를 어느 쪽으로 재배치하든 자리만 옮기면 그대로 쓴다. 그래서 여기선 배지를 억지로 맞춰 넣기보다, 구조 결정을 기다리기로 했다.

---

## 정리

- **넓히려던 대상 재확인** — 관심종목엔 미니차트가 없고 홈 미니차트는 이미 끝난 거라, 실제 대상은 관심종목 현재가의 실패 표시였다. 조사에 들어가기 전에 방향을 바로잡았다.
- **single → multi 이식** — 종목 현재가에 했던 collapse(500→200)를 관심종목 multi quote에 그대로 옮겼다.
- **부분 실패는 티커별로** — 30개 중 하나만 실패할 수 있어, 응답 맨 위에 티커별 실패 map을 얹어 멀쩡한 종목까지 깎이지 않게 했다. #077 지수 map을 가변 키로 바꾼 셈이다.
- **화면** — 전일 종가 값이 남으니 "일시 지연" 배지만 얹었고, 홈 프리뷰는 배지보다 프리뷰 자리 자체를 먼저 정하기로 미뤘다.

이번 건 새로 설계했다기보다, #077에서 세운 걸 마지막 표면에 옮긴 확산에 가깝다. 그래서 무게는 오히려 "넓히려던 게 실제로 뭐였는지"를 다시 본 앞쪽에 실렸다. #075부터 이어온 "실시간이 잠깐 안 될 때" 이야기는 이제 종목·지수·관심종목 세 표면에 다 붙은 셈이다.

여느 편과 같은 한계도 그대로다. 실제 KIS 다운을 재현하기 어려워서, 이번에도 강제로 켠 값으로 화면만 확인했다. 장중에 직접 눌러 확인할 몫이 몇 개 남아 있다.

## 다음 작업

관심종목까지 붙이면서 실시간 실패 표시는 얼추 마무리됐다. 남은 건 실패 그 자체보다, 위에서 걸린 홈 레이아웃 쪽이다.

- **E16 — 홈 관심종목 프리뷰 재배치** — 프리뷰가 넓은 칸을 혼자 차지하는 문제. 옆에 시장 상위 슬레이트를 놓아 두 단으로 갈지, 프리뷰를 미니로 줄일지 정한다.
- **X11 — KIS 순위 API 조사** — 옆칸을 등락률·거래량 상위 같은 데이터로 채우려면 이게 먼저다.
- **장중 실측** — 이번을 포함해 강제값으로만 확인한 실패 표시들을, 장중에 실제로 눌러 확인한다. 급하진 않아 우선순위는 낮다.

프리뷰 재배치는 실패 표시를 붙이다가 눈에 걸린 거라, 다음엔 이쪽 구조부터 손볼 생각이다.
