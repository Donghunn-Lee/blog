정말, 이제 정말 마무리 페이즈에서 남은 작업은 README 마감(G1)이다. 직전 세션에 홈 캐러셀의 카드 여백을 줄였다가 데스크톱 홈의 레이아웃 이동 점수(CLS)가 0.016에서 0.126으로 올랐는데, README에 성능 수치를 적기 전에 이것부터 되돌려야 했다.

계획은 가운데 카드의 문구를 줄여 이동을 없애는 홈 캐러셀 정비(E100)를 끝내고, 화면을 다시 찍어 README를 마감하는 것이었다. 실제로는 계획에 없던 수정이 여럿 붙어 커밋이 열다섯 개가 됐고, README는 이미지 교체까지만 마쳤다. 성능 수치와 회고는 다음 세션으로 넘겼다.

## 계획에 없던 수정과 진행한 근거

제출 직전이라 범위를 늘리지 않으려 했지만, 아래 다섯 건은 각각 지금 해야 할 이유가 있었다. 기준은 두 가지로, 제출물을 가볍게 훑어보는 사람의 눈에 보이는가와 README의 문장과 어긋나는가였다.

| 수정 | 진행한 근거 |
| --- | --- |
| 모바일 히어로 문구 축소 | 히어로를 바꾸면 스크린샷과 성능 측정을 다시 해야 함. 캐러셀 정비와 같은 배포에 묶으면 재촬영 · 재측정 1회로 끝남 |
| 시장 순위 카드 추가 | 히어로 설명이 줄어 캐러셀이 서비스 소개를 맡게 됨. 가운데 카드 문구를 줄이면서 소개에서 순위가 빠짐 |
| 카드 높이 통일과 후속 조정 | 카드가 4장이 되자 카드마다 다른 바닥 높이가 드러남 |
| 실패 배지 라벨 분리 | 값이 비는 자리에 '일시 지연'은 사실과 다른 표현 |
| 다우 시세 조회 제외 | README의 "외부 API 호출 수를 사용자 수와 분리"가 다우에서 성립하지 않음 |

## 모바일 히어로 문구

모바일 첫 화면에서는 서비스명, 제목 2줄, 설명 2줄이 캐러셀 위에 쌓여 「주요 지수」가 화면 절반 아래로 밀려 있었다. 캐러셀이 소개를 하고 있으니 문구는 한 줄이면 되지 않을까 싶어, 후보 문구를 화면에 주입해 폭별 줄 수와 높이부터 쟀다.

| 후보 | 판정 |
| --- | --- |
| 제목과 설명을 지우고 한 줄 문구만 | 기각. 전 폭 1줄 · 모바일 70 ~ 90px 확보. 데스크톱은 왼쪽 열이 비고, 모바일도 설명이 없으니 허전 |
| 글자 크기 축소 | 기각. 설명은 이미 13px. 제목은 16px로 줄여도 360px 폭에서 1줄 불가(계산) |
| **모바일에서만 문구를 다듬어 각 1줄** | **채택.** 제목의 앞 구절을 덜고, 덜어낸 내용은 설명으로 옮김. 360px · fallback 글꼴에서도 여유 32px 이상 |

모바일 문구는 「주식 시세 · 재무 · 공시를 한 곳에서」와 「흩어진 국내 상장 종목 정보를 구조화해 제공합니다」가 됐고, 데스크톱은 그대로 두었다. 390px 폭에서 「주요 지수」의 시작 위치는 462px에서 414px로 올라왔다. 직전 세션에는 글꼴 교체로 줄 수가 바뀌지 않도록 줄바꿈 위치를 고정했는데, 이번에는 제목과 설명이 한 줄씩이라 그 문제가 생길 여지가 없다.

## 글꼴에 좌우되지 않는 캐러셀 높이

데스크톱 CLS 0.126의 원인은 가운데 카드의 설명이었다. fallback 글꼴에서는 2줄이다가 웹 글꼴이 도착하면 1줄이 되면서 캐러셀이 17px 낮아지고 아래 섹션이 따라 올라온다. 직전 세션에 후보로 남겨 둔 고정 높이 복원은 줄인 여백을 되돌리는 방법이어서, 높이를 붙잡는 대신 글꼴에 따라 줄 수가 달라지는 지점을 없애기로 했다.

| 글꼴에 따라 달라지던 것 | 조치 |
| --- | --- |
| 가운데 카드 설명 2 ↔ 1줄 (1024px 이상 · 390px) | 문구를 「장중 시세와 일봉·분봉 차트 제공」으로 축소. 10개 폭 × 두 글꼴 전부 1줄 |
| 공시 카드의 유형 칩 3 ↔ 2줄 (390px 부근, 23px 차이) | 칩 영역을 2줄 높이로 제한하고 셋째 줄은 통째로 가림. 가려지던 「AI 요약」 칩은 맨 앞으로 이동 |

칩 쪽은 처음에 그대로 두기로 했었다. PSI의 모바일 측정 폭(412px)에서는 두 글꼴의 줄 수가 같아 점수에 잡히지 않기 때문이다. 다만 0.1을 넘으면 다시 본다는 조건을 달아 두었는데, 히어로가 짧아져 움직이는 영역이 화면에 더 많이 들어오자 0.095가 0.102로 올라 그 조건에 걸렸다. 고정 높이는 빈 여백을 만들기 때문에 넘치는 줄을 가리는 쪽을 택했다.

```
글꼴 응답을 2초 늦춘 재현 (CLS)
데스크톱 1350px  0.126 → 0.017
모바일   390px   0.095 → 0.102 (히어로 축소 직후) → 0.002
```

## 시장 순위 카드와 카드 높이 통일

네 번째 카드는 캐러셀 높이를 바꾸지 않는다는 조건으로 넣었다. 프리뷰는 순위 3행인데, 종목명 자리에 중립 막대를 두었더니 로딩 중인 화면처럼 보여 실제 종목명으로 바꿨다. 등락률은 핵심 지표 카드의 PER과 마찬가지로 표본 값이다. 아이콘은 하단 탭 「순위」와 같은 것을 쓰려 했으나 가운데 카드의 아이콘과 겹쳐서, 카드와 탭을 모두 목록 모양으로 바꿨다.

카드가 4장이 되자 카드마다 높이가 달라(모바일 164 / 161 / 164 / 160px) 넘길 때 바닥이 어긋나는 것이 눈에 띄었다. 직전 세션에 카드 아래 여백을 줄인 터라 짧은 카드를 다시 늘리는 것이 맞는지 좀 망설였는데, 카드는 가장 높은 카드에 맞추되 남는 높이를 바닥이 아니라 설명과 프리뷰 사이로 보내는 방식으로 정리했다. 높이를 맞추고 나니 가려져 있던 문제가 몇 개 더 드러났다.

| 드러난 문제 | 조치 |
| --- | --- |
| 핵심 지표 카드만 설명과 프리뷰 사이가 26px로 벌어짐 | 지표 배치를 1×4에서 2×2로 |
| 768 ~ 835px에서 칩이 3줄이 되어 네 카드가 함께 23px 높아짐 | 칩 2줄 제한을 1024px 미만 전체로 확대 |
| 640 ~ 767px에서 활성 카드가 499px까지 넓어짐 | 캐러셀 컨테이너 상한 384px. 448px은 480 ~ 639px에서 설명 줄 수가 글꼴에 따라 바뀌어 기각 |
| 설명이 음절 중간에서 줄바꿈 | 단어 단위로 줄바꿈 |

## 캐시되지 않던 다우 시세

README를 코드와 한 줄씩 대조하다가 "외부 시세 API 호출 수를 사용자 수와 분리했다"는 문장이 다우존스 지수에서는 성립하지 않는다는 것을 찾았다. 지수 시세는 route에서 캐시하므로 조회자가 몇 명이든 KIS 호출은 일정해야 하는데, 다우만 요청마다 캐시 미스가 났다. 이전에 내린 두 결정이 만나는 자리였다. 다우는 KIS가 장중 시세를 주지 않아 일봉 종가만 표시해 왔고(#107), 조회 실패는 캐시에 남지 않도록 즉시 축출하게 해 두었다(#075).

```
KIS 응답   정상 처리인데 값이 전부 0
 → 0 값은 무효로 보고 null로 바꿈
 → route는 null을 조회 실패로 보고 캐시를 축출
 → 다음 요청은 캐시 미스, KIS를 다시 호출 (조회자 N명이면 분당 N회꼴)
```

| 후보 | 판정 |
| --- | --- |
| 0 값 응답을 빈 응답으로 캐시 | 기각. 다른 지수에서 같은 응답이 오면 0 값이 캐시 유효기간 동안 남음 |
| **장중 시세를 주는 7종만 조회** | **채택.** 다우는 호출 없이 null. 화면은 그대로 일봉 종가 + '종가 기준' 캡션 |

수정 후 route를 두 번 호출해 KIS 호출이 7건이고 다우는 0건인 것을 확인했다. KIS가 다우 시세를 다시 열어도 앱이 자동으로 따라가지 않는다는 점은 감수했고, 출처 페이지에는 이미 일봉 종가만 표시한다고 적혀 있다. 나머지 7종도 KIS 장애 중에는 같은 경로로 요청마다 호출이 나가는데, 이는 실패를 캐시하지 않기로 한 선택의 대가여서 추후 backlog에 있는 실패 · 부재 구분 작업에서 다룰 생각이다.

## 실패 배지 라벨과 README 이미지

부분 실패를 알리는 배지는 전부 '일시 지연'이었는데, 국내 증권 앱에서 '지연'은 지연 시세를 뜻하는 말이라 값이 아예 비어 있는 자리에는 맞지 않았다.

| 상황 | 라벨 | 적용 |
| --- | --- | --- |
| 전일 종가 같은 대체값이 남음 | 일시 지연 | 6곳 유지 (관심종목 · 종목 헤더 · 검색 결과 · 시장 순위) |
| 값이 빔 | 로딩 실패 | 2곳 (핵심 지표의 PER · PBR · 시가배당률, 관심종목 페이지의 공시 건수) |

README 이미지는 GitHub 첨부 주소에서 저장소 안 상대 경로로 옮기고 8장을 새로 찍어 넣었다. 첨부 주소는 캡처 스크립트로 갱신할 수 없기 때문이다. 모바일 화면은 종목 상세 이미지 옆에 나란히 두었다가, 렌더링 결과 폭이 105px로 줄어 글자가 읽히지 않아서 「반응형」 항목 아래로 옮겼다.

## 정리

- **E100 종결** — 가운데 카드 문구 축소 · 칩 2줄 제한으로 캐러셀 높이의 글꼴 의존 제거. 재현 CLS 데스크톱 0.126 → 0.017, 390px 0.095 → 0.002. 시장 순위 카드 추가 · 카드 높이 통일
- **모바일 히어로 문구** — 제목 · 설명 각 1줄, 「주요 지수」 48px 상승. 한 줄 문구로 줄이는 안은 측정 후 기각
- **다우 시세 조회 제외** — 0 값 응답이 캐시를 매번 비우던 문제. 조회 대상을 7종으로 제한, 화면 변화 없음
- **실패 배지 라벨 분리** — 대체값이 남으면 '일시 지연', 값이 비면 '로딩 실패'
- **G1 진행** — README 이미지 8장 상대 경로 전환 · 수치 갱신. 배포본 성능 재측정과 수치 기재 · 회고는 이월

가운데 카드의 문구 한 줄을 줄이려던 세션이 커밋 열다섯 개로 끝났다. 카드 추가와 높이 통일까지는 첫 화면에서 바로 보이는 변화였지만, 그 뒤의 폭 상한과 줄바꿈 다듬기는 보는 사람이 적은 구간이었고, 클래스 한두 줄을 바꿀 때마다 폭 예닐곱 개와 글꼴 두 종을 재는 비용이 변경 크기에 비해 꽤 컸다. 다우 건은 반대로 화면을 아무리 봐도 나오지 않고, README 문장을 코드와 맞춰 봐야 나오는 종류였던 것 같다.
