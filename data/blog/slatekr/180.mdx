README(G1)는 제출물의 본체이고, 채용 담당자가 GitHub에서 직접 읽는다는 전제로 써 왔다. 직전 세션까지 문구와 이미지는 끝났고, 배포본에서 잰 성능 수치와 그 한계, 그리고 회고가 남아 있었다.

계획은 홈 성능을 다시 재서 수치를 적고 회고를 써서 README 내용을 닫는 것이었다. 내용은 계획대로 닫았다. 다만 모바일 수치가 이틀 전보다 나쁘게 나와 실제로 느려진 것인지 가리는 probe가 하나 끼었고, 두 줄로 잡았던 회고는 세 줄이 됐다.

## 이틀 전보다 나빠진 모바일 수치

직전 세션에 홈 히어로 문구와 캐러셀을 고쳤기 때문에, PageSpeed Insights(PSI)로 배포본 홈을 다시 쟀다. 조합마다 세 번씩 재서 중앙값을 냈다.

| 홈 | 10/9 | 10/11 |
|---|---|---|
| 데스크톱 | 성능 95 · 레이아웃 이동(CLS) 0.126 | 성능 99 · CLS 0.015 |
| 모바일 | 성능 85 · LCP 3.9초 | 성능 70 · LCP 5.6초 |

데스크톱의 CLS는 직전 세션의 수정이 배포본에서도 확인된 것이다. 문제는 모바일이었다. 가장 큰 콘텐츠가 그려지는 시점(LCP)이 1.7초 늦어졌는데, 세 번의 범위가 4.1 ~ 5.6초이고 이틀 전에도 5.0초가 한 번 있었으니 세 번으로는 회귀인지 편차인지 가를 수 없었다. 이상한 점도 하나 있었다. LCP로 잡힌 요소는 서버에서 렌더한 히어로 제목인데, 텍스트라면 첫 페인트(FCP) 2.9초와 거의 같이 잡혀야 할 것이 중앙값 기준으로 2초 넘게 벌어져 있었다.

| 선택지 | 판정 |
|---|---|
| 5.6초를 그대로 적고 README를 닫음 | 기각. 직전 세션의 변경이 원인이면 느려진 첫 화면을 모른 채 제출 |
| **코드를 고치지 않는 probe 1회** | **채택.** 수정 금지 · 40분 제한. 측정이 수정으로 번져 범위가 커진 #178의 반복 방지 |

## 두 커밋 비교와 재현

히어로를 고치기 전 커밋과 현재 커밋을 각각 프로덕션 빌드로 띄우고, 느린 기기 조건을 계산이 아니라 실제로 걸어 번갈아 다섯 번씩 로드했다.

```
조건            412px · CPU 4배 감속 · Slow 4G · 캐시 없음
이전 커밋        FCP 1.51초 = LCP 1.51초
현재 커밋        FCP 1.51초 = LCP 1.51초
글꼴 요청 차단    FCP = LCP (1.6 ~ 1.7초)
```

| 가설 | 결과 |
|---|---|
| 직전 세션의 변경이 LCP를 늦춤 | 기각. 두 커밋의 FCP · LCP 동일, 리소스 차이 약 1KB |
| 웹 글꼴이 제목 렌더를 늦춤 | 기각. 글꼴 요청을 막아도 LCP = FCP. 글꼴 교체는 LCP를 다시 기록하지 않음 |
| 제목이 JS 실행 뒤에 그려짐 | 기각. 서버 응답 HTML에 문구 포함, FCP와 LCP 사이에 끝난 JS · long task 없음 |
| **PSI의 계산 방식에서 생긴 값** | **확정.** 같은 방식의 Lighthouse를 로컬에서 돌리자 추정 FCP 2.7초 · LCP 5.0초로 벌어짐 |

PSI는 느린 회선을 실제로 거는 것이 아니라, 빠른 환경에서 한 번 로드한 기록으로 느린 기기에서의 수치를 추정한다. 같은 코드인데도 그 한 번의 로드에서 제목이 그려진 시각이 달라지자 추정 LCP가 5초에서 9초까지 흔들렸고, 이틀 사이의 차이도 이 편차로 보는 것이 맞는 듯했다. 추정이 왜 5초가 되는지는 요청 완료 시각으로 역산해 본 정도여서(제목이 그려지기 전에 끝난 JS와 글꼴 다운로드가 비용에 더해지는 것으로 보인다) 확인된 사실로 다루지는 않았다.

## README에 적은 것

수치는 고치지 않고 70점 · 5.6초를 그대로 적었다. 대신 그 값을 어떻게 읽어야 하는지를 한계 절에 붙였는데, 재현으로 확인한 사실만 싣고 추정한 원리는 뺐다.

| 위치 | 적은 내용 |
|---|---|
| 「품질」 | PSI 표(홈 · 종목 상세 × 모바일 · 데스크톱). 홈 모바일은 범위 병기(성능 66 ~ 77 · LCP 4.1 ~ 5.6초) |
| 「알려진 한계」 본문 | 모바일 LCP 수치와 렌더링 차단 CSS 2개 · 종목 상세 모바일 CLS 0.113과 원인 · 분해하지 않은 차트 컴포넌트(약 1,200줄) |
| 「알려진 한계」 접힘 블록 | 홈은 실제 조건에서 LCP = FCP였고, 둘이 벌어지는 것은 시뮬레이션에서만 재현됨 |

종목 상세의 LCP 3.8초는 손대지 않았다. LCP 요소가 클라이언트에서 그리는 현재가라 홈과 사정이 다르고, 확인하지 않은 것을 홈의 결론으로 덮을 수는 없어서 "같은 확인은 하지 않았다"고 적어 두었다. 커밋 수 같은 수치 줄에는 기준일을 붙여, 이후 커밋마다 고치지 않아도 되게 했다.

## 회고 세 줄

README 끝에 「다시 한다면」 절을 두기로 했었다. 후보는 README에 이미 있는 서술과 이어지는지, 개발 일지로 확인되는지, 한계 절과 겹치지 않는지로 걸렀다.

| 후보 | 판정 |
|---|---|
| **화면 측정 시점** | **채택.** 지정한 웹폰트가 5개월 반 동안 적용되지 않았고(#166), 레이아웃 이동과 PSI는 마무리 단계에야 측정(#178) |
| **선언의 동작 확인** | **채택.** 동작한 적 없던 revalidate와 한 달 멈춰 있던 차트 당일 봉(#174). 둘 다 마무리 단계에 발견 |
| **고르기 전 적용 조건 확인** | **채택(추가).** 적용 나흘 만에 되돌린 Parallel Routes(#045), 거래소 공표가 다음 날 아침이라 당일 적재가 불가능했던 일봉 소스(#098) |
| 재무 데이터 소스 | 기각. "다른 소스였다면 더 정확했다"를 기록이 지지하지 않음 |
| 실패를 null로 돌려주는 규약 | 보류. 코드 읽기(G2)에서 답을 정리한 뒤 |
| `use cache` 미도입 · 렌더 테스트 부재 | 기각. 한계 절과 중복 |

처음에는 위의 두 줄만 쓸 생각이었다. 데이터 정합에 들인 시간이 길었던 터라 그 얘기를 넣을지 고민했는데, "데이터 범위를 줄이겠다"고 쓰면 수집부터 배포까지 혼자 한 일이 후회로 읽힌다. 아쉬움이 남는 쪽은 범위보다 순서였다. 소스와 도구를 정하기 전에 어디까지 되는지를 확인하지 않아 되돌린 선택이 여럿이었고, 세션 기록에서 뽑아 보니 다섯 건이었다(일봉 소스, 상장주식수 소스, 분봉 API, 스케줄러, 라우팅 구조). 그중 고르기 전에 확인할 수 있었던 두 건을 실었다. 재무 소스도 같은 사례로 넣으려 했으나, 대안이었던 KIS 재무는 DART와 값이 맞지 않았고 숨긴 종목을 KIS 값으로 채우는 검증에서도 179개 중 77개만 통과했던 터라 "더 정확했을 것"이라고 쓸 근거가 없었다.

## 데모 영상과 남은 검토

직전 글에는 다음 정규장에 데모 영상을 찍겠다고 적었는데, 넣지 않기로 했다. 영상 링크를 누를 사람이라면 배포 링크도 누를 것이고 실물이 영상보다 낫다. 손으로 찍은 무편집 영상은 품질이 낮으면 오히려 감점이 될 것 같았다. 아무것도 누르지 않는 사람에게 닿는 수단은 README 안에서 재생되는 짧은 GIF뿐이어서, 그건 다음 세션에 README의 렌더된 화면을 검토하면서 정할 생각이다. 지금까지는 문구와 근거만 봤고 GitHub에 그려진 모습을 판정한 적이 없다.

제출 전에 저장소를 통째로 읽히는 검토도 한 번 돌려 봤다. 이번에 반영한 것은 한계의 차트 컴포넌트 한 줄뿐이고, 나머지 지적은 사실 확인부터 필요해 다음 세션으로 넘겼다.

## 정리

- **G1 내용 종결** — 성능 표 · 한계 3줄 · 「다시 한다면」 3줄 · 수치 줄 기준일. 남은 것은 렌더 화면 검토
- **홈 모바일 LCP 판별** — 두 커밋 모두 FCP = LCP 1.5초, 글꼴 무관. PSI의 4.1 ~ 5.6초는 추정값의 편차이고 직전 세션의 회귀가 아님. 수정 없음
- **데스크톱 CLS 확인** — 배포본 0.126 → 0.015
- **회고 세 줄** — 화면 측정 시점 · 선언의 동작 확인 · 고르기 전 적용 조건. 재무 소스 사례는 근거가 없어 제외
- **데모 영상 제외** — 배포 링크보다 나은 점이 없음. 짧은 GIF는 렌더 화면 검토에서 판단

코드는 한 줄도 바꾸지 않은 세션이다. 회고에 적은 세 줄은 모두 확인 없이 넘어간 가정이 뒤에서 비용이 된 경우인데, 5.6초를 회귀라고 짐작하고 고치러 들어갔다면 네 번째가 될 뻔했다. 엄밀히는 홈만 확인한 것이고, 종목 상세의 3.8초가 무엇인지는 아직 모른다.
