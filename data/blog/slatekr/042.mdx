#040에서 종목 상세 페이지를 Parallel Routes로 재설계하기로 결정했고, #041에서 토큰 시스템을 정리했다. 이번 세션은 본 적용 차례다.

작업하면서 화면을 보다가 종합정보 탭과 공시 탭의 개편안이 같이 떠올랐다. 흥미로운 건 그 개편안이 Parallel Routes의 본래 가치인 **비활성 슬롯 상태 보존**을 실제로 활용하게 만든다는 점이었다. #040에서 결정했던 근거가 한 층 더 보강된 셈이다.

순서상 개편안을 먼저 짚고, 그 위에 슬롯 구조를 얹는 흐름으로 정리한다.

---

## 떠오른 개편안 두 가지

### 1. 종합정보 탭 — 2×2 그리드

지금 종합정보 탭은 이런 구조다.

- 약식 차트 (60일)
- 공시 미리보기 (5건)

세로로 두 개. 정보 밀도가 낮고, "한눈에 보는 종합" 역할을 못 한다.

개편안은 한 화면을 **2×2 네 칸**으로 나누는 거다.

```null
┌──────────────────┬──────────────────┐
│  약식 차트       │  재무 요약       │
│  (60일)          │  (2년 + 2분기)   │
├──────────────────┼──────────────────┤
│  최근 공시       │  TBD             │
│  (5~10건)        │  (52주 레인지 등)│
└──────────────────┴──────────────────┘
```

각 칸 우측 상단에는 "전체 보기 →" 버튼을 둔다. 클릭하면 해당 탭으로 이동. 네 번째 칸은 52주 레인지나 거래량 미니 차트가 후보로, 다음 세션에서 확정한다.

### 2. 공시 탭 — 인라인 확장

지금 공시 탭의 UX엔 두 가지가 걸렸다.

- AI 요약 버튼이 **row hover** 시에만 보인다 → 모바일에서 발견 불가능, 안내 메시지가 있어도 전달력 약함
- AI 요약을 클릭하면 **사이드 Sheet**가 열린다 → 목록과 분리된 공간이라 컨텍스트가 끊김

개편 방향:

1. 각 row 우측에 **DART 방문 버튼**과 **AI 요약 버튼**을 상시 노출
2. 공시 텍스트 자체의 외부 링크 동작은 제거 (DART 버튼이 통로)
3. AI 요약 클릭 시 **해당 row 아래로 인라인 확장**되어 그 자리에서 요약이 펼쳐짐
4. 확장된 동안 다른 row들은 **비활성 스타일로 흐려짐**
5. 선택된 row의 AI 요약 버튼은 **닫기 버튼**으로 전환

사이드 패널(`SummarySlate`)은 폐기. 목록과 요약이 같은 공간에 있어 컨텍스트가 끊기지 않는다.

## 개편안이 만드는 의미

여기서 Parallel Routes의 본래 가치가 살아난다.

Parallel Routes의 특징 중 하나는 **비활성 슬롯의 상태가 보존된다**는 점이다. 슬롯이 활성 상태일 때 unmount되지 않고 React tree에 유지된다. 슬롯 안에서 useState가 들고 있던 값, 라이브러리 내부 상태, 스크롤 위치 같은 게 다른 슬롯 동작과 무관하게 살아있다.

#040에서 이 가치를 언급하긴 했지만, 사실 그때 슬롯들엔 보존할 만한 상태가 거의 없었다. 이번 개편안에서 그게 바뀐다.

- **공시 탭** — row 확장 상태가 차트 탭 다녀와도 유지된다. 펼쳐둔 요약이 그대로 펼쳐져 있음.
- **차트 탭** — 다음 사이클에 일봉/주봉 토글, 캔들/선 토글이 들어올 예정. 이런 UI 상태도 같은 방식으로 보존됨.
- **재무 탭** — 연간/분기 토글은 사실 보존 가치가 약하다. 다만 다른 탭에서 보존이 동작하는데 이 탭만 초기화되면 UX가 일관되지 않는다. 일관성 차원에서 함께 적용.

라우트 분리(`/stocks/[ticker]/chart`를 일반 페이지로 두는 방식)로 갔다면 페이지가 통째로 교체되어 다른 탭의 상태는 다 날아간다. Parallel Routes에선 layout과 비활성 슬롯이 유지되니까 상태 보존이 자동으로 따라온다.

> 결정의 근거가 본 적용 단계에서 한 층 더 단단해진 셈이다.

## 슬롯 구조

본 적용 구조는 이렇게 잡았다.

```null
app/stocks/[ticker]/
├── layout.tsx              ← {tab} 슬롯 받음
├── page.tsx                ← null
├── default.tsx             ← children fallback
└── @tab/
    ├── default.tsx
    ├── page.tsx            ← /stocks/[ticker] (종합정보)
    ├── loading.tsx
    ├── error.tsx
    ├── chart/page.tsx      ← /stocks/[ticker]/chart
    ├── financials/page.tsx ← /stocks/[ticker]/financials
    └── disclosures/page.tsx← /stocks/[ticker]/disclosures
```

핵심은 슬롯이 **`@tab` 하나**라는 점이다. 내부에 sub-route 4개를 두고 URL이 바뀌면 슬롯 안의 page만 갈아끼워진다.

처음엔 슬롯을 4개(`@overview`, `@chart`, `@financials`, `@disclosures`) 따로 두는 그림을 생각했는데, Parallel Routes의 기본 동작은 **모든 슬롯을 동시에 렌더**하는 거였다. 슬롯 4개를 깔면 4개가 한 화면에 다 보인다. 슬롯은 영역 분리 도구지 URL로 영역을 전환하는 도구가 아니다. URL 전환은 슬롯 안의 sub-route가 담당한다.

layout 시그니처는 다음과 같다.

```tsx
export default async function StockDetailLayout({
  children,
  tab,
  params,
}: {
  children: React.ReactNode;
  tab: React.ReactNode;
  params: Promise<{ ticker: string }>;
}) {
  // ... StockHeader + StockMetrics + StockTabNav 고정
  return (
    <main>
      {/* 고정 영역 */}
      <StockTabNav ticker={ticker} />
      <div>{tab}</div>
    </main>
  );
}
```

`children`은 받기만 하고 렌더에는 사용하지 않는다. 실제 콘텐츠는 `{tab}` 슬롯이 담당하게 된다.

## default.tsx

작업 중 한 군데 막혔다.

빌드도 통과하고 dev 서버에서 탭 전환도 잘 됐다. 그런데 `/stocks/005930/chart`로 **hard refresh** (브라우저에서 직접 진입 또는 새로고침)하니 404가 떴다.

원인은 `children` implicit slot의 fallback 부재였다.

- Next.js는 모든 슬롯에 `default.tsx`가 필요하다
- `children`도 슬롯이므로 fallback이 있어야 한다
- soft navigation은 이전 상태를 들고 있어서 문제없지만, **hard navigation은 이전 상태가 없어** Next.js가 `children`에 무엇을 채울지 결정 못 한다 → 404

해결은 루트와 `@tab` 양쪽에 `default.tsx`를 두는 것.

```tsx
// app/stocks/[ticker]/default.tsx
export default function Default() {
  return null;
}
```

## 부수 변경

본 적용 과정에서 콘텐츠 컴포넌트도 같이 손봤다.

**`StockChartSection`에 `limit`과 `label` prop 추가**
같은 컴포넌트가 종합정보 탭(60일 약식 차트)과 차트 탭(250일 전체 차트)에서 같이 쓰여야 했다. `StockChart`의 제목도 `"최근 1년"` 하드코딩에서 prop으로 분기.

**`StockChart`를 `next/dynamic` lazy load로 전환**
`lightweight-charts`가 무거운 라이브러리인데 정적 import 상태였다. 슬롯이 분리되면서 종합정보 탭 진입 시 차트 탭의 큰 차트 번들을 안 받게 됐다. #040에서 약점으로 잡혀있던 항목.

**`getCorpCode`와 `getDisclosures`에 `React.cache` 적용**
종합정보 탭의 공시 미리보기와 공시 탭이 같은 요청 안에서 호출될 가능성이 있다. DB 왕복을 한 번으로 합치기 위해서.

세 가지 모두 슬롯 분리가 만들어준 자연스러운 정리 지점이었다.

## 정리

이번 작업의 본체는 슬롯 구조 적용이었지만, 개편안과 함께 봤을 때 Parallel Routes의 본래 가치가 살아난다. 결정 자체는 #040에서 끝났는데, 본 적용 단계에서 그 결정이 더 단단해졌다.

탭 전환 시 layout(헤더·지표·nav)은 그대로 남고 슬롯만 갈아끼워진다. 네이버 증권이나 기존 증권사 HTS류처럼 페이지 전체가 깜빡이며 다시 그려지는 레거시 패턴과 다른, 한 단계 모던한 동작이다. 같은 정보 구조를 모토로 했지만 사용자 경험은 한 발 더 나가는 구도가 된다.
