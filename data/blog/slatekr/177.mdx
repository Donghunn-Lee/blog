관심종목은 로그인 없이 쿠키로 식별해 서버에 스냅샷을 백업한다. 직전 글에서 localStorage만 비고 쿠키가 남은 상태로 페이지를 열면, 서버 조회가 끝나기 전에 넣은 편집 한 건이 서버 목록 전체를 덮는다는 것을 재현했고, 병합하지 않고 로드 중 편집을 막기로 정해 두었다(F123). 이번 세션은 그 구현에서 시작했다. #170부터 프로젝트 마무리 전 해소해야하는 오류를 처리중이다.

계획은 F123 하나였다. 마무리 일정을 당기면서 같은 조사에서 나온 세 건, 곧 실패가 빈 값으로 보이는 곳(F124), 지수 페이지의 숫자 표기(E98), 전부 실패해도 정상 종료하는 수집 스크립트(F125)를 함께 넣었고, 지수 시각에 날짜를 붙여 한국 시간으로 통일하는 작업(E99)을 새로 추가했다. 다섯 건을 모두 끝냈는데 판단이 갈린 곳은 F123과 E99였다.

## 분기 삭제로 막히지 않는 모달 경로

차단안은 두 부분이다. "조회 중에 편집이 있었으면 로컬이 더 새것"이라는 분기(#141)를 지워 로드 결과를 항상 서버가 덮게 하고, 로드가 끝날 때까지 편집을 비활성화한다. 구현에 앞서 직전 글에서 코드로만 따라갔던 두 경로를 먼저 실측했다.

```
그룹 관리 모달
서버 3건 → localStorage 삭제 → 조회 응답을 붙잡아 둠
→ 모달 열기: 빈 기본 상태의 사본을 잡음
→ 응답 도착: 스토어가 서버 3건으로 교체됨
→ 모달에서 그룹 1개 추가 후 저장: 사본으로 전체 교체 → 서버 3건 → 0건

메모
서버 2건 → 조회 중 1건 저장 → 응답 도착 시 서버 2건이 로컬을 덮음
→ 방금 저장한 메모 유실, 알림 없음
```

모달은 열 때 스토어의 사본을 잡고 저장할 때 전체를 교체한다. 모달을 여는 것은 편집이 아니어서, 분기를 지워도 이 경로는 그대로 남았다. 메모는 반대로 서버는 지켜지지만 방금 쓴 내용이 조용히 사라진다. 서버 로드 전에 편집하는 케이스 자체가 재현성은 희박하지만 해결해서 나쁠 것은 없다는 판단에 착수했고, 두 경로 모두 저장 시점이 아니라 편집을 시작하는 시점을 막아야 했다.

## 차단 조건과 위치

| 후보 | 판정 |
|---|---|
| 저장 · 삭제 동작마다 차단 | 기각. 진입점 5곳, 모달은 열린 뒤에는 이미 사본을 잡은 상태 |
| **여는 쪽 4곳 차단** | **채택.** 관심 등록 버튼 · 메모 버튼 · 그룹 관리 열기 · 목록의 행 삭제. 저장과 삭제는 팝오버 · 모달 안에 있고, 로드가 끝난 뒤 로드 중으로 돌아가는 전이가 없음 |
| 로드 중(loading)에만 차단 | 기각. 버튼이 동기화 훅보다 먼저 hydration되면 그 틈의 편집이 로드에 덮임 |
| **로드 전(idle)부터 차단** | **채택.** 서버 렌더의 초기 상태와 같음. 첫 방문자는 조회 없이 바로 완료 상태로 넘어가 영향 없음 |

비용은 새로고침 직후 버튼이 0.1~0.2초 더 비활성인 것이다. 개발 환경에서 잰 값이고 조회 자체가 0.1초 남짓이라 사실 체감은 거의 없다. 구현 중에 걸린 것은 목록의 행 삭제 버튼이었다. 기본 비활성 스타일은 클릭을 통과시켜서, 클릭이 행을 감싼 링크로 빠져 종목 페이지로 이동했다. 이 버튼만 클릭을 받되 반응하지 않는 표현으로 따로 두었다. 수정 뒤 같은 절차를 다시 돌렸고 서버 3건은 그대로 남았다.

## 현지 시각으로 남아 있던 곳

지수 헤더에는 장중이면 갱신 시각이, 마감 뒤에는 마감 시각이 붙는다. 여기에 날짜가 없었고, 해외 지수 일부는 현지 시각으로 보였다. 어디가 현지 기준인지부터 화면마다 문자열과 값의 출처를 표로 뽑았다. 시각 라벨은 #150에서 이미 한국 시간으로 맞춰 둔 상태였고, 현지 기준은 다른 세 곳에 남아 있었다.

| 표시 | 기준 | 조치 |
|---|---|---|
| 헤더의 갱신 · 마감 시각 | 한국 시간 | 날짜 추가 |
| 국내 장중 시각 | 브라우저 시간대 | 한국 시간으로 고정 |
| 해외 "전일 종가"의 날짜 | 거래소 거래일 | 한국 시간 마감 시점으로 교체 |
| 해외 분봉 차트의 눈금 · crosshair | 거래소 현지 시각 | 한국 시간으로 표시 |
| 일봉 날짜 · 기준일 | 거래소 거래일 | 유지 |

## 값은 두고 표시만 변환

분봉의 시각 값은 거래소 현지의 시 · 분을 그대로 담고 있다. 이 값을 한국 시간으로 바꾸는 쪽이 단순해 보였지만, DB 봉과 실시간 봉의 병합, 마감 후 프린트 병합, 직전 종가 조회, 오늘 · 전일 구간 필터, 전일 구간 흐림 처리, 초기 표시 범위까지 여섯 곳이 이 값을 현지 시각으로 읽고 있었다. 미국 세션은 한국 시간으로 자정을 넘기 때문에, 값을 옮기면 같은 날로 묶던 계산이 전부 어긋난다.

| 후보 | 판정 |
|---|---|
| 봉의 시각 값을 한국 시간으로 변환 | 기각. 여섯 곳이 현지 시각 전제에 의존, 세션이 자정을 넘어 날짜 기준 계산이 깨짐 |
| **값은 그대로, 눈금과 crosshair에서만 변환** | **채택.** 변환 함수 1개. 관련 시간대와의 차이가 전부 정시 단위라 눈금 위치와 5 · 15분 봉 경계 유지 |

일 · 주 · 월 차트에 변환이 새면 거래일이 하루 밀린다. 그래서 지수 차트는 해외 지수의 분봉일 때만 시간대를 넘기고, 그리는 쪽은 분봉 표시일 때만 그 값을 쓰도록 양쪽에서 막았다. 눈금 문자열은 직접 만들었는데, 차트 라이브러리의 기본 포맷이 자정을 24:00으로 내고 한국 시간 자정이 미국 세션 한가운데에 오기 때문이다.

```
S&P500 1분 차트 (10월 7일 세션)
이전   눈금 11:00 … 16:00 · 마지막 봉 10-07 16:00
이후   눈금 00:00 … 05:00 · 마지막 봉 10-08 05:00   ← 헤더 "장 마감 · 10.08 05:00"과 일치
```

## 날짜를 붙이면서 없앤 분기

#150에서 해외 마감 라벨을 국내와 같은 두 상태로 맞췄다. 한국 시간으로 환산한 마감 시각이 오늘이면 "장 마감 · 05:00", 아니면 "전일 종가 · MM.DD"다. 이 구분은 날짜 없는 시각이 오늘일 때만 읽히기 때문에 둔 것이어서, 날짜를 붙이자 조건이 필요 없어졌다. 지금은 세션이 언제였든 "장 마감 · 10.08 05:00" 하나로 나오고, 같은 세션이 토요일에는 한국 시각으로 일요일에는 현지 날짜로 바뀌던 것도 함께 사라졌다.

어긋남은 둘 남는다. 미국 지수는 헤더가 10월 8일 05:00인데 일봉과 기준일은 10월 7일이다. 시점은 한국 시간으로, 거래일은 거래소 일자로 둔다는 기준이고, 일봉까지 옮기면 10월 7일 세션이 8일 봉이 되므로 받아들였다. 다른 하나는 국내가 여전히 "전일 종가 · MM.DD"를 쓴다는 점이다. #150에서 일부러 맞춘 대칭을 한쪽만 푼 셈이라 좀 걸리긴 한다.

## 재무 조회 실패의 표시

실패가 빈 값으로 보이는 곳(F124) 가운데 종목 상세의 핵심 지표는 계획과 다르게 고쳤다. 재무 조회만 실패하면 PER · EPS · BPS가 "—"로 남는다고 보고 실패한 값마다 배지를 붙일 생각이었는데, 값마다 어느 조회에 기대는지 따져 보니 지표 여섯 개가 전부 재무를 거쳤다. 계획대로면 값이 하나도 없는 섹션에 배지만 여섯 개가 붙는다. 재무 실패는 섹션 오류로 올리고, 가격만 실패하면 가격이 필요한 세 지표에만 "—"와 지연 배지를 붙였다. 적자나 기준 불일치로 일부러 숨긴 "—"와 실패의 "—"가 같은 모양이던 것도 이 배지로 갈린다. 함께 보려던 가격 통계는 이미 실패와 빈 상태를 구분하고 있어서 손대지 않았다.

## 정리

- **F123 종결** — "로컬이 더 새것" 분기 삭제, 로드 전 · 로드 중 편집 진입점 4곳 비활성. 모달 · 메모 경로 실측 후 같은 절차로 재검증, 쿠키 이름 상수 단일화
- **E99 신설 · 종결** — 지수 시각 라벨에 날짜 추가, 해외 마감은 항상 한국 시간 마감 시점. 해외 분봉 차트는 값 유지 · 눈금과 crosshair만 변환
- **F124 종결** — 재무 실패는 섹션 오류, 가격만 실패는 지표 3개에 지연 배지. 관심종목 페이지의 실패 기준을 홈과 통일, 홈 지수의 실시간 표시는 실시간 값이 있을 때만. 가격 통계는 조치 불요
- **E98 종결** — 지수 페이지 숫자를 홈과 같은 포맷으로, 당일 차트의 마지막 값 라벨 숨김
- **F125 종결** — 수집 스크립트 5개가 시도한 대상이 전부 예외로 끝나면 비정상 종료, collector 테스트 CI 편입. 외부 API의 오류 응답 전량은 backlog

작은 수정 다섯 건으로 잡았는데 계획 그대로 간 것은 숫자 표기 하나였다. 나머지는 고치기 전에 현재 동작을 표로 뽑는 단계에서 전제가 한 번씩 틀렸다. 엄밀히는 계획이 틀렸다기보다 직전 조사에서 추정으로 적어 둔 것을 확인 없이 옮긴 쪽에 가깝다. F125는 예외만 잡고 오류 응답은 남겨서 절반만 닫혔다.
