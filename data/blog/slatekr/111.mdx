#110 마무리에서 예고한 대로 리팩토링 sweep에 들어갔다. 첫 순번은 R4 — 지수 API 응답의 명시 필드 구조를 Record로 통일하는 작업이다. 일요일이라 장 실측이 필요한 항목들은 어차피 못 하니, 시장 시간과 무관한 리팩토링이 정확히 맞는 날이기도 했다. 세션 후반엔 작업하며 따로 메모해뒀던 자잘한 발견들을 로드맵으로 병합했는데, 그중 countup 건 하나가 즉결 크기라 이번 세션에 같이 처리했다.

---

## 명시 필드가 쌓아온 번역표

국내 지수 route 응답은 이런 모양이었다.

```ts
type IndexQuotes = {
  kospi: IndexCellData;
  kosdaq: IndexCellData;
  kospi200: IndexCellData;
  kosdaq150: IndexCellData;
};
```

지수가 4종 고정이던 시절엔 자연스러운 모양이다. 문제는 코드베이스의 나머지가 `"KOSPI"` 같은 코드 union으로 지수를 다룬다는 것 — registry에서 타입이 파생되고, 순회도 코드 배열로 돈다. 응답만 lowercase 필드명이라, 화면 컴포넌트마다 코드→필드명 번역표(`CELL_KEY`)를 따로 들고 있어야 했다.

이 모양이 유지된 데는 이유가 있다. #077에서 실패 flag를 붙일 때 "응답 모양을 바꾸면 소비처를 전부 수정해야 하니, 모양은 두고 맨 위에 map만 얹는다"로 갔었다. 그 시점엔 맞는 판단이었는데, 이후 소비처가 계속 늘면서 번역표도 같이 늘었다. 지수는 12종이 됐고, #110에서 신규 route를 처음부터 Record로 만들면서 구패턴과 신패턴이 공존하는 상태가 됐다. 이번 작업은 그때 미뤄둔 모양 변경을, 이번엔 파급을 전수 실측한 뒤에 치르는 것이다.

---

## 소비처 전수 확인 — 필드명은 번역표 안에만 있었다

대상은 세 route다. 국내 quotes, 국내 intraday, 그리고 해외 intraday(spx·comp·ndx 명시 키). 손대기 전에 훅과 컴포넌트를 따라가며 응답 필드명이 어디까지 퍼져 있는지 전부 훑었다.

결과가 작업을 쉽게 만들어줬다. route와 훅 밖에서 필드명을 직접 참조하는 코드가 **한 곳도 없었다.** 전부 `quotes[CELL_KEY[code]]` 식으로 번역표를 경유한다. 그 말은, 응답 키를 코드값으로 바꾸면 번역표가 통째로 사라지고 소비처는 `quotes[code]` 직접 인덱싱만 남는다는 뜻이다. 고쳐야 할 곳이 곧 지워질 곳이었다.

세다가 틀린 것도 하나 있었다. 번역표를 5개로 알고 시작했는데 지우면서 grep을 돌리니 8개가 나왔다 — 4개 파일이 국내용·해외용을 하나씩 들고 있어서, 파일 수로 센 게 정의 수와 어긋난 거다. 지울 파일 자체는 같아서 결과에 영향은 없었다.

---

## 바꾼 것 하나, 안 바꾼 것 넷

바꾼 건 응답 키 축뿐이다. 세 route 모두 `Record<코드 union, ...>`로 전환하고, 조립은 코드 배열 순회 + `Object.fromEntries`로 통일했다. lowercase 변환 없이 코드값을 그대로 키로 쓴다 — #110 신규 route와 같은 모양이다.

나머지는 전부 의도적으로 두고 갔다.

| 유지한 층 | 만들어진 곳 | 두고 간 이유 |
|---|---|---|
| intraday failed 맵 계약 | #077~078 | 실패 UI까지 배선 완료된 계약. 키 모양만 바뀐다 |
| quotes의 null 흡수 + 캐시 evict | #075 | 실제 캐시 오염 사고의 수정 결과물 |
| 캐시 키의 세션+거래일 축 | #102 | 별도 아크로 종결된 층. 캐시는 code 단위로 돌아서 이번 diff에 안 걸린다 |
| envelope 타입의 훅 co-locate | — | 소비처가 훅 경유뿐이라 shared 승격은 근거 없는 확장 |

각자 자기 문제를 풀러 이미 손댄 영역들이라, 여기까지 건드리면 shape 리팩토링이 재설계로 번진다. 다만 "확인된 층"이라는 말의 무게가 층마다 달랐다 — null 흡수는 실제 사고를 겪고 고친 거지만, failed 맵은 구현 시점 검증 이후 실전 발화 기록이 없다. 마침 이번에 failed의 키 모양이 바뀌니, 실패 경로는 어차피 밟아야 했다.

그래서 검증에 강제 실패 주입을 넣었다. 코스닥150 하나만 fetch가 throw하게 임시로 심고 응답을 보니 `failed.KOSDAQ150=true`, 나머지 세 지수는 40봉씩 정상 — 부분 실패 격리가 새 모양 위에서 그대로 살아 있었다. 주입을 원복한 뒤 파일 hash가 주입 전 baseline과 일치하는 것까지 확인하고 닫았다. #077 때 "강제 flag로만 검증했다"고 남겼던 층이 모양을 바꾸면서 실측 한 번을 더 얻은 셈이다.

정적 검증은 tsc·lint·build·vitest 395개 통과, 세 route 응답의 키가 전부 코드값으로 나오는 것도 curl로 확인했다. 번역표 8개는 grep 기준 정의·참조 0건으로 소멸.

## 지수 탭 전환에서 도는 countup

메모해뒀던 것 중 하나가 이거였다. 지수 차트 페이지에서 탭을 바꾸면 가격이 카운트업 애니메이션으로 도는데, 어떤 지수 간 이동은 돌고 어떤 이동은 안 돈다. 애초에 탭 전환은 값이 변한 게 아니라 보는 대상을 바꾼 거라 도는 것 자체가 이상하다.

probe를 돌려보니 프레임이 바뀌었다. 지수 쪽 countup은 전부 `from={price} to={price}`로 넘기는 패턴이라 마운트 애니가 원천 봉쇄돼 있고, 폴링으로 값이 갱신될 때만 돈다 — 내가 원하던 정책("폴링 갱신 시에만 애니")이 사실상 이미 구현돼 있던 거다. 구멍은 두 개뿐이었다.

- **탭 전환** — detail pane이 key 없이 리렌더만 되니, 양쪽 지수가 모두 live면 countup 인스턴스가 살아남아 `to`만 이전 지수 가격→새 지수 가격으로 교체된다. 값 변화 신호가 아닌데 값 변화처럼 도는 유일한 경로
- **종목 헤더** — 유일하게 from(SSR 가격)≠to(라이브 가격)로 넘겨서 마운트 애니가 가능한 사용처

부분 비대칭도 여기서 풀렸다. 애니가 안 도는 이동은 상대편이 fallback 분기(EOD 표시)라 countup이 언마운트·재마운트되는 경우다. 다만 S&P500이 안 돌았다는 관측 하나는 코드로 설명이 안 됐다 — 나스닥 계열과 완전히 같은 경로를 타서, 관측 시점에 분봉 응답이 일시적으로 비어 있었다는 데이터 조건으로만 성립한다. 이건 해외 intraday 모니터링 항목(F27)에 관측 1건으로 적어뒀다.

수정은 정책을 컴포넌트에 내장하는 쪽으로 갔다. `from`/`to` 두 prop을 `value` 하나로 바꿔서 "마운트는 정적, 이후 value 변경만 애니"가 API 수준에서 강제되게 하고, detail pane엔 `key={selected}`를 줘 탭 전환 시 remount로 리셋시켰다. from/to를 잘못 넘겨 마운트 애니가 생기는 실수 자체가 불가능해진 게 트릭 유지보다 나은 점이다. 종목 헤더의 첫 quote 도착 애니는 실제 값 변화 신호라 그대로 뒀다 — 폐장 시간대엔 SSR값과 첫 quote가 같아서 어차피 안 돈다.

폴링 갱신 애니가 살아 있는지는 일요일이라 확인할 장이 없다. 장중 관측으로 넘겼다.

## 지수 페이지엔 해외 현재가가 없다

countup을 정리하다 **새로 추가한 해외 지수들은 애니메이션이 없다** 는 것을 확인했다. 간단했다. 애니메이션을 걸 라이브 값이 그 페이지에 없었다.

| 위치 | 해외 현재가 |
|---|---|
| 홈 (#110) | 8종 전부 quote 폴링 |
| 지수 페이지 | S&P500·나스닥·나스닥100만 지연 분봉 값, 나머지 5종은 전일 종가 고정 |

원인은 구조의 나이 차이다. 지수 페이지의 해외 live 판정은 #101에 만들어졌는데, 그 시점 해외 라이브 소스는 분봉뿐이라 "live = 최신 분봉 존재"로 정의될 수밖에 없었다. #110에서 현재가 quote route가 생기며 그 전제가 깨졌는데, 배선이 홈에만 갔다. 홈에서 닛케이 라이브 값을 보다가 지수 페이지로 들어가면 전일 종가가 보이는, 페이지 간 신선도 불일치가 지금 상태다.

수정 자체는 quote route를 지수 페이지에도 소비시키고 live 판정을 quote 우선으로 넓히는 배선 작업이다 — KIS 호출도 캐시도 이미 있다. 다만 분봉 값과 quote가 공존할 때의 우선순위, 지수별 세션 기준시각 라벨 같은 표시 설계가 붙어서 즉결 크기는 아니다. E49로 등록하고 다음 세션 최우선으로 올렸다. 분봉 승격(E43)과는 독립이라, 분봉 없는 지수도 현재가부터 먼저 살릴 수 있다.

## 정리

- **R4 종결** — 3 route 응답을 코드 union 키 Record로 통일, 번역표 8개 소멸. failed 계약·캐시 축 등 검증된 층은 스코프 밖으로 재단
- **강제 실패 주입** — 새 모양 위에서 부분 실패 격리 실측, 원복 hash 일치 확인
- **countup 정책 통일** — value 단일 prop으로 "폴링 갱신 시에만 애니"를 API에 내장, 탭 전환 오재생은 remount로 차단
- **E49 신설** — 지수 페이지 해외 현재가 부재 발견, 다음 세션 최우선 등록

diff만 보면 삭제가 많은 조용한 세션인데, 실속은 probe와 문답 쪽에 있었다. 번역표가 왜 생겼는지 거슬러 올라가니 #077의 보수적 결정이 나왔고, countup을 파니 정책은 이미 있고 구멍만 있었고, 그 구멍을 따라가니 페이지 하나가 현재가를 통째로 못 받고 있었다. 리팩토링 세션의 수확이 리팩토링 바깥에서 나온 셈이다.

## 다음 작업

메모로 흩어져 있던 발견들을 로드맵으로 병합하면서 다음 순번도 같이 정리됐다.

- **E49** — 지수 페이지 해외 현재가 배선. 홈과의 신선도 불일치 해소가 목적이고, 헤더 값 우선순위와 세션 라벨 설계가 같이 붙는다
- **F28** — 프리마켓 08:20 창 실측. 조조 세션이 잡히는 날 우선 전환

E49는 사용자가 실제로 보는 값의 문제라 sweep류보다 앞에 뒀다. 이번에 등록한 sweep 항목들(로딩 상태·차트 폴리싱·스타일가이드 정합)은 그 뒤를 잇는다.
