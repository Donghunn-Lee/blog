종목별 메모(X8)는 #125 트리아지에서 관심종목 서버 저장(X7) 뒤에 붙이기로 한 항목이다. X7이 어제 닫혔고, 로그인 없이 브라우저를 식별해 서버에 저장하는 인프라가 생겼으니 그 위에 메모를 얹을 차례였다. 남겨뒀던 결정은 둘이었다. 쿠키를 어디서 발급할지, 메모 UI를 상세 페이지 어느 패널에 둘지.

일요일 전일을 배정했고, 서버 2커밋 → 상세 헤더 4커밋 → 관심종목 페이지 2커밋 → 문서 1커밋으로 아홉 개를 닫고 prod까지 확인했다. 남겨뒀던 결정 둘은 막상 착수하니 둘 다 앞선 결정 하나에 딸려 있었다.

---

## 메모를 관심종목에 붙일지, 따로 둘지

계획서에는 "서버 저장 인프라 위 memo 컬럼 + CRUD 소형"으로 적어뒀었다. 관심종목 스냅샷에 메모 필드를 하나 얹는 그림인데, 착수 전에 이게 정말 원하는 기능인지부터 다시 물었다.

| 후보 | 판정 |
|---|---|
| 관심종목 항목의 속성으로 | 기각. 관심 등록한 종목에만 메모 가능, 관심 해제하면 메모도 사라짐. 저장 경로는 기존 PUT 그대로라 코드는 절반 |
| **독립 엔티티** | **채택.** 관심 여부와 무관하게 아무 종목에나 남기고, 메모한 종목만 따로 모아 볼 수 있음. route·스토어·동기화를 새로 둠 |

메모를 쓰는 장면을 떠올리면 관심종목에 담으면서 이유를 적는 경우도 있지만, 그냥 눈에 밟혀서 한 줄 남기는 경우가 더 많을 것 같았다. 관심 해제와 메모 삭제가 묶이는 것도 어색했다. 코드가 두 배가 되더라도 독립으로 가기로 했고, 이렇게 정하니 나머지 둘은 자연스럽게 풀렸다. 편집 UI는 관심종목 맥락에 종속되지 않으니 종목 상세 헤더에 두면 되고, 쿠키 발급은 probe해보니 이미 헬퍼로 분리되어 있어 메모 PUT에서 같은 함수를 부르면 끝이었다. 미결로 적어뒀던 것이 실은 미결이 아니었다.

## 저장 모양은 X7 그대로

독립으로 가되 저장 구조를 새로 설계하지는 않았다.

| 후보 | 판정 |
|---|---|
| ticker별 행 + CRUD route | 기각. route 표면이 늘고 동기화 규칙을 따로 짜야 함 |
| **JSONB 스냅샷 한 행, 서버 우선 덮어쓰기** | **채택.** X7의 route·동기화·롤백·배지·조회 게이트를 그대로 복제. 메모 50개 × 500자여도 25KB 남짓이라 Neon 왕복 대비 무의미 |

```ts
type MemoSnapshot = {
  memos: Record<Ticker, { body: string; name: string; market: "KOSPI" | "KOSDAQ"; updatedAt: string }>;
};
```

종목명과 시장을 메모에 같이 넣은 건 관심종목 페이지 때문이다. 메모한 종목을 모아 보여주려면 이름이 필요한데, 관심·최근 조회 스토어 어디에도 없는 종목이 있을 수 있다. 저장 시점에 헤더가 이미 들고 있는 값을 동봉하는 게 최근 조회 스토어와 같은 방식이고, 종목명이 바뀌었을 때 stale해지는 것도 같은 수준으로 받아들였다.

본문 500자, 항목 200개로 상한을 뒀고, 본문을 비우고 저장하면 키를 지우는 것으로 삭제를 대신한다. 서버는 빈 본문을 거부하고 trim은 클라이언트가 한다. 요청 본문 파서는 X7 route에 스키마가 박혀 있어 스키마를 인자로 받게 바꿔 `lib/`로 옮겼다.

## 동기화 훅 재사용

X7의 동기화 훅을 그대로 복사한 뒤 관심종목 스냅샷에 묶여 있던 부분만 제거했다.

| 걷어낸 것 | 이유 |
|---|---|
| 전체 치환 시 종목 메타 GC | 메모엔 메타 테이블이 없음 |
| 조회 중 편집 시 서버 값을 기준선으로만 잡고 로컬 유지 | 서버 우선 규칙 하나로 단순화. 조회 창은 페이지 로드 직후 수백 ms라 편집이 끼어들 여지가 없음 |
| 빈 스냅샷 판정의 "기본 그룹 1개" 가정 | 키 개수만 보면 됨 |
| 로컬 데이터 1회 마이그레이션 | 신규 기능이라 선행 로컬 데이터가 없음. 마커 쿠키 없으면 조회 생략, 첫 저장이 쿠키를 만듦 |

265줄이 219줄이 됐다. 두 훅을 제네릭으로 합치지는 않았다. 두 번째 사용에서 공용화하면 세 번째가 어떤 모양일지 모르는 채로 인터페이스를 굳히게 되고, 지금은 복제본이 무엇을 빼고 무엇을 남겼는지 훅 하나만 읽어도 보이는 쪽이 낫다고 봤다. 리팩토링 sweep(R2)에 적어뒀다.

한 가지는 알고 남겼다. 쿠키를 지운 뒤 로컬에 메모가 남아 있으면 마커가 없어 조회를 건너뛰고 로컬을 기준선으로 잡는데, 이때 X7처럼 즉시 PUT하지 않는다. 다음 편집에서 전체 스냅샷이 올라가니 결과는 같고, 그 사이 "저장됨" 상태가 실제와 어긋나는 것만 남는다(F84).

## 편집은 상세 헤더에서만

처음엔 관심종목 행에서도 편집하려 했는데, 행에 "최근 공시 N건 → 공시 탭"이 있는 것처럼 행은 표시만 하고 편집은 상세로 보내는 게 단순했다. 관심 행에는 "메모 없음" 상태를 그릴 필요조차 없어졌다.

헤더의 관심종목 버튼 왼쪽에 아이콘 버튼을 두고, 누르면 Popover 안에 textarea와 저장 버튼이 뜬다. 관심종목 버튼은 "관심종목 추가"가 좁은 폭에서 길어 "관심 등록"으로 줄이고 모바일에선 별만 남겼다.

![](/static/images/velog/459a2d28-be7a-4669-8aa6-244651c227df-image.png)

첫 구현을 써보고 세 군데를 고쳤다. 메모가 있을 때 버튼 배경과 테두리가 눌린 상태로 바뀌던 것을 아이콘 색만 바뀌게 했고, 하단의 취소 버튼이 헤더의 닫기와 동작이 같아 없앴다. 삭제는 처음에 AlertDialog로 확인을 받았는데, 메모 한 건 지우는 데 화면 전체가 어두워지는 건 과했고 Popover 바깥에 portal로 뜨는 다이얼로그가 Popover의 외부 클릭 판정에 걸려 닫고 여는 순서까지 강제됐다. Popover 본문을 "정말 메모를 삭제할까요?" 확인 뷰로 바꾸는 것으로 교체하니 portal도 오버레이도 없어졌다.

폰트에서 잠깐 헤맸다. 데스크톱 11px로 줄이면서 모바일은 shadcn 관례대로 16px을 유지했는데, iOS가 16px 미만 입력창에 포커스하면 확대되는 걸 막기 위한 규칙이라고 알고 있었다. 그런데 헤더 검색창은 모바일 14px인데 확대되지 않는다. 확인해보니 #104에서 iOS일 때만 viewport에 `maximum-scale=1`을 런타임으로 넣는 컴포넌트가 이미 확대를 막고 있었고, 폰트 16px 규칙은 이 프로젝트에 존재하지 않았다. 반응형 값이 이미 들어 있는 타이포 role 토큰(`text-micro`, 10/11px) 하나로 끝냈다.

## 관심종목 페이지

관심 행에는 처음에 아이콘만 뒀는데, "최근 공시 2건" 바로 왼쪽에 놓이니 그 라벨의 접두 아이콘처럼 읽혔다. 좌측 종목코드 옆으로 옮기는 안은 눈에 안 띌 것 같아 접고, 공시 라벨과 같은 문법으로 "메모 [아이콘]" 텍스트 라벨을 만들어 간격을 조금 벌리는 것으로 정리했다. 링크가 아니라는 걸 텍스트는 무채색, 아이콘만 파란 계열로 구분했다.

![](/static/images/velog/d9994ee8-6957-4e52-acb9-01b1a790054b-image.png)


메모한 종목을 모아 보는 건 "최근 조회" 옆에 "메모" 고정 탭으로 뒀다. 최근 조회가 스토어에 없는 페이지 상수인 것과 같은 방식이라 그룹 관리 모달은 손댈 게 없었고, 고정 탭 둘과 커스텀 그룹 사이에 구분선만 넣었다. 탭 안의 행은 메모 스토어를 최근 편집 순으로 정렬해 최근 조회 항목과 같은 모양으로 넘긴다.

## 검증

| 시나리오 | 결과 |
|---|---|
| 메모 저장 | PUT 1건, 아이콘 전환, 쿠키 만료 갱신 |
| 새로고침 | GET 1건, 내용 유지 |
| 본문 비우고 저장 | PUT 본문에서 키 제거, 아이콘 복귀 |
| 외부 클릭·esc | 편집 중이던 내용 폐기 |
| 관심종목 아닌 종목에 메모 | 메모 탭에만 표시, 행 클릭 시 상세 이동 |
| 메모 삭제 | 관심 행 라벨·메모 탭 항목 즉시 제거 |
| prod | Set-Cookie 2건 `Secure`, 새로고침 유지, 메모 탭 표시 |

쿠키가 새로 발급되는 장면은 이번에 못 봤다. 브라우저에 X7 쿠키가 이미 있어 만료 갱신만 관측됐는데, 같은 함수를 부르는 경로라 X7 검증으로 갈음했다.

## 정리

- **X8 종결** — 관심종목과 독립된 메모. 스냅샷 한 행·route·스토어·동기화 훅을 X7에서 복제, 상세 헤더 Popover 편집기, 관심 행 라벨, /watchlist 메모 고정 탭. 9커밋
- **결정 하나가 둘을 풀었음** — 독립 엔티티로 정하니 UI 위치가 정해지고, 쿠키 발급 미결은 probe로 이미 해결된 것이었음
- **복제하되 합치지 않음** — 동기화 훅은 네 곳을 걷어낸 복제본. 공용화는 세 번째 사용에서
- **UI는 써보고 세 번 고침** — 트리거 강조 제거, 취소 버튼 제거, AlertDialog를 Popover 내 확인 뷰로
- **F84 backlog** — 쿠키 삭제 후 로컬 잔존분 즉시 미동기화

X7이 하루에 끝난 건 결정이 코드 앞에 있어서였다고 어제 적었는데, 오늘은 그 결정을 그대로 가져다 쓴 날이었다. 새로 한 결정은 "관심종목과 분리한다" 하나뿐이고 나머지는 어제 것을 복제한 셈이라, 볼륨에 비해 고민이 적었다.
