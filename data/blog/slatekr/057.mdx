#056에서 종목 상세 4탭의 명백한 반응형 결함을 잡았고, 남은 건 둘이었다. 모바일 스크롤 추종 탭 리모컨(C18)과, 코드로 단정 못 해 미뤄둔 실물 점검(F1). 이번 세션은 그 둘을 같이 들고 시작했는데, 점검을 돌다 보니 결국 무게는 점검에서 나온 수정 쪽으로 옮겨갔다.

먼저 리모컨부터 정리하고 넘어가야 했다.

## 탭 리모컨을 접고 top 버튼으로

C18은 모바일에서 스크롤을 내려도 아무 데서나 탭을 바꿀 수 있게 하려던 floating UI였다. #048에서 탭 nav의 sticky를 빼면서 "그럼 내려간 상태에선 탭을 어떻게 바꾸지"에 대한 답으로 예고해둔 거다.

그런데 막상 구현에 들어가기 전에 이게 정말 필요한가를 따져보니 전제가 흔들렸다. 리모컨이 주는 가치는 "스크롤을 내린 상태에서 다른 탭으로 바로 점프"인데, #046에서 4탭을 nested layout의 독립 라우트로 바꿨다. 다른 탭으로 이동하면 그 탭의 맨 위부터 보게 된다 — 스크롤 위치를 유지한 채 탭만 갈아끼우는 시나리오가 애초에 없는 구조다. 그러면 리모컨이 절약해주는 건 결국 "위로 한 번 스크롤하는" 동작 하나뿐이다.

그 한 동작은 맨 위로 가는 버튼이 그대로 대체한다. top 버튼은 탭 전환뿐 아니라 긴 페이지를 위로 올리는 범용 용도까지 겸하니, 리모컨의 상위호환에 가깝다. 자리 문제도 있었다. 모바일은 이미 #055·#056에서 가로 폭을 px 단위로 회수해온 화면이라, 가로 막대형 리모컨이 들어갈 여유가 없었다. 코너에 박히는 작은 원형 버튼은 폭을 두고 경쟁하지 않는다.

| | 탭 리모컨(C18) | top 버튼(C19) |
| --- | --- | --- |
| 동작 | 내려간 상태에서 탭 점프 | 맨 위로 (탭 nav 다시 노출) |
| 라우트 전제 | 스크롤 유지 점프 필요 | 불필요 |
| 가로 폭 | 막대형, 폭 경쟁 | 코너 고정, 비경쟁 |
| 용도 | 탭 전환 전용 | 범용 |

그래서 C18은 폐기하고, scroll-to-top 버튼(C19)으로 대체했다. 안 만든 기능이 하나 늘었지만, 만들었다면 라우트 구조와 어긋난 채 자리만 차지했을 거다.

### sentinel로 출현 판정

버튼을 언제 띄울지가 작은 결정 하나였다. `scrollY`가 특정 px를 넘으면 띄우는 방식은 매직넘버가 필요하고, 탭 nav 높이가 바뀌면 같이 깨진다. 대신 `IntersectionObserver`에 sentinel을 물렸다.

탭 nav 바로 뒤에 높이 0짜리 빈 `div`를 하나 두고, 그게 화면에 보이면 버튼을 숨기고 사라지면 띄운다.

```tsx
// sentinel이 보이면 visible=false, 벗어나면 visible=true
const observer = new IntersectionObserver(
  ([entry]) => setVisible(!entry.isIntersecting),
  { threshold: 0 }
);
```

이 방식의 이점은 "긴 탭만 자동으로" 처리된다는 거다. 차트 탭처럼 짧아서 nav가 화면 밖으로 안 밀려나는 경우엔 sentinel이 계속 보이니 버튼이 아예 안 뜬다. 탭마다 길이를 따로 분기할 필요가 없다. 컴포넌트는 종목 상세에서만 쓰니 `entities/stock`에 두고, 두 번째 호출처가 생기면 그때 일반 위치로 올리기로 했다.

## 공시 행 — 모바일에서 컬럼을 더 덜어내기

여기서부터가 실물 점검에서 나온 수정이다. #056에서 공시 테이블을 7컬럼에서 모바일 4컬럼으로 묶어서 시각적 최적화를 했었다. 어제까진 괜찮아 보였는데, 다시 보니 여전히 불편했다.

![](/static/images/velog/9135c55e-258c-42e2-a885-ab77ab629621-image.png)

하나는 제출인·접수일자가 보고서명과 같은 좌측 영역에 묶여서, 보고서명이 쓸 폭이 짧아진 거였다. 그렇게까지 긴 공시가 아니어도 두 줄로 넘어가는 게 불편했다.

다른 하나는 더 근본적인 인상이었는데 — 모바일로 작은 뉴스 기사도 아무렇지 않게 읽는 화면에서, 공시 열 개 남짓에 글자와 여백을 너무 후하게 쓰고 있었다. 명목상 주식 정보 서비스인데 정보 밀도가 이렇게 낮을 이유가 없다.

현재 상태는 모바일 4컬럼이 `[1fr | 96px | 32px | 60px]`이고, 제출인+날짜 묶음이 가운데 96px 고정 컬럼을 통째로 차지하고 있었다. 보고서명이 받는 1fr은 그만큼 깎인다.

그래서 모바일에서 덜어낼 수 있는 걸 차례로 추렸다.

- **회사명** — 상세 페이지 안에서 보는 공시다. 회사는 이미 정해져 있으니 행마다 회사명을 반복하는 건 100% 중복이다. 모바일에선 뺀다.
- **제출인** — 대부분 임원 개인명이라 공시 식별 기여가 낮다. 모바일에선 생략하고 데스크탑만 둔다.
- **비고**(거래소 코드 배지) — 보조 신호라 32px 컬럼을 양보시킨다.

남는 건 유형 배지·접수일자·보고서명·AI요약. 회사명 자리에 날짜를 넣고 — 날짜는 고정 길이라 가변 폭인 보고서명보다 앞에 와야 정렬이 안정적이다 — 보고서명은 아래 줄에서 폭을 거의 다 쓰게 했다.

![](/static/images/velog/9c09b0f4-8fbd-4b51-b77a-ece9d1fd79fa-image.png)


모바일 그리드는 `[1fr | 60px]` 2컬럼까지 줄었다. 제출인·날짜 묶음 wrapper를 `hidden md:contents`로 처리한 게 작은 트릭인데, 모바일에선 wrapper가 통째 사라져 그리드 자식에서 빠지고, 데스크탑에선 `display: contents`로 자식이 7컬럼 그리드에 직접 올라간다. 덕분에 모바일 2컬럼과 데스크탑 7컬럼이 마크업 한 벌로 갈린다. 접수일자만은 모바일(메타 줄 인라인)과 데스크탑(독립 컬럼)에서 부모가 달라 `md:contents`로 안 풀려서, #056의 유형 배지처럼 두 번 렌더하고 한쪽씩 `hidden` 처리했다.

밀도는 폰트와 패딩을 같이 내렸다. 보고서명을 `text-sm`에서 `text-xs`로, 메타 줄을 `text-[11px]`로, 행 세로 패딩을 모바일만 한 단계 줄였다. AI요약 버튼은 좌우 패딩이 길어 보여서 `px-2`에서 `px-1`로 좁혔다. 한 번에 맞진 않아서, 1차로 적용한 뒤 실물을 보며 메타 줄 정렬과 배지 세로 위치를 몇 번 손봤다.

공시 개수를 늘리는 것도 같이 검토했는데, 밀도가 안정된 다음에 보기로 하고 이번엔 미뤘다.

## 관심종목 행 — 구조를 두 줄로 다시 잡기

관심종목 페이지도 같은 인상이었다. 행간이 너무 벌어지고 폰트가 커서 한 화면에 몇 개 안 들어왔다. #049에서 카드를 리스트로 바꾸며 잡아둔 행인데, 밀도만 손보려다 구조까지 다시 짰다.

당시 행은 세 줄이었다.

```
사명  코드·시장
가격  변동폭(%)  7일
신규 공시 N건 (있을 때만)
```

문제가 둘 보였다. 7일 등락은 들여다보니 딱히 의미 있는 정보가 아니었다 — 1일 등락과 기간 수익률 사이 어중간한 값이라 행에서 빼기로 했다. 신규 공시는 있을 때만 셋째 줄이 생기는 구조라, 공시가 있는 행과 없는 행의 높이가 달라졌다. 행 높이가 들쭉날쭉하면 스캔 리듬이 깨진다는 건 #056 공시 보고서명에서 한 번 부딪힌 문제다.

그래서 신규 공시를 셋째 줄에서 우측 상단으로 올리고, 행을 두 줄로 정리했다.

![](/static/images/velog/308aa26a-e044-4aa7-b386-e4ad3ec672a1-image.png)


신규 공시가 있든 없든 윗줄은 코드·시장과 휴지통 때문에 항상 존재하니, 셋째 줄이 사라지면서 높이가 일정해졌다.

### PC는 사명·가격을 세로로

여기서 모바일과 PC가 갈렸다. 처음엔 PC도 같은 2줄 구조를 그대로 쓰려고 했는데, 막상 보니 사명과 가격을 한 줄에 양 끝으로 두면 PC의 넓은 폭에서 둘이 너무 멀어져 같이 읽기가 불편했다. 그렇다고 붙여두면 사명 길이가 종목마다 달라 가격 위치가 들쭉날쭉해진다.

| 화면 | 사명·가격 배치 | 이유 |
| --- | --- | --- |
| 모바일 | 한 줄, 양 끝 | 폭이 좁아 가로로 둬도 한눈에 읽힌다 |
| PC | 세로로 쌓기 | 폭이 넓어 가로로 두면 시선 이동이 크다 |

그래서 아랫줄을 모바일은 `flex-row justify-between`, PC는 `md:flex-col`로 방향만 갈랐다. 보통 모바일이 세로고 PC가 가로인데 여기선 반대다. 사명·가격이 줄 영역 안에서 방향만 바뀌는 거라 부모가 달라지지 않아서, 마크업 두 벌 없이 `md:` 분기 몇 개로 끝났다. 폰트도 PC는 이전 크기를 복원하고 모바일만 줄인 채로 뒀다.

윗줄의 코드·시장 / 신규 공시 / 휴지통이 한 라인으로 안 맞는 것도 같이 잡았다. 휴지통을 윗줄 flex 안으로 옮겨 세 요소를 같은 줄에 두고, 글리프 박스 높이를 `leading-none`으로 맞춘 다음, 휴지통 크기를 줄여 라인 높이에 맞췄다. 윗줄에 `min-h-7`을 박아서 휴지통 유무나 탭 전환과 무관하게 높이가 28px로 고정되게 했다.

휴지통을 옮기면서 신경 쓴 건 클릭 동선이었다. #049에서 행 전체를 `<Link absolute inset-0>`으로 덮고 휴지통을 `relative z-10`으로 그 위에 띄워 이벤트를 격리해둔 구조라, 휴지통을 옮기더라도 이 쌓임 순서만 유지하면 동선은 그대로다. 위치만 바꾸고 격리 속성은 손대지 않았다.

![](/static/images/velog/6dd21ce6-a299-42c7-b83d-7ed9c8ed50f9-image.png)


행을 이렇게 바꾸니 로딩 skeleton이 옛 구조(세 줄, 큰 폰트)대로 남아 실데이터로 바뀔 때 높이가 튀었다. skeleton 점프 최소화는 캐싱 작업 때 세운 원칙이라, placeholder 박스의 높이·패딩을 실제 행과 1:1로 맞췄다. 방금 만든 변경이 직접 부른 회귀라 같은 흐름에서 닫는 게 맞았다.

7일 등락은 표시만 뺐다. `/api/prices`의 `change7d` 응답과 타입은 그대로 둔다. 미사용 코드는 나중에 한꺼번에 정리하는 게 낫고, 지금 타입까지 걷으면 작업만 커진다.

## 상장 1년 미만 종목의 기간 수익률

실물 점검에서 하나 더 잡혔다. 5월에 상장한 종목(마키나락스, 477850)의 종합정보 탭을 보니 1M·3M·1Y 수익률이 전부 같은 값이었다.

```
1M    3M    1Y
-9.00%  -9.00%  -9.00%
```

처음엔 이게 정상인가 싶었는데, 따져보니 거짓 값이었다. 상장한 지 한 달 남짓이라 3개월·1년 전 가격이 아예 없는데, 계산 로직이 데이터가 없으면 가장 오래된 행(상장 시초가)으로 대체하고 있었다. 그래서 3M·1Y가 사실은 "상장 후 전체 수익률"인데 라벨만 3개월·1년으로 붙은 셈이었다. 우연히 같은 게 아니라 상장 1년 미만 종목에선 구조적으로 항상 이렇게 나온다. 정보를 정확히 구조화하는 게 목적인 서비스에서 틀린 수익률을 보여주는 건 그냥 버그다.

가드는 단순하다. 각 기간의 시작일이 가장 오래된 데이터보다 앞서면 — 즉 그 기간을 계산할 과거 데이터가 없으면 — 값을 대체하지 말고 `null`을 반환하게 했다. UI는 `null`이면 "—"를 표시한다.

```ts
const calcReturn = (cutoff: Date): number | null => {
  if (oldestDate > cutoff) return null; // 기간 시작일이 데이터 범위 밖
  // ...
};
```

조회 구간을 1년에서 13개월로 살짝 넓힌 게 곁가지 보정이다. 주말·공휴일로 마지막 거래일과 오늘 사이에 갭이 있으면, 1년 이상 종목인데도 1Y 가드에 잘못 걸려 "—"가 뜰 수 있었다. 한 달 버퍼를 둬서 정상 종목은 1년 전 시점 데이터가 항상 잡히게 했다. UI와 타입은 이미 `null`을 받게 돼 있어서 소비처는 손댈 게 없었다.

## 정리

- **C18 폐기 → C19** — 라우트가 독립 탭이라 스크롤 유지 점프 시나리오가 없어 리모컨을 접고, sentinel 기반 scroll-to-top 버튼으로 대체
- **공시 행 모바일 재배치** — 회사명·제출인·비고를 덜어 2컬럼으로, 폰트·패딩을 내려 밀도를 높임
- **관심종목 행 재구성** — 신규 공시를 우측 상단으로 올려 행 높이를 고정, PC는 사명·가격을 세로로, 7일 등락 제거
- **기간 수익률 가드** — 상장 1년 미만 종목의 거짓 수익률을 `null`로 막고 "—" 표시

기능적으로 큰 작업은 없었다. 점검을 돌다 발견한 밀도 문제를 따라가다 보니 공시와 관심종목 행을 둘 다 다시 짰는데, 두 화면에서 매번 같은 질문으로 돌아왔다 — 이 정보가 이 자리에 꼭 있어야 하나. 회사명, 제출인, 7일 등락처럼 덜어낸 것들은 다 그 질문에 못 버틴 항목이었다. 밀도를 높이는 가장 확실한 방법이 폰트 축소가 아니라 안 쓰는 정보를 빼는 거였다는 게 이번의 인상이다.
