앞선 글에서 국내 시세를 공개 서비스에 쓸 수 없다는 판정을 내리고, 가격 계열만 가상 데이터로 바꾸는 데모 모드로 방향을 정했다. 재무 · 공시는 DART 실데이터로 남고, 현재가 · 분봉 · 일봉 · 지수 · 순위가 생성기 몫이 됐다.

이 글은 그 생성기의 설명서다. 세션 기록과는 다른 방향으로 "왜 사용해야 하는가"보다 "어떻게 작동하는가"를 적는다. 모듈 구성부터 함수별 규칙, 테스트가 보장하는 것, 안 한 것까지. 어찌보면 서비스의 근간이라 할 수 있는 가격 데이터들을 생성하는 장치이므로, 그 명세서와 같은 역할이다.

## 난수 — `prng.ts`

결정론이 가상 시세의 기반이라 `Math.random`은 쓰지 않는다. 입력 조각을 `"|"`로 이어 FNV-1a 32bit로 해시하고, 그 값을 mulberry32의 시드로 쓴다. 정규 난수는 Box-Muller.

```ts
export const hashSeed = (...parts: (string | number)[]): number => {
  const s = parts.join("|");           // ("A","B") 와 ("AB","") 가 같은 시드가 되지 않게
  let h = 0x811c9dc5;
  for (let i = 0; i < s.length; i++) {
    h ^= s.charCodeAt(i);
    h = Math.imul(h, 0x01000193);
  }
  return h >>> 0;
};
```

시드 키는 세 종류다.

| 시드 | 결정하는 것 |
|---|---|
| `hash(ticker, "profile")` | 종목 프로필(tier · σ · β · 거래량 규모 · NXT 적격 · 사다리 난수) |
| `hash(ticker, date)` | 그날의 수익률 · 갭 · 고저 · 거래량 노이즈. 분봉은 `(ticker, date, 구간)` |
| `hash("market", market, date)` | 그날의 시장 팩터. 모든 종목 · 지수가 공유 |

## 입력 — `universe.ts`

SQL 두 개를 병렬로 읽어 종목마다 `DemoAnchor`를 만든다. 가격 테이블은 읽지 않는다. 결과는 모듈 레벨 `Map`에 1시간 메모되고, 적재 중 동시 요청은 하나의 promise를 공유한다.

```ts
export type DemoAnchor = {
  eps: number | null;      // 최신 연간
  bps: number | null;
  pins?: DemoPin[];        // { date: "YYYY-12-31", price }
};
```

핀은 DART 배당 공시의 두 숫자에서 역산한다. 주식병합 · 분할로 EPS 기준이 어긋난 해는 재무 슬레이트와 같은 판정 함수로 걸러 낸다.

```ts
const toPins = (ticker, rows, shares): DemoPin[] =>
  rows
    .filter((row) => (row.dps ?? 0) > 0 && (row.dart_yield ?? 0) > 0)
    .filter((row) => !isRowBasisMismatch({ /* year, net_income, eps */ }, shares))
    .map((row) => ({
      date: `${row.year}-12-31`,
      price: row.dps / (row.dart_yield / 100),   // 결산일 주가 수준
    }));
```

EOD 축도 여기서 정한다. "오늘 일봉"은 거래일 20:10 이후에만 존재하고, 그 전엔 직전 거래일이 최신이다. 실데이터 때 EOD 적재가 돌던 시각과 같고, 장중 당일 봉은 기존처럼 클라이언트가 live 시세를 병합한다.

## 종목 프로필 — `getTickerProfile`

종목당 한 번 계산해 메모한다. 전부 `hash(ticker, "profile")` 한 시드에서 순서대로 뽑는다.

| 항목 | 규칙 |
|---|---|
| tier | large 10% · mid 30% · small 60% |
| σ (일 변동성) | large 1.2% · mid 2.0% · small 3.2%, × 0.8~1.25 난수 |
| β (시장 민감도) | large 0.9 · mid 1.0 · small 1.2, ± 0.2 |
| volumeScale | tier별 log-uniform (large 5e5~5e6 · mid 1e5~1e6 · small 2e4~3e5 주/일) |
| nxEligible | 40% true — KRX/NXT 탭 · 08:00~20:00 세션 로직 유지용 |
| clusterPhase | 변동성 군집 위상 (아래) |
| anchorPrice | 핀이 있으면 마지막 핀에서 앵커 날짜까지 걸어간 값, 없으면 사다리 |

변동성은 날마다 같지 않다. 20거래일 주기 sin 파로 0.7~1.3배 사이를 오가게 해 조용한 주와 시끄러운 주가 생기게 했다.

```ts
const sigmaDayOf = (profile, date) => {
  const cluster = (Math.sin((2 * Math.PI * dayIndex) / 20 + profile.clusterPhase) + 1) / 2;
  return profile.sigma * (0.7 + 0.6 * cluster);
};
```

## 가격 수준 — 핀과 사다리

가격의 자릿수는 두 가지 고정점으로 정한다. 둘 다 출처는 DART뿐이고, 보관 중인 실데이터는 입력에 쓰지 않는다.

| 고정점 | 조건 | 값 |
|---|---|---|
| 핀 (결산일마다) | DPS > 0 · 수익률 > 0 · 기준 불일치 아님 · 앵커 날짜 이전 | DPS ÷ 수익률, 틱 반올림 |
| 단일 앵커 (핀 없는 종목) | 사다리 | 아래 |

사다리는 각 단계의 결과가 500~1,000,000원 안이면 채택하고 아니면 다음 칸이다. 배수는 `u²`로 낮은 쪽에 치우치게 했다.

```ts
const ladderPrice = (anchor, uMultiple, uFallback) => {
  const accept = (p) => (p !== null && p >= 500 && p <= 1_000_000 ? p : null);
  const skew = uMultiple * uMultiple;
  const byEps = eps > 0 ? accept(roundTick(eps * (5 + 35 * skew))) : null;    // PER 5~40
  if (byEps !== null) return byEps;
  const byBps = bps > 0 ? accept(roundTick(bps * (0.3 + 4.7 * skew))) : null; // PBR 0.3~5
  if (byBps !== null) return byBps;
  return roundTick(logUniform(1_000, 200_000, uFallback));
};
```

실측(2,654종목): 핀 1,348 · EPS 407 · BPS 751 · 균등 148. 핀 종목의 평균 핀 수 3.8개. 앵커 가격 p10 / p50 / p90 = 1,215 / 6,030 / 53,100원.

## 일 수익률 — 1-팩터

그날의 수익률은 시장 팩터와 종목 고유 노이즈의 합이다. 시장 팩터는 `hash("market", "KRX", date)` 하나에서 나오므로 모든 종목이 같은 값을 본다. 지수도 같은 팩터를 쓴다.

```ts
const dayReturn = (ticker, profile, date) => {
  const rng = createRng(hashSeed(ticker, date));
  return profile.beta * marketReturnDaily("KRX", date) + sigmaDayOf(profile, date) * gaussian(rng);
};
```

시장 팩터의 σ는 KRX 0.9%, 해외 지역(US · JP · HK · CN · DE) 1.0%. 이 한 항이 "지수 ↑ 날에 대부분 종목 ↑, β 큰 소형주가 더 ↑"를 만든다. 섹터 팩터는 같은 꼴로 한 항 더 더하면 되지만 넣지 않았다.

## 정규장 종가 경로 — 구간별 규칙

하루 1스텝 랜덤워크가 원본이다. 고정점에 따라 구간을 나눠 다르게 걷는다.

| 구간 | 방법 | 평균회귀 |
|---|---|---|
| 핀 ↔ 핀 | 브라운 브리지 — 워크를 돌린 뒤 선형 보정으로 양 끝 고정 | 없음 (끝점 고정) |
| 마지막 핀 → 앵커 날짜 → 이후 | 자유 워크 | 기준 = 마지막 핀 |
| 첫 핀 이전 | 역방향 자유 워크 `R(d-1) = R(d) / exp(r)` | 기준 = 첫 핀 |
| 핀 없음 | 앵커에서 양방향 자유 워크 | 기준 = 앵커 |

```ts
// 브리지: 누적 로그 수익률에 (목표 − 도달)/n 을 i번째 날에 i배 더한다
const correction = (Math.log(end) - logs[n - 1]) / n;
for (let i = 0; i < n; i++)
  out[i] = clampTo(roundTick(Math.exp(logs[i] + correction * (i + 1))), limitBand(prev));
```

```ts
// 평균회귀(OU 항): 기준 수준에서 멀어진 만큼 되돌리는 힘. θ = 0.008, 반감기 ≈ 90거래일
const meanReversion = (price, level) => -MEAN_REVERSION_THETA * Math.log(price / level);
```

평균회귀 전후 200거래일 뒤 `ln(R / 기준)`의 표본 표준편차는 small 0.45 → 0.27, mid 0.16, large 0.09. 모든 날은 틱 반올림 뒤 전일 정규장 종가 기준 ±30% 밴드로 클램프한다.

## 일봉 조립 — `buildDailyBar`

정규장 종가 R(d)가 정해지면 나머지 값을 그날 노이즈(`hash(ticker, date)`의 2~6번째 추첨)로 만든다. 전부 전일 정규장 종가 기준 상하한 밴드 안이다.

| 필드 | 규칙 |
|---|---|
| `regularClose` | R(d) — 15:30 정규장 종가 |
| `close` | 20:00 애프터마켓 종가. `R × exp(0.3σ · z)` |
| `open` | 전일 20:00 종가에서 갭. `C(d-1) × exp(0.4σ · z)` |
| `high` / `low` | `max/min(open, R, close)`에서 `0.6σ · |z|`만큼 확장 (R 포함 — 15:30 가격이 고저 밖이면 분봉 브리지가 성립 안 함) |
| `volume` | `volumeScale × lognormal(0.5) × (1 + 2·|r|/σ)` — 큰 등락 날 거래량 ↑ |
| `basePrice` | R(d-1) — 헤더 등락 기준가 |

20:00 캔들 축과 "등락 기준 = 전일 15:30"은 실데이터 때 세운 규칙 그대로다.

## 분봉 — 일봉 안의 브리지

분봉은 하루를 세 구간으로 나눠 각각 브리지로 잇고, 정규장 구간은 고저를 일봉 H/L에 맞춘다. 오늘과 전일만 생성한다.

| 구간 | 창 (KST) | 양 끝 | σ 비율 | 거래량 몫 |
|---|---|---|---|---|
| pre | 08:00~09:00 (NXT 적격만) | O(d) → O(d) | 0.3 | 3% |
| regular | 09:00~15:30 | O(d) → R(d) | 1.0 | 92% |
| after | 15:31~20:00 (비NXT는 16:00부터) | R(d) → C(d) | 0.4 | 5% |

```ts
const minuteBridge = (gauss, start, end, n, sigmaMinute) => {
  let acc = Math.log(start);
  for (let i = 0; i < n; i++) { acc += sigmaMinute * gauss(); closes[i] = acc; }
  const correction = (Math.log(end) - closes[n - 1]) / n;
  for (let i = 0; i < n; i++) closes[i] = Math.exp(closes[i] + correction * (i + 1));
  return closes;
};
```

고저 맞춤은 시가–종가 현(chord) 위쪽 초과분의 최대가 정확히 high, 아래쪽 최대가 low가 되게 선형 스케일한다. 최소 비율을 고르므로 어떤 봉도 [low, high]를 넘지 않는다.

```ts
const fitHighLow = (closes, start, end, high, low) => {
  // 1) 각 봉의 현 대비 초과분으로 scaleUp = min((high − chord) / excess), scaleDown 도 같은 꼴
  // 2) 초과분 × scale 로 다시 쓴다 → max = high, min = low
  // 3) 한쪽에만 머문 극단은 n/3 · 2n/3 지점을 high · low 로 고정
};
```

분 거래량은 장 초반 · 막판이 두꺼운 U자 프로파일 `1 + 2x²`에 lognormal 노이즈를 곱하고, 합이 일봉 거래량이 되게 정수 배분한다. 봉의 `timestamp`는 KST를 UTC로 위장한 START 라벨 epoch 초로, 기존 차트 관례와 같다.

## 현재가 — `quoteAt`

현재가를 따로 만들지 않는다. 오늘 분봉에서 지금 시각 이전 마지막 봉의 종가가 현재가고, open · high · low · volume은 그 시점까지의 집계다. 헤더와 차트가 같은 봉 배열을 보므로 "헤더 = 차트 마지막 봉"이 구성상 성립한다.

```ts
export const quoteAt = (ticker, profile, now, channel): StockQuote | null => {
  if (channel === "NX" && !profile.nxEligible) return null;
  const tradingDate = getKrxTradingDate(now);
  const [prev, today] = generateDailyBars(ticker, profile, prevDate, tradingDate);
  const untilMin = date === tradingDate ? minutes : Infinity;     // 오늘이면 진행 중인 봉까지
  const bars = buildIntradayBars(ticker, profile, tradingDate, today, channel, untilMin);
  const basePrice = prev.regularClose;
  // bars 를 cutoff 까지 접어 price · open · high · low · volume
  // 오늘 봉이 없는 개장 전 창은 전일 정규장 종가 · 등락 0 · OHL 0 (실제 J quote 와 같음)
};
```

| 채널 | 의미 |
|---|---|
| `UN` | 통합. 전체 경로 |
| `J` | KRX. 08:00~09:00 프리마켓 제외 |
| `NX` | NXT. 적격 종목이면 전체, 아니면 `null` — route의 실패 판정이 이 동작에 기댄다 |

세션 밖(마감 후 · 주말)은 마지막 봉 값이 고정된다. 비NXT 종목의 개장 전 창은 전일 정규장 종가에 등락 0이다.

## 지수 — `index-model.ts`

종목과 같은 뼈대에 상수만 다르다. 틱 · 상하한 없음, 소수 2자리, 국내는 15:30 단일 마감.

| 지수 | 앵커 | β | σ |
|---|---|---|---|
| KOSPI · KOSPI200 | 2,600 · 350 | 1.0 | 0.9% |
| KOSDAQ · KOSDAQ150 | 780 · 1,100 | 1.3 · 1.35 | 1.3% |
| SPX · COMP · NDX · .DJI | 5,800 · 18,500 · 20,500 · 42,000 | 1.0 · 1.15 · 1.15 · 0.9 | 1.0% |
| NI225 · HSI · SHCOMP · DAX | 39,000 · 20,000 · 3,300 · 19,500 | 1.0 | 1.0% |

앵커 값은 자릿수만 맞춘 상수다. 해외는 지역별 시장 팩터와 거래소 로컬 세션 · 타임존을 기존 상수에서 그대로 쓴다. 상승 · 하락 종목 수는 전 종목을 세지 않고 지수 자신의 당일 수익률로 sigmoid 근사한다. 실데이터의 특이 케이스는 그대로 흉내 낸다 — `.DJI`는 분봉 없음 · 체결시각 null, SPX · NDX는 거래량 0, 해외 지연 분은 기존 상수.

## 어댑터 — 시그니처 유지

KIS를 부르던 세 파일은 export 이름 · 인자 · 반환 타입을 그대로 두고 본문만 바꿨다. route는 import 경로 외에 손대지 않았다.

```ts
export const fetchStockQuote = async (ticker: string, marketDiv: QuoteMarketDiv) => {
  const entry = await getDemoEntry(ticker);
  if (!entry) return null;
  return quoteAt(ticker, entry.profile, new Date(), marketDiv);   // "J" | "NX" | "UN" 그대로
};
```

| 어댑터 함수 | 생성기 대응 | 남는 실패 |
|---|---|---|
| `fetchStockQuote` · `fetchMultiQuote` | `quoteAt` | 미등록 ticker → null / `failed[t]` |
| `fetchStockIntradayChart` | 오늘 봉 + 전일 tail 30봉, preopen · closed는 전일 전체 | `failed` 항상 false |
| `fetchStockMarketAction` | 항상 `null` (시장조치 없음) | — |
| `fetchIndexQuote("0001")` | KIS 코드 → `IndexCode` → `indexQuoteAt` | 미지원 코드 → null |
| `fetchRanking(kind, session)` | 전 종목 `quoteAt` → 정렬 → 30건. `changeSign`은 KIS 코드 1~5(상한 · 상승 · 보합 · 하한 · 하락), 상 · 하한은 `limitPrices` | universe 조회 실패 |
| 마감 스냅샷 `fetchQuoteSnapshot` | 20:00 종가 · 거래량을 스냅샷 row 형태로 | — |

순위는 (EOD 날짜 · 분 · 채널) 키로 전 종목 quote 표를 메모해 kind 6 × 시장 3이 한 번의 계산을 공유한다.

## 정리

- **생성기 = 순수 함수 넷 + 어댑터 셋** — `f(종목, 날짜, 분)`, DB · cron 없음, 서버 계산 · 클라 폴링 유지
- **시드 3종** — 프로필 · 날짜 · 시장 팩터. 결정론이 서버리스 상태 공유 문제를 없앰
- **가격 수준 = DART 핀 + 사다리** — DPS ÷ 수익률 역산, 핀 사이 브리지, 자유 워크엔 평균회귀 θ 0.008
- **분봉 = 일봉 안의 브리지** — 세 구간, 고저 맞춤, 집계 일치를 테스트로 보장. 현재가는 분봉 커서
- **보장 범위** — 결정론 · 이력 불변 · 시장 규칙 · 정합 9건

설계라고 해 봐야 시드 · 워크 · 브리지 · 팩터 네 개 생각이고, 나머지는 그 넷을 기존 시그니처에 맞추는 배관이었다. 진짜 데이터를 못 쓰는 제약이 오히려 5년 궤적을 DART로 복원하는 방법을 찾게 했다.
