#068 에서 per 산식을 재정비하고, 이제 메모해뒀던 수정이 필요한 사항들을 하나씩 지울 차례다. 아직 AI 공시 요약 컨텍스트 수정 등이 큰 작업으로 남아있지만, 이들은 마무리에 하기로 하고 그전에 수정 필요 사항 목록을 하나씩 지우기로 했다.

그래서 이번엔 홈 관심종목이 전일 종가로 떠 있던 것, 검색 UI 두 자리, 그리고 #066부터 미뤄온 지수 차트 페이지까지. 새로 설계한 건 별로 없고, 대부분 앞 세션에서 만들어둔 걸 제자리에 붙이는 작업이었다.

## 홈페이지 관심 종목에 현재가 미반영

관심종목을 #063에서 실시간으로 바꿨는데, 그때 관심종목 페이지만 손대고 홈 화면 미리보기를 놓쳤다. 그래서 같은 종목이 홈에선 어제 종가로, 관심종목 페이지에선 실시간 현재가로 떠 있었다. 값이 틀린 건 아니지만, 한 서비스 안에서 같은 데이터가 화면마다 다르게 보이는 건 그냥 결함이다.

고칠 방법은 이미 #063에 다 있었다. 관심종목 페이지를 라이브화하면서 만들어둔 것들 —

- `useMultiQuote` — 개장 중에만 60초 폴링하고 장이 닫히면 멈추는 훅
- `PriceChange` — 등락 부호·색·포맷을 통합한 컴포넌트
- live 값이 있으면 실시간, 없으면 EOD로 떨어지는 병합 규칙

홈 미리보기는 이걸 그대로 가져다 배선만 했다. 기존엔 `useEffect` 안에서 `fetch`로 종가만 받아 `useState`에 넣고 있었는데, 이걸 `useQuery`로 바꾸고 `useMultiQuote`를 하나 더 얹었다. 표시값은 관심종목 페이지의 병합 규칙 네 줄을 그대로 옮겼다.

잠깐 고민한 건 그 병합 규칙 네 줄을 함수로 뽑을지였다. 지금 쓰는 데가 관심종목 페이지랑 홈 두 군데인데, 두 곳뿐이라 공용 함수로 빼면 오히려 파일만 하나 는다. 세 번째로 같은 코드를 쓰게 되면 그때 뽑기로 하고 인라인으로 뒀다.

## 검색 결과 페이지 드롭다운 표시 동작 수정

#068에서 검색 쪽 두 개를 묶어서 처리하겠다고 적어뒀다.

하나는 `/search` 결과 페이지에서 검색창에 포커스하면 미리보기 드롭다운이 뜨는 문제였다.

원인은 검색 결과 이후, 결과 페이지에서도 마우스 포커싱이 그대로 남아서 드롭다운이 켜진 채 남아있던 것이었다.

결과 페이지엔 이미 아래에 결과 카드가 깔려 있으니, 드롭다운은 같은 내용을 두 번 보여주는 꼴이다. 검색 입력에 `showPreview` prop을 하나 두고 결과 페이지에서만 `false`로 내려 드롭다운을 껐다. 홈은 기본값이라 그대로 뜬다.

## 지수 차트 페이지 — 이미 만들어둔 컴포넌트

#066에서 지수 미니 차트를 슬레이트에 붙일 때, 원래 초안으로 만들었던 풀사이즈 차트는 지우지 않고 참조만 끊어서 남겨뒀다. 그때 "큰 차트는 별도 지수 페이지로 간다"고 미뤄둔 게 이번 G6다.

그래서 이번엔 차트 컴포넌트를 새로 만들 게 없었다. `IndexChart`(당일/일봉/월봉 탭에 폴링·폴백까지 내장)와 섹션 래퍼가 이미 완성돼 있었으니, 남은 건 세 가지였다.

- 라우트 `app/stocks/indices/page.tsx`
- 코스피·코스닥·코스피200을 고르는 선택기
- 지수 코드·라벨 상수 (여기저기 흩어져 있던 걸 한 파일로)

선택기는 클라이언트 상태 대신 `searchParam`으로 갔다. `/stocks/indices?index=KOSDAQ`처럼 URL에 선택을 담고, 선택지는 `Link`로 깔았다. 이러면 페이지는 Server Component로 두고, 지수를 바꿀 때마다 서버에서 해당 지수 일봉을 다시 받는다. 클라이언트 state로 세 지수 데이터를 다 들고 있다가 토글하는 방법도 있었는데, 지수 셋 전환에 그렇게까지 할 이유가 없고, URL에 상태가 남으면 특정 지수 화면을 그대로 공유할 수 있는 편이 낫다고 봤다.

섹션 래퍼는 기존 `indexCode` prop 하나로 페이지 요구가 다 맞아서 손대지 않았다. 홈 슬레이트 헤더엔 이 페이지로 가는 "전체 보기" 링크를 하나 달았다.

### 캔들/선 토글은 종목 차트와 같이

차트엔 캔들/선 토글 등 차트 보조 기능을 추가할 계획이었다. 지수 차트에는 기간 전환 토글만 들어 있는 상태.

그래서 기간 토글 외에도, 차트 유형 버튼 등을 새로 만들어야 하는 상황인데, `IndexChart`는 이미 탭 세 개에 폴링·폴백까지 얹혀 상태가 꽤 빽빽하다. 여기에 캔들↔선 축을 하나 더 넣으면 조합이 늘어난다. 페이지를 띄우는 일과 토글은 별개고 토글은 나중에 붙여도 되는 거라, 이번엔 페이지만 올리고 토글은 트랙을 따로 파서 미뤘다.

## 정리

이번 세션은 앞에서 만들어둔 걸 제자리에 붙이는 작업이 대부분이었다.

- **E18** — 홈 관심종목 미리보기를 #063의 실시간 배선으로 이식. 새 route·컴포넌트 없이 병합 규칙만 옮겼다
- **E7 / E1** — 결과 페이지 드롭다운은 `showPreview`로 껐고, "색상 버그"는 실체가 없어 확인 후 폐기했다
- **G6** — #066에서 보존해둔 `IndexChart`를 살려 지수 차트 페이지를 열었다. 선택기는 `searchParam` 기반


돌아보면 코드를 새로 짠 자리가 거의 없다. 실시간 배선도 차트 컴포넌트도 앞 세션들에서 이미 만들어뒀고, 이번엔 그걸 놓친 화면에 붙이거나 미뤄둔 페이지로 꺼내는 일이었다. 트랙이 하나씩 닫히면서 남은 게 눈에 띄게 줄었다.

## 다음 작업

화면·실시간 쪽은 거의 정리됐다. 이제 남은 디자인·품질 항목을 backlog로 접고 마무리 단계로 넘어갈지를 정할 차례다.

- **C / D / E 잔여** — 슬레이트 명도 조정, AI 요약 프롬프트 개선 같은 폴리시 항목. 데모에 꼭 필요한 것만 남기고 나머지는 접을지 판단한다

- **H(신설) — 차트 컴포넌트 통합** — 지금 종목 차트와 지수 차트가 별도 컴포넌트인데, 원래 의도는 "데이터만 꽂는 하나의 차트"였다. 종목 차트에도 일봉/월봉 토글과 도구를 붙이려다 보니 둘의 차이가 줄어서, 이참에 하나로 합칠지 다음에 따져보기로 했다

차트 통합은 앞서 한 번 "분리 유지"로 결론 낸 자린데, 양쪽에 같은 기능을 넣기 시작하니 그 근거가 흔들린다. 합치는 게 맞는지 두 컴포넌트를 나란히 놓고 다시 볼 생각이다.
