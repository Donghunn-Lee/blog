[#022](https://velog.io/@dh82680/SlateKR-022-AI-공시-요약-5-사이드-패널-추가-및-동작-검증)에서 AI 공시 요약을 사이드 패널까지 붙이고 트랙을 닫았다. 다음 순서는 EC2 배포로 계획했었다.

근데 막상 배포로 들어가려고 하니 마음에 걸리는 게 있었다. 현재 모든 페이지 디자인은 전부 최소한만 만든 기본 디자인이다. 기능 구현을 우선해 이렇게 작업했고, 가닥이 잡히면 전반적인 디자인을 고치려고 생각했었다. 그리고, 직전 작업을 통해 목표 했던 기본 기능들은 전부 구현이 되었다.

게다가 종목 상세에 추가하려고 했던 사업보고서 정적 정보, 매출 비중, 동종업계 비교 같은 패널들도 남아 있다. 현재 디자인에 이 패널들을 일단 추가하자니, 디자인 작업 시 수정 비용이 더 커질 것 같았다.

순서를 바꿨다. 디자인을 먼저 잡고, 별건 이슈들 확인 및 해결, 배포 순으로 가기로 했다.

---

## 라이트 모드 변경

지금까지 다크 모드를 기본으로 두고 있었다. 아직 디자인 테마를 명확히 정하지 못한 상태에서, dark모드가 내게 익숙했기 때문이다.

다만 내가 프로젝트 기획 단계에서부터 추구한 디자인 언어([#10](ttps://velog.io/@dh82680/SlateKR-010-패널-래퍼와-디자인-언어))는 SlateKR이라는 이름의 의미를 살리는 것이었다. "색색의 슬레이트가 모여 하나의 종목을 구성한다"는 의미의 SlateKR. 

기획 초기에 만들어둔 로고 모티브 디자인이 그 의도를 가장 잘 보여준다.

<div style={{maxWidth: '480px', margin: '0 auto'}}>
  <img src="/static/images/velog/802b73cf-8bad-4ce2-a633-26eff3ae5fc1-image.png" alt="SlateKR 임시 로고 — 색색의 슬레이트가 적층된 육면체" style={{width: '40%'}} />
</div>

육면체 하나가 하나의 종목, 그 안에 쌓이는 색색의 판이 종목을 구성하는 정보 단위를 의미한다. 이걸 화면에 살리려면 베이스가 밝아야 한다.

라이트로 갔다. 차가운 순백이 아니라 따뜻한 오프화이트로. Notion이나 Things 같은 노트 앱이 차갑지 않게 느껴지는 이유가 베이스 색에 미세한 노란 기운이 들어 있어서다. 같은 방식을 따랐다.

```css
--bg-base:     oklch(0.98 0.005 85);  /* 따뜻한 오프화이트 */
--bg-elevated: oklch(0.995 0.003 85); /* 패널이 떠있을 때 */
```

`hue 85`(노란 기운)가 핵심이다. 이걸 0으로 두면 같은 명도라도 차갑게 느껴진다.

---

## 다섯 색의 슬레이트

베이스 위에 올릴 색을 정해야 했다. 너무 많으면 산만하고, 너무 적으면 슬레이트라는 이름이 무색해진다. 다섯 가지로 잡았다.

<span style={{color: '#7ba6c8'}}>●</span> **Sky** — 핵심 지표  
<span style={{color: '#5fa67f'}}>●</span> **Sage** — 재무 요약  
<span style={{color: '#c9883e'}}>●</span> **Amber** — 공시  
<span style={{color: '#8a64a8'}}>●</span> **Lavender** — AI 요약  
<span style={{color: '#cc8b58'}}>●</span> **Peach** — 관심종목

각 색은 배경(가장 옅음) / 테두리 / 액센트(아이콘·강조) 세 단계로 운용한다. 한 색을 단일 톤으로 쓰면 패널 안에서 위계가 안 살고, 너무 많이 쪼개면 토큰 관리가 무거워진다.

색 매핑은 우선 당장 괜찮다고 생각되는 의미를 조합했다. 핵심 지표는 차분한 신뢰감으로 sky, 재무는 안정·건전성 메타포로 sage, 공시는 알림 성격으로 amber, AI 차별화 신호로 lavender, 개인화 영역인 관심종목에 따뜻한 peach.
큰 고민 없이 지정한 거라, 추후 바뀔 수 있다.

모든 패널을 색으로 칠하지는 않았다. 헤더와 차트는 무색(`bg-elevated`)으로 둔다. 헤더는 가장 중요한 정보라 색이 들어가면 다른 패널과 위계가 흐려지고, 차트는 데이터 자체가 시각 무게를 가지니 패널 색이 충돌한다.

## 인터랙션은 강함으로

색만으로는 노트 앱 같은 부드러움이 안 나온다. 인터랙션이 받쳐줘야 한다. 기왕이면 최대한 인터렉티브하게 만들고 싶었다.

판단 근거는 두 가지였다. 첫째, **슬레이트라는 메타포 자체가 정적인 판이 아니라 들어 올리거나 펼치는 동작과 어울린다**. 둘째, 이 프로젝트의 차별화 기능인 AI 공시 요약이 사이드 패널 형태인데, **패널 인터랙션이 약하면 차별화가 시각적으로 안 살아난다**.

```css
--duration-fast: 150ms;  /* hover, 색 변화 */
--duration-base: 250ms;  /* expand, 패널 등장 */
--duration-slow: 400ms;  /* 페이지 전환 */
--ease-smooth:   cubic-bezier(0.4, 0, 0.2, 1);
```

타이밍 토큰을 먼저 박았다. 모든 인터랙션이 이 셋 중 하나로 떨어지게 하면 화면 전체의 호흡이 통일된다. 도입할 인터랙션 후보는 패널 hover, 패널 expand, 공시 행 위 보조 액션 슬라이드 인, 가격 카운트업 정도. 한 번에 다 적용하면 산만해지니 단계별로 가져가기로 했다.

## /styleguide 라우트

여기까지가 결정 단계였다. 근데 결정만 해두고 곧장 페이지에 적용으로 들어가려니 막혔다.

솔직히 말하면, 머릿속에 떠오른 그림을 시각적으로 표현할 능력이 부족했다. 색이 어떻게 어울리는지, 패널 간격이 적절한지, shadow가 떠 있는 느낌을 만드는지 — 이런 건 머리로 그려보고 표현할 수 있을 만큼 감각이 뛰어나진 않았다.

그래서 페이지 적용 전에 `/styleguide` 라우트를 따로 만들기로 했다. 토큰만 한 화면에 늘어놓고 보는 페이지다. 디자인 시스템 카탈로그 느낌도 있지만, 결정을 누적하기 위한 작업 도구에 가깝다.

```
/styleguide
├─ Color Tokens   — base / functional / accent 5색 × 3단계
├─ Typography     — display / headline / body / caption / mono
├─ Slate Panels   — 6종 패널 변형
└─ In-Context     — 실제 데이터에 적용한 미리보기
```

  <img src="/static/images/velog/ee69e940-129b-4fbd-841e-70259dd313f3-image.png" alt="/styleguide의 Color Tokens 섹션 — 색 견본과 토큰명, oklch 값이 카드로 정렬됨" style={{width: '100%', borderRadius: '8px'}} />

각 swatch에 토큰명과 oklch 값을 같이 표시했다. 이게 있으면 "이 색이 너무 진하다"가 아니라 "0.96 0.04를 0.95 0.05로"라고 말할 수 있다. 결정을 추상적인 인상이 아니라 구체적인 숫자로 다룰 수 있게 된다.

In-Context 섹션을 따로 둔 게 의외로 가장 도움이 됐다. 토큰만 봐선 어떻게 어울릴지 감이 안 잡혔는데, 종목 헤더 / 핵심 지표 / 공시 행을 더미 데이터로 그려놓으니 실제 페이지에 적용했을 때의 그림이 잡혔다.

라우트는 production에서 노출돼도 무방하다고 봤다. 디자인 시스템 자체가 포트폴리오 측면에서 보여줄 가치가 있고, 작업 진행에 따라 갱신되는 살아있는 문서로 두는 게 자연스럽다.

## 인터랙션 데모

토큰은 정적이라 `/styleguide`에 swatch로 늘어놓으면 끝나지만, 모션은 정적 페이지에 박아도 의미가 안 산다. 별도 섹션으로 인터랙션 데모 4종을 추가했다.

**1. Panel Hover** — 마우스를 올리면


 패널이 살짝 떠오른다. `translateY(-3px)` + shadow 강조 + 위쪽에 미세한 inset highlight를 더해 들어 올린 느낌을 만든다. 150ms로 가볍게.

</div>

**2. Panel Expand** — 패널 헤더를 누르면 내부 컨텐츠가 펼쳐진다. 재무 요약 패널에서 분기별 데이터를 펼쳐 볼 때 쓸 패턴이다. chevron이 180도 회전하면서 250ms로 부드럽게.

**3. 행 hover로 보조 액션 노출** — 공시 행에 마우스를 올리면 우측의 "AI 요약" 버튼이 슬라이드 인한다. 평소엔 시야가 분산되지 않고, 필요할 때만 보조 액션이 드러나는 패턴이다.

## 데모 구현 후 수정 사항

데모를 직접 보고 나니 손볼 거리가 몇 가지 떠올랐다. 이번 단계 작업과는 결이 달라 메모만 남겼다.

**재무 요약 expand의 표 축**  
지금 데모는 행이 연도, 열이 항목이다. 분기 데이터가 들어오면 행을 항목, 열을 기간으로 뒤집는 게 읽기 좋다. 연간/분기 토글도 같이. 분기 데이터 수집 경로 결정과 묶여 있어 종목 상세 페이지 내용을 고치며 함께 봐야 할 듯하다.

**AI 요약 버튼의 발견 가능성**  
공시 행의 hover로만 노출되니 처음 들어온 사용자가 기능 존재를 모를 수 있다. 첫 행만 미리 노출, 우측에 ghost 톤으로 상시 노출, 키보드 힌트 — 옵션이 여러 가지라 styleguide 데모에서 결정하기보다 실제 공시 섹션에서 사용자에게 기능의 존재를 효과적으로 전달하기 위한 방안을 검토해야 할 것 같다.

**카운트업의 호가 단위**  
지금은 부드러운 보간이라 어떤 가격대든 같은 step으로 움직인다. 1만원 미만은 1원, 5만원 미만은 5원처럼 가격대별 호가 단위로 틱이 이동하면 주식 정보 서비스다운 디테일이 산다. 데이터 수집 여건 상 실시간 정보를 다루는 서비스는 아니지만, 페이지 진입 시 전 거래일 종가에서 당일 종가로 카운트업하는 형태로 두면 가격의 존재감을 전달하는 장치가 된다.

## 다음 작업

종목 상세 페이지에 토큰을 실제로 적용한다. 슬레이트 6종이 실제 데이터 위에 올라갔을 때 어떻게 보이는지가 이번 토큰 시스템의 진짜 검증이다.

테마와 함께 서비스 디자인을 전체, 또는 단위별로 수정하면서 위 수정 사항들도 그 흐름에서 같이 다루고자 한다.
