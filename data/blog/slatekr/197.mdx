서류를 내기 전에 README의 성능 수치를 한 번 더 검수했다. 개선 폭만 적혀 있던 수치를 Core Web Vitals 기준과 대조하고, 로컬에서 잰 값이 섞여 있지 않은지 확인하는 작업이었다. [지난 글](/blog/slatekr/196/)에서 잰 표의 세 페이지는 전부 기준 안이었는데, 표에 없는 종목 두 개가 레이아웃 이동 점수(CLS) 기준 0.1을 일부 회차에만 넘었다.

계획은 주말에 고치고 바로 다시 재는 것이었다. 실제로는 토요일이라 장중 측정을 할 수 없었고, 휴장 상태로 재 보니 문제의 절반은 재현되지 않았다. 그래서 측정 방법을 먼저 바꿨고, 원인을 확정한 뒤 종목 헤더의 줄 구조를 고쳐 배포했다. 장중 측정은 다음 거래일로 남겼다.

---

## 대표 종목 밖에서 넘은 기준

README 표의 종목 상세는 삼성전자 한 종목으로 잰 값이다. 종목명이 긴 종목은 10월에 로컬에서 CLS 0.17 ~ 0.23이 나온 적이 있어 한계에 적어 뒀는데, 이번에 그 값을 배포본에서 다시 쟀다. LIG디펜스앤에어로스페이스(이하 LIG디펜스)와 피엔케이피부임상연구센타(이하 피엔케이)를 PageSpeed Insights(PSI)로 장중에 6회씩 잰 결과다.

| 종목 · 기기 | CLS (6회) |
|---|---|
| 삼성전자 · 모바일 | 0 ~ 0.002 |
| LIG디펜스 · 모바일 | 0.032 · **0.16** · **0.16** · 0 · 0.014 · **0.16** |
| 피엔케이 · 데스크톱 | **0.27** · 0.01 · 0.01 · **0.275** · 0.014 · 0.01 |

값이 0 근처와 0.16으로 갈려서, 중앙값(0.096)으로 적으면 한 번도 나오지 않은 값이 기준 통과로 읽힌다. 그래서 이런 값은 분포로 적기로 했다. PSI가 표시한 원인은 두 종목 모두 웹 글꼴이었고, 밀린 요소는 헤더 아래의 핵심 지표 카드와 탭 영역이었다.

## 휴장 측정으로는 확인할 수 없던 수정

장중에 재려는 이유는 README 표와 조건을 맞추기 위해서다. 시세가 가상 데이터라 시계만 장중으로 바꿔 재는 방법도 생각했지만, 시각을 읽는 곳이 서버와 브라우저에 흩어져 있고 그렇게 바꾼 빌드는 배포본이 아니어서 접었다. 대신 휴장 상태에서도 같은 현상이 나오면 주말에 수정 전후를 비교할 수 있겠다고 보고, 고치기 전의 배포본을 같은 방법으로 먼저 쟀다.

| 조합 | 금요일 장중 | 토요일 휴장 |
|---|---|---|
| LIG디펜스 · 모바일 | 6회 중 3회 0.16 | 6회 중 0회 (최대 0.031) |
| 피엔케이 · 데스크톱 | 6회 중 2회 0.27 | 6회 중 1회 0.27 |

한쪽은 고치기 전에도 나오지 않았으니, 고친 뒤에 나오지 않아도 확인이 되지 않는다. 다른 쪽은 12회 중 3회라서 고친 뒤 6회가 깨끗해도 고쳐지지 않은 채 우연히 그렇게 나올 확률이 18%쯤 된다. 드물게 나오는 현상을 반복 측정으로 확인하려면 회차가 훨씬 많아야 했고, 그렇게 해도 원인이 무엇인지는 알 수 없었다.

## 글꼴 응답 지연으로 재현

PSI가 원인으로 웹 글꼴을 표시했으니, 글꼴이 첫 화면보다 늦게 도착하는 회차에만 생기는 문제라고 가정했다. 로컬 프로덕션 빌드에서 글꼴 파일의 응답을 2초 늦춰 매번 늦게 도착하게 만들고, 글꼴을 아예 막아 교체가 일어나지 않는 경우를 대조군으로 뒀다. 이동이 생기면 움직인 요소의 좌표를 전후로 기록했다. [#178](/blog/slatekr/178/)에서 홈을 볼 때 쓴 방법에 가로 좌표를 더한 것이다.

| 종목 · 화면 폭 | 글꼴 지연 | 글꼴 차단 |
|---|---|---|
| LIG디펜스 · 412px | 0.158 | 0 |
| 피엔케이 · 1350px | 0.43 | 0 |
| 삼성전자 · 412px | 0.003 | 0 |

3회씩 쟀고 회차 사이의 차이는 0.002 이내였다. 글꼴을 막으면 0이 되므로 글꼴 교체가 원인이라는 가정은 맞았다. 크기도 PSI와 맞아서 모바일의 0.158은 PSI의 0.16과 같았고, 데스크톱은 0.156과 0.273 두 번의 이동으로 나뉘는데 뒤쪽이 PSI의 0.27이었다.

## 줄을 넘은 요소

종목명이 길어서 첫 줄이 감기는 것이 원인이라고 짐작하고 있었는데, 모바일에서 움직인 것은 첫 줄이 아니라 가격 아래의 통계 줄이었다.

```
LIG디펜스 · 412px    통계 줄(거래량 · 시가총액 · 기준일) 2줄 → 1줄
  줄의 폭 348px      내용 폭 356.7px(대체 글꼴) → 342.6px(웹 글꼴)
  "기준일"           둘째 줄 → 첫 줄, 가로로 231px 이동
  그 아래 전체       35.5px 위로

피엔케이 · 1350px    헤더 첫 줄(종목명 · 코드 · 시장 · 업종 · 홈페이지 링크) 2줄 → 1줄
  줄의 폭 659.9px    내용 폭 662.6px → 640.0px
  홈페이지 링크      둘째 줄 → 첫 줄, 가로로 626px 이동
  그 아래 전체       약 27px 위로
```

레이아웃 이동 점수는 움직인 영역의 면적 비율에 이동 거리 비율을 곱한 값이고, 이동 거리는 그 순간 가장 많이 움직인 요소 하나를 기준으로 잡는다. 아래 영역은 한 줄만큼 움직였을 뿐인데 줄을 넘은 요소가 가로로 수백 px 움직여서 점수가 커졌다. #178의 홈 제목과 같은 원리인데, 그때는 종목 헤더에 같은 구조가 있다는 것까지 보지 못했다. PSI의 이동 요소 표에는 면적이 큰 요소만 나와서, 줄을 넘은 작은 요소는 좌표를 직접 기록하고서야 보였다. 줄이 넘어가는 조건도 여기서 나왔다.

- 두 줄 모두 줄의 폭과 내용 폭의 차이가 몇 px
- 통계 줄에는 거래량 같은 값이 들어가 시간대에 따라 내용 폭이 달라짐
- 대체 글꼴은 기기마다 다름. 피엔케이 모바일은 내 PC에서 0.153, PSI에서는 0.054 이하
- 그래서 걸리는 종목이 값과 기기에 따라 달라짐. 휴장 PSI에서 LIG디펜스가 나오지 않은 것도 이 때문인 듯함

## 줄 나눔 고정

| 후보 | 판정 |
|---|---|
| 글꼴 표시 방식을 optional로 변경 | 기각. #178에서 접은 이유 그대로. 한글 글꼴은 미리 받아 둘 수 없어 첫 방문이 시스템 글꼴로 남을 수 있음 |
| 걸리는 종목만 처리(긴 종목명 말줄임 등) | 기각. 걸리는 종목이 값과 기기마다 달라 목록을 만들 수 없음 |
| **줄 나눔을 화면 폭 구간으로 고정** | **채택.** 글자 폭과 무관하게 줄 수가 정해짐 |

헤더의 스켈레톤은 이미 줄 구조를 고정해서 그리고 있었고, 실제 마크업만 폭이 모자랄 때 다음 줄로 넘기는 자연 줄바꿈에 맡겨져 있었다. 실제 마크업을 스켈레톤과 같은 구조로 맞추는 방식이라 새로 정할 것은 많지 않았다.

```
전  한 줄에 나열하고 폭이 모자라면 다음 줄로 (flex-wrap)

후  640px 미만     종목명 / 코드 · 시장 / 업종 · 홈페이지 링크
                   세션 라벨과 기준일은 항상 다음 줄
    640px 이상     종목명 / 배지 한 줄, 라벨과 기준일은 같은 줄
    1024px 이상    첫 줄은 줄바꿈 없는 한 줄, 폭이 모자라면 업종만 말줄임
```

```tsx
<span>거래량 {…}</span>
<span>시가총액 {…}</span>
<span className="basis-full sm:basis-auto">기준일 {…}</span>
```

처음 정한 범위는 두 군데를 다시 고쳐야 했다. 가격 줄은 문제가 확인된 적이 없어서 뺐는데 아래 스캔에서 5종목이 걸려 같은 방식으로 고쳤고, 모바일의 배지 줄은 한 줄로 고정하고 업종만 말줄임했다가 412px에서 103종목 중 65종목의 업종명이 잘려서 업종을 별도 줄로 내렸다. 대가는 높이와 동작이다. 이름이 짧은 종목도 모바일 헤더의 첫 영역이 세 줄이 되고, 폭이 넉넉한데도 라벨과 기준일이 아래 줄에 있는 구간이 생긴다.

## 103종목 스캔

세 종목만 보고 고쳤다고 하기는 어려웠다. 그래서 활성 종목에서 100개를 뽑아 세 종목과 함께 글꼴 지연 상태로 열고, 글꼴 전후로 줄이 바뀌는 요소가 있는 종목을 셌다.

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 412px · 첫 줄이 바뀐 종목 | 9 | 0 |
| 412px · 가격 줄이 바뀐 종목 | 5 | 0 |
| 412px · 통계 줄이 바뀐 종목 | 76 | 0 |
| 412px · CLS 0.1 초과 | 76 (최대 0.36) | 0 (최대 0.003) |
| 1350px · CLS 0.1 초과 | 1 (0.43) | 0 (최대 0.003) |

수정 전의 76종목은 내 PC의 대체 글꼴에서 글꼴을 일부러 늦춘 조건의 값이라, 실제 방문자가 겪는 빈도는 아니다. 다만 일부 종목의 문제로 보던 범위는 틀렸고, 통계 줄은 모바일에서 대부분의 종목이 걸릴 수 있는 구조였다. 360px에서도 줄이 바뀌는 종목은 없었고, 삼성전자는 네 가지 폭에서 스켈레톤과 실제 헤더의 높이가 같아졌다.

## 내려간 줄의 간격

줄 구조를 고정하고 보니 아래로 내려간 줄이 떨어져 보였다. 가로 간격으로 준 12 ~ 16px이 줄 간격에도 그대로 쓰이고 있어서, 라벨과 정규장 종가, 거래량과 기준일처럼 한 묶음인 줄 사이가 묶음 사이보다 넓었다. 가로 간격과 줄 간격을 나눠 가격 / 라벨 · 정규장 종가 / 거래량 · 시가총액 · 기준일 세 묶음으로 보이게 했고, 묶음 안의 줄 간격은 4px · 2px · 0px를 화면으로 비교해 0px로 정했다.

## 정리

- **README 성능 수치 검수** — Core Web Vitals 기준과 대조, 표의 3페이지는 통과, 표에 없는 2종목이 일부 회차에 CLS 기준 초과
- **원인 확정** — 글꼴 응답 지연과 차단 대조군으로 매번 재현, 글꼴이 바뀔 때 헤더의 요소가 줄을 넘음
- **종목 헤더 줄 구조 고정** — 첫 줄 · 가격 줄 라벨 · 통계 줄의 줄 나눔을 화면 폭 구간으로, 스켈레톤과 같은 구조
- **103종목 스캔** — 글꼴 지연 조건에서 모바일 CLS 0.1 초과 76 → 0, 데스크톱 1 → 0
- **줄 간격 조정** — 가로 간격과 줄 간격 분리, 세 묶음으로 정리
- **장중 측정 이월** — 수정은 배포했고, 배포본의 장중 PSI는 다음 거래일에 측정

지난 글 끝에 이제 마지막이길 바란다고 적었는데 한 편이 더 나왔다. #178에서 홈 제목을 고칠 때는 종목 헤더까지 보지 않았고, 한 달 뒤에 같은 종류를 다시 만난 셈이다. 재는 종목을 바꿔 보지 않았으면 그대로 냈을 것 같다.
