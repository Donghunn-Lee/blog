UI 마무리 버킷으로 돌아왔다. #119에서 등록한 F62(거래정지 공시 배지 누락)와 E46(UI 소형 배치)을 묶었고, 작업 중 푸터에서 KIS 출처 누락을 발견해 출처 표기 재구성까지 편승했다.

---

## 절차 키워드가 정지 사유 괄호에 걸린다

F62는 #119에서 발견한 문제다. 에코마케팅(230360)의 주권매매거래정지 공시에 시장조치 배지가 안 붙어 있었다 — 거래정지는 배지 체계에서 가장 센 신호에 속하는데, 정작 그게 무배지로 지나가고 있던 거다. 분류기 어디서 떨어지는지부터 probe로 확정했다. 문제의 공시 제목은 이렇다.

```
주권매매거래정지 (주식의 병합, 분할 등 전자등록 변경, 말소)
```

#083에서 만든 분류기는 거래소 발신 공시가 절차성 키워드(PROCEDURAL_KEYWORDS)에 하나라도 걸리면 배지 없이 null을 반환한다. "전자등록 변경"이 괄호 안 사유 표기에 그대로 들어 있으니 `.includes()`가 걸고, MARKET_ACTION이어야 할 공시가 컷된다.

#083 때 키워드를 짜면서 "정지·해제 같은 어미로 거르면 안 되고 사유로만 걸러야 한다"고 정리했었다. 그 원칙 덕에 정리매매 개시 같은 고신호가 살아남았는데 — 거래정지 공시가 자기 사유를 괄호로 달고 나온다는 것까지는 그땐 못 봤다. 사유로 거르기로 한 키워드가 정확히 그 사유 표기에 걸린 거다.

fixture(거래소 발신 177건) 기준 규모는 이랬다.

| 구분 | 건수 |
|---|---|
| 거래정지류 공시 | 39건 |
| 그중 null 오분류 | **20건 (51.3%)** |

최대 오탐원은 "변경상장" 9건. 거래정지**해제** 공시가 해제 사유(액면병합 주권 변경상장 등)를 달고 나오는 패턴이다.

## 우선 판정 한 줄

원인이 키워드 개별 문제가 아니라 "정지 사유 ↔ 절차 키워드"의 구조적 충돌이라, 수정도 키워드 손질이 아니라 판정 구조에서 골라야 했다. 선택지는 둘이었다.

| 안 | 걸리는 점 |
|---|---|
| 괄호 제거 후 키워드 매칭 | "기타시장안내(약명및영문명)" 같은 정상 절차성 공시가 역으로 MARKET_ACTION 오탐 전환 |
| 거래정지 우선 판정 | — |

수정이 새 오분류를 만드는 첫 안은 접었다. 거래정지는 사유가 뭐든 주가 관련성 신호 그 자체라 사유를 보고 거를 대상이 아니다 — 판정 하나를 컷 앞에 두는 걸로 갔다.

```ts
if (isExchangeFiled(flrNm)) {
  if (disclosureNm.includes("매매거래정지")) return DisclosureType.MARKET_ACTION;
  if (PROCEDURAL_KEYWORDS.some((kw) => disclosureNm.includes(kw))) return null;
  return DisclosureType.MARKET_ACTION;
}
```

"매매거래정지" 서브스트링 하나로 정지·해제·기간변경 전 변형이 커버된다(39건 전수 포함 확인). 회사 발신 경로는 무변경이다.

---

## OR 검사 아래 잠복해 있던 20건

더 걸린 건 테스트 쪽이다. 오분류 20건이 전부 fixture 안에 이미 들어 있었다. 그런데 회귀 가드용 테스트의 assert가 `result ∈ {MARKET_ACTION, null}` 합집합 검사라, 어느 쪽이어야 하는지를 묻지 않아 20건이 전부 통과 중이었다. 테스트가 데이터를 들고 있어도 assert가 묻지 않으면 없는 것과 같다.

불변식을 하나 추가했다 — "매매거래정지"를 포함하면 MARKET_ACTION이어야 한다. 잠복해 있던 20건이 이 한 줄로 회귀 가드로 전환됐고, 대표 3건은 명시 expected 케이스로도 박았다. vitest 557 passed.

## 공시 개수 배지를 직접 링크로

E46은 미뤄둔 소형 UI 잔손질 배치다. 본체는 공시 개수 배지 — 관심종목·순위 행의 "최근 공시 N건" 배지가 시각 표시일 뿐이고, 클릭하면 행 링크를 따라 종목 상세 개요로 간다. 공시가 궁금해서 누르는 건데 목적지가 다르다. 배지를 공시 탭 직행 링크로 바꾸는 게 목표였다.

사실 처음엔 다른 데를 고쳤다. 상세 페이지 공시 프리뷰 헤더의 "전체 보기 →"를 "총 N건 →"으로 바꾸는 방향으로 갔다가, 화면을 보고 나서야 원래 의도가 행 배지 쪽이었다는 걸 확인하고 커밋 전에 접었다. 헤더 라벨은 "전체 보기"가 링크라는 걸 더 정확히 말해주기도 한다.

본체 구현의 제약은 중첩 `<a>`다. 행 전체가 이미 링크인데 그 안에 배지 링크를 넣을 수 없다.

- **WatchlistRow** — 이미 stretched-link(absolute 오버레이) 패턴이라 배지만 relative + z-10으로 위에 올렸다
- **RankingRow** — 그리드 전체를 감싸던 wrapping-link를 오버레이로 전환했다

클릭 대상은 "N건" 텍스트만이다. "최근 공시" 라벨까지 링크로 만들면 행 클릭 영역이 애매하게 갈라진다. Tab 순서는 행 → 배지가 되도록 오버레이를 DOM 앞으로 옮겼다.

AI 요약 로딩 표시도 같이 정리했다. 스켈레톤 5줄이었는데, 스켈레톤은 레이아웃 점프를 줄이는 도구지 대기 신호가 아니다. AI 요약은 요청 시점 생성이라 소요가 가변이고(503 재시도 포함) 결과 형태도 미정이라 자리 채울 대상이 없다. 스피너 + "요약 생성 중…"으로 교체했다.

## 푸터 KIS 출처 누락

작업 중 푸터를 봤는데 출처에 KIS가 없다. 시세 소스가 pykrx에서 KIS로 넘어온 게 #097~#098인데 표기는 그대로였던 거다.

카테고리별 6줄로 채워 넣고 보니 이번엔 푸터가 과했다. 그리고 공시 테이블엔 이미 "출처: DART 전자공시시스템"이 붙어 있다 — 소스↔데이터 매핑은 섹션 인라인이 맡고 있으니, 푸터가 전체 매핑을 중복으로 짊어질 이유가 없다.

- **푸터** — disclaimer + "데이터 출처·라이선스" 링크 + GitHub, 두 줄
- **/credits** — 카테고리별 출처 + 오픈소스 라이선스 정적 페이지

라이선스 쪽에서 하나 걸렸다. lightweight-charts는 attribution notice와 tradingview.com 링크를 사용자 접근 가능한 페이지에 두는 게 요건인데, 그 충족 수단인 차트 코너 로고(attributionLogo)를 우리 차트 3개가 전부 명시적으로 꺼둔 상태였다.

로고를 다시 켤지 봤는데, 공식 문서가 "링크 요건을 다른 방식으로 충족하면 로고를 꺼도 된다"고 명시하고 있다. NOTICE 원문(npm 패키지엔 미동봉이라 GitHub 저장소에서 확보)과 링크를 /credits에 게재하는 걸로 요건을 채우고, 로고 off라는 기존 UI 결정은 유지했다.

## 정리

- **F62 종결** — 거래정지 우선 판정 한 줄로 fixture 기준 오분류 20건 회복. OR-검사에 잠복해 있던 20건은 불변식 assert로 회귀 가드 전환
- **E46 종결** — 공시 개수 배지 → 공시 탭 직행 링크(stretched-link 전환) + AI 요약 로딩 스피너 교체
- **출처 표기 재구성(비계획)** — 얇은 푸터 + /credits 페이지 분리, lightweight-charts attribution 요건 정리

키워드 분류는 넣을 때의 의도와 실제로 걸리는 문자열이 다를 수 있다는 걸 #083의 선을 다시 그으며 확인했다. 38세션 전에 만든 fixture가 오분류를 고스란히 보존하고 있었던 덕에, 이번 수정의 규모 산정과 회귀 가드 전환이 같은 데이터 위에서 끝났다.
