#050부터 #052까지 세 세션에 걸쳐 관심종목 그룹 기능을 쌓았다. store를 다대다로 갈아엎고(#050), 그룹 CRUD와 다중 그룹 선택을 붙이고(#051), 그룹 관리 모달까지 만들었다(#052). 이번 #053은 그동안 미뤄둔 잔여 수정들을 한 세션에 모아 처리하면서 E5 트랙을 닫는 회차다.

수정 항목은 다섯 개였는데, 대부분은 짧게 끝났다. 실제로 고민한 건 두 군데 — **그룹 안 종목에 순서를 주는 작업**과 **모달에서 그룹을 지웠을 때 화면이 빈 탭으로 떨어지는 문제**였다. 이 둘을 중심으로 적는다.

---

## 그룹 내 종목 순서

그룹끼리는 #051에서 `▲▼`로 순서를 바꿀 수 있게 해뒀는데, 정작 그룹 안에 든 종목은 순서 개념이 없었다. 추가한 시간(`addedAt`) 순으로만 나열될 뿐이라, 사용자가 보고 싶은 순서대로 정렬할 방법이 없는 상태였다.

종목에 순서를 주려면 membership(어떤 종목이 어떤 그룹에 속하는지를 담는 단위)에 `order` 필드를 추가해야 한다. 그리고 이미 저장돼 있는 기존 사용자의 데이터에도 이 필드를 채워 넣어야 하니, persist 마이그레이션이 한 번 더 필요했다.

### 데이터만 깔면 죽는다

처음엔 작업 범위를 "`order` 필드 + 순서를 바꾸는 순수 함수"까지로 잡았다. 그런데 여기까지만 하면 `order`는 항상 추가 순서대로 박히고, 사용자가 그걸 바꿀 수단이 없다. 화면에 ▲▼ 버튼이 없으면 필드를 만들어놓고 아무도 못 건드리는 **죽은 필드**가 되는 셈이다.

그래서 이번엔 데이터 레이어와 UI를 한 커밋으로 묶었다. 순서를 바꾸는 순수 함수 `moveMembershipIn`을 만들고, 그걸 호출하는 ▲▼ 버튼을 그룹 관리 모달의 종목 행에 같이 붙였다. 함수만 먼저 만들고 UI를 다음 세션으로 미루는 선택지도 있었지만, `order` 도입의 목적 자체가 "사용자가 순서를 정하는 것"이라 둘을 떼면 의미가 없었다.

순서 변경 로직은 그룹 순서를 바꿀 때 쓴 `moveGroupIn`과 같은 스왑 방식을 그대로 가져왔다. 다만 대상을 **같은 그룹 안의 종목으로만** 한정한다.

```ts
moveMembershipIn(snapshot, ticker, groupId, dir: "up" | "down")
// 같은 groupId 안에서만 정렬·스왑, 양 끝에서는 no-op
```

### 마이그레이션 정렬 방향

진짜 판단이 필요했던 건 마이그레이션이었다. 기존 사용자의 데이터에 `order`를 채워 넣을 때, 어떤 순서로 번호를 매길지 정해야 했다.

선택지는 둘이었다.

| 방향 | 결과 |
| --- | --- |
| addedAt **asc** (오래된 것부터 0번) | 마이그레이션 직후 화면 순서가 뒤집힌다 |
| addedAt **desc** (최신부터 0번) | 마이그레이션 전 화면 그대로 유지된다 |

기존 화면은 최신 추가가 위에 오도록 정렬돼 있었다(`addedAt` 내림차순). 만약 asc로 번호를 매기면, 마이그레이션이 도는 순간 사용자가 보던 순서가 위아래로 뒤집혀버린다. 데이터 구조만 바뀌었을 뿐인데 화면이 달라지면, 쓰는 사람 입장에선 영문 모를 변화다.

그래서 desc로 번호를 매겼다. 마이그레이션의 기본값은 **"보던 게 안 바뀐다"** 여야 한다고 봤다. 구조를 바꾸는 작업과 사용자 눈에 보이는 순서를 바꾸는 작업은 별개고, 후자는 사용자가 직접 ▲▼를 누를 때만 일어나야 자연스럽다.

마이그레이션 이후 selector의 정렬 기준도 `addedAt` 내림차순에서 `order` 오름차순으로 바꿨다. 이제 종목 순서는 추가 시간이 아니라 사용자가 정한 값을 따른다.

## 빈 탭으로 떨어지는 문제

관심종목 페이지는 좌측에 그룹 탭, 우측에 선택한 그룹의 종목을 보여준다. 어떤 탭이 선택됐는지는 페이지가 `selectedTab`이라는 로컬 상태로 들고 있다.

문제는 이런 상황이었다. A 그룹을 보고 있다가, 그룹 관리 모달을 열어 A 그룹을 삭제하고 저장한다. 모달은 store를 통째로 갈아끼우니 그룹 목록에서 A가 사라진다. 그런데 `selectedTab`은 여전히 사라진 A의 id를 들고 있다. 결과는 — 헤더가 비고, "이 그룹에 종목이 없습니다"라는 엉뚱한 메시지가 뜨고, 어느 탭도 선택 표시가 안 되는 어정쩡한 화면이다. 그룹은 사라졌는데 페이지는 아직 있는 척을 하는 거다.

원인은 한 줄로 정리된다. 그룹이 사라졌을 때 `selectedTab`을 고쳐줄 지점이 어디에도 없었다.

### 네 가지 방법

해결 방향을 네 개 놓고 봤다.

| 방법 | 문제 |
| --- | --- |
| (a) effect로 그룹 변화 감지 → `setSelectedTab` 보정 | effect 안에서 setState — lint 충돌(#052에서 같은 이유로 뺐던 패턴) |
| (b) 렌더 도중 빈 그룹이면 `setSelectedTab` | 렌더 중 setState — 같은 충돌 |
| (c) `selectedTab`을 진실로 쓰지 않고, 렌더 때 유효한 탭으로 파생 | 없음 |
| (d) 모달이 저장 후 콜백으로 알려줌 | API 표면이 늘고, 별표 같은 다른 삭제 경로는 못 잡음 |

(a)와 (b)는 setState를 동반해서 lint에 걸린다. #052에서 비슷한 패턴을 한 번 들어낸 적이 있어서, 다시 끌어오고 싶지 않았다. (d)는 모달이 저장될 때는 잡지만, 종목 상세의 별표 팝오버에서 그룹의 마지막 종목을 빼 그룹이 비는 경우 같은 다른 경로는 놓친다.

(c)로 갔다. `selectedTab`을 화면의 진실로 삼지 않고, 렌더할 때마다 "이 id가 아직 살아있는 그룹인가"를 확인해서 유효한 값을 따로 뽑아낸다.

```ts
const effectiveTab =
  selectedTab === RECENT_TAB
    ? RECENT_TAB
    : sortedGroups.find((g) => g.id === selectedTab)?.id ?? RECENT_TAB;
```

이후 화면이 쓰는 모든 값(현재 그룹, 종목 목록, 탭 활성 표시, 모달에 넘기는 초기 그룹)을 `selectedTab`이 아니라 `effectiveTab` 기준으로 바꿨다. `setSelectedTab`은 사용자가 탭을 클릭할 때만 호출한다.

이렇게 두면 그룹이 어느 경로로 사라지든 — 모달에서 삭제하든, 별표에서 마지막 종목을 빼든 — `find`가 그 id를 못 찾으니 자동으로 "최근 조회" 탭으로 떨어진다. 보정 코드를 따로 둘 필요가 없다.

### 덤으로 따라온 것

(c)에는 의도하지 않았던 이점이 하나 있었다. setState로 `selectedTab`을 강제로 바꾸지 않기 때문에, 만약 같은 id의 그룹이 되살아나면(되돌리기 같은 상황) `selectedTab`은 그 값을 그대로 들고 있었으니 화면도 즉시 그 그룹으로 복귀한다.

(a)나 (b)였다면 그룹이 사라진 순간 `selectedTab`에 "최근 조회"를 박아버리니, 그룹이 돌아와도 이미 값이 덮였다. 파생만 하고 원본을 안 건드린 게 이 복귀를 공짜로 만들어줬다. 사실 작업할 땐 거기까지 노리고 고른 건 아니었는데, 따져보니 이쪽이 더 깔끔했다.

## 기타 수정 사항

그밖에 이번 세션에서 작업한 자잘한 수정사항들이 있다.

**검색 대소문자.** `lg`로 LG전자가 안 잡혔다. Postgres의 `LIKE`가 대소문자를 가리는 탓이라, 검색 쿼리의 `LIKE`를 `ILIKE`로 바꿔 해결했다.

**모달 검색 키보드 탐색.** 모달에서 종목을 검색할 때 방향키와 Enter로 결과를 다룰 수 있게 했다. 여기서 한 번 길을 바꿨다. 처음엔 이미 그룹에 든 "등록됨" 항목에도 커서가 멈추되 Enter만 막는 식으로 짰는데, 막상 써보니 Enter를 눌렀는데 아무 일도 안 일어나는 게 매번 거슬렸다. 그래서 방향키 이동 자체가 비활성 항목을 건너뛰고 다음 활성 항목으로 점프하도록 고쳤다. Enter는 항상 동작한다.

**"등록됨" 비활성 스타일.** 위의 등록됨 항목이 `cursor-not-allowed`로 커서만 바뀌는 게 어정쩡해서, 커서 변경을 빼고 배경을 톤다운하고 글자를 흐리게 하는 색상 처리로 바꿨다.

## 정리

이번 세션 작업 내용을 정리하면 다음과 같다.

- **종목 순서(E8)** — membership에 `order` 도입, persist 마이그레이션은 기존 화면 순서를 보존하는 방향으로, ▲▼ UI까지 한 커밋
- **빈 탭(E11)** — `selectedTab`을 파생값으로 다뤄 사라진 그룹에서 자동 복구
- **잔여 셋** — 검색 `ILIKE`, 모달 검색 키보드 탐색, "등록됨" 비활성 스타일

이걸로 관심종목 그룹 기능은 닫혔다. 그룹을 만들고 정리하고, 종목을 검색해 담고, 원하는 순서로 배열하는 흐름이 전부 돈다. #050에서 store를 다대다로 갈아엎을 때만 해도 칸이 꽤 남아 보였는데, 네 세션에 나눠 담으니 한 칸씩 메워졌다.
