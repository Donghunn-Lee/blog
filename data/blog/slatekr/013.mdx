#012에서 예고한 대로 이번엔 홈 UI를 보완했다.

기존 홈은 로고와 검색창만 있는 상태였다. 기능은 동작하지만, 재방문했을 때 아무것도 없는 빈 화면이었다. 검색창 하나만 달랑 있으면 서비스가 뭘 보여주는지도 모르고, 이전에 봤던 종목으로 돌아가는 진입점도 없다.

---

## 홈 구성 결정

어떤 섹션을 넣을지부터 정해야 했다. 여러 가지를 검토했지만 결국 세 가지로 압축했다.

**Hero** — 기존 검색창 유지, 최근 검색어 칩 추가.
**관심종목 미리보기** — 저장한 종목을 홈에서 바로 확인.
**서비스 소개** — 이 서비스가 뭘 보여주는지 3장 카드로 요약.

시장 대시보드, 거래대금 상위, 뉴스 피드 같은 것들도 후보였지만 지금 단계에선 뺐다. MVP 본체는 조회형 서비스 구조 완성이고, 홈부터 이것저것 붙이면 방향이 흐려진다.

## HomePanel을 따로 만들지 않았다

홈 섹션들에 패널 래퍼가 필요했다. 처음엔 `HomePanel`을 별도로 만들까 생각했는데, 기존 `StockPanel`을 보니 그냥 재사용해도 될 것 같았다. 홈 섹션들도 종목 상세와 동일한 패널 스타일이고, 홈 전용 variant가 필요한 것도 지금으로선 딱히 없었다.

굳이 만들면 파일만 늘어나니, `StockPanel` 그대로 썼다.

---

## page.tsx의 use client

현재 `page.tsx`에 `use client`가 붙어 있다. `useRouter`, `useState`, `useRecentSearchesStore` 같은 클라이언트 훅을 직접 쓰기 때문이다.

아키텍처 원칙상 페이지 전체 `use client`는 지양하는 방향이지만, 지금 홈 `page.tsx`에서 서버에서 fetch할 데이터가 없다. DB 조회 없이 클라이언트 상태만 쓰는 구조라 분리해봤자 구조만 복잡해진다.

나중에 거래대금 상위나 시총 상위 같은 패널이 생기면 그때 달라진다. 서버에서 직접 데이터를 가져와야 하니까 `page.tsx`는 Server Component로 올리고, `HeroSection`이나 `WatchlistPreview`처럼 클라이언트 훅이 필요한 부분만 별도 컴포넌트로 분리하면 된다. 지금은 그 시점이 아니라고 판단했다.

## 관심종목 미리보기

<img src="/static/images/velog/c0143335-07d8-45da-a19d-e4730ccbd14b-image.png" style={{width: '100%', maxWidth: '600px'}} />

이 프로젝트의 핵심 플로우가 검색 → 상세 → 저장 → 재방문이다. 홈에 관심종목 미리보기가 없으면 재방문 루프가 끊긴다.

구조상 고민이 하나 있었다. 관심종목 목록은 Zustand persist(localStorage)에 있는데, 현재가와 등락률은 DB에서 가져와야 한다. Server Component로 만들면 localStorage에 접근할 수 없고, 그렇다고 종목 수만큼 개별 API를 호출하는 건 비효율적이다.

`/api/prices` 라우트를 새로 만들어서 여러 ticker를 쿼리 파라미터로 받아 배치 조회하는 방식으로 해결했다. `WatchlistPreview`는 mount 시점에 store에서 ticker 목록을 읽고, 이 API를 한 번 호출해서 전체 가격 데이터를 받아온다.

관심종목이 없을 때는 섹션 자체를 렌더링하지 않는다. 빈 상태를 보여주는 것보다 없는 편이 낫다고 판단했다.

## 최근 검색어

<img src="/static/images/velog/e14f9042-8834-4af8-9a7b-c8628085858b-image.png" style={{width: '100%', maxWidth: '600px'}} />

`useRecentSearchesStore`를 새로 만들었다. Zustand persist 기반으로, 종목 선택 시 ticker와 종목명을 저장한다. 최대 5개, 중복 선택 시 맨 앞으로 이동한다.

`useWatchlistStore`에 이어 두 번째 persist store다. 관심종목과 구조는 같지만 역할이 다르다. 관심종목은 명시적으로 저장하는 것이고, 최근 검색어는 행동 흐름에서 자동으로 쌓이는 것이다.

Hero 하단에 칩으로 렌더링했고, 클릭하면 종목 상세로 바로 이동한다.

## 다음 작업

홈 완성 이후엔 검색 플로우를 마저 정리할 예정이다. 현재 검색창에서 엔터를 치면 입력값 그대로 URL에 붙는데, 이걸 `/search?q=` 라우트로 분리하고 자동완성에만 의존하지 않는 결과 페이지를 구현할 생각이다.
