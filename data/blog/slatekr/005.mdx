데이터 적재 작업 중, 우선 `fetch_stocks.py`가 완성된 상태다. 종목 목록은 FSS API로 해결했고, 나머지 두 스크립트가 남아 있었다.

## fetch_prices.py

pykrx로 OHLCV를 적재하는 스크립트다. 구조는 단순하다. pykrx의 `get_market_ohlcv(시작일, 종료일, 종목코드)`로 데이터를 받아서 `daily_prices` 테이블에 넣는다.

삼성전자 단일 종목으로 먼저 테스트했다. 6건이 정상 적재됐다. 그 다음 1년치로 범위를 늘려서 다시 확인했고, 244거래일이 그대로 들어왔다.

전체 종목으로 넘어갔다. 2659개 종목 × 0.3초 간격으로 약 13분. 완료: 성공 2659, 스킵 0, 오류 0. `COUNT(*)`는 636,099건이었다. 2659 × 244 이론치보다 적은 건 상장일이 1년 안쪽이거나 거래 정지된 종목들 때문이다.

## fetch_financials.py

DART `fnlttSinglAcntAll` API로 재무제표를 적재하는 스크립트다. 여기서 예상 못 한 문제가 몇 가지 나왔다.

**account_id가 달랐다.**
영업이익의 account_id가 `ifrs-full_ProfitLossFromOperatingActivities`일 거라 생각했는데, 삼성전자 실제 응답에서는 `dart_OperatingIncomeLoss`였다. EPS도 마찬가지였다. 예상한 dart_EPS가 아니라 `ifrs-full_BasicEarningsLossPerShare`로 나왔다.
문서에 나온 account_id와 실제 응답이 다른 경우가 있었다. 결국 API 응답을 직접 출력해서 실제 필드명을 하나씩 확인하는 방식으로 해결했다.

**당기순이익이 0으로 들어왔다.**
실제 데이터를 넣어보고 나서야 발견했다. `ifrs-full_ProfitLoss`가 응답 목록에 여러 번 등장했고, 마지막 값인 0으로 덮어씌워진 탓이었다.
DART 재무제표 응답은 동일한 account_id가 지배구조나 회계 기준에 따라 여러 번 나올 수 있다. 동일한 account_id가 나오면 첫 번째 값만 쓰도록 수정했다.

**bps/dps는 DART에서 직접 제공하지 않는다.**
이건 설계 단계에서 "DART에서 받을 수 있다"고 가정했던 부분인데, 실제로는 없었다. BPS는 자본총계 ÷ 발행주식수로 계산해야 하고, DPS는 별도 API가 필요하다. 지금 단계에서는 있는 것만 넣고 보완은 나중으로 미뤘다.

전체 적재 결과는 성공 2031, 스킵 628이었다. 현재 임시로 2024년 데이터를 활용중인데, 스킵된 종목들은 2024년 사업보고서를 아직 제출하지 않은 곳들이다. 사업보고서 제출 기한이 3~4월이라 시점에 따라 스킵 수가 달라진다.

## 파이프라인 완성

세 스크립트가 모두 완성됐다.

| 스크립트 | 소스 | 상태 |
|---|---|---|
| `fetch_stocks.py` | FSS API | 완료 |
| `fetch_prices.py` | pykrx | 완료 |
| `fetch_financials.py` | DART API | 완료 |

이제 데이터는 DB에 들어가 있다. 다음은 Next.js에서 이 데이터를 읽어서 도메인 모델로 변환하는 `lib/` 계층을 만드는 단계다.
