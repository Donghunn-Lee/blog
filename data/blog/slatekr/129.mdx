#127에서 국내 지수 4종의 1분봉을 DB에 쌓기 시작했고, #128에서 마감 경계 봉을 다루는 규칙을 정했다. 남은 건 그 DB를 화면에 잇는 서빙 연결이었다. 지수 상세의 당일 차트는 아직 10분봉 on-demand로 그리고 있었고, 1분 데이터는 적재만 되고 어디서도 읽히지 않는 상태였다.

계획은 1분 route를 만들고 지수 상세 당일 차트에 붙이는 것까지였다. 연결은 됐는데, 계획 단계에서 정한 결정 둘을 세션 안에서 뒤집었고 차트 툴바에 버튼이 하나 늘었다. 토요일이라 장중 검증은 못 했고, DB와 live가 같은 금요일 데이터를 들고 있는 조건에서 정적으로만 확인했다. 수정이 여러 번 오갔지만 전부 지수 차트 하나 안에서 벌어진 일이라, 순서보다는 결정 단위로 묶어 적는다.

## 1분 route — 해외 경로를 국내로

해외 지수 1분 route(#094)를 probe로 읽고 그 구조를 국내에 그대로 옮겼다. 병합 함수와 실패 계약도 같은 것을 쓴다.

```
DB 하루치(거래일 필터)
  + live tail(지수 1분 TR, 최근 100여 분)
  → 시각 키 병합, 충돌 시 live 우선
  → 세션 × 거래일 캐시
```

국내 사정에 맞춰 손댄 건 두 곳이다.

| 항목 | 걸린 점 | 처리 |
|---|---|---|
| 시각 인코딩 | dedup 키가 epoch라 DB·live 변환이 어긋나면 같은 분이 두 봉으로 남음. 오류 없이 조용히 남는 종류 | live가 쓰던 변환 함수 하나를 DB 읽기에도 통과시키고, 같은 시각 = 같은 epoch를 테스트로 고정 |
| 요청 날짜 | 첫 구현이 장중에도 날짜를 보냈는데 collector는 장중엔 날짜 없이 호출 | 검증된 요청 형상대로 장중엔 빼고, 응답을 거래일로 거르는 필터만 항상 유지 |

금요일 데이터로 확인한 값은 전부 미리 계산한 기대치와 같았다.

| 항목 | 우리 | 기준 | 차이 |
|---|---|---|---|
| 봉 수 (KOSPI·KOSDAQ·KOSPI200 / KOSDAQ150) | 278 / 277 | 계산값 278 / 277 | 0 |
| 마감 봉 종가 4종 | 6788.88 · 838.41 · 1065.70 · 1458.56 | 공식 종가 (코스닥150은 #128 편차 −0.06 수용) | 0 |
| KOSPI 마감 봉 거래량 | 7,578 | 15:30 raw 7,547 + 마감 후 프린트 0 + 31 | 0 |

#128의 병합 규칙이 1분에서도 그대로 성립한다.

## 10분봉을 지운 결정

probe에서 확인한 사실 하나가 판단을 갈랐다. 10분 on-demand는 당일 하루만 커버한다. 1분 DB가 있는 이상 10분봉은 1분을 묶어 만들 수 있다는 뜻인데, 그래도 계획 단계에서는 10분 경로를 남기기로 했었다.

| 시점 | 판단 | 근거 |
|---|---|---|
| 계획 단계 | 10분 존치, 1분은 상세 전용 | 홈 미니가 10분 사용 중 · 10분 TR은 collector 무관 독립 소스라 적재가 멈춰도 홈은 유지 · 홈 폴링 payload 10× |
| **route 연결 후** | **단일화, 10분 경로 삭제** | 10분은 #066의 제약(1분 TR 최근 100봉만, 하루치 불가) 우회였고 적재가 그 제약을 없앰 · #106에서 툴바를 종목과 공유한 뒤라 종목엔 1·5·15분 그룹, 지수엔 없는 비대칭 |

적재가 붙은 뒤에도 우회 경로를 유지하는 건 앞뒤가 맞지 않았다. 남기려던 근거는 다시 저울질했고, 셋 다 반전을 막을 만큼은 아니었다.

- **적재 의존이 홈까지 확산** — 해외 미니가 이미 DB + live tail 구조라 새로운 종류의 위험은 아님
- **collector 결손** — 30분 주기에 100분 창 중첩이라 3회 연속 결손 전엔 갭 없음. 그 이상은 알림(F27) 영역
- **payload** — 지수 4종 × 하루 1분봉, gzip 수십 KB 수준

임시로 붙였던 `-1m` route와 훅은 남기지 않고 기존 route를 교체했다. 결과적으로 코드는 늘지 않고 줄었다. 미니 차트 간격은 상수 하나로 뒀는데, 1분이 너무 촘촘해 보이면 5분으로 바꾸는 건 한 줄이다.

엄밀히는 probe가 틀렸다기보다 요구가 하나 늘어난 것이다. 툴바 대칭을 처음부터 목표에 넣었다면 첫 결정이 달랐을 텐데, 절단선을 "route와 당일 1분선"으로만 잡아서 그 너머를 보지 않았다.

## END 변환, 다시 클라로

분봉 툴바를 넣으면 클라에서 리샘플이 생기고, 그러면 END 라벨 변환이 서버에 있을 수 없다. #126의 원칙이 "변환은 마지막 리샘플 이후"였고, 지수는 리샘플이 없어서 서버 서빙 단계가 그 위치였을 뿐이다. 첫 결정 때 "분봉 토글을 넣게 되면 START 출력과 클라 END로 바꿔야 한다"고 결합 관계를 적어 뒀는데, 그게 같은 날 발동했다.

```
전: 서버 — DB + live 병합 → 마감 후 프린트 병합 → END 변환(1분) → 클라 표시
후: 서버 — DB + live 병합 → 마감 후 프린트 병합 → START 출력
    클라 — 리샘플(1/5/15분) → END 변환 → 표시
```

옮기면서 손댄 곳은 둘, 그중 하나는 #128 결정의 수정이다.

| 위치 | 내용 | 이유 |
|---|---|---|
| 클라 | 신규 유틸 없이 #128의 세션 분할 리샘플 유틸을 경계 15:30 하나로 재사용 | NXT 애프터마켓이 없어 두 번째 세그먼트는 비고, 마감 후 프린트는 서버에서 이미 15:30으로 합쳐져 경계를 넘는 raw가 없음 |
| 서버 | 마감 후 프린트 처리를 "시각만 15:30으로 변경"에서 "변경 + 병합"으로 재정의 | #128은 병합을 END 변환 유틸의 충돌 병합에 맡겼는데, END가 클라로 가면 응답에 15:30 봉이 세 개 남음. 라벨이 유일하지 않은 응답은 소비처마다 병합을 기대하게 만듦 |

병합 규칙은 END 변환 유틸에서 함수로 빼내 양쪽이 같은 것을 쓴다.

```
open = 앞 봉 · close = 뒤 봉 · high/low = 극값 · volume = 합
→ 순서만 지키면 서버에서 먼저 합치든 클라에서 합치든 결과 동일 (테스트로 고정)
```

## 지수를 바꿔도 줌이 남는 문제

배선을 끝내고 차트를 만지다가 오래된 항목 하나가 다시 떠올랐다. 전에 "차트 줌 초기화"를 조치 불요로 닫은 적이 있는데, 그때는 종목 차트에서 기간을 바꿔도 줌이 유지되는 게 자연스럽다고 봤다. 처음 등록했던 관찰은 지수 페이지 쪽이었다. 지수 상세는 #074에서 전환 깜빡임을 없애려고 차트 remount를 걷어낸 구조라, 코스피에서 줌을 바꾸고 코스닥으로 넘어가면 그 뷰포트가 그대로 따라온다. 종목은 라우트가 바뀌며 차트가 새로 뜨니 같은 문제가 없다.

전환할 때 강제로 초기화하는 쪽으로 가려다 멈췄다. 코스피와 코스닥, 코스피와 나스닥을 같은 구간에서 비교하는 건 꽤 흔한 사용이고, 그 경우엔 뷰포트가 유지되는 게 오히려 맞다.

| 후보 | 판정 |
|---|---|
| 전환 시 뷰포트 자동 초기화 | 기각. 동기간 비교 사용을 막음 |
| 전환 시 툴바까지 전부 초기화(remount) | 기각. #074가 걷어낸 remount 복원 |
| **유지 + 리셋 버튼** | **채택.** 사용자가 원할 때만 초기 화면으로 |

버튼 사양은 이렇게 잡았다.

- **범위** — 줌·팬만. 당일 뷰는 잠금 범위(#090), 전체 뷰는 현재 봉수 기준 범위로 복귀. 당일/전체·분봉·캔들/선은 유지
- **위치·라벨** — 봉수 입력 오른쪽, "기본 배율". "보기 초기화"는 어감, "기간 초기화"는 옆의 일·주·월과 뜻이 겹쳐 기각
- **아이콘** — 되감기 모양. 새로고침 모양은 데이터를 다시 받는 것으로 읽힘
- **종목 차트** — 툴바가 공유라 같은 자리에 동일 배치

이미 기본 화면일 때는 버튼을 비활성으로 두기로 했는데, 이 판정이 생각보다 비쌌다. "사용자가 움직였는가"를 차트 라이브러리의 범위 변경 콜백으로 판정했더니, 프로그램이 범위를 세팅한 직후에도 콜백이 늦게 한 번 더 오는 경우가 있어 첫 방문이나 당일↔전체 왕복에서 버튼이 켜졌다. 애니메이션 프레임 가드를 한 겹, 두 겹 둬도 완전히 막히지 않아 판정 근거 자체를 바꿨다.

```
전: 라이브러리 범위 변경 콜백 → "사용자 조작" 판정 + 봉수 입력 되돌림
후: 컨테이너 wheel / mousedown / touchstart → "사용자 조작" 플래그
    범위 변경 콜백 → 플래그가 선 뒤에만 봉수 되돌림
```

이 수정으로 같이 정리된 게 둘 있다.

- **#074 잠재 버그** — 전체 뷰 봉수가 설정값 대신 123 같은 값으로 떠 있던 원인이 그 지연 콜백의 입력 칸 덮어쓰기. 게이트 이후 설정값 유지
- **리셋 효과 의존성** — 뷰 모드 값이 의존성에 들어가 리셋을 한 번 누른 뒤엔 국내↔해외 전환마다 초기화가 발동할 상황. 값은 ref로 읽고 의존성은 리셋 카운터 하나로

## 정리

- **E61 서빙 연결** — 국내 지수 intraday를 DB 1분 + live tail 단일 route로. 10분 on-demand 경로는 삭제, 코드는 순감소
- **결정 반전 둘** — 10분 존치와 서버 END 변환을 같은 날 뒤집음. 10분은 #066 제약의 우회였고, END 위치는 리샘플 위치에 종속
- **마감 후 프린트 병합 재정의** — 시각 변경만에서 병합까지로. 병합 규칙은 유틸에서 추출해 공유
- **E63 기본 배율 버튼** — 지수 전환 시 뷰포트 유지는 의도한 동작으로 재확정하고, 줌·팬만 되돌리는 버튼을 지수·종목 툴바에. 부수로 #074 봉수 덮어쓰기 교정
- **월요일 이월** — 장중 DB·live 병합, 09:00부터의 커버, 개장 전후 전환은 실측 전

절단선을 넘겨 세 번 커밋했는데, 뒤집은 결정들은 probe가 틀려서가 아니라 목표를 route에만 좁게 잡아서 나온 것이었다. 오늘 쓴 코드가 아직 손에 있을 때 뒤집는 게 다음 세션에 다시 여는 것보다 쌌고, 결과가 코드 감소로 끝난 걸 보면 방향은 맞았던 듯하다.
