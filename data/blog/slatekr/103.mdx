## 현황 probe — 반응형 분기 5%

수정에 들어가기 전에 타이포가 지금 어떻게 적용돼 있는지부터 훑었다.

- `text-*` 스케일 사용 285건 중 반응형 프리픽스(`sm:` 등) 동반이 15건, 약 5%. 데스크톱 단일 스케일이 모바일에 그대로 나가고 있었다
- `text-[11px]` `text-[13px]` 같은 arbitrary px가 약 70건 산포
- styleguide에 타이포 role 5종이 정의돼 있긴 한데, 인라인 style 시연일 뿐이었다. 실제 코드는 `text-sm`과 arbitrary px로 각자 가고 있었다

[#023](/blog/slatekr/022/)에서 styleguide를 만들며 role을 잡아뒀는데, 대부분 적용하려 했으니 코드와 이어지지 않은 부분이 아직 많았다는 게 이번에 드러난 셈이다. 사실 그동안 작업하면서 이 간극을 망각했던 것 같다.

선택지는 둘이었다. 사용처마다 `sm:` 프리픽스를 붙이는 컴포넌트별 수정은 300건 가까운 산포 위에 프리픽스를 더 얹는 거라 두 번째 drift를 만든다. role 토큰 층을 세우고 사용처를 role로 치환하면 이후 모바일 스케일 재조정이 토큰 값 수정 하나로 끝난다. 후자로 갔고, 치환 범위는 이번 스코프(홈·종목 상세)로 잘랐다. 잔여 페이지는 리팩토링 트랙으로 넘긴다.

role은 실사용 분포에 맞춰 7종으로 확장했다.

| role | desktop | mobile | 대체 대상 |
| --- | --- | --- | --- |
| display | 36px | 28px | 라이브 현재가 |
| headline | 24px | 20px | h1·페이지 타이틀 |
| value | 18px | 16px | 지표 값 |
| body | 14px | 13px | text-sm |
| body-sm | 13px | 12px | text-[13px] |
| caption | 12px | 11px | text-xs |
| micro | 11px | 10px | text-[11px] |

## @theme inline과 var() 간접 참조

Tailwind v4는 `@theme`의 `--text-*` 키로 유틸리티를 자동 생성해준다. 문제는 기존 globals.css가 `@theme inline`이라는 것 — inline은 값을 빌드 타임에 유틸리티로 박아 넣는다. 리터럴로 정의하면 미디어쿼리에서 변수를 바꿔도 유틸리티가 안 따라온다.

그래서 shadcn 색 토큰이 쓰는 것과 같은 간접 참조로 갔다. `:root`의 런타임 변수를 경유시키면, 인라인되는 건 `var()` 참조라 미디어쿼리 오버라이드가 그대로 먹는다.

```css
:root { --fs-body: 0.875rem; }
@media (width < 40rem) {
  :root { --fs-body: 0.8125rem; }
}
@theme inline {
  --text-body: var(--fs-body);
  --text-body--line-height: 1.5; /* unitless — 모바일에서 자동 비례 */
}
```

이제 `text-body` 하나만 붙이면 640px 경계에서 알아서 줄어든다. 사용처에 반응형 프리픽스가 필요 없어졌다.

styleguide Typography 섹션도 이 참에 role명 = 유틸리티 = 데모가 일치하게 재작성했다. 샘플이 실제 클래스로 렌더되니 창을 좁히면 그 자리에서 줄어드는 걸 볼 수 있다.

## 버튼만 커진 화면 — tailwind-merge 오분류

치환을 종목 상세에 적용하고 모바일을 보는데 버튼들이 이상했다. 공시 필터 칩, 차트 탭 컨트롤, 요약 보기 버튼이 주변 텍스트보다 크게 떠 있었다.

처음 확인한 건 치환 누락 쪽이었고, 실제로 하나 있었다. 공시 필터 컴포넌트가 치환 대상 목록에서 빠져 12px 고정으로 남아 있던 것. 고쳤는데 화면이 그대로였다. 그제야 구조 쪽으로 가설이 섰다.

probe로 확인하니 `cn`은 `twMerge(clsx(...))`이고 `extendTailwindMerge` 설정이 없었다. tailwind-merge 기본 config는 `text-*`를 두 그룹으로 분류한다 — 내장 스케일과 arbitrary 값은 font-size, 나머지는 전부 text-color. `text-caption` 같은 커스텀 이름은 font-size 패턴에 안 걸려서 **색상으로 분류**된다.

그래서 증상이 두 갈래로 갈렸던 거다.

| 조합 | tw-merge 판정 | 결과 |
| --- | --- | --- |
| `text-caption` 뒤에 색상 클래스 | 같은 color 그룹 충돌 | role 클래스가 출력에서 **제거** → 폰트 상속(~16px) |
| shadcn variant `text-sm` + `text-caption` | 다른 그룹이라 비충돌 | 둘 다 잔존 → 스타일시트 순서로 14px 승리 |

기존 `text-xs` 오버라이드가 멀쩡했던 이유가 정확히 반대다. 내장 스케일이라 정상 인식돼 variant의 `text-sm`을 지워주고 있었다. role 도입이 그 안전망을 모르고 걷어낸 셈이다.

수정 전에 재현부터 했다. `cn("text-caption", "text-muted-foreground")`를 평가하니 `"text-muted-foreground"` — role이 소실되는 게 그대로 찍혔다. 수정은 한 지점이다.

```ts
const twMerge = extendTailwindMerge({
  extend: {
    classGroups: {
      "font-size": [
        { text: ["display", "headline", "value", "body", "body-sm", "caption", "micro"] },
      ],
    },
  },
});
```

role 7종을 font-size 그룹에 등록하면 `text-sm`과는 정상 충돌하고(나중 클래스 승리), 색상과는 비충돌한다. 전 사용처가 한 번에 복구됐고, 같은 사고가 조용히 재발하지 않게 cn 회귀 테스트 4건을 같이 박았다.

커스텀 유틸리티는 Tailwind에게만 가르치면 되는 게 아니라 tw-merge에게도 가르쳐야 한다는 걸 배운 사건이었다.

## 종목 상세·홈 적용

기준이 서고 나니 적용은 대체로 기계적이었다. 매핑 표대로 치환하고, 밀도는 포인트 몇 개를 짚었다.

- **StockPanel `p-6` → `p-4 sm:p-6`** — 패널 패딩이 한 파일에 하드코딩돼 있어서, 이 한 줄이 홈·상세 전 슬레이트의 모바일 여백을 24→16px로 내렸다. 이번 밀도 작업에서 비용 대비 효과가 가장 컸던 지점이다
- **핵심 지표 `grid-cols-2 sm:grid-cols-4`** — 스켈레톤은 이미 데스크톱 4열을 가정하고 있었는데 실제 컴포넌트만 2열이었다. 실제가 스켈레톤을 따라가며 불일치도 같이 닫혔다
- **차트 높이는 호출부에서** — PriceChart 기본값을 건드리는 대신 `useIsMobile` 훅을 새로 두고 호출부가 결정한다. 미니차트 300→170, 차트 탭 450→320
- **OHLC legend 잘림** — separator가 `inline-block` 빈 스팬이라 브라우저가 줄바꿈 지점을 못 잡고 있었다. 실제 공백으로 바꾸고 legend에 max-w를 걸어 자연 wrap으로 해결
- **재무 탭** — 셀 패딩을 모바일만 한 단계 줄여, 폰트 13px 축소와 합쳐 가로 스크롤 전 보이는 열이 늘었다

차트 탭 툴바는 버튼 그룹마다 높이·패딩이 제각각이던 걸 통일하고(모바일 24px·데스크톱 28px), 행이 넘어갈 때 좌측으로 붙던 정렬도 우측 고정으로 잡았다.

## 지수 슬레이트 — 행형 기각과 2×2 페어

홈에서 가장 오래 붙든 건 지수 슬레이트다. 모바일에서 국내 4셀 + 해외 3셀이 전부 세로로 쌓여 화면을 통째로 먹고 있었다.

1차 안은 미니 셀(코스피200·코스닥150)을 이름·값·등락 1행 가로로 눕히는 거였다. 세로는 확실히 줄었는데, 실물을 보니 위계가 없었다. 이름과 값과 등락이 한 줄에 나열되니 뭐가 뭔지 시선이 안 잡혔다. 기각.

2차가 2×2 페어다. 코스피 | 코스닥을 위에, 그 아래 코스피200 | 코스닥150. 같은 시장 축끼리 열이 묶여 의미 단위가 생기고, 세로 절감도 행형보다 크다. 반폭이 된 대형 셀에선 인트라데이 차트의 축 라벨이 플롯을 잠식해서, 모바일 한정으로 높이 95px·축 폰트 10으로 눌렀다.

셀 내부는 라벨 bold, 값 semibold로 위계를 세웠는데, 값에 등락색을 입힐지는 잠깐 갈렸다. 등락 텍스트·화살표·스파크라인까지 방향 신호가 이미 3중이라 절제 쪽으로 기울어 있었다. 무채 버전을 먼저 구현하고 DevTools에서 색 클래스만 토글해 비교해 보니 — 유색이 확실히 잘 읽혔다. 채택했다. 변동폭과 등락률은 가격 옆에 위아래 2단으로 쌓고 괄호를 걷었다.

그러고 나니 해외 3셀만 옛 형태로 길게 남아 어색했다. 국내·해외를 패널 두 장으로 분리했다 — "주요 지수" 타이틀은 하나로 묶고, 해외 패널이 자기 기준일 헤더를 갖는다. 국내는 당일, 해외는 D-1이라 기준일 시차가 패널 경계로 자연스럽게 갈리는 부수 효과도 있었다. 해외 셀은 국내 미니 셀과 같은 카드형으로 수렴시켰고, 마크업이 같아진 시점에 MiniIndexCell 하나로 통합했다. prop 분기는 가격 포맷과 카운트업 렌더 둘뿐이다.

## F26 — 툴팁을 탭으로

Radix Tooltip이 터치에서 안 열리는 건 버그가 아니라 사양이다. 공식 입장은 "터치는 Popover를 써라"인데, Popover로 갈아타면 semantics가 바뀌고 사용처 4곳을 다 손대야 한다. 래퍼 단일 수정으로 좁혔다.

`hover: none`과 `pointer: coarse`가 동시에 참인 기기에서만 controlled 모드로 전환한다 — 탭으로 토글, 외부 탭·스크롤 시작·ESC로 닫기. hover 가능한 기기는 props를 전부 pass-through해서 기존 동작 그대로다. 사용처 4곳(핵심지표 산식, 차트 탭 시장 뱃지, 공시 2곳)은 무변경. #102에서 만든 시장 뱃지 툴팁의 실기기 검증도 이번에 같이 닫혔다.

## 정리

- **타이포 role 토큰 층** — 7 role, `:root` 변수 + 미디어쿼리 오버라이드 + `@theme inline` var() 매핑. styleguide를 role명 = 유틸리티 = 데모 일치로 재작성
- **tailwind-merge 오분류 해결** — 커스텀 role이 색상으로 분류돼 소실·미적용되던 걸 extendTailwindMerge 한 지점으로 복구, cn 회귀 테스트로 봉인
- **종목 상세·홈 전면 적용** — role 치환, StockPanel 반응형 패딩, 핵심 지표 4열, 차트 높이 호출부 분기, OHLC legend wrap, 재무 밀도
- **지수 슬레이트 재구성** — 2×2 페어 그리드, 국내·해외 패널 분리, MiniIndexCell 통합, 값 등락색·stacked 등락 표기
- **F26** — 툴팁 터치 하이브리드, 사용처 무변경

기준을 먼저 세우면 나머지는 기계적이 된다는 게 이번 세션의 구도였는데, 그 사이에 낀 tw-merge 사건이 오히려 기억에 남는다. 눈에 보인 증상(버튼이 크다)과 실제 원인(병합 라이브러리의 클래스 분류) 사이 거리가 이 프로젝트에서 겪은 것 중 가장 멀었다. 치환 누락이라는 그럴듯한 범인이 하나 실재했던 것도 판단을 늦췄다. 그리고 행형 기각과 등락색 채택 — 둘 다 화면을 보기 전 판단과 본 뒤 판단이 달랐다. 디자인 결정은 실물 앞에서만 닫힌다는 걸 이번에도 확인했다.
