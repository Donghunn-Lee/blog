디자인 토큰을 세우고(#023) 한 번 정합을 잡은 뒤(#041)로도 스타일가이드 점검 비고는 세션마다 한 줄씩 늘어 있었다. 등재되지 않은 채 쓰이는 공용 컴포넌트, 차트에 남은 색 하드코딩, 툴팁 다크값, 그리고 가격 숫자까지 등락색으로 칠할지 같은 결정이 미뤄진 채였다. 추석 휴장 첫날이라 시세가 필요한 실측은 어차피 불가능했고, 시세와 무관한 이 정합 점검(R7)과 타이포 role 잔여 치환(R6)을 한 유닛으로 닫기에 맞는 날이었다.

계획은 직전 세션과 같은 구조였다. 읽기 전용 probe 한 번으로 현황을 전수 조사하고, 판단이 필요한 넷만 먼저 정한 뒤 토큰·등락 색·role 치환 세 유닛을 순서대로 돌리는 것. 그대로 진행됐는데, 셋째 유닛 끝의 대비 감사에서 미달 아홉 곳이 나왔고, 마무리하며 히어로 문구 줄넘김을 실측하다 SUIT 글꼴이 다섯 달 넘게 적용된 적이 없다는 게 드러나 글꼴 결정까지 다시 했다. 커밋은 스물셋이다.

## 스타일가이드를 다시 넓힌 이유

#041에서 스타일가이드를 토큰 정의서로 좁혔었다. 본 페이지 컴포넌트를 복사한 시연 카드가 본 페이지가 바뀔 때마다 어긋났고, 그 동기화 비용을 내느니 시연을 빼자는 판단이었다. probe로 세어 보니 같은 문제가 다른 모양으로 남아 있었다. 등재된 값과 클래스가 실코드와 다른 곳이 16, 세 곳 이상에서 쓰이는데 등재되지 않은 공용 컴포넌트가 넷, #041 때 빼기로 한 시연 섹션 둘은 삭제되지 않고 마운트만 풀린 채 971줄로 남아 있었다.

| 조사 | 결과 |
| --- | --- |
| 정의됐으나 미사용 토큰 | 25 (shadcn 내부 사용 3 제외, 21 삭제) |
| 등재값 ↔ 실코드 불일치 | 16 |
| 3곳 이상 쓰이는 미등재 컴포넌트 | StockPanel 16 · PriceChange 11 · StatusBadge 8 · PriceCountUp 5 |
| 색 리터럴·팔레트 클래스 | 74 |
| raw 폰트 스케일 | 99 |
| 등락색 표면 / 색 클래스 맵 | 21곳 / 7벌 (공용 1, 파일별 복제 6) |

드리프트의 원인은 시연 자체가 아니라 복사였다. 그래서 등재 방식을 바꿔 스타일가이드가 실제 컴포넌트를 import해서 렌더하게 했고, 클래스 문자열을 옮겨 적은 예시는 하나도 두지 않았다. 시연 섹션 둘은 마운트된 섹션이 이미 다루는 내용이면 삭제(In-Context Preview), 아니면 마운트(Interaction Demo — hover lift·expand·count-up은 토큰 표만으로는 보이지 않는다)로 갈랐다. 불일치 16건은 코드가 표면 간에 일관되면 문서를 코드에 맞춘다는 #164·#165의 규칙대로 처리했는데, 전부 단일 표면이라 코드 쪽을 고친 건 없었다.

```
전   스타일가이드 = 토큰 정의서. 컴포넌트 시연은 두지 않음 (#041)
후   토큰 정의 + 3곳 이상 소비되는 공용 컴포넌트를 실컴포넌트 렌더로 등재. 복사본 예시 금지
```

## 가격 숫자까지 등락색으로

등락색은 두 층에서 어긋나 있었다. 화면 쪽은 가격 숫자까지 등락색인 곳이 홈 지수 셀 둘뿐이고 아홉 곳은 변동폭·률만 유색이었으며, 그 색을 정하는 클래스 맵이 파일마다 복사돼 일곱 벌, 보합 처리는 네 가지였다. 차트 쪽은 CHART_THEME의 상승·하락색이 "토큰과 매칭"이라는 주석과 달리 Tailwind red-600·blue-600 그대로여서, 같은 화면에서 텍스트와 캔들의 빨강이 서로 다른 빨강이었다.

| 후보 | 판정 |
| --- | --- |
| 단색 통일 — 가격은 기본색, 변동만 등락색 (9곳 다수) | 기각. 원칙 문구("헤더·차트는 무채색")와 다수에 맞으나, 실물에서 값이 무채인 셀이 덜 읽힘 |
| **2색 전면 — 가격·변동 모두 등락색, 보합은 기본 글자색** | **채택.** #103에서 홈 지수 셀에 유색을 넣고 확인했던 결론과 같음. 원칙 문구는 패널 틴트 기준으로 정정 |

어느 쪽이든 선행 작업은 같았다. 맵 일곱 벌을 변동값을 받아 클래스 하나를 돌려주는 순수 함수로 수렴시키고, 보합과 값 없음은 기본 글자색을 명시하게 했다. 상속에 맡기면 muted 톤 부모 아래에서 회색이 된다. 차트는 CSS 토큰이 기준이고 CHART_THEME 값을 그쪽으로 맞췄는데, oklch를 손으로 환산하지 않고 브라우저가 canvas에 그린 sRGB를 읽어 적었다. 미니차트가 따로 들고 있던 팔레트 26값도 이때 CHART_THEME 참조로 바꿔 로컬 색은 0이 됐다.

## 정합이 대비를 깨는 자리

색 리터럴을 토큰으로 옮기는 셋째 유닛에서 걸린 게 하나 있었다. 시장조치 배지의 amber 글자를 팔레트 클래스에서 amber accent 토큰으로 바꾸자 라이트 대비가 6.4에서 3.7:1로 떨어졌다. 12px 글자 기준 AA(4.5)에 못 미치는 값이다. 같은 조합을 이미 쓰던 주주총회 배지도 3.7이었으니 토큰 정합이 새 문제를 만든 게 아니라 있던 문제를 넓힌 셈이었고, 정합의 방향이 잘못됐다고 봤다.

| 후보 | 판정 |
| --- | --- |
| accent 토큰 자체를 진하게 | 기각. 같은 토큰을 쓰는 공시 아이콘·테두리까지 번짐 |
| 대비 미달 수용, 정합 우선 | 기각. 검증·타입 안전성처럼 절감 대상이 아닌 축 |
| **글자용 단계 토큰 신설 (amber-text·sky-text)** | **채택.** 공시 배지 토큰이 이미 bg/text 두 단계라 같은 형태 |

accent를 글자색으로 쓰는 곳을 전수로 다시 재니 틴트 배경 위 여섯, 일반 패널 위 셋이 4.5 미만이었고 아홉 곳 전부를 새 토큰으로 바꿨다. 아이콘 다섯 곳은 비텍스트 기준 3:1을 넘어 손대지 않았다. 이력에 대비가 떨어진 상태가 남지 않게 amber 배지는 팔레트에서 새 토큰으로 바로 넘기는 커밋으로 잡았는데, 일반 패널 위 셋은 push 뒤에 나와 별도 커밋이 됐다.

## 다섯 달 넘게 적용되지 않은 SUIT

히어로 문구가 모바일에서 "한 곳에서"의 "서" 한 글자만 다음 줄로 떨어지는 것(E91)을 구절 단위 nowrap으로 고치며 320·360·390·430px에서 폭을 실측했는데, 헤드라인 첫 줄 폭이 계산과 달랐다. 대체 글꼴 폭이었다. globals.css의 @theme이 next/font가 만든 변수 대신 글꼴 이름 문자열을 쓰고 있어서, next/font가 woff2를 preload해 두고도 그 페이스는 한 번도 쓰이지 않았다(F103). next/font는 페이스 이름을 코드 변수명으로 등록하니 "SUIT Variable"이라는 이름은 어떤 기기에서도 풀리지 않았고, 4월 5일 초기 세팅 커밋부터 그대로였다. 다섯 달 반 동안 SUIT가 적용이 되었다고 착각하고 있었던 거다.

```
전   @theme inline { --font-sans: "SUIT Variable", sans-serif; }   ← 이름이 풀리지 않아 늘 sans-serif
후   Noto_Sans_KR({ weight: "variable", variable: "--font-noto" })    next/font/google
     @theme inline { --font-sans: var(--font-noto), sans-serif; }
```

변수를 연결해 SUIT를 살리고 보니 화면이 전부 가늘어져 낯설었다. 다섯 달 동안 본 글꼴로 크기·굵기·행간을 다 맞춰 왔으니 그쪽을 기준으로 두는 게 맞았는데, 그 글꼴이 무엇인지부터 틀렸다. 스크린샷 글리프만 보고 Windows 기본 맑은 고딕이라 짚고 시스템 글꼴 스택으로 바꿨다가 적용해 보니 또 달라서, 문자열 폭을 재 보니 그동안 그려지던 건 PC에 따로 설치돼 있던 Noto Sans KR이었다.

| 후보 | 판정 |
| --- | --- |
| SUIT를 살려 쓰기 | 기각. 다섯 달의 크기·굵기 판단이 전부 다른 글꼴 기준. 소형 role만 굵기를 올려도 낯섦이 남음 |
| 시스템 글꼴 스택 | 기각. 맑은 고딕은 굵기가 300·400·700뿐이라 라벨과 값을 가르던 500·600이 뭉개짐 |
| 로컬 Noto Sans KR 참조 | 기각. 내 PC와 Android에서만 재현, 방문자 대부분은 맑은 고딕 |
| **next/font/google Noto Sans KR 셀프 호스팅** | **채택.** 검증본 그대로 전원 재현, 재보정 0. 한글은 unicode-range 슬라이스라 페이지당 16개 약 285KB만 받음 |

폭은 이전과 소수점까지 같다. 하나 남은 게 굵기 600이다. 설치본은 600을 700으로 그리고 있어서 semibold 자리가 실제보다 굵게 보였던 건데, 진짜 600으로 갈지 bold로 올릴지는 실물을 보고 정하기로 했다.

## 정리

- **R7 종결** — probe 377행. 미사용 토큰 21 삭제, 불일치 16 정정, 실컴포넌트 등재 5종, 등락 2색 전면·맵 7 → 1·차트 색 토큰 정합
- **R6 종결** — raw 폰트 95 → role, body-lg 신설, 리터럴 38 → 토큰
- **AA 대비** — amber-text·sky-text 신설, 글자 9곳 4.5 이상, 아이콘은 3.0 충족 확인
- **E91 종결** — 히어로 문구 구절 nowrap, 문구 수정
- **F103 종결** — SUIT는 초기 세팅부터 미적용, 실제 검증 글꼴은 로컬 설치 Noto Sans KR. next/font/google 셀프 호스팅으로 전원 동일 렌더, 차트 캔버스는 폰트 로드 후 재그리기
- **남긴 것** — semibold 600 굵기는 실물 판단. 모바일 홈 상단 밀도(E92)는 출시 후. 폰트 슬라이스 전송량은 성능 측정(G2)에서

정합을 잡으러 들어가서 정합이 틀린 자리와 정합이 있는 줄 알았던 자리를 둘 다 만났다. 글꼴은 맑은 고딕이라고 한 번 잘못 짚고 시스템 스택까지 갔다가 폭 측정으로 되돌아온 건데, 눈으로 글꼴을 판정하는 게 얼마나 못 믿을 일인지 좀 뼈아프게 배웠다. 다음 성능 측정은 그래서 내 PC가 아니라 깨끗한 환경 기준으로 잡을 생각이다.
