# JavaScript 실행 컨텍스트 — FE 개념 탐구 #001

## 핵심 요약

- 실행 컨텍스트는 JavaScript 코드가 실행될 때 필요한 **실행 환경 정보**를 담는 구조다.  
- JavaScript 엔진은 코드를 실행하기 전에 실행 컨텍스트를 생성하여 변수, 함수, 스코프 등의 정보를 먼저 준비한다.  
- 이 과정에서 변수와 함수 선언이 등록되며, 이 때문에 **호이스팅 같은 현상**이 발생한다.

## 왜 이런 개념이 필요할까

JavaScript를 공부하다 보면 다음과 같은 상황이 궁금해진다.

- 왜 함수 선언은 코드보다 먼저 호출해도 실행될까?
- 왜 `var` 변수는 선언 전에 접근하면 `undefined`가 나올까?
- 함수가 호출될 때 내부 변수들은 어디에 저장될까?

처음에는 이런 동작을 단순히 **JavaScript의 문법 특징**이라고 생각했다.  
하지만 조금 더 살펴보니 JavaScript는 코드를 바로 실행하는 것이 아니라,  
**코드를 실행하기 위한 환경을 먼저 만들고 그 안에서 실행한다는 것**을 알게 되었다.

이때 만들어지는 실행 환경이 바로 **실행 컨텍스트(Execution Context)**다.

---

## 개념 정의

실행 컨텍스트는 **JavaScript 코드 실행에 필요한 환경 정보를 담고 있는 실행 환경**이다.

JavaScript 엔진이 코드를 실행하려면 다음과 같은 정보가 필요하다.

- 어떤 변수들이 존재하는지
- 어떤 함수들이 선언되어 있는지
- 현재 코드의 스코프가 어디인지
- `this`가 무엇을 가리키는지

JavaScript 엔진은 코드를 실행하기 전에 먼저 실행 컨텍스트를 생성하고  
이 정보를 정리한 뒤 실제 코드를 실행한다.

---

## 동작 원리

실행 컨텍스트는 크게 **두 단계**를 거쳐 생성된다.

```
1. 생성 단계 (Creation Phase)
2. 실행 단계 (Execution Phase)
```

처음 실행 컨텍스트를 공부할 때는  
단순히 “함수가 실행되면 만들어지는 환경” 정도로 이해했다.

하지만 실제로는 **코드가 실행되기 전에 먼저 준비되는 단계**가 있다는 점이 중요하다.

### 1. 생성 단계

코드를 실행하기 전에 JavaScript 엔진은 실행 환경을 먼저 준비한다.

이 단계에서 다음 작업이 수행된다.

**1️⃣ 변수 등록**

```javascript
var a = 10;
```

생성 단계에서는 다음과 같이 등록된다.

```
a: undefined
```

아직 값은 할당되지 않는다.

---

**2️⃣ 함수 선언 등록**

함수 선언은 생성 단계에서 **완전히 메모리에 올라간다.**

```javascript
function test() {}
```

그래서 다음 코드가 가능하다.

```javascript
test();

function test() {}
```

이 현상이 바로 **호이스팅(Hoisting)**이다.

---

**3️⃣ 스코프 체인 생성**

JavaScript는 변수를 찾을 때 다음 순서로 탐색한다.

```
현재 스코프
→ 상위 스코프
→ 전역 스코프
```

이 연결 구조를 **스코프 체인(Scope Chain)**이라고 한다.

---

**4️⃣ this 바인딩 결정**

실행 컨텍스트가 생성될 때 `this` 값도 함께 결정된다.

예를 들어

- 전역 실행 컨텍스트 → `window`
- 함수 실행 컨텍스트 → 호출 방식에 따라 결정

---

### 2. 실행 단계

생성 단계가 끝나면 JavaScript 엔진은 실제 코드를 실행한다.

예를 들어

```javascript
var a = 10;
```

생성 단계에서는

```
a: undefined
```

상태였지만 실행 단계에서

```
a: 10
```

으로 값이 할당된다.

즉 JavaScript는 다음과 같은 순서로 코드를 실행한다.

```
생성 단계 → 실행 환경 준비
실행 단계 → 코드 실행
```

---

## 예시

다음 코드를 살펴보자.

```javascript
function a() {
  b();
}

function b() {
  console.log("hello");
}

a();
```

이 코드가 실행되면 실행 컨텍스트는 다음 순서로 생성된다.

```
Global Context
↓
a()
↓
b()
```

그리고 함수 실행이 끝나면 이전 실행 환경으로 돌아간다.

이 과정은 **스택 구조**로 관리된다.

```
새 실행 컨텍스트 생성
→ 스택에 push
→ 실행
→ 종료 후 pop
```

이 구조를 **Call Stack**이라고 한다.

---

## 정리

실행 컨텍스트는 JavaScript 코드 실행을 이해하는 핵심 개념이다.

핵심 내용을 정리하면 다음과 같다.

- 실행 컨텍스트는 **코드 실행에 필요한 환경 정보를 담는 구조**다.
- JavaScript는 코드를 실행하기 전에 **생성 단계와 실행 단계**를 거친다.
- 생성 단계에서 변수와 함수가 등록되며 **호이스팅**이 발생한다.
- 함수가 호출될 때마다 새로운 실행 컨텍스트가 생성된다.
- 실행 컨텍스트는 **Call Stack 구조**로 관리된다.

---

### 개인 정리

정리하면, 실행 컨텍스트는 단순히 “함수가 실행될 때 만들어지는 환경”이 아니라  
**JavaScript 코드 실행을 위해 필요한 모든 환경 정보를 관리하는 구조**라고 이해할 수 있다.

특히 중요한 점은 JavaScript가 코드를 바로 실행하는 것이 아니라  
먼저 실행 환경을 준비하는 **생성 단계**를 거친다는 것이다.

이 과정 덕분에 함수 선언이 먼저 등록되고  
결과적으로 **호이스팅 같은 동작이 발생한다**는 점을 이해할 수 있었다.
