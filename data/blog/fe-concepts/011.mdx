## 왜 이 개념을 알아야 할까

모달 안쪽 버튼을 눌렀는데 바깥쪽 클릭 이벤트까지 같이 먹어서 모달이 닫히는 경우가 있다.  

혹은 리스트 안에 있는 버튼을 눌렀는데, 리스트 전체에 걸린 클릭 이벤트가 같이 실행되기도 한다.

이런 상황을 처음 보면 “왜 이것까지 같이 실행되지?” 싶다.  
그런데 결국 원인은 대부분 비슷하다. 이벤트가 한 요소에서만 끝나는 게 아니라, DOM 구조를 따라 전파되기 때문이다.

## 버블링과 캡처링이란

이벤트 버블링과 캡처링은 브라우저에서 발생한 이벤트가 DOM 트리를 따라 전달되는 방식이다.

조금 더 쉽게 말하면, 클릭 같은 이벤트가 발생했을 때 그 이벤트가 관련된 요소들 사이를 그냥 한 번에 처리하는 게 아니라, 일정한 순서대로 이동한다는 뜻이다.

- **캡처링**: 바깥쪽 상위 요소에서 시작해서 실제 클릭된 요소까지 내려가는 과정
- **버블링**: 실제 클릭된 요소에서 시작해서 다시 부모 요소 쪽으로 올라가는 과정

실무에서는 버블링 쪽을 더 자주 체감하게 된다.
이벤트 리스너의 기본값이 버블링이기 때문이기도 하다.

버튼을 눌렀는데 부모의 클릭 핸들러까지 같이 실행되는 게 대표적이다.

## 이벤트는 어떻게 이동할까

예를 들어 이런 구조가 있다고 해보자.

```html
<div class="parent">
  <button class="child">클릭</button>
</div>
```

여기서 버튼을 클릭하면 이벤트는 그냥 버튼에서만 처리되는 게 아니다.  
브라우저는 이벤트를 대략 이런 순서로 다룬다.

### 1. 캡처링 단계

상위 요소에서 시작해서 실제 클릭된 요소까지 내려온다.

대충 이런 느낌이다.

`window → document → html → body → parent → child`

평소에는 이 단계가 잘 드러나지 않는다.  
보통 이벤트를 등록하면 기본적으로 버블링 단계에서 처리되기 때문이다.

### 2. 타깃 단계

이벤트가 실제로 발생한 요소에 도착한다.  
위 예시라면 `child`, 즉 버튼이 타깃이다.

### 3. 버블링 단계

이제 다시 부모 방향으로 올라간다.

`child → parent → body → html → document → window`

그래서 버튼을 눌렀는데 부모에 걸린 클릭 이벤트도 같이 실행될 수 있다.

간단한 코드를 보면 더 이해가 쉽다.

```html
<div id="parent">
  <button id="child">클릭</button>
</div>
```

```js
const parent = document.getElementById('parent');
const child = document.getElementById('child');

parent.addEventListener('click', () => {
  console.log('parent');
});

child.addEventListener('click', () => {
  console.log('child');
});
```

여기서 버튼을 클릭하면 보통 이렇게 찍힌다.

```js
child
parent
```

처음에는 부모가 왜 실행되는지 헷갈릴 수 있는데,  
이건 이벤트가 자식에서 끝나는 게 아니라 부모로 버블링되기 때문이다.

캡처링 단계에서 실행되게 하고 싶다면 이렇게 설정할 수도 있다.

```js
parent.addEventListener(
  'click',
  () => {
    console.log('parent capture');
  },
  { capture: true }
);
```

이 경우엔 내려오는 단계에서 먼저 실행된다.

## 실제로 자주 만나는 상황

### 모달 바깥 클릭으로 닫기

모달을 만들 때 바깥 배경을 누르면 닫히게 처리하는 경우가 많다.  
그런데 모달 내부를 클릭했는데도 바깥 이벤트까지 전파되면 의도치 않게 닫혀버릴 수 있다.

이럴 때는 전파를 무조건 막기보다, `currentTarget`을 비교하여 정말 배경 자체를 클릭한 건지 확인해서 처리하는 경우가 많다.

```js
overlay.addEventListener('click', (e) => {
  if (e.target === e.currentTarget) {
    closeModal();
  }
});
```

이 방식이 더 읽기 쉽고, 나중에 봐도 의도가 분명하다.

### 이벤트 위임

리스트가 길어지면 항목마다 이벤트를 하나씩 다는 것도 꽤 번거롭다.  
특히 항목이 동적으로 추가되는 구조라면 더 그렇다.

그래서 부모 요소 하나에만 이벤트를 달고, 실제 어떤 자식이 클릭됐는지 확인해서 처리하는 방식도 많이 쓴다.  
이게 이벤트 위임이다.

```js
list.addEventListener('click', (e) => {
  const button = e.target.closest('[data-action="delete"]');
  if (!button) return;

  const id = button.dataset.id;
  deleteItem(id);
});
```

이 방식이 가능한 이유도 결국 버블링 때문이다.  
자식에서 발생한 이벤트가 부모까지 올라오니까, 부모 하나만 보고 처리할 수 있는 것이다.

## 헷갈렸던 부분들

### `event.target`과 `event.currentTarget`

이 둘은 비슷해 보여서 처음에 많이 헷갈린다.

- `event.target`: 실제 이벤트가 발생한 요소
- `event.currentTarget`: 현재 이벤트 핸들러가 등록된 요소

부모에 이벤트를 달아두고 자식을 클릭했다면,  
`target`은 자식이고 `currentTarget`은 부모일 수 있다.

이벤트 위임을 이해하려면 이 차이를 알아두는 게 중요하다.

### 캡처링은 잘 안 보이지만 없는 개념은 아니다

평소엔 버블링만 많이 보니까, 캡처링은 거의 안 쓰는 개념처럼 느껴질 수 있다.  
그런데 브라우저 이벤트 흐름 자체는 캡처링 → 타깃 → 버블링 순서로 이루어진다.

다만 우리가 기본 설정으로 이벤트를 등록하면 보통 버블링 단계에서 동작할 뿐이다.

### `stopPropagation()`은 편하지만 습관적으로 쓰면 별로다

당장은 문제를 쉽게 막아주는 것처럼 보인다.  
그런데 나중에 상위 로직까지 같이 끊겨서 오히려 흐름이 더 헷갈릴 수 있다.

그래서 먼저 어떤 요소에서 이벤트가 발생했고, 어디까지 전파되는지 파악한 뒤에 쓰는 편이 낫다.  
생각보다 조건 분기로 해결되는 경우도 많다.

## 정리

- 이벤트는 클릭한 요소 하나에서만 끝나는 게 아니라 DOM 구조를 따라 이동한다.
- 캡처링은 위에서 아래로 내려오는 흐름이고, 버블링은 아래에서 위로 올라가는 흐름이다.
- 실무에서는 특히 버블링을 많이 체감하게 되고, 이벤트 위임도 이 흐름을 활용하는 방식이다.
- 모달, 드롭다운, 리스트 클릭 처리 같은 UI를 다룰 때 이 개념을 알고 있으면 훨씬 덜 헷갈린다.

이벤트 버블링과 캡쳐링은 크게 어려운 개념은 아니지만, 복잡한 브라우저 이벤트를 다룰 때 은근히 자주 걸리는 부분이다.  
특히 “왜 부모 이벤트까지 같이 실행되지?” 같은 상황을 설명할 수 있게 되면, 보다 다양한 상황에 대응하고 구현할 수 있을 것 같다.
