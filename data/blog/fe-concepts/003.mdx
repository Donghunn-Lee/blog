## 왜 이런 개념이 필요할까

JavaScript를 공부하다 보면  
이런 상황을 한 번쯤 만나게 된다.

“함수가 이미 실행이 끝났는데,  
왜 그 안에 있던 값이 계속 유지되지?”

예를 들어 debounce 같은 함수를 보면  
이전 값을 계속 기억하고 있는 것처럼 보인다.

FE 입문 시절엔 단순히 “JavaScript가 그런가 보다”라고 생각했는데,  
실제로는 **클로저라는 개념** 때문이었다.

---

## 개념 정의

클로저는

**함수가 자신이 선언된 스코프를 기억하고,  
그 스코프에 계속 접근할 수 있는 구조**다.

조금 더 직관적으로 말하면

**함수가 만들어질 때의 변수 환경을 계속 들고 다니는 것**이다.

이 덕분에 함수 실행이 끝난 이후에도  
외부 변수에 접근할 수 있게 된다.

---

## 동작 원리

처음에는 “값을 복사해서 들고 있는 건가?”라고 생각했는데,  
실제로는 그렇지 않았다.

클로저는 값을 복사하는 게 아니라  
**스코프(환경)를 참조**한다.

간단한 예제로 보면 이해가 쉽다.

```js
function outer() {
  let count = 0;

  function inner() {
    count++;
    console.log(count);
  }

  return inner;
}

const fn = outer();

fn(); // 1
fn(); // 2
```

여기서 중요한 흐름은 이렇다.

1. `inner` 함수가 선언될 때  
   → `outer`의 스코프를 기억한다  

2. `outer` 함수 실행이 끝나더라도  
   → `inner`가 그 스코프를 계속 참조한다  

3. 그래서 `count` 값이 유지된다  

“함수가 끝나면 변수도 사라지는 거 아닌가?” 하고 생각하기 쉽지만,
**참조가 남아있으면 메모리에서 사라지지 않는다**는 점이 핵심이다.

---

## 예시

### debounce에서의 활용

```js
function debounce(fn, delay) {
  let timer;

  return function () {
    clearTimeout(timer);
    timer = setTimeout(fn, delay);
  };
}
```

여기서 `timer`는 계속 유지되어야 한다.

만약 클로저가 없다면  
함수를 호출할 때마다 `timer`가 초기화되어  
debounce가 제대로 동작하지 않는다.

---

### 상태를 기억하는 함수

```js
function createCounter() {
  let count = 0;

  return () => {
    count++;
    return count;
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
```

각 함수가 **자기만의 상태를 가지는 것처럼 동작**한다.

---

## 정리

- 클로저는 함수가 선언된 스코프를 기억하는 구조다  
- 함수 실행이 끝나도 변수에 접근할 수 있다  
- 값이 아니라 스코프를 참조한다는 것이 핵심이다  
- 상태 유지, debounce, 캡슐화 등에 활용된다  
- 잘못 사용하면 메모리가 계속 유지될 수 있다  

---

## 개인 정리

처음에는 클로저를 단순히 “외부 변수 접근” 정도로만 이해했는데,  
실제로는 **함수가 스코프 자체를 기억한다는 점**이 핵심이었다.

특히 debounce처럼  
“이전 상태를 유지해야 하는 구조”에서  
왜 클로저가 필요한지 확실히 이해할 수 있었다.

핵심적인 개념이기에 FE 개발을 배우기 시작했을 때부터 들었왔던 개념인데도, 어느정도 이해도가 쌓인 뒤 개념을 다시 보니 더 명확하게 이해가 되는 것 같다.
