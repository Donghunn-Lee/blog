## 핵심 요약

- `this`는 함수가 실행될 때 결정되는 실행 문맥의 참조값이다.
- JavaScript의 `this`는 선언 위치보다 호출 방식의 영향을 크게 받기 때문에 헷갈리기 쉽다.
- 화살표 함수는 자체 `this`가 없고 바깥 `this`를 사용하며, `call`·`apply`·`bind`로 `this`를 명시적으로 제어할 수 있다.

## this는 무엇일까

`this`는 함수가 실행될 때 결정되는 **현재 실행 문맥의 참조값**이다.

조금 더 직관적으로 말하면,  
`this`는 **“이 함수가 지금 누구 기준으로 실행되고 있는가?”** 를 나타낸다.

여기서 중요한 점은, `this`는 보통 **함수가 어디에 선언됐는지**보다 **어떻게 호출됐는지**의 영향을 많이 받는다는 것이다.  
그래서 처음 배울 때 스코프와 비슷하게 이해하면 오히려 더 헷갈리기 쉽다.

## 왜 this가 헷갈릴까

객체 안에 메서드가 있으면 자연스럽게 이런 생각을 하게 된다.

> 이 함수는 이 객체 안에 있으니까, 당연히 이 객체를 가리키겠지?

하지만 JavaScript에서는 그렇지 않은 경우가 많다.  
핵심은 **함수가 객체 안에 “존재하는가”가 아니라, 호출할 때 그 객체와 연결된 형태로 실행되는가** 이다.

예를 들어 아래 코드는 직관적으로 이해하기 쉽다.

```js
const user = {
  name: 'Donghun',
  getName() {
    console.log(this.name);
  },
};

user.getName(); // Donghun
```

이 경우에는 `user.getName()` 형태로 호출했기 때문에 `this`가 `user`를 가리킨다.

그런데 이렇게 바꾸면 이야기가 달라진다.

```js
const user = {
  name: 'Donghun',
  getName() {
    console.log(this.name);
  },
};

const fn = user.getName;
fn();
```

여기서는 더 이상 `user.getName()`으로 호출한 것이 아니라 `fn()`이라는 일반 함수 호출이 된다.  
즉, 원래 객체와 연결된 메서드였던 함수가 **분리되어 실행**되면서 `this`도 달라질 수 있다.

처음에는 “메서드를 넘겼으니 여전히 user를 기억하지 않나?”라고 생각했는데, 실제로는 함수가 객체를 자동으로 기억하는 게 아니라 **호출 방식이 문맥을 결정한다**는 점이 핵심이었다.

## this는 어떻게 결정될까

### 1. 일반 함수로 호출한 경우

```js
function foo() {
  console.log(this);
}

foo();
```

이처럼 일반 함수로 호출하면 strict mode에서는 `this`가 `undefined`가 된다.  
예전 브라우저 환경에서는 전역 객체를 가리키는 경우도 있었지만, 실무에서는 모듈 환경과 strict mode를 전제로 보는 편이 더 안전하다.

### 2. 객체의 메서드로 호출한 경우

```js
const user = {
  name: 'Donghun',
  getName() {
    console.log(this.name);
  },
};

user.getName();
```

이 경우 `this`는 `user`다.  
중요한 건 “메서드로 선언했다”가 아니라 **`객체.메서드()` 형태로 호출했다**는 점이다.

### 3. 명시적으로 바인딩한 경우

JavaScript는 `call`, `apply`, `bind`를 통해 개발자가 직접 `this`를 지정할 수 있다.

```js
function introduce(age) {
  console.log(`${this.name}, ${age}`);
}

const user = { name: 'Donghun' };

introduce.call(user, 27);
introduce.apply(user, [27]);

const boundFn = introduce.bind(user);
boundFn(27);
```

- `call`: `this`를 지정하고 즉시 실행
- `apply`: `this`를 지정하고 즉시 실행, 인자는 배열로 전달
- `bind`: 즉시 실행하지 않고, `this`가 고정된 새 함수를 반환

셋 다 이름은 비슷하지만, 실무에서는 특히 `bind`의 동작 차이를 분명히 기억해야 한다.

## 화살표 함수는 왜 다르게 동작할까

화살표 함수는 일반 함수처럼 자신의 `this`를 새로 만들지 않는다.  
대신 **바깥 문맥의 `this`를 그대로 사용한다.**

```js
const user = {
  name: 'Donghun',
  regular() {
    const arrow = () => {
      console.log(this.name);
    };

    arrow();
  },
};

user.regular(); // Donghun
```

여기서 `arrow`는 자기 `this`가 없기 때문에, 바깥의 `regular`가 사용하던 `this`를 그대로 사용한다.

이 특성 때문에 화살표 함수는 콜백 안에서 문맥을 유지할 때 자주 유용하다.  
예전에는 `const self = this` 같은 패턴도 많이 썼지만, 지금은 화살표 함수가 그 역할을 훨씬 자연스럽게 해결해준다.

다만, 그렇다고 해서 **객체 메서드 자체를 항상 화살표 함수로 만드는 게 좋은 건 아니다.**  
화살표 함수는 호출 방식에 따라 `this`가 바뀌지 않기 때문에, 메서드 문맥이 필요한 자리에서는 오히려 의도와 다르게 동작할 수 있다.

## 실무에서 자주 만나는 문제

가장 흔한 문제는 **객체 메서드를 콜백으로 그대로 넘겼을 때**다.

```js
const user = {
  name: 'Donghun',
  getName() {
    console.log(this.name);
  },
};

setTimeout(user.getName, 1000);
```

이 코드는 얼핏 보면 1초 뒤에 `Donghun`을 출력할 것 같지만, 실제로는 그렇지 않다.  
`setTimeout`에 전달되는 순간 `user.getName()`이 아니라 **함수 참조만 전달**되기 때문이다.  
나중에 실행될 때는 원래 객체와의 연결이 끊어진 상태라 `this`가 `user`가 아닐 수 있다.

이 문제는 보통 이렇게 해결한다.

### 1. bind로 고정하기

```js
setTimeout(user.getName.bind(user), 1000);
```

### 2. 화살표 함수로 감싸기

```js
setTimeout(() => user.getName(), 1000);
```

두 방식 모두 많이 사용된다.  
다만 실무에서는 아예 `this` 의존도를 줄이고, 필요한 값을 명시적으로 전달하는 설계를 더 선호하는 경우도 많다.  
특히 React 함수형 컴포넌트 환경에서는 `this`보다 클로저와 props/state 흐름으로 사고하는 경우가 훨씬 많다.

## 정리

`this`는 JavaScript에서 가장 자주 헷갈리는 개념 중 하나지만, 기준은 생각보다 단순하다.

- 일반 함수의 `this`는 보통 **호출 방식**에 따라 결정된다.
- 객체 메서드도 **분리해서 호출하면** 원래 객체를 잃을 수 있다.
- 화살표 함수는 자신의 `this`가 없고 **바깥 `this`를 그대로 사용**한다.
- `call`, `apply`, `bind`로 `this`를 명시적으로 제어할 수 있다.

처음에는 `this`를 스코프처럼 이해하려고 해서 더 헷갈렸는데,  
지금은 **“변수 탐색 규칙이 아니라 실행 문맥의 주체를 가리키는 값”**이라고 생각하니 훨씬 정리가 잘 된다.

결국 `this`를 이해하는 핵심은  
“이 함수가 어디에 있지?”가 아니라  
**“이 함수가 지금 어떤 형태로 호출됐지?”** 를 먼저 보는 습관인 것 같다.
