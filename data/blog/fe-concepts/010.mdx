## 왜 DOM과 Virtual DOM을 같이 볼까

React를 공부하면 Virtual DOM이라는 개념을 듣게 된다.
이름부터 가상 DOM인 만큼, 이 개념은 DOM이 무엇인지 먼저 알아야 자연스럽게 이해된다.

프론트엔드에서 화면이 바뀐다는 건 결국 브라우저가 관리하는 구조가 바뀐다는 뜻이다.  
즉, DOM은 실제 화면과 연결된 구조이고, Virtual DOM은 **그 변경을 더 효율적으로 다루기 위한 방식**이라고 보면 된다.

## DOM과 Virtual DOM의 차이

DOM은 브라우저가 HTML 문서를 객체 트리 형태로 표현한 구조다.  
JavaScript는 이 DOM에 접근해서 텍스트를 바꾸거나 요소를 추가할 수 있다.

반면 Virtual DOM은 실제 화면을 직접 그리는 구조가 아니다.  
React가 메모리 안에서 현재 UI 상태를 표현하고, 이전 상태와 비교하기 위해 사용하는 가상 트리다.

- DOM: 실제 화면과 연결된 구조
- Virtual DOM: 변경점을 비교하기 위한 가상 구조

즉 Virtual DOM이 실제 DOM을 대체하는 것이 아니라, **실제 DOM 업데이트 전에 한 번 더 비교하는 단계**라고 이해하는 편이 정확하다.

## React는 화면을 어떻게 갱신할까

React에서 상태가 바뀌면 바로 실제 DOM을 마구 수정하는 게 아니다.

실제 흐름은 다음고 같다.

1. state가 바뀐다.
2. 새로운 Virtual DOM을 만든다.
3. 이전 Virtual DOM과 비교한다.
4. 바뀐 부분만 실제 DOM에 반영한다.

그래서 React의 핵심은 “화면 전체를 다시 만드는 것”이 아니라,  
**어디가 바뀌었는지 계산한 뒤 필요한 부분만 업데이트하는 것**에 있다.

다만 Virtual DOM이 있다고 해서 React가 항상 무조건 빠른 건 아니다.

문서 구조가 단순해서 Virtual Dom 처리 비용이 더 크거나,
불필요한 리렌더링이 많거나, 큰 리스트를 비효율적으로 다루면 여전히 성능 문제는 생길 수 있다.

## 예시

예를 들어 검색어를 입력할 때마다 목록이 바뀌는 UI를 생각해보자.

```jsx
function UserList({ users, keyword }) {
  const filteredUsers = users.filter((user) =>
    user.name.toLowerCase().includes(keyword.toLowerCase())
  );

  return (
    <ul>
      {filteredUsers.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

여기서 개발자는 DOM을 직접 지우고 다시 만드는 코드를 쓰지 않는다.  
현재 상태에 맞는 UI를 선언하면, React가 이전 결과와 비교해서 필요한 부분만 실제 DOM에 반영한다.

이게 Virtual DOM을 이해할 때 가장 실무적으로 와닿는 지점이다.

## 정리

DOM은 브라우저가 실제 화면을 구성하고 관리하는 객체 트리다.  
Virtual DOM은 이 실제 DOM을 없애는 개념이 아니라, **UI 변경 전후를 비교하기 위한 가상 구조**다.  

React는 상태가 바뀌면 새로운 Virtual DOM을 만들고, 이전 구조와 비교해서 어떤 부분이 달라졌는지 확인한 뒤, 그 결과를 바탕으로 실제 DOM에 필요한 부분만 반영한다.

즉 핵심은 다음처럼 정리할 수 있다.

- DOM은 실제 브라우저 화면과 연결된 구조다.
- Virtual DOM은 변경점을 비교하기 위한 중간 계산 단계다.
- React는 Virtual DOM 비교를 통해 실제 DOM 업데이트를 좀 더 효율적으로 관리한다.
- 그렇다고 Virtual DOM이 실제 DOM을 대체하는 것은 아니다.
- 또한 Virtual DOM이 있다고 해서 React가 항상 무조건 빠른 것도 아니다.

보다 Virtual DOM의 작동 원리도 궁금한데, 이건 다음에 조금 더 알아보는 것으로 하자.
