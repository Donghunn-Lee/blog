## 왜 이런 개념이 필요할까

JavaScript 코드를 작성하다 보면 이런 경험을 자주 한다.

어떤 변수는 정상적으로 접근되는데,  
어떤 변수는 `ReferenceError`가 발생한다.

예를 들어 다음 코드를 보자.

```javascript
function test() {
  const a = 10;
}

console.log(a);
```

이 코드를 실행하면 `a`는 정의되지 않았다는 에러가 발생한다.

왜 이런 일이 발생할까?

이 질문의 답은 **스코프(scope)**라는 개념에 있다.

스코프는 **변수나 함수가 어디에서 접근 가능한지를 결정하는 규칙**이다.  
그리고 JavaScript 엔진은 변수를 찾을 때 **일정한 탐색 규칙**을 따른다.

이 탐색 방식이 바로 **스코프 체인(scope chain)**이다.

---

## 개념 정의

### 스코프 (Scope)

스코프는 **변수나 함수에 접근할 수 있는 유효 범위**를 의미한다.

조금 더 쉽게 말하면

> 어떤 변수나 함수를 **어디에서 사용할 수 있는지를 결정하는 규칙**

이라고 볼 수 있다.

예를 들어 다음 코드를 보자.

```javascript
function test() {
  const a = 10;
  console.log(a);
}
```

여기서 변수 `a`는 `test` 함수 내부에서만 접근할 수 있다.

즉

```
a의 스코프 = test 함수 내부
```

---

### 스코프 체인 (Scope Chain)

JavaScript는 변수를 찾을 때 다음 순서를 따른다.

```
현재 스코프
→ 상위 스코프
→ 전역 스코프
```

이처럼 스코프가 연결된 탐색 구조를 **스코프 체인(scope chain)**이라고 한다.

---

## 동작 원리

JavaScript에서 변수는 다음 순서로 탐색된다.

### 1. 현재 스코프에서 찾는다

코드가 실행될 때 JavaScript 엔진은  
먼저 **현재 실행 중인 스코프**에서 변수를 찾는다.

```javascript
function test() {
  const a = 10;
  console.log(a);
}
```

이 경우 `a`는 현재 스코프에서 바로 발견된다.

---

### 2. 없으면 상위 스코프로 올라간다

현재 스코프에 변수가 없다면  
JavaScript는 **외부 스코프**로 올라가며 탐색한다.

```javascript
const a = 1;

function test() {
  console.log(a);
}

test();
```

탐색 과정은 다음과 같다.

```
test 스코프
→ global 스코프
→ a 발견
```

---

### 3. 스코프는 중첩될 수 있다

스코프는 여러 단계로 중첩될 수 있다.

```javascript
const a = 1;

function outer() {
  const b = 2;

  function inner() {
    const c = 3;
    console.log(a, b, c);
  }

  inner();
}

outer();
```

변수 탐색 과정은 다음과 같다.

```
c → inner 스코프
b → outer 스코프
a → global 스코프
```

이처럼

```
inner → outer → global
```

구조로 연결된 것이 **스코프 체인**이다.

---

### 중요한 특징

스코프 탐색은 **항상 위 방향으로만 진행된다.**

즉

- 하위 스코프 → 상위 스코프 접근 가능
- 상위 스코프 → 하위 스코프 접근 불가능

예를 들어 다음 코드는 에러가 발생한다.

```javascript
function outer() {
  function inner() {
    const a = 10;
  }

  console.log(a);
}
```

`a`는 `inner` 스코프에만 존재하기 때문이다.

---

### 렉시컬 스코프

JavaScript는 **렉시컬 스코프(Lexical Scope)**를 사용한다.

이는

> 변수의 스코프가 **함수가 선언된 위치**에 의해 결정된다는 의미다.

다음 코드를 보자.

```javascript
const a = 1;

function test() {
  console.log(a);
}

function wrapper() {
  const a = 2;
  test();
}

wrapper();
```

결과는 `1`이 출력된다.

그 이유는 `test` 함수가 **전역 스코프에서 선언되었기 때문**이다.

---

## 예시

간단한 스코프 체인 예제를 살펴보자.

```javascript
const name = "global";

function outer() {
  const name = "outer";

  function inner() {
    console.log(name);
  }

  inner();
}

outer();
```

출력 결과

```
outer
```

탐색 과정

```
inner 스코프 → 없음
outer 스코프 → name 발견
```

이처럼 JavaScript는 변수를 찾을 때  
**현재 스코프에서 시작해 상위 스코프로 올라가며 탐색한다.**

---

## 정리

스코프와 스코프 체인의 핵심은 다음과 같다.

- 스코프는 변수나 함수에 접근할 수 있는 범위이다.
- JavaScript는 변수를 찾을 때 **현재 스코프에서 시작한다.**
- 변수가 없으면 **상위 스코프로 올라가며 탐색한다.**
- 이 구조를 **스코프 체인(scope chain)**이라고 한다.
- JavaScript는 **렉시컬 스코프**를 사용한다.

---

## 개인 정리

스코프를 직관적으로 이해하는 것은,
코드를 작성해봤다면 어렵지 않다.

그러나 스코프 체인의 구조나 렉시컬 스코프는 정확히 모를 수도 있다고 생각한다.
그래서 개념을 명확히 해 둘 필요가 있다고 생각했다.

JavaScript 엔진이 변수를 찾을 때는
**현재 스코프 → 상위 스코프 → 전역 스코프** 순서로 탐색한다.

특히 JavaScript는 **렉시컬 스코프**를 사용하기 때문에  
함수가 어디에서 호출되는지가 아니라  
**어디에서 선언되었는지**가 스코프를 결정한다는 점이 중요하다.

이 개념은 이후에 배우게 되는 **클로저**를 이해하는 데도  
중요한 기반이 된다.
