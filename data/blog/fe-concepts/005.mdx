## 핵심 요약

- 프로토타입은 객체가 자신에게 없는 프로퍼티나 메서드를 상위 객체를 통해 참조할 수 있게 하는 연결 구조다.
- 프로토타입 체인은 현재 객체에 값이 없을 때 상위 프로토타입으로 올라가며 탐색하는 방식이다.
- 요즘 실무에서 `prototype`을 직접 다루는 경우는 많지 않지만, `class`, 배열 메서드, 상속 구조를 이해하려면 꼭 알아야 한다.

---

>프로토타입이라는 단어는 JavaScript를 공부하다 보면 자주 보이지만, 실제로는 꽤 낯설게 느껴지는 개념이다.
>요즘 프론트엔드 코드에서는 `prototype`을 직접 수정하는 경우가 많지 않고, 대부분 `class` 문법이나 객체 리터럴, 함수형 패턴을 더 자주 사용하기 때문이다.
>
>그런데도 프로토타입은 여전히 중요하다. 배열 메서드가 왜 동작하는지, `class extends`가 내부적으로 어떤 구조인지, 인스턴스가 자신에게 없는 메서드를 어떻게 사용할 수 있는지를 이해하려면 결국 이 개념으로 돌아오게 된다.

## 프로토타입은 무엇일까

프로토타입은 객체가 자신에게 없는 프로퍼티나 메서드를 **다른 객체를 통해 참조할 수 있게 하는 연결 구조**다.

조금 더 직관적으로 말하면,  
객체 입장에서 **“내게 없으면 한 번 더 찾아볼 수 있는 상위 객체”** 라고 이해하면 된다.

자바스크립트는 전통적인 클래스 기반 언어처럼 동작하기보다, 이런 객체 간 연결을 통해 상속과 비슷한 구조를 만든다.  
그리고 그 기반이 바로 프로토타입이다.

## 왜 이 개념을 알아야 할까

처음에는 이런 생각이 들 수 있다.

> 요즘 `prototype` 직접 쓰는 코드 거의 없지 않나?

맞다. 실무에서 `Constructor.prototype.method = ...` 같은 코드를 새로 작성하는 경우는 많지 않다.

하지만 중요한 건 **직접 자주 쓰느냐** 보다, **자바스크립트가 어떻게 동작하느냐** 다.

예를 들어 아래처럼 배열 메서드를 사용할 때,

```js
const arr = [1, 2, 3];
arr.map(x => x * 2);
```

우리는 보통 그냥 자연스럽게 사용한다.  
그런데 `map`은 각 배열이 자기 자신 안에 직접 들고 있는 메서드가 아니다.

즉, 평소에는 잘 드러나지 않지만  
배열 메서드, 인스턴스 메서드 공유, `class` 상속 구조를 이해하려면 결국 프로토타입 개념이 필요하다.

## 프로토타입 체인은 어떻게 동작할까

객체에서 어떤 프로퍼티를 읽으려고 하면, 자바스크립트 엔진은 먼저 **현재 객체 자신**을 확인한다.

여기에 원하는 값이 있으면 바로 사용한다.  
없으면 그다음에는 **연결된 프로토타입**을 확인한다.  
거기에도 없으면 다시 그 상위 프로토타입으로 올라간다.

이렇게 현재 객체에서 시작해서 상위 프로토타입으로 계속 올라가며 값을 찾는 구조를 **프로토타입 체인**이라고 한다.

핵심은 단순하다.

- 먼저 나 자신에게서 찾고
- 없으면 상위 객체에서 찾고
- 체인의 끝에는 `null`이 있으며 접근 결과는 `undefined`가 된다

즉, 객체가 자기 자신에게 없는 메서드를 사용할 수 있는 이유는  
엔진이 거기서 멈추지 않고 **프로토타입 체인까지 탐색하기 때문**이다.

## class와는 어떤 관계가 있을까

이 개념이 중요한 이유 중 하나는, `class` 문법도 결국 프로토타입 기반으로 동작하기 때문이다.

예를 들어 `extends`를 사용하면 겉보기에는 클래스 상속처럼 보인다.

```js
class Animal {
  eat() {
    console.log('eat');
  }
}

class Dog extends Animal {
  bark() {
    console.log('bark');
  }
}
```

이 코드는 Java나 C++ 같은 클래스 상속처럼 보이지만,  
자바스크립트 런타임에서는 결국 **프로토타입 체인**을 통해 메서드를 찾는다.

즉, `class`는 더 읽기 쉬운 문법을 제공할 뿐이고,  
내부 동작의 기반 자체가 완전히 바뀐 것은 아니다.

반대로 TypeScript의 `interface`는 다르다.  
인터페이스는 타입 체크를 위한 문법이라 런타임에는 사라지고, 프로토타입 체인을 만들지 않는다.

## 예시로 알아보기

생성자 함수와 프로토타입을 이용한 예시는 아래처럼 볼 수 있다.

```js
function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

const p1 = new Person('Donghun');

console.log(p1.name); // Donghun
console.log(p1.sayHi()); // Hi, Donghun
```

여기서 `name`은 `p1` 자신이 가진 값이다.  
반면 `sayHi`는 `p1` 객체 안에 직접 들어 있는 메서드가 아니라 `Person.prototype`에 있다.

그런데도 `p1.sayHi()`가 가능한 이유는,  
엔진이 먼저 `p1`에서 `sayHi`를 찾고, 없으면 연결된 프로토타입으로 올라가서 찾기 때문이다.

배열도 같은 방식으로 이해할 수 있다.

```js
const arr = [1, 2, 3];

console.log(arr.hasOwnProperty('map')); // false
console.log(arr.map(x => x * 2)); // [2, 4, 6]
```

`map`은 잘 동작하지만 `hasOwnProperty('map')`는 `false`다.  
즉, `arr` 자신이 `map`을 직접 가진 것은 아니라는 뜻이다.

처음에는 “분명 쓰고 있는데 왜 자기 것이 아니지?” 싶었는데,  
이걸 프로토타입 체인으로 이해하고 나니 배열 메서드가 어디서 오는지 자연스럽게 연결됐다.

## 정리

프로토타입은 객체가 자신에게 없는 프로퍼티나 메서드를 상위 객체를 통해 참조할 수 있게 하는 연결 구조다.  
그리고 프로토타입 체인은 현재 객체에 원하는 값이 없을 때 상위 프로토타입으로 올라가며 탐색하는 방식이다.

요즘 실무에서 `prototype`을 직접 다루는 경우는 많지 않다.  
하지만 그렇다고 중요하지 않은 개념은 아니다.

- 배열 메서드가 왜 동작하는지
- `class`가 내부적으로 어떻게 연결되는지
- 인스턴스 메서드가 어떻게 공유되는지

이런 것들을 이해하려면 결국 프로토타입 개념이 필요하다.

결국 프로토타입은  
**“요즘 잘 안 쓰는 옛 문법”** 이라기보다,  
**자바스크립트의 객체 시스템을 이해하기 위해 꼭 알아야 하는 기반 개념**으로 보는 편이 더 정확하다.
