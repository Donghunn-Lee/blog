호이스팅은 자바스크립트를 배울 때 초반부에 등장하는 개념이다. 그동안 개발을 하면서 호이스팅정도는 당연하게 이해하고 있다고 생각해왔는데, 문득 그래서 호이스팅이 어떻게 이뤄지는지 구체적으로 설명해보자, 하면 말문이 막혔다.

## 1. 호이스팅(Hoisting)

호이스팅이란 JavaScript 엔진이 코드를 실행하기 전에, 변수와 함수의 선언을 **해당 스코프의 최상단으로 끌어올리는 것처럼 보이는 동작**을 말한다. 이는 실제로 코드가 이동하는 것이 아니라, JavaScript 엔진이 **코드를 실행하기 전**에 변수와 함수 선언을 **메모리에 저장**하는 과정을 의미한다.

### 변수 호이스팅
```js
console.log(x);  *// undefined*

var x = 1;

console.log(x);  *// 1*
```
위 코드는 실제로는 다음과 같이 동작한다:

```js
var x;  *// 선언이 최상단으로 끌어올려짐*

console.log(x);  *// undefined*
  
x = 1;  *// 할당은 원래 위치에 남음*

console.log(x);  *// 1*
```

### 함수 호이스팅

```js
sayHello();  *// "Hello"*

function sayHello() {
  console.log("Hello");
}
```

함수 선언문은 전체가 호이스팅되어 선언 전에 호출이 가능하다.

---

## 2. 호이스팅의 특징

### var vs let/const

- `var`: 선언과 초기화가 동시에 호이스팅됨 (`undefined`로 초기화)
- `let/const`: 선언만 호이스팅되고 초기화는 호이스팅되지 않음 (TDZ)

```js
console.log(varVariable);  *// undefined*
console.log(letVariable);  *// ReferenceError*

var varVariable = 1;
let letVariable = 2;
```

### 함수 선언문 vs 함수 표현식

- 함수 선언문: 전체가 호이스팅됨
- 함수 표현식: 변수 호이스팅 규칙을 따름

```js
sayHello();  *// "Hello"*
sayGoodbye();  *// TypeError*

function sayHello() {
  console.log("Hello");
}

var sayGoodbye = function() {
  console.log("Goodbye");
};
```
## 3. 호이스팅의 장단점

### 장점
- 함수 선언문을 코드 하단에 작성해도 사용 가능
- 코드 구조를 더 자연스럽게 작성 가능
- 함수 선언문을 코드 하단에 작성해도 사용 가능
- 코드 구조를 더 자연스럽게 작성 가능

### 단점
- 예측하기 어려운 동작 가능성
- 변수 스코프와 관련된 혼란
- 디버깅이 어려울 수 있음


### 호이스팅 피하기

호이스팅으로 인한 혼란을 피하기 위한 방법들이다. 일반적으로 자바스크립트 코드를 작성할 때 공통적으로 권장되는 사항들이기도 하다.

- var 대신 let과 const 사용
- 함수는 사용하기 전에 선언
- 변수는 스코프의 시작 부분에서 선언
- 함수 표현식 사용 시 주의

## **5. 정리**

호이스팅은 JavaScript의 중요한 특성 중 하나로, **코드의 실행 순서**와 관련된 중요한 개념입니다. 하지만 이는 **실제로 코드가 이동하는 것**이 아니라, JavaScript 엔진이 **코드를 실행하기 전에 변수와 함수 선언을 메모리에 저장하는 과정**을 의미합니다.
