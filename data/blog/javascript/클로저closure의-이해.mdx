>
클로저는 자바스크립트의 개념 중에서도 난해하기로 유명하다. 나 또한 처음 배울 때 정확히 이해하진 못하고, 그저 함수가 중첩되어 선언되었을 때 그 환경을 기억하는 개념 정도로 생각했다. 하지만 상태를 안전하게 변경하고 은닉하기 위해 필요하고 자바스크립트 뿐만 아니라 함수형 프로그래밍 언어에서 모두 사용되는 개념인 만큼, 클로저는 분명하게 알고 가야겠다고 생각했다.

## 1. 클로저란?
우선 클로저의 정의부터 정리하자면 다음과 같다.

>
클로저는 함수와 그 함수가 선언된 렉시컬 환경의 조합이다.
-MDN

글만으로는 그래서 클로저가 무엇인지 쉽게 이해되지 않는다.
렉시컬 스코프는 [이전 포스팅](/blog/javascript/렉시컬-스코프와-스코프-체인/)에서 한 번 다루었으니, 우선은 위 정의에서 **함수가 선언된 렉시컬 환경**이 클로저의 핵심임을 기억하고, 클로저가 어떻게 생성되는지 예시와 함께 살펴보자.

## 2. 클로저의 생성

```js
function outer() {
  let count = 0;  // 외부 함수의 변수

  return function() {  // 내부 함수
    count++;  // 외부 함수의 변수에 접근
    return count;
  }
}

const counter = outer();
console.log(counter());  // 1
console.log(counter());  // 2
console.log(counter());  // 3
```

코드의 실행 결과를 보고 우리는 의문이 들어야 한다. `counter`가 실행될 때마다 `outer`가 실행되는 셈인데, 그렇다면 실행될 때마다 `count`가 초기화되어 `0, 0, 0`이 출력되어야 하지 않을까?

이런 결과가 나타나는 이유는 **클로저**때문이다. 그럼 클로저가 언제 생성되어 어떻게 이 결과를 만들어 내는지 실행 순서대로 확인해보자.

#### 1. outer 함수 정의
`outer`가 정의된다. `outer`는 내부 변수 `count`를 가지고, `count`는 `outer`함수의 스코프 안에 위치한다.

#### 2. outer() 함수 호출
`oute()`가 실행되고, `count`가 0으로 초기화된다. 내부의 익명 함수는 반환되어 `counter`에 저장된다.

**그리고 여기서 클로저가 생성된다.**
- 내부 함수는 `count` 변수에 대한 참조를 유지한다.
- `outer`함수의 실행 컨텍스트는 `counter`에 내부 함수를 할당하면서 종료되었지만, `count`변수는 클로저에 의해 사라지지 않고 보존된다.

#### 3. console.log로 counter()의 반환값을 출력
`counter`가 실행되고, `count`를 증가시키는 이 함수는 클로저를 통해 `count`변수에 접근할 수 있다. `count`를 0에서 1로 증가시키고, 그 반환값이 로그로 출력된다.
이후의 호출 역시 마찬가지로, 결과적으로 매번 같은 `count`변수를 참조하여 값이 유지되고, 2와 3이 이어서 출력된다.

#### outer의 스코프와 클로저
`count`변수는 `outer` 함수의 스코프에 존재한다. 원래 같았으면 `outer` 함수의 종료와 동시에 `count`가 메모리에서 해제되어야 하지만, 클로저가 이를 방지한다. 내부 함수가 `count`를 참조하고 있기 때문에, JavaScript 엔진은 이 변수를 가비지 컬렉션에서 제외하고 유지한다.

## 3. 클로저의 활용

### 데이터 은닉(Information Hiding)
```javascript
function createCounter() {
  let count = 0;  // private 변수
  
  return {
    increment() {
      count++;
      return count;
    },
    decrement() {
      count--;
      return count;
    },
    getCount() {
      return count;
    }
  };
}

const counter = createCounter();
console.log(counter.getCount());    // 0
console.log(counter.increment());   // 1
console.log(counter.increment());   // 2
console.log(counter.decrement());   // 1
```

이 예시에서 `count` 변수는 외부에서 직접 접근할 수 없다. 오직 `increment`, `decrement`, `getCount` 메서드를 통해서만 조작 가능하다. 이는 객체지향 프로그래밍의 캡슐화와 유사한 개념이다.

### 함수 팩토리
```javascript
function createMultiplier(x) {
  return function(y) {
    return x * y;
  };
}

const multiplyByTwo = createMultiplier(2);
const multiplyByThree = createMultiplier(3);

console.log(multiplyByTwo(4));  // 8
console.log(multiplyByThree(4));  // 12
```

이 예시에서 `createMultiplier`는 새로운 함수를 생성하는 팩토리 역할을 한다. 각각의 반환된 함수는 자신만의 클로저를 가지고, `x` 값을 기억한다.

### 이벤트 핸들러
```javascript
function createButton(id) {
  let clickCount = 0;
  
  document.getElementById(id).addEventListener('click', function() {
    clickCount++;
    console.log(`버튼 ${id} 클릭 횟수: ${clickCount}`);
  });
}

createButton('button1');
createButton('button2');
```

이 예시에서 각 버튼은 자신만의 `clickCount`를 가진 클로저를 생성한다. 이는 각 버튼의 클릭 횟수를 독립적으로 추적할 수 있게 해준다.

## 4. 클로저의 주의사항

### 메모리 관리
클로저는 참조하는 변수를 계속 유지하기 때문에, 불필요한 클로저는 메모리 누수의 원인이 될 수 있다.

### 루프에서의 클로저
```javascript
// 잘못된 예
for (var i = 0; i < 3; i++) {
  setTimeout(function() {
    console.log(i);  // 각 반복마다 클로저가 생성되지만 i의 참조값이 동일하여 모두 3이 출력
  }, 1000);
}

// 올바른 예
for (let i = 0; i < 3; i++) {
  setTimeout(function() {
    console.log(i);  // 각 클로저가 모두 다른 참조값의 i를 참조하여 정상적으로 1, 2, 3이 출력
  }, 1000);
}
```

## 5. 정리

클로저는 함수와 그 함수가 선언된 렉시컬 환경의 조합입니다. 함수가 자신이 선언된 환경의 변수를 기억하고, 이 변수에 접근할 수 있는 메커니즘을 제공합니다. 

클로저의 핵심은 **함수가 정의된 시점의 환경을 기억**한다는 점입니다. 이는 함수가 호출되는 위치와 관계없이, 자신이 선언된 위치의 스코프에 있는 변수들에 접근할 수 있게 해줍니다. 이러한 특성은 **데이터 은닉**, **상태 유지**, **모듈화**와 같은 프로그래밍 패턴을 구현할 수 있게 해주며, 특히 JavaScript에서 private 변수를 구현하거나 함수형 프로그래밍을 할 때 매우 유용합니다.

클로저는 스코프 체인을 통해 외부 환경의 변수에 접근할 수 있으며, 이는 함수가 자신이 선언된 환경의 변수들을 '기억'할 수 있는 원리이기도 합니다. 이러한 특성은 코드의 **재사용성**과 **유연성**을 높이며, **함수형 프로그래밍**의 핵심 개념 중 하나로 자리잡고 있습니다.
