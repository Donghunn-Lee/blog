## 1. 왜 실행 컨텍스트를 알아야 할까?

처음 코딩을 시작했을 때부터 **스코프**라는 것은 변수나 함수의 유효 범위라는 것 정도만 직관적으로 이해했었다. 하지만 점점 복잡한 코드를 작성하게 되면서, 함수나 변수의 참조 범위를 까다롭게 고려해야 하는 상황을 마주하고 헷갈리는 내 모습을 보게 되었다. 정확히는 렉시컬 스코프에 대한 부분이었지만, 기본적으로 스코프에 대한 개념을 다시 확실하게 정리해야겠다고 생각했다.

예를 들어, 아래 코드를 한번 보자. 비슷한 상황인데도 결과가 완전히 다르다. 왜 이런 일이 일어나는 것일까?

```js
console.log(name);     // undefined
console.log(age);      // ReferenceError: age is not defined
var name = "John";

function sayHello() {
    console.log(this.name);
}
sayHello();            // "John"
```
이 모든 의문의 중심에는 바로 **실행 컨텍스트(Execution Context)**가 있다.

실행 컨텍스트를 이해한다면,

- **변수 호이스팅**이 왜 발생하는지,
- **스코프**가 어떻게 형성되는지,
- **클로저**가 어떻게 동작하는지,
- 그리고 `this`가 어떻게 결정되는지

이 모든 것의 **원리**를 속 시원하게 알 수 있게 된다. 이 글에서는 실행 컨텍스트의 개념을 중심으로 다루고, 다른 주제는 다른 포스팅에서 따로 다루겠다.

## 2. 실행 컨텍스트란?

자바스크립트가 코드를 실행하기 전에 뭘 할까? 바로 **환경을 먼저 설정**한다. 자바스크립트는 미리 타입을 정해두는 정적 언어가 아니라, 실행 중에 타입을 결정하는 **동적 타입 언어**이자 **인터프리터 기반 언어**이다. 이런 유연함 덕분에 편리하지만, 실행 전에 변수나 함수에 어떤 값이 들어올지 미리 확정할 수 없어서 예상치 못한 오류가 생길 수도 있다.

그래서 자바스크립트 엔진은 코드를 실행하면서 **변수, 스코프, `this` 같은 정보들을 그때그때 결정**해야 한다. 이 정보들을 한데 모아 효율적으로 관리하려고 만든 것이 바로 **실행 컨텍스트**이다.

간단히 말해, **실행 컨텍스트는 자바스크립트 코드가 실행되기 위한 모든 필요한 환경 정보들을 담고 있는 객체**라고 생각하면 된다. 이 객체 안에 변수, 스코프 체인, `this` 같은 핵심 정보들이 들어있는 것이다.

### 실행 컨텍스트의 생성 시점

실행 컨텍스트는 코드가 실행되는 특정 시점에 맞춰 만들어진다.

1. **전역 실행 컨텍스트**: 자바스크립트 코드가 처음 시작될 때 딱 한 번 생성된다. 브라우저 환경에서는 `window` 객체를, Node.js에서는 `global` 객체를 전역 객체로 삼는다고 생각하면 된다.
2. **함수 실행 컨텍스트**: 함수가 **호출될 때마다** 하나씩 생성된다. 함수가 아무리 여러 번 호출되어도, 호출될 때마다 새로운 실행 컨텍스트가 만들어지는 것이다.
3. **`eval()` 실행 컨텍스트**: `eval()` 함수가 실행될 때 생성되지만, 보안이나 성능 문제 때문에 실제 개발에서는 거의 쓰지 않는다.

아래 코드로 실행 컨텍스트가 어떻게 생성되는지 간단한 흐름을 살펴보자.

```js
const global = "전역 변수";

function first() {
    const firstVar = "첫 번째 함수";

    function second() {
        const secondVar = "두 번째 함수";
    }

    second(); // second 함수 호출!
}

first(); // first 함수 호출!
```

이 코드가 실행될 때, 실행 컨텍스트는 다음과 같은 순서로 생성되고 쌓인다:

1. 스크립트가 시작되면서 **전역 실행 컨텍스트**가 가장 먼저 생성되어 스택의 맨 아래에 놓인다.
2. `first()` 함수가 **호출**되면, `first` 함수를 위한 **실행 컨텍스트**가 새롭게 만들어져 스택의 바로 위에 쌓인다.
3. `first` 함수 안에서 `second()` 함수가 **호출**되면, `second` 함수를 위한 **실행 컨텍스트**가 또다시 생성되어 스택의 가장 꼭대기에 쌓인다.

이렇게 실행 컨텍스트는 마치 쌓아 올린 접시처럼 **스택(Stack)** 구조로 관리되는데, 스택의 맨 위에 있는 컨텍스트가 현재 실행 중인 코드의 환경을 담당한다. 함수 실행이 끝나면 해당 컨텍스트는 스택에서 제거된다.

## 3. 실행 컨텍스트의 구성 요소

하나의 실행 컨텍스트는 크게 세 가지 핵심 구성 요소를 가진다. 이 세 가지가 모여서 코드 실행 환경을 완벽하게 정의해 준다.

### Variable Environment (변수 환경)

`Variable Environment`는 실행 컨텍스트가 **처음 생성될 때의 스냅샷**과 같은 역할을 한다.

- 주로 **`var`로 선언된 변수들**과 **함수 선언문(function declaration)**이 저장되는 곳이다.
- 함수의 **매개변수(parameters)** 또한 여기에 저장된다.
- 이 단계에서 `var` 변수는 일단 `undefined`로 초기화되고, 함수 선언은 바로 사용할 수 있게 완전히 초기화된다. 우리가 흔히 말하는 **변수/함수 호이스팅**이 바로 이 `Variable Environment`에서 일어나는 과정이다.

### Lexical Environment (렉시컬 환경)

`Lexical Environment`는 **현재 스코프의 모든 식별자(변수, 함수 선언 등)**와 더불어, 자신을 감싸는 **외부 렉시컬 환경에 대한 참조**를 기록하는 공간이다.

- **`let`과 `const`로 선언된 변수**가 주로 저장되는 곳이다. 중요한 건 얘네들은 이 단계에서 아직 초기화되지 않고 **TDZ(Temporal Dead Zone)**라는 곳에 머물러 있다가, 실제 코드 실행 단계에서 변수 선언문에 도달해야 비로소 초기화된다는 점이다.
- 이 `Lexical Environment`는 **스코프 체인(Scope Chain)을 형성하는 가장 중요한 요소**이다. 각 렉시컬 환경은 자신을 둘러싸는 **외부 렉시컬 환경(Outer Lexical Environment Reference)**에 대한 참조를 가지고 있어서, 변수를 찾을 때 이 참조를 따라 상위 스코프로 쭉 거슬러 올라갈 수 있게 해준다.

### This Binding

`This Binding`은 실행 컨텍스트가 생성될 때, 해당 컨텍스트 내에서 `this` 키워드가 **어떤 객체를 가리킬지 결정**하는 부분이다.

- `this`의 값은 함수가 **어떤 방식으로 호출되었는지**에 따라 동적으로 달라진다. 일반 함수 호출, 메서드 호출, `call`/`apply`/`bind` 메서드 사용, 화살표 함수 등 다양한 호출 방식에 따라 `this`가 바라보는 대상이 결정되는 규칙이 적용된다.

## 4. 실행 컨텍스트의 생성 과정

실행 컨텍스트는 크게 두 단계를 거쳐 생성된다. 이 과정은 매우 빠르게 진행되며, 자바스크립트 엔진이 코드를 실행하기 전 환경을 완벽하게 준비하는 핵심 단계라고 할 수 있다.

### 생성 단계 (Creation Phase)

코드가 실제로 실행되기 전, 해당 실행 컨텍스트가 스택에 올라올 때 이 단계가 진행된다.

1. **Lexical Environment 생성:**
    - 먼저 현재 스코프의 모든 식별자(매개변수, 함수 선언, `var`, `let`, `const` 변수)를 싹 모아서 초기화한다.
    - 특히 `let`과 `const` 변수는 이 단계에서 선언만 되고, 아직 `undefined`로 초기화되지 않은 채 **TDZ**에 머무른다.
    - 그리고 가장 중요한 **외부 렉시컬 환경에 대한 참조(Outer Lexical Environment Reference)**를 설정해서, 나중에 스코프 체인을 통해 외부 스코프에 접근할 수 있는 길을 만든다.
2. **Variable Environment 생성:**
    - `Lexical Environment`가 만들어진 다음, `Variable Environment`가 생성된다.
    - 여기서 **`var`로 선언된 변수**는 `undefined`로 초기화되고, **함수 선언문**은 아예 완전히 초기화되어 바로 실행 가능한 상태가 된다. 이게 바로 `var` 변수와 함수 선언이 마치 코드 맨 위로 '끌어 올려지는' 것처럼 보이는 **호이스팅의 실체**이다.
3. **This Binding 결정:**
    - 마지막으로, 함수가 어떤 방식으로 호출될지에 따라 `this`의 값이 결정되어 해당 컨텍스트에 바인딩된다.

### 실행 단계 (Execution Phase)

생성 단계가 완벽하게 끝나면, 이제 자바스크립트 엔진은 코드를 **위에서 아래로 순차적으로 실행**하기 시작한다.

- 변수에 실제 값이 **할당**된다.
- 함수가 **호출**되면, 해당 함수를 위한 **새로운 실행 컨텍스트**가 또다시 생성되어 스택에 푸시되고, 다시 생성 단계부터 반복된다.
- 이 단계에서 `let`과 `const` 변수는 선언문이 실행되기 전까지는 TDZ에 머물러 있기 때문에, 만약 이때 접근하려고 하면 `ReferenceError`가 발생하게 된다.

## 5. 실행 컨텍스트와 다른 개념들의 관계

실행 컨텍스트는 자바스크립트의 여러 핵심 개념들과 아주 밀접하게 얽혀 있다. 실행 컨텍스트를 이해한다는 건, 이 개념들을 따로따로 보는 게 아니라 **하나의 큰 그림 안에서 통합적으로 이해**할 수 있다는 의미이다.

- **호이스팅**: 실행 컨텍스트의 **생성 단계**에서 변수와 함수 선언이 메모리에 미리 할당되는 과정 덕분에 발생하는 현상이다.
- **스코프**: `Lexical Environment`가 **스코프 체인**을 형성하면서 변수의 접근 범위를 결정하는 규칙을 만들어낸다. 어떤 변수에 접근할 수 있고, 어디까지 탐색해야 하는지 등의 규칙이 여기서 정의되는 것이다.
- **클로저**: 함수가 **자신이 정의될 때의 `Lexical Environment` (스코프 체인)**를 '기억'하고, 나중에 호출될 때 그 환경의 변수에 접근할 수 있는 강력한 기능이다. 실행 컨텍스트의 렉시컬 환경이 클로저의 핵심적인 작동 메커니즘을 제공하는 것이다.
- **`this`**: 실행 컨텍스트가 생성될 때 **`This Binding`** 구성 요소를 통해 `this`의 값이 결정된다. 우리가 종종 헷갈려 하는 `this`의 동적인 동작 방식이 바로 실행 컨텍스트의 생성 시점과 함수 호출 방식에 따라 결정되는 것이다.

## 6. 정리

### 실행 컨텍스트 (Execution Context)

**실행 컨텍스트**는 자바스크립트 코드가 실행되기 위한 환경을 제공하는 **핵심 객체**입니다. 코드가 실행되기 전, **변수, 스코프, `this`** 등의 모든 실행에 필요한 정보를 미리 담고 준비합니다. 이는 자바스크립트가 동적 타입 언어이면서도 안정적으로 동작할 수 있는 근본적인 이유가 됩니다.

실행 컨텍스트는 코드가 실행되는 시점(전역 코드 실행, 함수 호출 등)에 따라 생성되어 **스택** 구조로 관리되며, 각각의 컨텍스트는 **`Variable Environment`**, **`Lexical Environment`**, **`This Binding`**의 세 가지 주요 구성 요소를 가집니다.

이러한 실행 컨텍스트의 동작 방식은 자바스크립트의 여러 핵심 개념들을 설명합니다. 예를 들어, 실행 컨텍스트의 **생성 단계**에서 변수와 함수 선언이 메모리에 미리 할당되는 것이 **호이스팅** 현상으로 나타나고, `Lexical Environment`는 **스코프 체인**을 형성하여 변수의 유효 범위를 결정하며, 함수가 정의될 때의 `Lexical Environment`를 기억하게 함으로써 **클로저**를 가능하게 합니다. 또한, 실행 컨텍스트가 생성될 때 **`This Binding`**을 통해 `this`의 값이 결정되기도 합니다.

결론적으로, 실행 컨텍스트는 자바스크립트 코드가 실제로 어떻게 해석되고 실행되는지를 이해하는 데 필수적인 개념이며,  **더 예측 가능하고 견고한 코드**를 작성할 수 있게 합니다.
