처음 코딩을 시작했을 때부터 스코프라는 것은 변수나 함수의 유효범위 라는 것 정도만 직관적으로 이해했었다. 하지만 점점 복잡한 코드를 작성하게 되면서, 함수나 변수의 참조 범위를 까다롭게 고려해야하는 상황을 마주하고 헷갈리는 내 모습을 보게 되었다. 정확히는 렉시컬 스코프에 대한 부분이었지만, 기본적으로 스코프에 대한 개념을 다시 확실하게 정리해야겠다고 생각했다.

## 1. 스코프(Scope)

스코프란 **변수**와 **함수**의 접근성과 생존 기간을 결정하는 규칙이다. 선언된 변수가 있을 때, 이를 참조하려고 하는 위치의 스코프에 따라 참조 가능 여부를 결정한다.

### 스코프의 종류
스코프에는 그 참조 범위에 따라 **전역 스코프**, **함수 스코프**, **블록 스코프** 까지 3가지로 분류할 수 있다.

```js
let global = "전역";  // 전역 스코프

function func() {
    let functionScope = "함수";  // 함수 스코프
    
    if (true) {
        let blockScope = "블록";  // 블록 스코프
    }
}
```

1. 전역 스코프:
- 브라우저 환경에서는 `<script>` 태그로 연결된 파일들 간에 공유
- Node.js 환경에서는 각 파일이 독립적인 모듈로 취급
- 전역 객체(window 또는 global)를 통해 접근 가능
  
2. 함수 스코프: 현재 함수 내에서만 참조 가능
3. 블록 스코프: 현재 블록 안에서만 참조 가능

함수와 블록 스코프는 직관적이지만, 전역은 위와 같이 실행 환경에 따라 조금씩 다르게 취급된다.

## 2. 렉시컬 스코프(Lexical Scope)

정적 스코프(Static Scope)라고도 한다.

렉시컬 스코프는 프로그래밍 언어에서 **변수의 유효 범위(Scope)**를 결정하는 방식 중 하나이다. 코드가 작성된 시점(정적, 컴파일 시점)에 변수의 유효 범위가 결정된다는 의미이다.

> Lexical이란 단어는 직역하면 '어휘적인', '사전적인'이라는 뜻이다. 처음엔 단어 의미랑 렉시컬 스코프랑 잘 매칭이 안 됐는데, 우리가 사전에서 특정 글자를 기준으로 단어를 찾아가듯이, 렉시컬 스코프도 코드가 작성된 시점, 위치를 기준으로 유효 범위가 결정된다고 생각하면 얼추 이해할 수 있었다.

### 렉시컬 스코프의 핵심 원리

#### 1. 코드가 작성된 물리적 위치
변수의 유효범위는 해당 변수가 선언된 함수 또는 블록이 **코드 상에서 어디에 위치하는지**에 따라 결정된다.

#### 2. 함수 정의 시점
함수 내부에서 외부 변수에 접근할 수 있는지 여부는 **함수가 정의될 때** 이미 결정된다. 함수가 어디에서 호출되든, 이 정의 시점의 스코프 체인을 따라 변수를 찾는다.

#### 3. 스코프 체인(Scope Chain)
어떤 변수에 접근하고자 할 때, 연결된 스코프를 따라 변수를 찾는 과정에서 이 스코프의 연속을 **스코프 체인**이라고 한다. 뒤에서 좀 더 정확히 알아보겠다.

```js
function outer() {
  const outerVar = "I am from outer";

  function inner() {
    const innerVar = "I am from inner";
    console.log(outerVar); // inner 함수가 정의될 때 outer 함수의 스코프에 접근 가능
    // console.log(anotherVar); // 에러: anotherVar는 inner의 스코프 체인에 없음
  }

  return inner;
}

const myInnerFunc = outer(); // outer 함수를 호출하여 inner 함수를 반환받음
myInnerFunc(); // inner 함수를 실행. outer 함수는 이미 실행이 끝났지만 outerVar에 접근 가능!

//---------------------------------------------------------

const globalVar = "I am global";

function funcA() {
  const varA = "I am A";
  console.log(globalVar); // funcA는 전역 스코프에 접근 가능

  function funcB() {
    const varB = "I am B";
    console.log(globalVar); // funcB는 전역 스코프에 접근 가능
    console.log(varA);      // funcB는 funcA 내부에서 정의되었으므로 varA에 접근 가능 (렉시컬 스코프)
  }

  funcB();
}

funcA();
```
예시를 기준으로 조금 더 살펴보겠다.
- `inner`함수는 `outer`함수 안에서 정의되었기 때문에, `inner`가 실행될 때 `outer`의 스코프 안에 있는 `outerVal`에 접근할 수 있다.
- `myInnerFunc`는 `outer`가 반환한 `inner`이다. `outer`는 이미 실행을 마쳤지만, `inner`는 자신이 정의될 때의 환경(colosure, 클로저. 다른 게시글에서 따로 다룸)을 기억하고 있으므로 `outerVar`에 여전히 접근할 수 있다.
- `funcB`는 `funcA` 내부에서 정의되었기 때문에, `funcA`의 스코프에 있는 `varA`에 접근 가능하다. `funcB`가 어디에서 호출되든, 정의된 곳에서의 스코프(`funcA`의 내부)를 기억한다.

## 3. 스코프 체인
스코프 체인이란 앞서 변수를 찾을 때 확인하는 스코프의 연속이라고 했다. 조금 더 정확히 얘기하자면

스코프 체인은 일종의 리스트로써 전역 객체와 중첩된 함수의 스코프의 참조를 차례로 모두 저장하고, 각각의 스코프가 어떻게 연결되고 있는지 보여주는 것을 말한다.

### 스코프 체인의 핵심 원리

1. 현재 스코프에서 시작
어떤 코드 블록이나 함수에서 변수를 참조하면, 해당 변수를 찾는 탐색은 현재 실행중인 스코프에서 시작된다.

2. 외부 스코프로 연결
현재 스코프에서 변수를 찾지 못하면, 그 변수를 둘러싼 **외부(상위) 스코프)**로 탐색 범위를 확장한다.

3. 정적 결정
이 외부 스코프는 코드가 작성된 물리적 위치에 따라 결정된다. 호출 위치에 상관 없이, 앞서 살펴본 렉시컬 스코프에 의해 스코프 체인이 결정된다.

4. 전역 스코프 탐색
찾고자 하는 변수를 찾을 때까지, 상위 스코프를 거슬러 탐색해 올라가며 최종적으로 최상위의 **전역 스코프**까지 탐색한다.

5. 탐색 실패 시 에러
전역 스코프에서도 변수를 찾지 못한 경우, 해당 변수는 정의되지 않은 것으로 간주되어 `ReferenceError`와 같은 오류가 발생한다.

### 스코프 체인 예시
```js
const globalVar = "전역 변수"; // 스코프 3: 전역 스코프

function outer() {
  const outerVar = "외부 함수 변수"; // 스코프 2: outerFunction의 스코프

  function inner() {
    const innerVar = "내부 함수 변수"; // 스코프 1: innerFunction의 스코프

    console.log(innerVar);  // 스코프 1에서 찾음
    console.log(outerVar);  // 스코프 1에 없으므로 스코프 2로 올라가서 찾음
    console.log(globalVar); // 스코프 1, 2에 없으므로 스코프 3(전역)으로 올라가서 찾음
    // console.log(nonExistentVar); // 스코프 1, 2, 3 어디에도 없으므로 ReferenceError
  }

  inner();
}

outer();
```

#### 스코프 체인 형성

- `inner` 의 스코프 체인:

  - `inner`의 자체 스코프 (스코프 1)
  - `outer`의 스코프 (스코프 2)
  - 전역 스코프 (스코프 3) (`inner`가 변수를 찾을 때는 이 스코프 1 -> 스코프 2 -> 스코프 3 순서로 탐색.)
  
- `outer` 의 스코프 체인:

  - `outer`의 자체 스코프 (스코프 2)
  - 전역 스코프 (스코프 3) (`outer`가 변수를 찾을 때는 이 스코프 2 -> 스코프 3 순서로 탐색.)

## 4. 렉시컬 스코프의 장점
정적 스코프라고 불리기에 그러면 동적 스코프와는 어떤 차이가 있는지 궁금할 수 있다. 먼저 렉시컬 스코프의 장점을 얘기하자면 다음과 같다.

#### 1. 예측 가능성
코드를 읽는 사람의 입장에서 변수의 유효 범위를 쉽게 파악할 수 있어 코드가 더 이해하기 쉽고, 예측 가능하게 된다.

#### 2. 안정성
스코프가 동적으로 변하지 않기 때문에 예상치 못한 참조로 인한 버그의 발생 가능성이 현저히 낮아진다.

#### 3. 클로저 구현 가능성
클로저는 매우 유용하고 강력한 프로그래밍 패턴을 구현 가능하게 하는 렉시컬 스코프의 특징이다. 앞서 살펴 본 예시처럼 선언시의 환경을 기억한다는 점은 상태 유지, 은닉 등 유용한 이점을 만든다.

앞서 한 번 얘기했듯이 중요한 개념이기에 따로 한 번 더 다루겠다.


### 그렇다면 동적 스코프는?

동적 스코프는 말 변수의 유효 범위가 **함수가 호출된(실행된) 위치**에 따라 결정된다. **렉시컬 스코프의 장점이 모두 충족되지 않는다**고 이해하면 쉽다. 코드만 보는 것이 아니라 런타임에서 실행되는 흐름을 모두 정확히 파악해야만 스코프를 예측할 수 있고, 예측이 어려운 만큼 버그도 유발하기 쉽다.

현대 사용되는 거의 모든 프로그래밍 언어(JavaScript 외에 Python, C/C++, Java, C#, Ruby 등등)가 동적 스코프가 아닌 정적 스코프, 즉 렉시컬 스코프를 사용하는지를 어렵지 않게 이해할 수 있다.

## 5. 정리

### 렉시컬 스코프 (Lexical Scope)

**렉시컬 스코프**는 **코드가 작성된(정의된) 물리적 위치**에 따라 변수와 함수의 유효 범위가 결정되는 방식을 의미합니다. 이는 **정적 스코프(Static Scope)**라고도 불리며, 함수가 호출되는 시점과 관계없이 코드를 읽는 것만으로 스코프를 예측할 수 있다는 것이 핵심입니다. 이러한 특성은 코드의 **예측 가능성**과 **안정성**을 높이며, **클로저(Closure)**와 같은 강력한 패턴을 가능하게 하는 기반이 됩니다.

### 스코프 체인 (Scope Chain)

**스코프 체인**은 변수나 함수를 찾을 때, **연결된 스코프들을 탐색하는 일련의 순서**를 말합니다. 변수를 참조할 때 **현재 스코프**에서 먼저 찾고, 없으면 **자신을 둘러싼 상위 스코프**로 차례대로 올라가 **전역 스코프**까지 탐색하게 됩니다. 이 탐색 경로는 렉시컬 스코프에 따라 **코드가 정의된 시점에 정적으로 결정**됩니다. 스코프 체인을 통해 외부 스코프의 변수에 접근하는 것이 가능하며, 이는 클로저가 외부 환경의 상태를 '기억'할 수 있는 원리이기도 합니다.
