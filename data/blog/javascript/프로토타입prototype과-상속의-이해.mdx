리엑트를 주로 사용한다면 아마도 class를 사용하게 되는 일은 많지 않을 것이다. 리엑트는 기본적으로 함수형 컴포넌트가 여러 방면으로 효율적이기 때문이다. 그래서 프로토타입에 대해서는 몇 번 들어보거나 디버깅 할 때 봤을 뿐 자세한 개념에 대해선 알지 못하고 있었다. 문득 디버깅시 보이는 프로토타입은 어떤 것인지 궁금해서 찾아보니, 자바스크립트는 객체지향 언어임과 동시에 프로토타입 기반의 언어라는 사실을 깨달았다. 모듣 객체가 프로토타입 기반으로 이루어져있다는 사실을 알고, 나는 이 프로토타입이란 것을 정확히 알아야겠다고 생각했다.


## 1. 프로토타입


프로토타입은 자바스크립트에서 **객체가 다른 객체의 속성과 메서드를 상속**받을 수 있게 해주는 메커니즘이다. **모든 객체**는 자신의 프로토타입을 참조하는 `[[Prototype]]` 내부 슬롯을 가지고 있으며, 이는 `__proto__` 접근자 프로퍼티를 통해 접근할 수 있다.

```javascript
const person = {
    name: 'John',
    age: 30
};

console.log(person.__proto__ === Object.prototype); // true
```

### 프로토타입 객체
프로토타입 객체는 생성자 함수로 생성된 객체가 공유하는 프로퍼티와 메서드를 포함하는 객체이다. 이 객체는 `prototype` 프로퍼티를 통해 접근할 수 있다.

```javascript
function Person(name) {
    this.name = name;
}

Person.prototype.sayHello = function() {
    console.log(`Hello, I'm ${this.name}`);
};

const person1 = new Person('John');
const person2 = new Person('Jane');

person1.sayHello(); // "Hello, I'm John"
person2.sayHello(); // "Hello, I'm Jane"
```
여기서 `Person.prototype`이 프로토타입 객체이고, `sayHello`는 프로토타입 객체의 메서드가 되는 셈이다.

---

## 2. 프로토타입 체인

프로토타입 체인은 객체의 프로퍼티에 접근할 때, 해당 객체에 프로퍼티가 없다면 프로토타입을 따라 올라가면서 프로퍼티를 찾는 메커니즘이다.

```javascript
const parent = {
    name: 'Parent',
    sayHello() {
        console.log(`Hello, I'm ${this.name}`);
    }
};

const child = {
    name: 'Child'
};

// child의 프로토타입을 parent로 설정
Object.setPrototypeOf(child, parent);

child.sayHello(); // "Hello, I'm Child"
```

이 예시에서 `child` 객체는 `sayHello` 메서드를 직접 가지고 있지 않지만, 프로토타입 체인을 통해 `parent`의 메서드를 사용할 수 있다.

### 프로토타입 체인의 동작 방식
1. 객체의 프로퍼티에 접근할 때, 해당 객체에 프로퍼티가 있는지 확인한다.
2. 없다면, 객체의 프로토타입을 확인한다.
3. 프로토타입에도 없다면, 프로토타입의 프로토타입을 확인한다.
4. 이 과정을 프로토타입 체인의 끝까지 반복한다.

프로토타입을 거슬러 올라가 확인하는 방식은 스코프 체인을 따라가 식별자를 찾는 것과도 비슷하고, 자식 클래스에서 부모 클래스의 요소를 찾는 과정과 동일하다.

## 3. 생성자 함수와 프로토타입

자바스크립트에서 객체를 생성하는 방법 중 하나는 생성자 함수를 사용하는 것이다. 생성자 함수는 `prototype` 프로퍼티를 가지며, 이 프로퍼티는 생성자 함수로 생성된 객체의 프로토타입이 된다.

```javascript
function Person(name) {
    this.name = name;
}

Person.prototype.sayHello = function() {
    console.log(`Hello, I'm ${this.name}`);
};

const person1 = new Person('Lee');
const person2 = new Person('Kim');

person1.sayHello(); // "Hello, I'm Lee"
person2.sayHello(); // "Hello, I'm Kim"
```

### 생성자 함수의 동작 방식
1. `new` 연산자로 생성자 함수를 호출하면, 빈 객체가 생성된다.
2. 생성된 객체의 프로토타입은 생성자 함수의 `prototype` 프로퍼티가 가리키는 객체로 설정된다.
3. 생성자 함수 내부의 `this`는 생성된 객체를 가리킨다.
4. 생성자 함수가 반환하는 객체가 없다면, 생성된 객체가 반환된다.

프로토타입을 잘 알지는 못했지만 우리는 아마 `new`에 대해선 익숙하다. 단순히 배열을 만들 때도 `new Array()`등을 사용한 경험이 있을 것이다.

## 4. ES6의 class와 프로토타입

우선 지금 우리가 사용하는 `class`문법은 2015년 ES6에서 도입된 문법이다. 프로토타입 기반 상속을 더 쉽게 사용할 수 있도록 하는 `synatactic sugar`로써 도입된 것인데, 이전에는 프로토타입 문법만이 사용되었다. 하지만 `class`는 `syntactic sugar`일 뿐, 내부적으로는 여전히 `prototype`을 사용한다.

```javascript
class Person {
  constructor(name) 
    this.name = name;
  }

  sayHello() {
    console.log(`Hello, I'm ${this.name}`);
  }
}

class Student extends Person {
  constructor(name, grade) {
    super(name);
    this.grade = grade;
  }
}

const student = new Student('Lee', 'A');
student.sayHello(); // "Hello, I'm Lee"
```

### class의 동작 방식
1. `class`는 생성자 함수의 문법적 설탕(syntactic sugar)이다.
2. `extends` 키워드는 프로토타입 체인을 설정한다.
3. `super()`는 부모 생성자 함수를 호출한다.

## 5. 프로토타입의 활용

### 메서드 공유
프로토타입을 통해 메서드를 공유함으로써 메모리를 효율적으로 사용할 수 있다. 우리가 `new Array`로 배열을 생성했을 때, 내장된 배열의 메서드들을 사용하는 것은 각각의 메서드가 따로 있는 게 아니라, `Array`라는 프로토타입 객체에 있는 메서드를 사용하는 것이다.

### 상속 구현
프로토타입 체인을 통해 상속을 구현할 수 있다. 앞서 말햇듯 이는 자바스크립트나 자바에서 사용하는 방식과 크게 다를 것이 없다.

### 동적 프로퍼티 추가
프로토타입에 프로퍼티를 추가하면, 해당 프로토타입을 참조하는 모든 객체에 즉시 반영된다. 프로토타입 기반으로 데이터를 구성한다면 유지보수성이 높아지는 셈이다.

---

## 6. 주의사항

### 프로토타입 오염
프로토타입에 프로퍼티를 추가할 때는 주의가 필요하다. 모든 객체에 영향을 미칠 수 있기 때문이다. 같은 프로토타입을 가진 모든 객체가 영향을 받을 수밖에 없다.

### 성능 고려
프로토타입 체인이 깊어질수록 프로퍼티 접근 속도가 느려질 수 있다.

---

## 7. 정리

프로토타입은 자바스크립트에서 객체지향 프로그래밍을 구현하는 핵심 메커니즘입니다. 객체 간의 상속을 가능하게 하고, 메서드와 프로퍼티를 효율적으로 공유할 수 있게 해줍니다. ES6의 `class` 문법은 프로토타입 기반 상속을 더 쉽게 사용할 수 있게 해주지만, 내부적으로는 여전히 프로토타입을 사용합니다. 프로토타입을 이해하면 자바스크립트의 객체지향적 특성을 더 깊이 이해할 수 있습니다.
